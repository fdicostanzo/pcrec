# src/findings — the shipped analyses ([FINDINGS])

The findings STORE: every analysis pcrec ships, as the same `.rxt` text a
user would write (`docs/spec/findings.md`, `docs/design/findings/design.md`
§8). Nothing here is compiled as library source by the `LIBSRCS` wildcard;
the Makefile compiles the store into `libpcrec` through two generated files
(`src/core/findings_store.inc`, `findings_table.inc`, COMMITTED and
regenerated by `make gen-findings` — a source tree must compile with no build
step, the Makefile's B1 comment says why), which `src/core/findings.c`
includes.

## Files

- **default.rxt** — the one AUTHORED analysis (step B1): the built-in
  terminal of every chain (by identity, never by name). A `freq` block whose
  256 counts are exactly the static byte-frequency prior `src/opt/prefix_k.c`
  shipped before B1, so it normalizes to that table entry for entry (design
  §0.7), and whose one `serves byte-rate when byte via unigram` line is the
  `byte`-only restriction D123-4 required to be written into the data. Its
  header carries where the numbers come from (moved from `prefix_k.c`). An
  edit here moves the `<PREFIX>_FINDINGS` digest of every artifact that
  consumed it; `tests/findings/` pins it to `tests/findings/default_ppm.tsv`.

- **log.rxt** — [B5] the shipped `log` analysis, GENERATED by
  `third_party/synth-log-lines-v1/generate.py` (the analyzer over a
  SYNTHESIZED Hadoop-DataNode-shaped corpus, `fidelity synthesized`): a
  `freq` block serving `byte-rate` under `byte` and a `cpfreq` block serving
  it under `utf8` via `encode-utf8`. Never edit by hand.
- **weblog.rxt** — [B5] the shipped `weblog` analysis, GENERATED by
  `third_party/elastic-examples-apache-logs-bc53b584/generate.py` (Apache
  combined-log request lines, Apache-2.0): the same two blocks. Never edit
  by hand.

`make gen-tables` regenerates the two generated bundles AND the store;
`make test-findings` sec. 12 fails when either is stale against its corpus,
finding each generator from the bundle's own provenance `source` (the
`third_party/` directory's name), so a new generated bundle needs no edit
there. Neither is consulted unless a compile names it: the chain of a
compile naming nothing is `default` alone.

The TEXT embed is `scripts/embed_text.sh` (`findings_store.inc`) and the
PRE-PARSE `scripts/findgen.c` (`findings_table.inc`; it lives outside `src/`
because fifteen test scripts compile every `src/**/*.c` into a reference
compiler, and a second `main` there would break them all).

Maintenance: update this file when files are added/removed or change role.
