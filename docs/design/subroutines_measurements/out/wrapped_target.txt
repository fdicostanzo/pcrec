=== AXIS Z0: A CALLEE DEFINED INSIDE `X{0}` =========================
# The classic pre-DEFINE idiom: a group that exists ONLY to be called,
# parked under a {0} repeat so it never runs lexically. pcrec emits
# NO CODE and allocates NO SLOTS for X{0} (probe_slotcount.py axis C),
# so the callee region has no slot instances counted for it -- the
# out-of-bounds write vm_count_slots' own header names (K27's class).
# These are the cells that make that a REAL construct family and not a
# hypothetical.
  ^(?:(?<g>a|ab)){0}(?&g)c$              'abc'      ((0, 3), [None])                # and the callee RETRIES into ab
  ^(?:(?<g>a|ab)){0}(?&g)c$              'ac'       ((0, 2), [None])                # control: first alternative suffices
  ^(x)?(?:(a(?2)?b)){0}(?2)$             'aabb'     ((0, 4), [None, None])          # a RECURSIVE callee in {0}
  ^(x)?(?:(a(?2)?b)){0}(?2)$             'ab'       ((0, 2), [None, None])          # control: depth 1
  ^(?:((?>a|ab))){0}(?1)z$               'az'       ((0, 2), [None])                # an ATOMIC callee in {0}
  ^(?:((?>a|ab))){0}(?1)z$               'abz'      None                            # and the atomicity travels WITH the callee: nomatch, because the (?> is INSIDE the group and is part of the body, unlike axis W3 where it WRAPS the group
  ^(?:(a?)){0}(?1)*b$                    'b'        ((0, 1), [None])                # a rung-bearing callee in {0}
  ^(?:((a)(?1)?(b))){0}(?1)$             'aabb'     ((0, 4), [None, None, None])    # three groups, recursive, in {0}
# CONTROLS -- the same callees WITHOUT the {0} wrapper:
  ^(?:(?<g>a|ab))?(?&g)c$                'abc'      ((0, 3), [None])                # optional instead of {0}

# W5 -- target inside a POSITIVE LOOKAHEAD, and inside a lookahead
#       nested in a quantified group.
  ^(?=(a|ab))..(?1)$                     'abab'     ((0, 4), [(0, 1)])            
  ^((?=(b))|a)+(?2)$                     'ab'       ((0, 2), [(1, 1), (1, 2)])    

# THE READING, AND IT IS THE EXIT -- NOT THE ENTRY. Every W row matches.
# An earlier version of this paragraph said a callee reached by jumping
# into its lexical position would inherit the LOOKBEHIND'S BACK-STEP.
# THAT WAS INVERTED (R34 V-6): lookaround_design.md §3.2-3.4 put the
# wrapper's machinery at L_entry / L_b_i (BEFORE L_body_i) and at
# L_ok / L_body_won / L_end_i (AFTER the body), so a jump to the GROUP's
# own label -- which lives inside the assertion's body -- lands AFTER
# the back-step. The back-step does not run and the cursor is already
# the call site's. The ENTRY is fine.
#
# What breaks is the EXIT. Falling out of the body reaches:
#   W1  L_end_i's end-check `pos != slot_values[SLOT_LOOK_POS]` -- a
#       comparison against the ASSERTION's saved position, meaningless
#       for a call -- then L_ok's RX_CUT and POSITION RESTORE, which
#       would throw the callee's consumed bytes away;
#   W2  the negative assertion's L_body_won: cut, then fail;
#   W3  the atomic group's exit cut, discarding the retry's choice
#       points -- nomatch where 10.46 matches;
#   Z0  nothing to fall out of: no code is emitted at all.
# So the rule is not "a wrapped target needs special handling"; the
# callee region needs ITS OWN EXIT, which is true of EVERY called
# group. Design §5.4, §6.3 and S-SR18 are written that way.
