=== R1.5: THE CONFOUND -- START-OPTIMIZE can turn a would-be -52 ====

# Found DURING this probe's own first run: five R1/R3 cells the rule

=== R3: NULLABLE PREFIX -- (P) depends on whether the prefix has ====
=== anything LEFT to eat, not on whether it ever ate anything ========
# x* is greedy: at the FIRST call it eats every available x in one
# bite, landing the recursion at a position beyond where any second
# same-group entry can ever reach (nothing left for x* to eat at the
# next level down) -- so predicate (P) is satisfied from the SECOND
# within-recursion attempt onward exactly as in R1, REGARDLESS of how
# many x's were actually present. This refines design §3.3's L3/L5
# findings (all measured -52) by explaining WHY: it is never about
# 'did the prefix advance the position at all', only about 'is there
# anything left for it to eat on the NEXT attempt'.

  ^(x*(?1)b)$                                'bb'           predict=RC:-52                 got=RC:-52             OK  # x* eats 0, nothing to differ next time

  ^(x*(?1)b)$                                'xxb'          predict=RC:-52                 got=RC:-52             OK  # x* eats every x on the FIRST attempt; the SECOND attempt (one level down) has none left, so (P) still trips one level in

=== R4: THE WHOLE-MATCH ABORT -- `return`, not `RRETURN` ============
# -52 is returned directly from match(), not routed through the
# ordinary backtrack-and-try-the-next-alternative machinery. So a
# TOP-LEVEL sibling alternative that never goes near the recursion at
# all should be UNREACHABLE once -52 fires on an earlier alternative
# -- decisive because a naive reader would expect PCRE2 to fall
# through to '|^Y$' the way an ordinary failed branch would.

  ^Y$                                        'Y'            predict=MATCH:((0, 1), [])     got=MATCH:((0, 1), []) OK  # control: bare alternative target matches on its own (sanity baseline, no recursion involved)
  ^Z$|^Y$                                    'Y'            predict=MATCH:((0, 1), [])     got=MATCH:((0, 1), []) OK  # control: an ORDINARY failed first alternative DOES fall through
  ^(a|(?1)a)$|^Y$                            'Y'            predict=RC:-52                 got=RC:-52             OK  # the runaway first alternative's -52 ABORTS the whole match before the second top-level alternative is ever tried -- 'Y' matches '^Y$' on its own (previous cell) but the compound pattern still -52s
  ^Y$|^(a|(?1)a)$                            'Y'            predict=MATCH:((0, 1), [None]) got=MATCH:((0, 1), [None]) OK  # order matters: recursion as the SECOND alternative is never reached at all when the first already matches -- confirms this is really about the FIRST alternative's own abort, not some pattern-wide veto

=== R6: (A) NEAREST-ANCESTOR-OF-THE-SAME-GROUP, not 'any ancestor' ===
# a chain that cycles through THREE distinct groups (p->q->r->p) only
# re-enters group p every THIRD hop; the search walks the WHOLE
# last_group_offset chain (not just the immediate parent) to find it
# there, so the rule predicts the guard still fires -- but only once
# the SAME group truly recurs, never on a hop to a DIFFERENT group.

  ^(?(DEFINE)(?<p>(?&q)a)(?<q>(?&r)a)(?<r>(?&p)a))(?&p)$ 'a'            predict=RC:-52                 got=RC:-52             OK  # 3-node same-position cycle p->q->r->p: (A) must walk 3 frames up the chain (past q and r) to find the nearest 'p' ancestor
  ^(?(DEFINE)(?<p>x(?&q)a)(?<q>x(?&r)a)(?<r>x(?&p)a))(?&p)$ 'xxxxxxaaaaaa' predict=not RC:-52             got=NOMATCH            OK  # same 3-node cycle, each edge now consumes: predicate (P) can never hold between two 'p' entries either, exactly like R2's 2-node case
