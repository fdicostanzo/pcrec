4. FOLD BEFORE NEGATE, over UTF
==========================================================================
  OS-1/D23's rule, restated: the fold is applied to the class
  BEFORE the negation, so [^k] caseless excludes every member of
  k's fold class. Measured rather than assumed, because the
  opposite order is a silently different language and only
  behaviour can tell them apart.

5. CLASS RANGES UNDER CASELESS -- does a range pull in a fold
   partner that lies OUTSIDE the range?
==========================================================================
  This is the sharpest lowering question in the section: if
  [a-z] caseless matches U+212A, then the caseless closure must be
  computed over the CODE POINT SET and can add intervals far from
  the ones written -- so the fold cannot be a post-pass over byte
  ranges, it has to happen while the set is still code points.
