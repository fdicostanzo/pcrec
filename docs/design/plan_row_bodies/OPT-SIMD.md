TARGET NOTE 2026-08-31 (Frank): "i have a macOS laptop using that fancy apple chip so we shouldn't assume i86" — DO NOT ASSUME x86: the design must be ISA-neutral from day one (an aarch64/NEON form beside the SSE one, or GCC/Clang vector extensions where they compile to the same shapes), and studies/simd1's numbers are x86-MEASUREMENTS only — the NEON equivalents (cmeq for cmpeq; tbl for the pshufb/shufti nibble lookup; the range trick via uqsub) exist but carry NO measured numbers until run on that machine; any emitted SIMD is gated per-ISA (#ifdef __SSE2__ / __ARM_NEON tier), with the scalar scan-* forms as the always-available fallback (the D82 candidate list makes this free — scan-simd simply doesn't select on an ISA without a measured form). RULING 2026-08-31 (Frank): BOTH ARCHS ARE SUPPORTED TARGETS — x86-64 and aarch64/NEON, neither primary. ARTIFACT-VARIANT DESIGN NOTE 2026-08-31 (Frank, for the non-memchr SIMD prefilter): "as its not a hot loop, i want to check if its reasonable to implement the simd stuff as a fallback so we don't have 4 versions of the pattern artifact e.g. 'if avx2 then ... else if sse ... else non-simd'" — the CHECK this row owes before emitting any SIMD: (a) MEASURE whether an outlined (noinline, or dispatch-once function-pointer) prefilter helper costs anything vs inline on prefilter-bound cells — if ~0 (plausible: the prefilter is not the innermost loop, and libc's own memchr is already an ifunc-dispatched indirect call that we happily pay today), then ONE emitted helper per class-shape carries the ISA ladder INSIDE it and the artifact has exactly one version of every loop site, with the ladder living in one place (or resolved at artifact-compile time by -march); (b) EVALUATE GCC/Clang portable vector extensions as the write-once alternative — they lower cmpeq/range forms well on both ISAs, but the shufti nibble-lookup (pshufb/tbl) and movemask (absent on NEON; needs the shrn trick) likely still need per-ISA intrinsics, so portable-vector may cover only part of the form table; (c) whichever wins, the D82 scan-simd form's BODY is that one helper — loop sites never grow ISA branches. memchr-shaped prefilters stay memchr (free ifunc dispatch in libc, already measured correct-as-is) EXCEPT where the window is provably short — D91's corollary: proven-short windows (minw/maxw or a counted bound) earn inline scalar/constant-length forms, since memchr never inlines. GOVERNED BY D91 (2026-08-31, Frank): scalar-first before SIMD, and the TWO dispatch budgets — the prefilter site (~once per match point: one artifact, runtime selection is noise — settled) vs the inside-the-pattern site (many hits per match: re-measure, never inherit the prefilter argument).
