E2 -- DOES EACH BODY FALL INSIDE THE SUBSET §2.5 SHIPS?
==============================================================================
A lookAHEAD body has NO width rule -- any body is legal. A lookBEHIND
body must have every top-level branch fixed-width. Measured per body by
asking libpcre2 for PCRE2_INFO_MAXLOOKBEHIND on a lookbehind built from
it, and by asking whether the body compiles as a lookbehind at all.

body          dir     note                           | pcre2 as (?<=B) | maxlb | ships?
----------------------------------------------------------------------------------------------------
(?<=\w)       behind  one class, width 1             | ok              | 1     | YES (fixed width 1)
(?!\w)        ahead   one class                      | ok              | 1     | YES (a lookahead has no width rule)
(?<!\w)       behind  one class, width 1             | ok              | 1     | YES (fixed width 1)
(?=\w)        ahead   one class                      | ok              | 1     | YES (a lookahead has no width rule)
(?<=\n)       behind  one literal, width 1           | ok              | 1     | YES (fixed width 1)
(?!\z)        ahead   an ANCHOR as the body          | ok              | 0     | YES (a lookahead has no width rule)
(?=\n)        ahead   one literal                    | ok              | 1     | YES (a lookahead has no width rule)
(?=\n?\z)     ahead   OPTIONAL + anchor -- widths 1..2 | ok              | 1     | YES (a lookahead has no width rule)

# BODIES pcrec's §2.5 RULE REFUSES AS LOOKBEHINDS THOUGH PCRE2 ACCEPTS
# THEM. Note the column: PCRE2 says `ok` to all three, because PCRE2
# ships variable-length lookbehind and pcrec does not. maxlb alone
# cannot show this -- an OPTIONAL body has minw 0 and maxw 1, and
# PCRE2 publishes only the max -- so the classification is by the
# BODY's own shape and is stated, not read off the oracle:
    (?<=\n?\z   )x  pcre2=ok       maxlb=1    minw=0 maxw=1  pcrec: REFUSED (variable)
    (?<=\n?     )x  pcre2=ok       maxlb=1    minw=0 maxw=1  pcrec: REFUSED (variable)
    (?<=\w?     )x  pcre2=ok       maxlb=1    minw=0 maxw=1  pcrec: REFUSED (variable)
    (?<=\n      )x  pcre2=ok       maxlb=1    minw=1 maxw=1  pcrec: SHIPS
    (?<=\w      )x  pcre2=ok       maxlb=1    minw=1 maxw=1  pcrec: SHIPS
    ^ `(?=\n?\z)` is a LOOKAHEAD in the \Z/$ expansion, so its
      optional body is legal THERE and would be refused as a
      LOOKBEHIND. The distinction is DIRECTION, not the body -- which
      is why every expansion in E1 compiles under §2.5 despite one of
      them containing an optional.
