# Artifact manager — organizing many pattern artifacts in one program

**STATUS: DIRECTION DOCUMENT, DESIGN ONLY. Nothing here is built, scheduled
or ruled.** Chartered by Frank 2026-09-30 as aspirational new functionality
("nothing concrete yet, a direction document to refine over time"). Plan row:
`[ART-MGR]` (docs/dev/plan.md, boonies). Lane `artmgr`, 2026-09-30. Revise
it in place as rulings arrive, keeping the refuted parts visible (this
directory's convention).

The document BUILDS ON prior rows: [V-E] (the rx_info organizer, D88),
[EMIT-SET] (optional emission units), [MULTI-PAT] (a set fused into one
scanner), [LIB] (subpattern libraries), [FREESTANDING], and the pcrec-bench
shim (the tree's only dynamic loader of pcrec artifacts today). It does not
replace any of them. Where this document and a plan row disagree, the row
holds until Frank rules.

## 0. The idea, as given (Frank, 2026-09-30)

When a program uses MULTIPLE pattern artifacts, something has to organize
them. Numbered so the requirements in §3 can trace to them:

- **F1 STATIC.** An array of `rx_info` structures plus helper scripts;
  `rx_info` holds a struct of function links to every user entry of the
  artifact.
- **F2 DYNAMIC.** Load `.so` files as needed.
- **F3 COMPILE-ON-DEMAND.** Possibly manage the compile, for a quasi-JIT
  experience.
- **F4 UNLOAD.** Unload `.so` files that are no longer needed.
- **F5 CACHE.** A dynamic file cache, so a pattern compiled once is only
  loaded afterwards.
- **F6 SHAPE.** A new library for dynamic support, pcrec changes to
  support it, and a CLI that runs against the library (a `pcrecgrep`?).
- **F7 FINDERS.** Tools to find patterns, static or dynamically loaded.
- **F8 ASPIRATIONAL.** Aspirational placement: the boonies, not the spine.

## 1. What exists TODAY vs what [V-E] proposed

### 1.1 `struct rx_info` today (abi 50 on main at this writing; lane k7980 is moving it to 54)

Source of truth: docs/spec/match_api.md §6. Its members, in order:
`abi` (first member, offset 0), `flags`, `encoding`, `ncaps`, `ngroups`,
`nnames`, `engine`, the four budgets/capacities, the two frame sizes,
`pattern` + `pattern_len`, `groups`, `engine_why`, `scan`, `prefilter`,
`match_form`, `name` + `nentries` ([DD-13b.W1.2]), `search_form`, `vars` +
`nvars` ([VAR]), `findings` ([FINDINGS] B1).

For an organizer, the relevant facts are:

| [V-E] item | today |
|---|---|
| (1) nested struct of ENTRY-POINT pointers | **ABSENT.** An artifact exports eight `<prefix>`-scoped entries (match_api.md §3): `_search`, `_match`, `_match_caps`, `_next_pos`, `_valid_upto`, `_search_in`, `_match_in`, `_match_caps_in`, plus `_info`. A caller reaches them only BY SYMBOL NAME. |
| (2) user-facing NAME + pattern source | **LANDED.** `name` (never NULL; defaults to the prefix) and `pattern`/`pattern_len`. **But `name` is not artifact identity.** One definition built under three configs is three artifacts with ONE name (§6's own worked case). The PREFIX is unique per artifact and is **not in rx_info**. |
| (3) unit-level `<unit>_patterns[]` + count + helper | **ABSENT.** Hand-rolled organizers stand in for it: the harness's `HARNESS_BATCH` dispatch (`tests/harness/dispatch_gen.sh`, [TT-4M] 2c, an argv-index `switch`, written as "by-name-lookup-compatible for [V-E]'s later implement-then-replace"), and D88 item 4's multi-prefix test drivers. |
| (4) array sorted by name, binary search | ABSENT (depends on 3). |
| (5) the whole surface optional ([EMIT-SET]) | ABSENT ([EMIT-SET] not started). |
| [V-E] input (b): linker-section self-registration | ABSENT; an alternative to (3)/(4), not ruled. |
| [V-E] input (c): several independent sets | ABSENT; membership declared in `.rxt` vs by flag is open. |

Two further facts matter here. First, the product version (D115) is stamped
only as the essential provenance COMMENT (`/* Generated by pcrec 0.2.0-beta
(abi 50). ... */`). It is not in `rx_info`, so a LOADED artifact cannot
report which pcrec built it. Second, `rx_info` lives in `.data.rel.ro`
(§3.4) because it holds pointers. Adding function pointers adds relocations
of the same kind. It does not add a new kind of cost.

### 1.2 The signature fact that shapes item (1)

Seven of the eight entries have **prefix-independent types**. `_search`
takes `(const unsigned char *, size_t, size_t, ptrdiff_t (*)[2])`, `_match`
IS `rx_matchfn`, and `_match_caps`, `_next_pos` and `_valid_upto` use only
`rx_ctx`, `size_t` and `ptrdiff_t`. The three `_in` entries do NOT. They
take `const <prefix>_buffers *`, and §10.2 makes that type PER-ARTIFACT **on
purpose**, because frame sizes differ and a fixed-literal type "would
advertise an interchangeability that does not exist". So a fixed-literal
entry-pointer struct can carry five entries today with no new decision. The
`_in` entries need one: see Q6.

### 1.3 The dynamic loader that already exists (pcrec-bench's shim)

`pcrec-bench/testees/pcrec/shim.c` (read-only reference) is the tree's
working prior art for F2. The driver compiles one `.so` per pattern (`shim.c`
`#include`s the artifact's `.c`) and `dlopen`s it. It exports a flat,
engine-neutral `pb_*` surface (105 lines naming `pb_`). It REFUSES an
artifact below an abi floor (`PB_SHIM_MIN_ABI`, read through `pb_abi()`).
The bench already times pcrec + gcc + dlopen as three compile phases
(harness_contract.md §3). Its lessons:
(a) the loader must not re-declare `struct rx_info`, or it becomes a
drifting second copy of the ABI;
(b) an abi FLOOR moves only when a FIELD the reader reads was added;
(c) the D46 macros are `.c`-only, so a reader that wants them must see the
`.c`.
An artifact manager that makes the shim's loader code unnecessary is the
cleanest D77 trigger this design has (§6).

## 2. Terms: the collisions, and the names this document uses

Seven words already have meanings in the tree. Using them loosely here would
create a second meaning.

| word | already means | this document |
|---|---|---|
| **library** | (a) `libpcrec.a`, the compiler library; (b) [LIB]'s subpattern libraries and the `.rxt` `lib` directive / `--lib-path`; (c) [LIB]'s shipped "library store" | Never used bare. The new runtime is **the loader** (`libpcrecload`, provisional). |
| **unit** | a C translation unit; [EMIT-SET]'s EMISSION UNITS; [V-E]'s "compilation unit" / `<unit>_patterns[]`; the bench's ".so unit" | Not used for the organizer. [V-E]'s `<unit>_patterns[]` becomes `<catalog>_catalog[]`. |
| **set** | D88's emission set (a directory + manifest); [MULTI-PAT]'s pattern set (one fused scanner); `PCREC_FEATURE_SET`; character sets | **pattern set** stays [MULTI-PAT]'s. **emission set** stays D88's directory. The organizer's grouping is a **catalog**. |
| **registry** | tests/registry (D24's syntax construct registry); [EST-REGISTRY] | Not used. |
| **store** | [LIB]'s library store (`lib <store>`); `oracle_store/`; pcrec-bench's `store/` | Not used. The dynamic side is **the cache**. |
| **name** | `rx_info.name`, which is DEFINITION identity, shared across configs | Artifact identity is the **prefix** (the symbol name) or a **cache key**, never `name` alone. |
| **manifest** | D88's per-emission-set header; many test manifests | Kept: a catalog's header is D88's manifest header. |

So there are three definitions:
- **Catalog.** A static, link-time, `const` collection of `rx_info` pointers
  with a lookup helper, all emitted code. It is [V-E] items 3-4 and [V-E]
  input (c)'s "several independent sets". A program may link several.
- **Loader.** A new hosted runtime library that opens, tracks and closes
  artifact shared objects and serves them to callers as handles.
- **Cache.** The loader's on-disk directory of compiled shared objects,
  keyed so that a hit is exactly "this compile, by this toolchain, for this
  target".

Naming the CLI (Q1): PCRE2 ships `pcre2grep`, and `pcrecgrep` is one
character from it. It is distinct enough, and it says what it is. The
finder tool is provisionally `pcrec-find`, on `pcrec-analyze`'s model.

## 3. Requirements

Each requirement traces to §0's items. MUST is a design requirement, not a
scheduled promise.

### R1 Static entry surface (F1)
- **R1.1** `rx_info` MUST let a caller reach every prefix-independent user
  entry of its artifact without knowing the prefix. The recommended form is
  a pointer to a fixed-literal `const struct rx_entries` (in the
  `PCREC_RX_ABI_H` block) holding `search`, `match`, `match_caps`,
  `next_pos` and `valid_upto`.
- **R1.2** The pointer struct MUST be reached through a POINTER appended
  after `findings` ([DD-13c]'s append-only shape), not embedded. This lets
  `rx_entries` grow later without moving any `rx_info` offset. `rx_entries`
  carries its own leading count or size for the same reason.
- **R1.3** `rx_info` SHOULD gain `prefix` (artifact identity; §2) and
  `version` (the D115 string as data, so a loaded artifact reports it).
- **R1.4** D82 stands: per-machine inline accessors never go behind a
  pointer, and a direct-call caller keeps the named symbol at zero cost.
- **R1.5** The surface is an optional emission ([V-E] item 5,
  [EMIT-SET]'s shape). It is default-on or default-off by Q7. Answer
  identity is unaffected either way.

### R2 Catalog: discovery and lookup, static (F1, F7)
- **R2.1** A generated catalog MUST include every member however many
  `.rxt` files or targets contributed ([V-E] input (b)).
- **R2.2** Lookup MUST work by any `rx_info` field with a linear scan, and
  by the catalog's sort key with a binary search. The key is `name`, then
  `prefix` as the tiebreak, so the three-configs-one-name case is ordered
  and complete ([V-E] item 4). The sort order is a stated contract that a
  check reads off the artifact.
- **R2.3** A program MAY link several catalogs ([V-E] input (c)).
  Catalog membership comes from the `.rxt` (a target property) or from an
  emission flag: Q3.
- **R2.4** The catalog and its helper are emitted code and MUST stay
  dependency-free and freestanding-clean. The compare loop is emitted,
  never `strcmp`/`bsearch` from libc ([FREESTANDING]'s census rule).
- **R2.5** A catalog MUST refuse to form over members of DIFFERENT abi,
  reading each member's stamp at generation time. It MUST NOT rely on the
  include guard, which is K80's hazard.
- **R2.6** A catalog MUST refuse duplicate prefixes (a static-link symbol
  collision) and report duplicate (name, config) pairs by name.

### R3 Dynamic load (F2)
- **R3.1** The loader opens a prebuilt artifact shared object and returns a
  HANDLE that carries the artifact's `rx_info`. The only symbol it resolves
  by name is `<prefix>_info` (or one canonical symbol, §4.4). Everything
  else comes through R1's pointers.
- **R3.2** Before touching any other member, the loader reads `abi`,
  relying on the offset-0 contract (Q8), and refuses an artifact outside its
  supported `[floor, ceiling]`. This is the bench shim's floor, made a
  library contract.
- **R3.3** The loader never re-declares `struct rx_info`. It is compiled
  against the ABI block pcrec emits, the shim's lesson (a).

### R4 Compile-on-demand (F3)
- **R4.1** Given a pattern and options, the loader produces a loaded
  handle, compiling if the cache misses: pcrec, then gcc (shared, PIC),
  then publish, then load.
- **R4.2** Every compile runs under a stated budget: wall, RSS and CPU,
  the `scripts/watchdog` shape as a library policy. A firing budget is a
  clean error, never a hang.
- **R4.3** pcrec has NO INTERPRETER, so the cold call has no slow-but-correct
  path, unlike PCRE2's interpreter-then-JIT. The cold-path policy (block,
  fail fast, or asynchronous with a caller callback) is explicit per call
  (Q5).
- **R4.4** A compile error is attributed to the caller's pattern and passes
  through pcrec's diagnostic with its tier ([V-E] input (a)'s
  error-attribution rule, per pattern).

### R5 Cache (F5)
- **R5.1 KEY.** A hit MUST mean all of the following are identical:
  (a) the canonical compile request (pattern bytes plus EVERY input that
  moves the artifact: flags, encoding, budgets, every deny/force axis, the
  engine, the analysis/findings bundle's content, the definitions/`lib`
  closure for a composed target, and the prefix while K79 stands);
  (b) the pcrec that compiled it, by build identity and not just the D115
  string, since one beta string spans a thousand commits;
  (c) the abi;
  (d) the C compiler's identity, by content or `--version` plus a hash, on
  ccache's `compiler_check` model (§8);
  (e) the C flags;
  (f) the target (triple, `-march`, OS object format).
- **R5.2 KEY OWNERSHIP.** Only pcrec knows which options move an artifact,
  so pcrec MUST publish the canonical request record, or its hash, as a CLI
  output. The loader MUST NOT keep its own list of "options that matter",
  which would be a second copy of one decision (D124 item 2; see §7).
- **R5.3 INVALIDATION** is by key, never by time. A new pcrec, compiler or
  abi simply misses. Eviction is LRU under a size limit.
- **R5.4 LOCATION.** Per-user by default: `$XDG_CACHE_HOME/pcrec` on
  Linux, `~/Library/Caches/pcrec` on macOS, or a caller-given directory.
  It is never world-writable and never on a `noexec` mount (§4.6).
- **R5.5 CONCURRENCY.** Many processes may share one cache. A writer
  builds in a private temp name and publishes with `rename(2)`, so the
  loser of a race discards its copy. A published file is NEVER rewritten in
  place, because rewriting a mapped `.so` crashes its users. Eviction
  unlinks, which is safe under a live mapping on POSIX.
- **R5.6 SECURITY.** §4.6. The cache directory holds code the process will
  execute.

### R6 Unload (F4)
- **R6.1** A handle is reference-counted. A caller-held `rx_info`
  pointer, function pointer, `pattern` string and `groups[]` name are all
  BORROWED from the handle: they point into the mapped object and die with
  it.
- **R6.2** The loader closes an object only at refcount zero and only by
  policy (explicit release, or LRU of zero-ref handles). It never unmaps
  implicitly under a live reference.
- **R6.3** A generated matcher holds no state across calls (§5.3), so "in
  use" means exactly "a live handle reference". There is nothing else to
  drain.

### R7 CLI consumer (F6)
- **R7.1** `pcrecgrep` (name: Q1) runs patterns from the command line or a
  file through the loader, on a cache hit or a compile, and reports matches.
  Its first job is to be the loader's integration test and demonstration,
  not a grep competitor.
- **R7.2** It MUST also accept prebuilt artifacts or a catalog-linked
  build, so the static and dynamic paths share one front end.

### R8 Finder tools (F7)
- **R8.1 Static.** List every catalog and member in a binary or object by
  reading the catalog symbol or section, then print `name`, `prefix`,
  `pattern`, engine, abi and version. `nm`-style, with no execution.
- **R8.2 Dynamic.** List, verify and evict cache entries. Each entry
  carries a small metadata sidecar (the key record plus `rx_info`
  essentials) so listing never `dlopen`s.
- **R8.3** Both tools are separate binaries on `pcrec-analyze`'s model:
  zero-dependency, linking neither libpcrec nor the loader where not needed.

## 4. Layering, constraints and hazards

### 4.1 The layers

| layer | what | dependency rule | owner |
|---|---|---|---|
| **L0 artifact scaffolding** | R1: `rx_entries` pointer, `prefix`, `version` in `rx_info` | generated, DEPENDENCY-FREE (APPROACH.md), freestanding-clean; an abi event (D76/D94) | pcrec emitter |
| **L1 catalog** | R2: `<catalog>_catalog[]`, count, sorted, lookup helper, the manifest header | generated, dependency-free, freestanding-clean | pcrec (a composer mode over targets or headers) |
| **L2 loader** | R3/R4/R5/R6: handles, `dlopen`, compile driver, cache | NEW SEPARATE HOSTED LIBRARY. It links `libdl` and a mutex. It NEVER links into an artifact, and artifacts never reference it. | new top-level dir (Q2) |
| **L3 pcrec changes** | canonical request record/key output (R5.2); catalog composer; `-shared`-friendly defaults | inside pcrec | cli/, src/gen |
| **L4 CLI consumer** | `pcrecgrep` (R7) | links L2 | beside L2 |
| **L5 tools** | finders (R8), helper scripts | separate binaries or scripts | tools/ or beside L2 |

The invariant that holds this together: **everything below L2 is
generated C with no dependency, and everything at L2 and above is hosted
and optional.** `dlopen` is a dependency the artifacts must never take. A
program that links a catalog pays nothing for the loader's existence.

Compile-on-demand should EXEC the pcrec CLI, not link `libpcrec` (Q4).
gcc is a child process anyway, so the process boundary costs little. It
isolates a hostile pattern's compile (crash, runaway allocation) from the
caller, reuses the watchdog shape, and keeps `libpcrec` (compiler memory,
jmp_buf error path) out of a long-running consumer.

### 4.2 abi mismatch across loaded objects (K80's lesson)
K80: the shared ABI block's guard is the literal `PCREC_RX_ABI_H`, so one
TU that includes two artifacts of different abi silently gets the first
one's block. That is a STATIC hazard, and a catalog's manifest header is
exactly the TU that would include every member. So K80's fix (an abi-keyed
guard or a static assert, filed as an abi event) is a PREREQUISITE of L1,
and R2.5's generation-time refusal is the second fence. DYNAMICALLY, each
`.so` is its own TU, so the hazard moves to the LOADER'S reading of
`rx_info`. That makes R3.2 (read `abi` at offset 0 first, then refuse
outside `[floor, ceiling]`) and Q8's offset-0 contract the fence.
Append-only growth ([DD-13c]) means an older loader can still read the
prefix of fields it knows from a newer artifact. Whether the ceiling is
"known max" or "any newer" is part of Q8.

### 4.3 Symbol collisions and the prefix
Static link: prefixes must be unique across the link. R2.6 refuses
duplicates, and [PFX-1] (prefix only on exported items) shrinks the
surface. Dynamic: open with explicit `RTLD_NOW | RTLD_LOCAL` and resolve
per handle. **macOS's `dlopen` defaults to RTLD_GLOBAL when neither is
given, and Linux's defaults to RTLD_LOCAL**, so always pass the flag. Build
cached objects with `-fvisibility=hidden` plus the exported entries, so
nothing interposes. Under RTLD_LOCAL the dynamic cache can use ONE
CANONICAL prefix for every object, which also takes the prefix out of R5.1's
key. That is blocked by K79 (the prefix LENGTH moves the VM entry shape)
until K79 is fixed, and is therefore a reason to fix it. Cross-artifact
references (a compiled matcher linked as another's callout, D38; a [LIB]
definition is SPLICED at compile, not linked) make an object depend on
another's symbol. The loader either refuses such objects in its first slice
or resolves them through explicit handles. It never relies on
RTLD_GLOBAL.

### 4.4 Thread-safety (D19)
D19: usable FROM threads, never threaded. L0/L1 stay in D19's audited
shape: all `const`, no mutable state, and the catalog helper is a pure
function. **L2 is the first pcrec-family component with mutable shared
state** (the handle table, refcounts, the cache index), so it needs a lock.
That makes it a pthread (or C11 `<threads.h>`) dependency, legitimate at L2
and never below. It spawns processes, not threads. Its guards follow D19's
"guards, not prose" rule: a TSan run of the loader under concurrent
acquire, release and evict is the check it owes when built.

### 4.5 Unloading while a matcher is in use
R6 is the whole answer. Refcounted handles, borrowed pointers, and close
only at zero. Two traps to write down now: (a) POSIX lets `dlclose` NOT
unload (glibc keeps objects with `RTLD_NODELETE` or with dependents, and
macOS keeps images it cannot unload), so "unloaded" must not be a promise
the loader makes about memory, only about the handle; (b) a `rx_info`
pointer copied into a caller's long-lived table outlives the handle
silently. The API should make the borrow visible (a handle-scoped
accessor, not a raw `const struct rx_info *` return), and the debug build
of the loader can poison closed handles.

### 4.6 Security of a cache directory that executes code
The cache is a code-loading path. Anyone who can write it can run code in
every consumer.
- The directory is owner-only (0700) and CHECKED on every open, the way ssh
  checks `~/.ssh`: owner equals euid, and no group or other write on it or
  its parents. On a failed check the loader refuses loudly. It does not
  "fix" permissions.
- A content hash in the sidecar detects CORRUPTION only. It is no defence
  against a writer, who can write a matching hash. The defence is the
  permission check.
- `noexec` mounts: `dlopen` of a file on one fails (PROT_EXEC). The default
  location avoids `/tmp`, and the error names the cause.
- A shared multi-user cache (ccache's setgid-group model) is OUT of the
  first slice. It widens the trust boundary to the group.
- **Compile-on-demand makes the EMITTER's escaping a code-injection
  boundary.** The pattern text reaches the generated C twice: in the
  essential comment (`emit_comment_safe_byte`) and as `rx_info.pattern`'s
  string literal. Today that escaping protects correctness. Under F3 with
  untrusted patterns (a grep over user input), it is what stands between a
  pattern and arbitrary C. A dedicated hostile-pattern check (comment
  terminators, trigraphs, backslash-newline, NUL, every byte 0-255) is a
  precondition of shipping F3.
- Hostile patterns can also exhaust the compiler. D84's caps plus R4.2's
  budgets bound that, and a pcrec that refuses cleanly is the success case.
- Apple Silicon requires a code signature on loaded code. `ld` applies an
  ad-hoc signature by default on arm64, but a hardened-runtime host with
  library validation refuses ad-hoc-signed objects. The loader documents
  this and does not try to work around it.

### 4.7 The cost of invoking gcc at runtime
The cold path is pcrec + gcc + `dlopen`. The bench already times these as
three phases (§1.3), so the number is MEASURED THERE, not estimated here.
The design pass reads the bench's compile-phase records at trigger time.
Structural facts: gcc dominates for large artifacts ([OPT] size caps D84,
`--warn-emit-bytes`), `-O2` vs `-O1` is a latency-vs-throughput knob the
cache key must carry (R5.1e), and a TWO-LEVEL key (request to `.c` hash,
then `.c` hash plus compiler plus flags to `.so`, ccache's direct vs
preprocessor mode) avoids re-running gcc when two requests emit identical
C. It is an option for when hit-rate data exists, not a first-slice
requirement.

### 4.8 Freestanding ([FREESTANDING])
L0 and L1 are const data, function pointers and an emitted compare loop.
They reach no libc and stay inside [FREESTANDING]'s gate. Function
pointers in `rx_info` are absolute-address relocations resolved at static
link, so they are fine for ROM (§3.4's existing note, with more entries).
L2 and above are HOSTED BY DEFINITION and never claim otherwise.

### 4.9 Linux / macOS differences
| | Linux (ELF, glibc/musl) | macOS (Mach-O, dyld) |
|---|---|---|
| object | `gcc -shared -fPIC -o x.so` | `-dynamiclib` (`.dylib`) or `-bundle`; Homebrew `gcc-16` is the house compiler on the Mac box, and bare `gcc` may be clang |
| default `dlopen` scope | RTLD_LOCAL | RTLD_GLOBAL — pass flags explicitly |
| linker-section registration ([V-E] input (b)) | `__start_<sec>`/`__stop_<sec>` | no `__start_`; `getsectiondata()` / `section$start$` — DIFFERENT CODE |
| unload | refcounted; RTLD_NODELETE | may not unload |
| signing | none | arm64 requires a signature (ad-hoc by default); library validation |
| cache default | `$XDG_CACHE_HOME/pcrec` | `~/Library/Caches/pcrec` |

The section row is the main reason §6 recommends the emitted sorted array
over linker sections for the first catalog. The array is one mechanism on
both platforms. Sections are two.

## 5. Relation to the neighbouring rows

- **[V-E]** is this design's L0 plus L1, and remains the row that builds
  them. [ART-MGR] adds L2 to L5 on top and must not re-charter [V-E].
- **[EMIT-SET]** is how L0 becomes optional (R1.5), and the catalog could
  be one of its named emission units.
- **[MULTI-PAT]** fuses a pattern set into ONE artifact. From a catalog's
  view, that artifact is ONE member with set semantics. The catalog neither
  fuses nor knows about fusing.
- **[LIB]** changes what goes INTO one artifact (spliced definitions). A
  composed artifact is still one catalog member. The `lib` word stays
  [LIB]'s (§2).
- **[FREESTANDING]** bounds L0/L1. **[PFX-1]** and **K79** bound the prefix
  story (§4.3). **K80** is L1's prerequisite (§4.2). **[DD-3]**
  (generated-API versioning policy) is where Q8's forward-compat rule
  belongs.
- **pcrec-bench's shim** is the first dynamic consumer (§1.3). The
  harness's `HARNESS_BATCH` dispatch is the first static one.

## 6. Staged options, each with its D77 trigger

No stage is built ahead of its trigger (D77, memory
`pcrec-build-under-measurement`). Each stage is useful on its own, so
nothing built early is rolled back later.

| stage | builds | D77 trigger |
|---|---|---|
| **S0** | this document | done (Frank 2026-09-30) |
| **S1 — the smallest useful step** | L0 only: `const struct rx_entries *entries` (five prefix-independent entries, counted), `prefix`, `version` appended to `rx_info`; one abi event with its spec hunk and grep-found re-pin | [V-E]'s own trigger, unchanged: the first real consumer that must call an artifact it knows only by `rx_info`. That is the bench shim's first multi-pattern sub-bench, OR the harness choosing to retire `dispatch_gen.sh`'s `switch` (implement-then-replace; the switch works, so this is a choice, not a need). |
| **S2** | L1: the sorted catalog, lookup helper, manifest header, composer; K80 fixed first | a consumer holding MORE THAN A HANDFUL of artifacts that looks them up by name or field, or Frank's "several independent sets" wanted by a named consumer |
| **S3** | L2 without compile: load prebuilt objects, abi floor/ceiling, handles, refcounts, explicit release | a runtime loader is wanted outside the bench. The measurable form is the bench asking to replace its hand-rolled `dlopen` + floor logic, or a second program doing the same by hand. |
| **S4** | L2 compile-on-demand + L3 key output + cache (R4/R5), and L4 `pcrecgrep` as its demonstration | a consumer whose patterns are UNKNOWN AT BUILD TIME. The cache's own justification is a measured repeat rate: the same request compiled more than once across runs. |
| **S5** | eviction / LRU unload policy (R6.2 beyond explicit release) | measured resident growth in a long-running consumer |
| **S6** | L5 finders | lands with S2 (static) and S4 (dynamic). A finder over nothing is not built. |
| **S7** | "quasi-JIT" polish: asynchronous cold compile, pre-warm hints, two-level key | measured cold-path latency complaints from a real S4 consumer |

**Recommended first step: S1**, gated exactly as [V-E] already gates it. It
is general (every consumer benefits), core rather than derived (identity
and entry surface are the artifact's own facts), fits the architecture
(append-only rx_info, a pointer and not a nested struct, one abi event),
and every later stage builds on it without changing it.

## 7. The design choices against the standing lenses

Lenses: specific-vs-general (S/G), core-vs-derived (C/D),
applicable-vs-assumption-changing (A/X), fits-architecture-vs-refactor
(F/R), and D124's shared-question / engine-hat (Q).

| choice | S/G | C/D | A/X | F/R | Q |
|---|---|---|---|---|---|
| entry pointers in rx_info (S1) | G: every consumer | C: the artifact's own entries | A: append-only | F: [DD-13c] shape | engine-neutral: one struct for DFA and VM, and `rx_info.engine` stays a row fact, not a separate table |
| pointer-to-struct, not nested | G | C | A: future growth moves no offset | F | — |
| `prefix` + `version` in rx_info | G | C: facts the emitter already knows | A | F | — |
| catalog as emitted sorted array (not sections) | G: one mechanism, both OSes | D: derived from members' rx_info | A | F: D88 "composition is linking" | the lookup is ONE table (first-match-table idiom: an ordered row list, first passing row wins), with no engine-specific catalogs |
| catalog as linker sections | G, but TWO platform mechanisms | D | A | R: new per-OS code | — |
| loader as a separate hosted library | G | D: consumer of artifacts | A: artifacts unchanged | F: `pcrec-analyze`'s separate-binary precedent | — |
| compile by exec of the CLI | G | D | A | F: gcc is already a child | — |
| cache key published BY PCREC | G | C: one owner of "what moves an artifact" | A | F | the D124 item 2 rule applied: a loader-side option list would be the second copy of a shared decision |
| canonical prefix in the cache | G | — | X until K79 is fixed (then A) | F after K79 | — |
| `_in` entries through the table (Q6) | G | C | **X**: contradicts §10.2's deliberate per-prefix buffer type | R if a fixed-literal `rx_buffers` | — |
| interpreter fallback for the cold path | — | — | **X**: pcrec has no interpreter by design (APPROACH.md) | R | rejected |

The two rows marked X are exactly the ones §8 sends to Frank.

## 8. Prior art outside pcrec

- **PCRE2 JIT** [PCRE2jit]. JIT happens in-process after `pcre2_compile`
  (`pcre2_jit_compile`) and is freed only with the pattern. Its contrast with
  pcrec is the whole point of R4.3: PCRE2 always has an interpreter to fall
  back on, and pcrec's cold path has none.
- **PCRE2 serialization** [PCRE2serialize]. It saves the BYTECODE and never
  the JIT code. Reload requires the same PCRE2 version, code-unit width,
  endianness, pointer width and `PCRE2_SIZE`. Load does only "simple
  consistency checking, not complete validation", and the data must be
  trusted. It is precedent for R5.1's key (version plus platform), and a
  warning for §4.6: a serialized artifact is trusted input, and pcrec's is
  worse, being native code.
- **Hyperscan serialization** [HSserialize], and the Hyperscan paper
  [Wan19+]. `hs_serialize_database` writes a flat, relocatable byte
  buffer. Deserialization requires the same Hyperscan version and platform
  features the host supports. `hs_serialized_database_info` reports a
  database's version and platform WITHOUT loading it, which is precedent for
  R8.2's sidecar (list without `dlopen`). Hyperscan's database is not flat
  in memory (pointers, alignment), so relocation needs the API. pcrec's
  `.so` pushes the same problem onto the dynamic linker.
- **ccache** [ccache]. The hash covers compiler identity, source, and
  options. `compiler_check` defaults to the compiler's mtime and size, with
  a `content` mode. Direct mode and preprocessor mode are the two-level
  keying of §4.7. A shared cache needs one group, umask 002 and setgid
  directories. It evicts LRU under a size limit (5 GB default). It is
  precedent for R5.1(d), R5.3, R5.5 and §4.6's rejected shared mode.

## 9. Open questions for Frank, each with a recommendation

- **Q1 Names.** "Catalog" for the static organizer (not set, unit or
  registry), `libpcrecload` for the runtime, `pcrecgrep` for the CLI and
  `pcrec-find` for the finder. *Recommend: adopt all four as provisional,
  rename freely at charter.*
- **Q2 Where L2 lives.** *Recommend a new top-level directory (`loader/`)
  on `analyze/`'s model: separately built, its own CLAUDE.md, never linked
  into `libpcrec.a`, and absent from a plain `make` until S3.*
- **Q3 Catalog mechanism and membership.** Emitted sorted array (needs
  one generation point that sees all members) or linker-section
  self-registration (link-composed, but two per-OS mechanisms, §4.9)?
  Membership declared in `.rxt` or by flag? *Recommend the sorted array
  first, sections only on a measured need for link-composed catalogs
  across independently built libraries. Declare membership in the `.rxt` as
  a target property, since targets already live there, with a CLI flag
  for header-only inputs.*
- **Q4 How the loader compiles.** Exec the pcrec CLI, or link libpcrec?
  *Recommend exec (§4.1): isolation, the watchdog shape, and gcc is a child
  process anyway.*
- **Q5 The cold path.** There is no interpreter. Should the first call
  block, fail fast, or go async? *Recommend: block under a caller-given
  budget by default, fail-fast as an option, and async deferred to S7.
  Reject a libpcre2 fallback: it adds a dependency and is a second
  semantics source at run time.*
- **Q6 The `_in` entries in the pointer table.** §10.2 deliberately makes
  `<prefix>_buffers` per-artifact. *Recommend: S1 carries only the five
  prefix-independent entries, and `rx_entries`' count lets `_in` join later.
  Decide at the first consumer that needs caller-provided storage through
  the table, between a fixed-literal `rx_buffers` (layout-identical; the
  frame SIZE is already an `rx_info` field) and type-erased emitted wrappers.*
- **Q7 Default-on or default-off.** Should S1's surface ride every artifact
  or wait for [EMIT-SET]? *Recommend default-ON. It is a few relocations
  and three fields, and an organizer that works only on artifacts built
  with a flag fails the "include every member" rule ([V-E] input (b)).
  [EMIT-SET]'s deny removes it later.*
- **Q8 The loader's ABI contract.** State "`abi` is `rx_info`'s first
  member, forever" as spec, and choose the ceiling rule. *Recommend: state
  the offset-0 contract in match_api.md §6 at S1. The loader accepts any
  abi ≥ its floor, because append-only growth makes newer artifacts
  readable for known fields. File the policy under [DD-3].*
- **Q9 Cache key ownership.** *Recommend pcrec publishes the canonical
  request record and its hash (a CLI output) as part of S4, and the key
  includes pcrec's BUILD identity (a content hash of the binary, or an
  embedded build id), not only `PCREC_VERSION`.*
