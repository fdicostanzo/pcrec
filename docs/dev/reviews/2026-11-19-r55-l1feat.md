### A. The TOP set step reads only the CHOSEN run (TABLE-1, CONTRACT-3, EMITTED-1) [design/doc + small speed; no answer]
`rb_top_set_step(set, run)` (`src/facts/req.c` ~1587, called at ~1629-1630 after `rb_top`) adds the one-byte positions of the run TOP CHOSE, and only members the set lacks. Three consequences:

No `rate:` token says so.
2. **TABLE-1:** every arm whose restore moves the chosen run (`tie`, `rep`, `alt`, `empty`) can now move `req_set` without a `harness:` token: `y(?=q)[pq].e(?=e)[ae]` default `req_set 101,113,121`, `--harness=restore=tie` → `101,121`, empty why. walk_arms.def's rows for those four arms list only `PF_REQ_WHOLE_RUN|PF_REQ_PIECES`; ¶4a under-states.
3. **EMITTED-1:** an EXISTING member keeps its looser offset: `[ac][ac](?<=ac)cc` → `req_set_maxoff 97:0,99:2` where the spelled `accc` gives `99:1`. Sound; it follows D-3's text ("if the set lacks it") literally; it is the compare's one DIFFER row.
- **PROPOSED: FIX-NOW (design call first).** Make the step choice-free: join every narrowed one-byte CONSUMED position where the meet narrows it (D-3's CAT-SET as first written) or over the root's best/head/tail, which restores `req_set`'s CORE property and makes TABLE-1 moot except where a restore removes a narrowing (the `look`/`zero` rows already carry it). Lowering a present member's offset (EMITTED-1) rides the same change only with its own non-lookaround census (EMITTED-1's caution: it is not a no-op without guards). If the manager prefers to keep the chosen-run form: reclassify the two facts DERIVED with a `rate:` why, widen walk_arms.def per TABLE-1, and say "of the chosen run" in ¶4a.
