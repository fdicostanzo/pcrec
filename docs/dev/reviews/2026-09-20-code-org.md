## [ORG-1] src/gen/emit_vm.c — the repeat rung ladder is decided three times

**Observation (manager, walking vm_count_slots with Frank):** `vm_cost_rep`
(2029), `vm_count_slots_rep` (2691) and the emitter's `vm_rep` each re-decide
CURSOR → REVDET → COUNTER → GENERAL by calling the same predicates
(`vm_cursor_fits`, `vm_revdet_fits`, `vm_counter_fits`) in the same order, with
`under_atomic` threaded into each. The invariant that they agree is held by
the banner "slot counting (must mirror the emitter's own rung decisions)" and
by mech rows, not by the code. A divergence sizes the slot array for a rung
other than the one emitted.

**Candidate:** one `vm_rung_of(Vm *v, const Ast *a, bool under_atomic)`
returning an enum (`VM_RUNG_CURSOR/REVDET/COUNTER/GENERAL`), consumed by all
three walks; each walk's ladder becomes a `switch` on the enum. Sub-question:
memoize the decision on the node (or a side table keyed by node) — today
`vm_cursor_fits` fills two scratch buffers (the stride sequence table and the
capture offsets) to answer yes/no in the pre-passes, then recomputes them at
emission.

**Why it might NOT be worth it:** the three ladders are short and the
predicates are already shared — the duplication is the ORDER and the
threading, ~15 lines total; mech rows S-series already witness the mirror;
a memo on the node is a new field for a compile-time-only fact. The measured
need would be a divergence that actually shipped (none recorded) or a fourth
walk arriving (a listing-only pass, say). Tier if built: opus, with
[TOUR-2]'s lane.

**Disposition:** OPEN.
