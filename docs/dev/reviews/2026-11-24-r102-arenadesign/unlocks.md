# Findings: lens unlocks (r102 arenadesign)

## Findings

### UNL-1 The base level stays a SECOND mechanism beside the registry (Arena.owned/AOwn vs LEnt), and that choice blocks the general "adopt = re-parent an entry" and base-level entries of other kinds
CONFIRMED (design text vs code). Severity: design. Effort: S (arena.c-internal). Blast radius: arena.c only, but it decides how U4/P4, U7 and K163-style holds join later.
- Design D-1 row S3 says `Arena.owned` is "kept, as the registry's BASE level (same release walk)". The API (§API) says otherwise: `AOwn *owned` (BASE) and `LEnt *top` (scope level) are two record types, and `pcrec_arena_free` is "release `top` newest-first (each record to `spare`), then `owned`, then free `spare`" - two walks. At F, `AOwn` is `{ next; void *p; }` allocated FROM THE ARENA (arena.c:42-45 `pcrec_arena_own_slot` -> `pcrec_arena_alloc`; internal.h:345), HEAP-only, released by its own loop (arena.c:62). LEnt is heap-allocated, kind-tabled (HEAP/STRBUF/ARENA).
- So "what dies with this arena" has two answers inside the new design: base = heap blocks only, in-arena records, no kind table; scope = three kinds, heap records. `pcrec_arena_hold` (R2) is a base HEAP entry and `pcrec_scope_malloc` a scope HEAP entry: two spellings of one registration, differing only by level.
- What it blocks (each a sibling that would JOIN as a row if base were the registry's bottom): (i) P4/U4: `job_cleanup`'s 6 `pcrec_sb_free` lines (compile.c:310-315: `csb`,`hsb`,`vmsb`,`irsb`,`scr_test`,`scr_desc`) are attempt-lifetime STRBUFs - base-level STRBUF entries, impossible on an AOwn base; (ii) a general ADOPT (move an entry from a scope to an outer level without copy or allocation): with LEnt at every level it is a relink of one record (cannot refuse); with an AOwn base it needs an arena allocation at adopt time (can refuse, the K155 two-step again). The design's adoption is StrBuf-only heap->heap (D-6) and so never meets this, but U7 (UNL-4) and any HEAP result grown on the heap inside a scope and kept (e.g. minimize's results, D-2 L3) does.
- Why the design kept it (inferred): G2a "attempt-arena high-water IDENTICAL" plus "a favourable move ... is reported, not kept" (Goals G2). Moving base records to the heap lowers arena bytes by 16 B per compound part; G2a as written forbids that. The over-tight goal is what forces two record types. Note the record HOME is independent of the record TYPE: an LEnt may be taken from the arena at base and from the heap in a scope, one type, one walk, one kind table.
- Fix shape: the base level is the registry's bottom (LEnt entries below every mark; `Scope base = { a, NULL, 0 }` is the arena's own level), `pcrec_arena_hold` = the HEAP kind at that level; `owned` deleted. Cost now: ~same lines as R2 (R2 already rewrites own_slot's one caller, compound.c `walk_part`). Cost later: equal (arena.c-internal), so this is NOT a must-decide-now item, but the D-1 claim "same release walk" is false as written and should be corrected or made true.

### UNL-2 D-1's deciding-site tally credits (B) with deleting S4's 33 lines "keyed on the FIELD", but the API has no field-keyed heap kind, and the release order would free Job fields after the Job
CONFIRMED (design text vs API vs code). Severity: design/doc (the D-1 choice still stands on S10/S12; the S4 capability row is what is wrong). Effort: S (one kind row + one sentence). Blast radius: D-1's table, D-3, P4's trigger text.
- D-1 table row S4: "(B) registry: CAN (an entry keyed on the FIELD survives realloc and the swap), all 33 lines"; bottom row "capability 33 lines / 0". D-3 repeats "the entry is keyed on the Job FIELD (the revend swap)".
- The API's kind table: HEAP "record holds `void *p`" - keyed on the VALUE. Only STRBUF and ARENA are field-keyed, and only because the object lives INSIDE the record (§API "THE ORDER": "A StrBuf or child Arena lives INSIDE its record"). A Job array cannot live in a record: it is a field of the heap Job, grown in place by `realloc` (nfa.c `nst`, dfa.c `tab_grow`, `intern`, dfamemo.c `pcrec_build_min_dfa`, arch S4) and swapped BY VALUE between Job fields (compile.c:587-591, `tn = job->nfa; job->nfa = job->xnfa; job->xnfa = tn;` x4 + adfa). A HEAP entry holding the old `p` after either is a double free / free of a live table.
- What S4 actually needs is a fourth row, FIELD: "record holds `void **fp`; release `free(*fp); *fp = NULL`" (the swap moves contents, the field's address is fixed, so the entry follows both). Plus an ORDER fact: today `job_cleanup` frees `cx->job` (compile.c:326) BEFORE `pcrec_arena_free(&cx->arena)` (compile.c:329), so FIELD entries released inside `pcrec_arena_free` would read freed Job memory. LIFO solves it only if the Job ITSELF is a base entry registered before its fields - which needs base-level kinds (UNL-1) - and S22's two end actions (compile.c:277, :279) become a RUN row registered right after the Job (released after the fields, before the Job).
- Unlock U4/P4 therefore needs: a FIELD row, the Job as a base entry, base-level kinds, and (for S22) a non-memory RUN row. The kind table form supports all four as rows ONLY IF the release function's signature takes the record's storage address generically (`void (*rel)(void *storage)`), not a per-kind union member - a choice made in F1. Cost now: one sentence in the kind-table spec. Cost later: re-signaturing every row.
- Trigger (unchanged, D-3): P4's own (the next Job heap array or end action a client adds). Correction now: D-1's S4 row should say "CAN with a FIELD row and the Job registered first (not built)", so the tally that chose (B) does not rest on a capability the specified API lacks.

### UNL-3 L5 ("a child arena is allocation-only: no scope opens on it") rests on a release-order reason that does not hold, and it blocks the owner's "special areas" form and a concrete sibling helper
CONFIRMED (design text + code paths). Severity: design. Effort: S (delete one refusal, add one close-time check). Blast radius: arena.c; the L5 sabotage row (6) changes to the replacement check.
- D-2 L5's reason: "One level of nesting per arena keeps the release order a single list." But the ARENA row's release IS `pcrec_arena_free(&ar)` (§API kind table), and `pcrec_arena_free` releases that arena's own registry first (§API: "release `top` newest-first ... then the blocks"). So a child holding scopes is released correctly by recursion with no change to the walk: the release order is already a tree walk, and the handler-top `pcrec_scope_unwind(&cx->arena)` reaches every child through its ARENA entry. The only real hazard is a NORMAL-path close of the parent scope while a child still has an open scope (a dangling `Scope`): one check at the ARENA row's release ("child depth == 0, else internal error") covers it, the same L1/L2 shape.
- What L5 blocks: (i) the owner's words, "allocated up and deallocated down the stack ... special areas like minimization" - a bump area with marks inside it. The design's own D-1 table, row S13 under (A), describes exactly that form ("child arena per call, plus a nested scope per refinement pass for `keyseen`") and L5 makes it illegal under (B). (ii) A sibling the design does not list: clskit.c's helpers take an `Arena *a` from BOTH the attempt arena and the clskit child. `intern_records(Arena *a, ...)` (clskit.c:358; its `slot` hash table, `pcrec_arena_alloc(a, sizeof *slot * cap)` at :363, is dead on return) is called from `build_pages` (:413, :428), reached from the public `pcrec_clskit_select`/`_whole_bytes` with `&cx->arena` (emit_vm.c:1610, :1678, :1889; emit_dfa.c:13154), AND from `emit_leaf_tables` (:985) under `pcrec_clskit_emit_kit`'s private arena (:1126, S14, which F2 makes the ARENA entry). If U1 ever scopes that scratch, the helper refuses on one caller path and not the other: L5 makes a helper's legality depend on its caller's arena kind ("a shape states the inputs it covers").
- Cost of deferring: low (lifting L5 later deletes a check and adds one; no data layout depends on it: a child Arena already carries `top`/`depth` by the struct). So not must-decide-now; but the stated reason should be corrected, and the trigger named: the first scope wanted inside a function reachable from a child arena (today: `intern_records`/`build_pages` under emit_kit), or a per-pass mark inside a special area.

### UNL-4 D-5 claims scopes give COST-1's sites "a fix that is one call"; true only for StrBuf builders. The array-shaped S19 members need a realloc on a HEAP entry the API does not have, and the hand rule they obey is a deletable "what dies when" answer the design does not count
CONFIRMED (API vs code). Severity: design/doc. Effort: S (one function, ~10 lines: `pcrec_scope_realloc(Scope *, void *p, size_t n)`, record found as `pcrec_scope_free` finds it). Blast radius: D-5's text; the U7 unlock row.
- D-5: "a builder grown in a loop can be a scope StrBuf (heap, freed at close, no retention) without any new mechanism, so a site that the trigger names has a fix that is one call."
- The S19 members the code names are ARRAYS, not StrBufs: dfa.c `arena_regrow` (dfa.c:703, 2 callers :775 `LCtxTab`, :896 `ContStack`) and possessify.c `fq_push` (possessify.c:423, "arena-owned, doubled, the old copy left to the arena"). The HEAP API is malloc/calloc/free only (§API), with the record holding the value `p`; a client `realloc` outside the API leaves the record stale (double free at close). So the array members are NOT one call today; they need `pcrec_scope_realloc` (keyed on the record, so the record is updated - the same rule the design states for StrBuf).
- The deletable answer the design misses: dfa.c:698-702 "Geometric regrow out of the ARENA rather than realloc(). Every table in this section is a local of pcrec_build_dfa and intern() can pcrec_ctx_fail (i.e. longjmp) straight past it, so heap ownership here would leak on the error path -- the rule this file's header states as R1 R-3a" (header dfa.c:105-106: "All scratch memory is arena-owned so pcrec_ctx_fail/longjmp cannot leak"). That rule IS a hand-kept answer to "what dies when" (it trades retained copies for longjmp safety), exactly the family D-1 counts; with a scope + realloc entry it retires (heap realloc in place, freed at the function's end and on the teardown), and its retention (COST-1's mechanism) goes with it.
- Cost of deferring: nil (additive). Trigger (U7, unchanged): an S19 member measured super-linear or a retained-garbage share of peak above noise. Correction now: D-5 should name the realloc entry as the array members' missing piece and list R1 R-3a as a family member the trigger would retire.

### UNL-5 GENFORM-9's "second non-memory member has not appeared" misses an uncounted population: the trace build's arrival-time state restores, one of them already at the very handler top where D-4 adds `pcrec_scope_unwind`
CONFIRMED (grep), trace build only. Severity: design/doc (no product-build answer moves). Effort: XS (state the count; classify). Blast radius: D-1's last paragraph, D-3, U6's trigger.
- D-1: "Non-memory kinds (FILE*, end actions) are NOT added: GENFORM-9's second non-memory member has not appeared (GENFORM-2's FILE* was fixed by reordering; S22 is classified in D-3)."
- At F, `compile_driver`'s recovery point already runs a non-memory arrival action: compile.c:2577-2580 `if (setjmp(cx.jb)) { #ifdef PCREC_CAND_TRACE pcrec_cand_eval_reset(); /* a predicate may have longjmped */ #endif`, which restores emit_dfa.c's `_Thread_local` predicate stack (internal.h:9726-9730: "A longjmp out of a predicate leaves the stack raised, so the compile's recovery point calls this"). D-4's new "one unconditional call at the top of the handler" lands beside it: two hand-placed arrival unwinds in one handler, i.e. the general form's (b) branch spelled twice.
- And 6 `pcrec_cand_trace_quiet++ / --` brackets (emit_dfa.c:11447, :11485, :11630, :12680, :14391, :16483) whose restore a longjmp SKIPS, by documented acceptance (emit_dfa.c:11474-11478: "A predicate that longjmps inside a quiet walk leaves the depth raised; that ends the compile, and a later compile in the same process would print no records, which the trace floor catches"). The :16483 block calls `mf_wdecide` and the :11630 block `pcrec_arena_alloc` + `mf_ask` inside the bracket, so the skip is reachable on a refusal.
- These are "restore on unwind" entries (save a value, put it back at release; release never allocates or refuses), the shape of a RESTORE row in the design's own kind table. They are thread-local, not attempt state, so they register on the attempt arena only if the release walk may touch a non-Arena object - another reason the row's release must take a generic storage pointer (UNL-2).
- Unlock: a RESTORE row (or RUN, with S22) deletes the handler-top `pcrec_cand_eval_reset` line, the 6 hand brackets' longjmp caveat and the trace-floor dependency. Trigger: D77 is the manager's ruling, but the count fed to it should be S22 (2) + this population (1 arrival reset + 6 brackets), not "none"; whether trace-build-only members count toward GENFORM-9 is the open classification to state.

### UNL-6 The `Ctx.lent` check counts uses at two allocation sites, not at the error channel, so the design's OWN new channel users (heap-record registrations) escape it; the general form is one count at the channel read
SUSPECTED (design text vs design text; confirm by reading F4's build or by planting a `pcrec_scope_open(&outer_cx->arena)` inside the inner compile and seeing the lent count stay 0). Severity: design (a check whose population is narrower than the class it guards: K163's class, D203). Effort: XS. Blast radius: arena.c, sb.c; sabotage row (9).
- Design §"Discipline and checks", K163 row: "`pcrec_arena_alloc` and `sb_grow` count a use on a lent Ctx". The K163 class (arch S21) is "an allocation under the inner Ctx through a handle whose error channel (`.cx`) is the OUTER Ctx".
- The design adds channel users that are neither: every registering call takes its record "spare, else malloc; a failure diagnoses through `a->cx`" (§API, THE ORDER step 1) - a HEAP record, so it never passes `pcrec_arena_alloc`; `pcrec_scope_malloc`/`_calloc`/`_sb` make heap resources the same way. A scope opened on the outer arena during the inner compile would therefore register through the outer channel with the lent count reading 0. Other existing channel users outside the two counted sites: sb.c:228 `sb_simd_fail` (`pcrec_ctx_fail(sb->cx, ...)`); sb.c:50-51's abort_over refusal is inside `sb_grow` and is covered.
- General form: the count belongs where the channel is READ - one arena.c/sb.c accessor that every `a->cx`/`sb->cx` refusal path and every registering call goes through - so a new user (a registry row, U6's RESTORE/RUN rows, a FIELD row) is covered by construction rather than by remembering to add a counter. This is the same "one question, one primitive" the design applies to release.
- Not a must-decide-now item if F4 lands the accessor form; if it lands the two-site form, every later registry row re-opens the check's population.

### UNL-7 D-11's check guards a value set at one line, in the one callback every pcrec-backed `mf_arena` would share, so it blocks the only pcrec-side route to S27's kit-scratch hazard
CONFIRMED (code), nit. Severity: maintenance/design. Effort: XS. Blast radius: memfn_sites.c, sabotage row (7).
- D-11: "the kit's allocation callback `pcrec_memfn_arena_alloc` (memfn_sites.c) refuses an arena with `child` set". At F the callback (memfn_sites.c:70) has ONE binder: memfn_sites.c:210-212 `ma->u = &cx->arena; ma->alloc = pcrec_memfn_arena_alloc;` - `u` is the attempt arena by construction, so the runtime check can never fire except under its sabotage row; the pin's real subject is line 211.
- Sibling it blocks: arch S27 (SUSPECTED) - the kit's `wd_blk` heap (window.c `wdecide_framed`) live across pcrec `def` hooks that can longjmp. A pcrec-side remedy is to hand the kit, for that SCRATCH, an `mf_arena` backed by a scope's child arena (released at close and on the teardown). That would reuse the same callback, and D-11's check refuses it. The pin is about the ART's arena, so the check (if any) belongs at the art binder (memfn_sites.c:211), not in the shared callback.
- Trigger for the unlock: S27 traced as real by the manager (arch S27: "the manager traces it, then states it to the kit as a FACT, D157"). Cost of deferring: nil if the check moves now; a re-placement later otherwise.

## PROBED-AND-HELD

- Explicit handle (D-1, S24): held. No unlock above needs an implicit "current arena"; `Scope` by value with `Arena *a` can be passed to callees (U1 helpers), and the 462 allocation calls keep their meaning.
- Records on the heap (D-1): held for the scope level; the only cost found is UNL-1's (it forces the base level to keep a second record type under G2a's "identical" wording) and UNL-6's (records bypass `pcrec_arena_alloc`, so the lent count misses them).
- Scopes only on Ctx arenas: not a design restriction (D-7 permits detached arenas, abort on failure). Held.
- `Ctx.lent` as a per-Ctx flag rather than a thread-local "innermost live Ctx": held. Only one nested-Ctx site exists at F (`pcrec_compile_driver` callers: compound.c:75 inside a compile; facts_dump.c:230, callouts_dump.c:151, compile_defs.c:47 from outside one), and coding.md 1.5 limits mutable file-scope objects (internal.h:9720-9724 names the trace build's as "the one"), so a per-Ctx flag is the house-legal form. Its population is UNL-6.
- FILE* sites (GENFORM-2 class): 14 `fclose` lines in 5 files (src/core/ks_measures.c, ksrc.c, src/gen/memfn_stamps.c (a name list, not a call), src/parse/rxt_source.c, cli/main.c). ks_measures.c:800-805 allocates BEFORE `fopen` (the reorder fix); ksrc.c:481-512 has no refusal between open and close. No second FILE* member: held, U6's FILE* trigger unmet.
- goto-out ladders in src/ and cli/: 4 labels (compile.c:534 `out:`, emit_dfa.c:11779 `out:`, :16520 `done:`, rxt_source.c:4013 `fail:`). The first three restore STATE (counters, trace levels), not memory - counted under UNL-5. rxt_source.c's `fail:` -> `pcrec_rxt_source_free`, a detached (cx NULL, no longjmp) tree of arenas freed children first: a "what dies when" answer with nested lifetimes, but under src/parse/, which L4 excludes from scopes by rule; no stranding exists, so it is NOT a client and needs no row. Noted as a sibling the L4 rule excludes, trigger: a longjmp-capable path into rxt_source.
- Kit arenas (`fh_arena`, `wd_blk`, `kb`): the design's non-goal (D157) holds; only S27's hand-off route is affected (UNL-7).
- The 22/23 scratch builders: 23 `pcrec_sb_scratch(` call lines outside sb.c/internal.h at F (one inside sb.c:692). U1 joins as a row either by pointer (`pcrec_scope_sb`) or by a child + by-value scratch. Held.
- S7 memo: no scope client allocates from it (D-4); after F1 its arena carries an empty registry. Held.
- Largest/most nested case reached: the release tree outer attempt arena -> ARENA entry (clskit child) -> helpers reached from both levels (`intern_records` via `build_pages` from emit_vm.c and via `emit_leaf_tables` under emit_kit), and the Job-field release order across `free(cx->job)` (compile.c:326) vs `pcrec_arena_free` (:329). 0 compiles run (reading only).
