## PROBED-AND-HELD


### CONFORM-1 (CONFIRMED, design/doc; effort S; radius F1+F4) `Ctx.lent` is a new Ctx field with three writers, contradicting D-7 and the register row 6a corollary
- Design §D-7: "Not a new Ctx field, not on the Job." Design §"Discipline and checks" K163 row: "`Ctx.lent`: `walk_part` sets it around `part_compile`; `pcrec_arena_alloc` and `sb_grow` count a use on a lent Ctx ... `walk_part` refuses ... if the count is nonzero".
- So the design adds a Ctx field written from compound.c (set/reset), arena.c and sb.c (count). Arch note "Register rows looked up", row 6a: "Its corollary binds any new field: one writer, named readers." Design lists no writer/reader table for `lent`, and D-7's "not a new Ctx field" reads as if no Ctx field is added at all.
- Also 6a's cousin: guide goal 2 (data with its writer): the counter is written by two core files the flag does not belong to. Fix shape: a single owner accessor in arena.c (`pcrec_lent_note(Ctx*)`) and the field named in the design with writer/readers; or hold the count in the Arena (`Arena.lent`) so arena.c is the one writer.

### CONFORM-2 (CONFIRMED by reading the design's own release rule, design; effort S; radius F1 sabotage set) Sabotage row (2) cannot go red under the checks it names
- Design §"Tests and sabotage" (2): "drop the release in `pcrec_scope_close` (LSan red on the normal path, `make asan`)". Design §API: "`pcrec_arena_free(a)`: release `top` newest-first ..., then `owned`, ...", and "`pcrec_arena_free` releases the whole registry before the blocks".
- Under the plant, entries stay in the registry above the closed mark; the same attempt's `pcrec_arena_free` (job_cleanup on the success path, which every compile runs) releases them. Nothing leaks, so LSan/ASan stay green, and `alloc_check`'s profile pass ("compile must succeed and give back every block", alloc_check.c child_attempt n==0) also stays green. The plant only raises peak (entries live to the attempt's end), which no make-test check reads (massif/high-water are manual: CONFORM-6).
- Also `pcrec_scope_check_closed` (L2) is stated over `depth`, which the plant leaves correct.
- Also `make asan` is opt-in (CLAUDE.md "make asan ... opt-in"), not in `make test`; the matrix has `SAB_REQUIRE=asan` rows (run_sabotage_matrix.sh:962,1470) but the design names no suite/arm for row (2).
- Fix shape: make close assert its own post-condition (`a->top == s->mark` after the walk) or make `check_closed` also require an EMPTY registry (top NULL) at a successful attempt's end; then row (2) goes red under the corpus compile. Without it the row is UNDETECTED and violates the row's own "each release path has a row" claim.

### CONFORM-3 (CONFIRMED by measurement, speed/design; effort M; radius T1, every later gate that cites W7) T1/W7 is unpriced and the measured trial population is 25-200x the existing witnesses
- Design §Clients T1: "W7 over W1-W6's patterns: every trial diagnosed", cost "(about 40 lines)". Makefile:2255-2260: `test-alloc` IS a `make test` section, "~60 s", running `run_alloc_tests.sh` whose default is `--both` (single-shot AND sustained, run_alloc_tests.sh ALLOC_ARGS default).
- Measured (callgrind on build/pcrec at the review tree, one compile each): W1 `[a-z]+` makes 2,660 `pcrec_arena_alloc` calls (372 M instr for W4 below; 32 M for W1); W4's ladder pattern makes 32,951 `pcrec_arena_alloc` calls and 274 malloc calls, vs the pinned W4 floor 81 of ~162 mallocs (alloc_check.c W4 row). A forked trial per arena allocation for W4 alone is ~33k compiles of ~0.1 s = about an hour single-shot, again for sustained; the existing section is ~60 s in total.
- Not stated: whether W7 samples, shares `call_n` with W1-W6 (if it shares, every exact pin moves: W6 "504 floor, 982 absorbed", W4 floor 81 are counts of the malloc stream), or has its own counter. Also T1 puts an `#ifdef` hook inside `pcrec_arena_alloc` (hot, 462 sites), against alloc_inject.h's founding rule "NOTHING UNDER src/, cli/ OR lib/ IS EDITED" and its stale-object warning (no -MMD; a stale arena.o without the hook would run W7 with zero trials silently unless a floor is set, D110).
- Consequence: sabotage (1) (drop the registry walk) depends on W7 to go red (CONFORM-2's counterpart), so a W7 cut for cost removes (1)'s only detector. T1's STOP condition is missing.
- Fix shape: state the sampling rule (every Nth arena alloc, or only allocations while a scope entry is live, which is the only population the feature needs), its own counter, a floor, and the budget in `make test`.

### CONFORM-4 (CONFIRMED, doc; effort S; radius register P6/RM-3) The design changes P6's trigger and declines RM-3 without saying it changes them
- Arch note P6 row: "P6 (only if RM-3 is not taken) | `Arena` initialised ... | event: a field added to `Arena`"; RM-3: "Lands first if D-1 makes a scope an `Arena` with a new field ... If D-1 adds no field, proposed row P6 holds it."
- Design §API gives `Arena` four new fields (`top`, `spare`, `depth`, `child`) and §Refactors says "P6 keeps its trigger: a field whose zero is not valid". The note's trigger was "a field added to `Arena`" (fired by this very design); the design's version is a different trigger. Reasoning ("every field's zero is valid, so the 33 writers need no change") may well be sound, but a register row's event is the manager's; the design must say "P6's event is re-worded from X to Y" and why RM-3's condition is judged not met.
- Also `child` is NOT zero-valid for a child arena: arena.c must set it, and `pcrec_arena_free` "resets every field but cx and child" - a second writer rule (arena.c only) the design states only implicitly.
