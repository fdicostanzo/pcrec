# Findings: lens simulate (r102 arenadesign)

## Findings

### SIM-1 CONFIRMED (by hand-execution of the stated rules) -- the L1 check (`s->depth != a->depth`) does not catch a stale/double close once another scope has opened at the same depth; with `spare` reuse the stale mark releases an ENCLOSING scope's live entry
Severity: memory (use-after-free on an internal-error path) / design (the L1 table row claims "double close" is caught). Effort: small. Blast radius: every scope client; the check, not the clients.
Where: design § "Discipline and checks" row L1; § API (`Scope { Arena *a; LEnt *mark; unsigned depth; }`, mark = a record pointer, records reused through `spare`).
Hand run (every kept guard in force): O = open (depth 1, mark NULL); e1 = scope_malloc(&O) (record R); I = open (depth 2, mark R); close(&I); close(&O) -> R to spare. Later: O2 = open (depth 1, mark NULL); e2 = scope_malloc(&O2) REUSES R; e3 = scope_malloc(&O2) (record R3); I2 = open (depth 2, mark R3). A stray second close(&I) (stale value, or a by-value copy of I closed by a helper): I.depth 2 == a->depth 2, the L1 check PASSES; the walk releases from top down to mark R: I2's entries AND e3 (O2's entry, R3) are freed; depth -> 1. O2's code then reads e3 (heap-use-after-free); only I2's own close later trips L1 (2 != 1), after the damage. The immediate double close (close(&I); close(&I)) IS caught (1 != ... ), so the gap is exactly "stale scope + an intervening open at its depth".
Expected: a close that is not the innermost OPEN scope refuses before releasing anything.
Fix shape (general, no new mechanism): make the mark a record the scope OWNS: `pcrec_scope_open` pushes a MARK record (no resource; kind row with a no-op release) and `Scope.mark` points to it; close requires `a->top`-chain to reach its own mark record AND `mark->depth == a->depth` (or a per-arena open serial stored in both the mark record and the Scope), then pops it. A mark record is never on `spare` while its scope is open, so reuse cannot alias it; `pcrec_scope_close` also poisons `*s` (depth 0). Cost: one record per open scope (spare-reused), well inside G2b. Cheaper alternative: a per-arena 32-bit open serial in Scope and in a small per-depth array -- but that is a second structure.


### SIM-2 SUSPECTED (design omission; would be CONFIRMED by the build's text) -- `pcrec_scope_free(s, p)` unlinks a record from the MIDDLE of `top`; if a nested scope's `mark` is that record, the nested close walks past it and releases the enclosing scope's entries
Severity: memory (over-release, use-after-free). Effort: one sentence + one check. Blast radius: the early-release call (minimize `keyseen` today; any later caller).
Where: design § API `pcrec_scope_free` ("early release of one HEAP entry (keyseen)"); D-2 has no rule for it.
Hand run: S = open; k = scope_malloc(&S) (record K); N = open (mark = K); pcrec_scope_free(&S, k) -> K unlinked to spare. close(&N): the walk releases newest-first "to the mark" K, which is no longer in the chain, so it runs to the end of `top`, releasing S's (and any outer scope's) live entries. If K was meanwhile reused from spare by an entry of N, the walk stops at K instead and N's entry K survives N (released later by S: order wrong, no leak).
Today's only caller is safe: minimize.c:132 allocates `keyseen` after the five tables and frees it at minimize.c:148 with no allocation and no nested scope in between, so `keyseen` is always the top record (O(1) pop). The design states no precondition, so nothing keeps it so.
Fix shape: rule L1b "early release only of an entry of the INNERMOST open scope" checked as `s->depth == a->depth` plus "the record is above `s->mark`" (found by the same search), internal error otherwise; with SIM-1's mark records the search simply stops at the first mark record.


### SIM-3 CONFIRMED (by reading) -- a record reused from `spare` carries its previous kind's state; the design's take step (1)-(4) never re-initialises it, and `pcrec_sb_free` / `pcrec_arena_free` reset only part of what lives in the record
Severity: answer (G1) and memory. Effort: one sentence ("take = zero the record, set its kind"). Blast radius: every registering call after the first close in an attempt.
Where: design § API "THE ORDER INSIDE EVERY REGISTERING CALL" step (1) "take a record (spare, else malloc ...)"; kind table (STRBUF record holds `StrBuf sb`, ARENA holds `Arena ar`); `pcrec_scope_sb` "heap storage, .cx = a->cx".
Read: the STRBUF release is `pcrec_sb_free(&sb)`, which resets ONLY `p`, `len`, `cap` (src/core/sb.c:481-486). StrBuf also holds `cmt_drop`, `cmt_depth`, `cmt_mute_depth`, `cmt_dropped`, `abort_over`, `ar`, the `simd_*`/`scaf_*` records and `layout_bytes` (internal.h:447-). The ARENA release is `pcrec_arena_free`, which per the design resets "every field but cx and child". `pcrec_sb_adopt` (D-6) empties `p` only.
Hand run: render_buf's `o` (record R, STRBUF) grows with a muted region open or a nonzero `cmt_dropped`/`layout_bytes` (stamp_lines writes into `o`, part_layout.c:630), is adopted, closed -> R to spare with those fields intact. splice_mark's `tail` then takes R: if only `.cx` is set, `tail` starts muted / with a stale `cmt_dropped` (moves `pcrec_sb_len_uncut`), or with a stale `ar` (then `pcrec_sb_free` would NOT free its heap bytes: sb_unstore frees only when `ar` is NULL, sb.c:22 -> leak). A STRBUF record reused as an ARENA entry reads StrBuf bytes as `Arena{head, cx, owned, ...}` -> release frees a garbage `head` (invalid free). malloc'd (not calloc'd) first records have the same hole.
Expected: step (1) says "a taken record is zeroed and its kind set before it is linked" (one memset); `pcrec_scope_sb` then sets `.cx` (and nothing else from the old record survives). Today's locals are `StrBuf o = { .cx = cx }` (part_layout.c:600, memfn_stamps.c:251, :366): all-zero but `cx`, which is exactly what the build must reproduce for G1.


### SIM-4 CONFIRMED (by reading the success path) -- "`pcrec_scope_check_closed(&cx.arena)` before the success `job_cleanup`", taken literally, sits AFTER the three takes have been published to the caller, so its own internal-error refusal strands the artifact strings
Severity: memory (a strand on the L2 refusal) + answer (a -1 with `out->c_src` set). Effort: one phrase. Blast radius: the L2 check and its sabotage row (5).
Where: design § "Discipline and checks" row L2 ("before the success `job_cleanup`"); src/core/compile.c:3738-3745.
Read: compile.c:3738-3743 takes `out_c`/`out_h`/`out_ir` and then MOVES them out (`out->c_src = cx.job->out_c; cx.job->out_c = NULL;` ...); 3745 is the success `job_cleanup(&cx)`. A check placed at 3744 that refuses longjmps to the handler; FIT_REFUSE's `job_cleanup` (compile.c:2658) no longer sees the strings (`out_*` are NULL), so `out->c_src`/`h_src`/`ir_out` are left allocated in the caller's struct on a -1 return: stranded (the caller frees nothing on -1) -- exactly what sabotage row (5) "delete a close" provokes, so the row would turn LSan red for the wrong reason or pass alloc_check while leaking.
Expected: the check sits before the first take (before compile.c:3738; e.g. immediately after the `[COMPOUND] A PART's FACTS` block, or before `facts_force`'s prefix render), where every artifact string is still a Job field `job_cleanup` frees. On the inner (part) compile it must also precede the facts block's write into the outer hold (F4) only if F4's store is not yet owned -- it is owned (hold linked at birth), so after the facts block is fine.


### SIM-5 CONFIRMED (by grep) -- the K163 class check counts uses at two of the error channel's entry points (`pcrec_arena_alloc`, `sb_grow`); the channel has more, and the design's own new registry adds two more, so "0 uses after F4" does not prove the class closed
Severity: design (the check's population is narrower than the class it claims, D203 / learnings §3 "a population nobody counts"). Effort: small (count at the channel, or list every entry). Blast radius: K163 closure and its sabotage row (9).
Where: design § "Discipline and checks" row "K163 class"; unit F4.
Read: Ctx-channel uses that bypass both counted sites: sb.c:472-473 `pcrec_sb_take` (heap `strdup`, then `sb_nomem(sb)` -> `pcrec_ctx_nomem(sb->cx)`); sb.c:792-793 `pcrec_sb_render_prefix` (`sb_store` -> for a heap StrBuf a raw `malloc`, then `sb_nomem`); sb.c:228 `sb_simd_fail` (`pcrec_ctx_fail(sb->cx)`); sb.c:51 the abort_over `pcrec_ctx_fail` is inside sb_grow (counted only if the count precedes it). NEW in this design: step (1) of every registering call ("take a record (spare, else malloc; a failure diagnoses through `a->cx`)") and `pcrec_arena_hold`'s record take, if records are heap as § "THE DESIGN IN ONE PARAGRAPH" says -- neither goes through `pcrec_arena_alloc`.
Why it matters for (b): after F4 the INNER compile's facts block writes the outer hold, and the outer's `walk_part` reserves the hold just before `part_compile`; if the build ever takes that hold record (or any scope record on the outer arena) while `lent` is set, the counter never sees it, and its malloc failure longjmps to the OUTER point from inside the inner compile -- K163 verbatim, invisible to the check.
Fix shape: count at ONE place every channel use passes -- a `static inline Ctx *chan(Ctx *cx)` (or the `lent` test) called by `pcrec_arena_alloc`, every sb.c site that can reach `sb_nomem`/`sb_simd_fail`, and the registry's record take -- and have the scanner hold "no `pcrec_ctx_nomem(`/`pcrec_ctx_fail(` on a `->cx` field outside chan's callers"; or state the counted-site list as a declared table the check walks.


### SIM-6 CONFIRMED (by reading) -- after F4 a failure of the copy into the outer hold is ABSORBED by the compound walk (the outer compile SUCCEEDS with the plain artifact), so F4's gate "W7 failing the inner copy: diagnosed at the INNER point" is not what alloc_check reads, and W6's EXACT absorption pin moves

Where: design § "Clients and migration order" unit F4 gate; tests/core/alloc_check.c W6 row (`504, 982, 0`, "the compound row's by-design fallback"); the verdict table (alloc_check.c header: exit 2 = "pcrec_compile SUCCEEDED despite the forced failure -- FAIL" unless absorbed-pinned).

Inner success block (compile.c:3713-3737): the heap copy of `memfn_forms` fails -> `pcrec_ctx_nomem(inner)` -> inner handler -> top unwind (inner arena only) -> FIT_PROPAGATE (compile.c:2637-2639): inner `job_cleanup`, inner memo freed, `return -1`. Today the same failure (when the copy opens a block) longjmps to the OUTER point and the compile is DIAGNOSED (K163's own text: "The outer compile is diagnosed ... correctly").

Expected: F4's gate reads "nothing stranded; the failing trial is absorbed by the by-design fallback (W6's pin re-measured and re-pinned in the same unit, D110), never diagnosed at the outer point", and the answer-under-OOM change (refusal -> plain artifact) is named as the by-design class, not a new behaviour.


### SIM-7 SUSPECTED (order unstated; confirmed by the build's text) -- `walk_part`'s lent refusal must come AFTER the part text is stored into its hold, or the refusal strands the inner compile's `c_src`
Severity: memory. Effort: one sentence. Blast radius: F4 + R2 in `walk_part` only.
Where: design § "Discipline and checks" row "K163 class" ("`walk_part` refuses (internal error, at the OUTER point, inner already torn down) if the count is nonzero"); units R2/F4; today's shape compound.c:182-191.
Hand run: R2 turns compound.c:183/191 into `void **h = pcrec_arena_hold(&w->cx->arena)` before `part_compile` and `if (rc == 0) *h = w->out[i].c_src` after it. The inner returned 0 with `c_src` a heap string the inner `job_cleanup` no longer owns (moved out at compile.c:3742). If the build puts the lent test between `part_compile`'s return and `*h = c_src`, the internal-error longjmp to the outer point leaves `c_src` owned by nobody: the very K155 strand R2 exists to prevent. Same for `lent`'s CLEAR: if the clear is after the store but the counter is read before it, the outer's own `*h` write is harmless (no allocation), but any outer allocation placed in that window is miscounted.
Expected: the F4 row says the order: reserve hold(s) -> set `lent` -> `part_compile` -> clear `lent` -> store `c_src` into its hold -> test the count. With that order every arrival (inner refusal, inner nomem, outer lent refusal, outer later refusal) leaves each heap result with exactly one owner.


### SIM-8 SUSPECTED (two readings of the design; each fails one of its own claims) -- the BASE level's record home is unstated: under "records are heap" the release text never frees the `owned` records; under "records are arena" G2a's premise is false only by wording
Severity: memory (reading 1) / doc (reading 2). Effort: one sentence. Blast radius: R2 (`pcrec_arena_hold`), every compound walk (2 holds per row today, plus F4's memfn_forms hold).
Where: design § "THE DESIGN IN ONE PARAGRAPH" ("Entry RECORDS are heap, not arena, so the attempt arena's bytes do not move at all"); § API (`AOwn *owned; /* BASE level */`, `void **pcrec_arena_hold(Arena *a); /* BASE entry, linked at birth */`); the `pcrec_arena_free` sentence ("release `top` newest-first (each record to `spare`), then `owned`, then free `spare`, then the blocks").
Reading 1 (hold records heap, as the paragraph says): `pcrec_arena_free` frees each owned record's `p`, but only `top` records go to `spare`; nothing frees the AOwn records themselves -> one leaked record per hold per attempt (LSan red on every compound pattern), unless "then `owned`" also returns its records to `spare` (unsaid). Also arena high-water then DROPS by 16 B per hold (today's `pcrec_arena_own_slot` takes the record from the arena, arena.c:42-45), so F1/R2's "arena high-water identical" gate reads a move the design says "cannot arise".
Reading 2 (hold records stay arena, as today's AOwn): safe -- they are read before the blocks are freed, as today (arena.c:62) -- but then step (1)'s "take a record (spare, else malloc)" is not the hold's step, and the hold's take diagnoses through `pcrec_arena_alloc` (counted by the lent check), which is the better answer for SIM-5.
Expected: one sentence naming reading 2 (or, for reading 1, "owned records go to spare too").


### SIM-9 CONFIRMED (wording) -- "count a use on a lent Ctx (no longjmp there)" has a reading that builds a half-built object: if "no longjmp" is read as "a FAILED allocation on a lent Ctx does not longjmp", `pcrec_arena_alloc`/`sb_grow` must return without storage, and no caller checks

Where: design § "Discipline and checks" row "K163 class".
Read: `pcrec_arena_alloc` has no NULL return to its callers (arena.c:25-27: `pcrec_ctx_nomem` then `abort()`); `sb_grow` likewise (sb.c:64-65). Under the intended reading (the COUNT never refuses; the allocation is made exactly as today) nothing is half-built: the counter increments, the object is whole, the refusal happens later in `walk_part` at the OUTER point after the inner teardown (with SIM-7's order).
