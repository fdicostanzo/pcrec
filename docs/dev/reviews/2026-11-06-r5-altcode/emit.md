    SUBJECT `-fno-altcls-merge` 205,065 (restored); SUBJECT `-fno-altcls-factor` 13.2M (not restored); BASE `-fno-alt-island` 12.7M — i.e. the 2b artifact runs at the no-island speed.

  - DEFAULT flags: `(Jan|Feb|Mar|Apr|May|Jun|Jul|Aug|Sep|Oct|Nov|Dec) \1` on 60 KB mixed-case random words: BASE islands 1, 1,063,823; SUBJECT islands 0, 3,247,958 (~3x).
  - The whole altwide set under `--engine=vm` (39 patterns): every word-list rung goes `RX_VM_ALT_ISLANDS 1 -> 13..98` (w-*, sh1-*, pfx3-*, nar4-*, srt-*, wb-*, cls*-*); program bytes mostly fall (e.g. w-256 143,470 -> 109,751), which is why a size view looks like a win.
- severity: speed
- effort: M ; blast radius: every VM artifact (forced, or auto-routed by a backref/lookbehind/capture need) whose alternation is a finite literal word list in which ANY two branches differ in one equal-width position — i.e. practically every real keyword/word list of size > ~20. DFA artifacts unaffected (auto picks DFA for the bare altwide rungs: only stamps move there).
- where: src/opt/altnf.c rule M at the altcls caller; src/gen/emit_vm.c:4012 `vm_isl_single` + :4127 `case A_CLASS` (a multi-member byte class declines, and the decline propagates through the `A_ALT`/`A_CAT` walks to the whole top-level alternation, :4150/:4172); design §5 Stage 2b "Predicted movers" and §3.3 table row "VM island: NOT a reader of the owner".
- argument: the island's own header (emit_vm.c ~4040-4050) records that this exact collision happened once before (altcls factoring, `w-256` 11 islands, +3.0%) and that the fix was to make the island read the subtree's LANGUAGE so an upstream rewrite cannot break it. Rule M re-breaks it in a way the language reading cannot absorb: M produces multi-member `A_CLASS` edges, which `vm_isl_single` declines, and one such class anywhere in the list declines the top island; the residue islands only cover sub-lists. The design lists "the VM island census" as a 2b mover and cites the old collision, but predicts neither direction nor magnitude, and G2/D186 require "no regime loses beyond noise" for a choice change — this is ~2 orders of magnitude on the bench's own altwide family under the VM. Both obvious repairs are already named in the design: (a) the island enumerates a multi-member byte class's members as words (disjoint single-byte edges keep the trie's argument; this is [ENG-ISL-S2]/U6's CLASS-MEMBER widening, whose trigger this measurement is), or (b) M declines inside an alternation the island would otherwise take (a row on M's admission). The asymmetry makes (a) the one-mechanism answer: under `-e utf8 --engine=vm`, `x(?:éa|èb|ça)y` merges (MERGES 0->1) yet keeps `RX_VM_ALT_ISLANDS 1` and byte-identical program bytes, because the stage-1 `A_WCLASS` arm reads the merged class as its member words; the byte twin `x(?:ea|fb|ga)y` merges and goes islands 1 -> 0 (program 1981 -> 1291 B, C file 23,680 -> 24,310 B), because the `A_CLASS` arm (:4127) declines a multi-member class. The same fact (a merged class of literals) is words in one arm and a decline in the other. Until one lands, 2b is a VM regression on the bench family it was meant to help; bit 10 restores it, so a stop-gap is to keep M out of the altcls caller's VM route.
### EMIT-2: the K139 `drop-islands` row sits BEFORE `drop-prefilter`/`drop-handoff`, so patterns that compiled at BASE by dropping only the prefilter now ship with BOTH dropped (~80x more instructions)
- status: CONFIRMED. Pattern = `(` + the first 400 of 1000 seeded random 8-letter words (`random.seed(11)`, generator `$R/emit/k139/gen2.py 400`) + `)\d+`, DEFAULT flags (auto: VM hybrid). BASE: note "dropped the VM hybrid's prefilter", `RX_VM_ALT_ISLANDS 1`, 212,833 B C. SUBJECT: notes "dropped the VM's alternation islands" THEN "dropped the VM hybrid's prefilter", `RX_VM_ALT_ISLANDS 0`, 145,068 B. Same at 700 words. SUBJECT `-fno-altcls-merge` gives the same double drop, so it is the row order, not rule M. Instructions on 2029 bytes of a no-match lowercase-word text, `--emit-main`, gcc -O2: BASE 259,377; SUBJECT 20,944,134 (~80x).
- severity: speed
- effort: S (move the row; or let a later row's success re-try without the earlier drop) ; blast radius: every VM artifact that has islands AND another droppable piece (hybrid prefilter, handoff) and is over a size cap: before 2b, any word-list capture pattern over ~350 words (`(list)\d+`, `(list)=...`).
- where: src/core/compile.c:1431 (`drop-islands` placed before `drop-anchored`/`drop-premul`/`drop-handoff`/`drop-prefilter`), `fit_seq_legal[]` :1902-1909; docs/spec/limits.md §8.4 rung 2b; known_issues.md K139 "the caller's own `-fno-alt-island` artifact".
- argument: the ladder is documented as ordered by measured cost (compile.c :1215 "Ordered by measured cost ... the prefilter drop's ~4x, so this row is tried first"; handoff ≤2.53x). Dropping the islands costs far more (EMIT-1: ~60x on w-256; here ~80x), yet the new row is tried first, and the ladder never puts a dropped piece back, so a pattern whose overage the prefilter drop ALONE fixes now loses both. The K139 fix was framed as "the island axis never refuses what the chain accepts"; it should not also change the artifact of a pattern BASE already accepted. The brief's question (4b) "does any pattern that compiled before now take a different rung": yes. Minimal fix: put `drop-islands` after `drop-prefilter` (last VM rung before `refuse`), which keeps K139's rescue (it only fires when everything cheaper failed) and restores BASE's artifact for this family; `fit_seq_legal[]` gains the mirrored pairs.
