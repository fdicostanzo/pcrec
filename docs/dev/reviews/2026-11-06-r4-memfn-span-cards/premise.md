### PREMISE-1 — CONFIRMED — design (answer of the pick at SIMD-on) — §2.3, §2.5 "Row 1's SIMD-on arm needs no SIMD card", §3.7 J6 "droppable alone"
The premise "row 1's SIMD-on arm needs no SIMD card" is already false on row 1's own witness. At SIMD-on the incumbent `{X,x}` of smp20 is rendered as fn-pair plus vrun:
```
build/pcrec -p rx -o n.c --pattern '(?i)x/1234'               -> RX_MEMFN_FORMS "none"
build/pcrec -p rx -fmemfn-simd -o s.c --pattern '(?i)x/1234'  -> RX_MEMFN_FORMS "vrun@w32+w16"
```
(s.c:60-170 `rx_mf1_ofsskip__body/__w16/__w32`; the diff against n.c is 91 lines.) The same holds for `(?i)hello world` and `(?i)union\s+select`, so caseless literals, which are the row-1 class, carry vrun at SIMD-on. D186 add. 2 C9 says "NOT smp20 (on '/' the SIMD build calls memchr, the same as scalar)". That is true of the CHALLENGER '/', not of the incumbent. At SIMD-on, row 1 compares vrun's cost against memchr's, so `find_byte.vrun-*` / `find_hit.vrun-*` are row-1 keys, not only keys of the C9 row. J6 is then not "separable, droppable alone": dropping it leaves row 1's SIMD-on comparison unpriced on its watched witness. §2.5's hedge ("a non-none site is a census finding") already has its answer.
Fix: move the vrun keys to row 1's reader list; J6's vrun half becomes non-droppable (or row 1 is declared SIMD-off only, with that limit stated). Effort: small text change; the vrun timing cell has to be redesigned (PREMISE-2). Blast radius: §2.5, §3.7, §9 S2d, §10.2.

### PREMISE-2 — CONFIRMED (text) — design — §3.1 "(G2) g2_win_gen.c --cards ... ONE window-site builder", §3.2 "one stop set S at offset 0", §2.3 SIMD forms as method tokens of find_byte/find_hit
The one-builder premise does not hold for three reasons.
(a) g2_win_gen.c is SIMD-off by construction. Every `mf_art_begin` call in it passes `MF_P_PORTABLE_ONLY` (W/memfn/tests/g2/g2_win_gen.c:639,646,657,740,795,847,852,931,952). It renders through `mf_wdecide` + `mf_emit` (:742,750,855,986), and `mf_define` only at :1048. The SIMD rows live in OTHER G2 families: vrun in g2_simd_gen.c (header :5-10, "policy word lacking MF_P_PORTABLE_ONLY", its own sink with bracket ops), and vany in g2_any_gen.c through `mf_kernel_find_any` (:9, :110).
(b) vany is "NOT ROUTED. No mf_site row" (W/memfn/src/vany.c:16-21). No mf_define/mf_emit call can render it, so no window-site builder can produce it.
(c) vrun cannot render on "one stop set S at offset 0". Its site is "ONE RUN term of length 2..VRUN_MAX_RUN ... REACH: the site's proven span is not shorter than VW + T" (W/memfn/src/vrun.c:19-25). Every candidate is verified by the run compare (vrun.c:33-37). It is reached only through window row B-fn (W/memfn/src/window.c:1764-1805). Its cost per byte and per hit therefore depends on run length, the mask filter and the verify, which a stop-set cell does not carry.
So the SIMD arms need the other two G2 families (or a site shape of their own), and the vrun cards need a RUN-term regime in the card's `subject`. The answer gate is also not "the scalar byte loop's find-all count". g2_win_run.c holds the reply to the reference's decision and every answer to the facts (g2_win_gen.c:18-19), which is a reference check, not a count against a byte loop. Effort: medium (producer design). Blast radius: §3.1, §3.2, §2.4 card `subject` column, J6.

### PREMISE-3 — CONFIRMED (code) — maintenance/design — §2.4 "ids marked NEW are added to formhash.c's canon()", §8.2 form-hash row, S2c
"canon() knows only walk and libc" holds (W/memfn/src/formhash.c:238-241). "Add the ids to canon()", however, understates the change. `mf_form_hash` is hard-wired to `mf_art_begin(..., MF_P_PORTABLE_ONLY, 0 /*denies*/, NULL, NULL)` + `mf_emit` (formhash.c:291-292), so it cannot render any vrun/vany text. vany renders outside any site: kit-kernels.tsv:20-22 says "the kernel renders outside any site, so mf_form_hash cannot hash it yet: the deps are OWED". PAIR "holds only for the asker that renders it (the asker fact SF_ASKER_PAIR)" (finder.c:36-38, :289, :656), i.e. a window-family asker, which canon()'s plain STMT/FIND site is not. The rc-* forms are compare rows inside a run verify (runcmp.c:102-120), not FIND sites. So S2c needs a new hashing entry shape (policy, entry, site kind per id), and maybe an MF entry change, not 12 table entries. Effort: medium. Blast radius: S2c, finder_check.py check C, sabotage (12).

### PREMISE-5 — CONFIRMED — design (a lever the design says does not exist) — §2.5 find_hit.walk.*.alt, §3.1 "the method chosen by the existing denies (--memfn=no-...) or force rows", J2/J3
