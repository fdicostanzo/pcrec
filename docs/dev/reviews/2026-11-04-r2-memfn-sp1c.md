## Findings (consolidated) with PROPOSED dispositions

### F1. `kit_run_member`'s `after` walk silently assumes T_MASS_STRETCH is a strict, translation-invariant order (SLOT-1, CONTRACT-3, EMIT-1) — maintenance

- **What happens:** under a TIE_EXCHANGE/PARKED/RESEED value, `kit_tie_takes` answers 0. The walk then skips every equal-mass position and returns pos -1. translate stores that as `rank_pos` 65535 while `rank_n` = n (window.c:1366), and vrun.c:238 indexes it.
- **Evidence:** the verifier re-ran the plant. A TIE_EXCHANGE row gives `rank` 0, 65535, 0, 65535; the control gives 3, 2, 1, 0.
- **Key spaces:** the same row is keyed run-relative in `kit_run_member` (window.c:777/780) and absolute in `a_mass_choose` (window.c:~573). The answers agree only because the row is TIE_HIGHER. kit.h:365 says "keys are offsets".
- **S1095:** its plant swaps only the pick spelling (:780), not the `after` filter (:777). Its mutant therefore detects through dropped and -1 entries, not through the leftmost tie its name describes.
- **No mover today.** mass_check does catch a row flip, with 3 FAIL.
- **PROPOSED: FIX-NOW (small).**
  - State the precondition in kit.h at `kit_run_member` and in the T_MASS_STRETCH row: a strict order invariant under translation, HIGHER or LOWER.
  - Make translate refuse, never cast, a pos of -1.
  - Either key `kit_run_member` in the row's documented key space, or amend kit.h's "keys are offsets" line.
  - Preferred general form: one before-relation used by both the pick and the `after` filter.
- **Reason:** the TIE table is meant to be re-ruled by stage-3 rows. This is the one place where re-ruling it corrupts a ranking instead of moving a pick.

## Lessons for the guide (proposed)

1. **A "MOVED" from a plant compare must check the plant's exit code first.** Both CHECK-1's and the verifier's compare scripts printed MOVED when the planted compiler FAILED, which is a loud catch, not a silent move. The verifier's script also never removed old outputs. The coordinator's re-run turned "answer-identical, only a byte sweep sees it" into "mostly loud `mf_define` refusals; one silent move". Proposed check-adequacy clause: "classify each plant outcome as SAME / SILENT-MOVE (rc 0, bytes differ) / LOUD (rc≠0); a LOUD plant is caught by every corpus compile; rm outputs before each compare."
2. **Denied files inside a directory a critic greps recursively leak.** CONTRACT's `grep -rn` over memfn/ printed one line of memfn/docs/journal.md. COMMON gave the git pathspec exclusions, but a plain `grep -r` ignores them. Proposed COMMON text: "for plain grep, use `--exclude=journal.md --exclude=responses.md` or `git grep` with the pathspecs."
