### FIXIND-1 — rev 2 makes `exact_len` depend on NFA SHAPE (subset identity), which rev 0/1's walk did not: the `-fno-altcls-factor` deny arm (and any tree-pass arm) loses covers §6 does not predict
- Status: SUSPECTED (rev-2 half is a trace of §3.1's text; today's half CONFIRMED). Severity: design / speed (deny arms) / doc (§6, §3.1's claim). Effort: S (state it; extend §6 / census to the axes arms). Blast: every axes arm that changes alternation shape.

That is language-level and independent of how the tree passes shaped the NFA. Rev 2's line requires ONE SUBSET (§3.1 step 3, "two or more" = branch). Two subsets are equal only if their entries are the same NFA nodes, so the walk's length now depends on whether altnf (`src/opt/altnf.c`, rules M/P/S) has already merged equal tails.

The census's "only 2 remain" is a DEFAULT-arm count, and it holds because S (suffix factoring) and M (merge) ran first.

These are two different subsets, both SURELY LIVE, so it is a decided branch: `exact_len = 1`, and C8 gives `producer-short`, so the cover is lost on that arm only. Every adjacent `A·T | B·T` corpus cover does the same. §6 names only `-fno-altcls-merge` with one pattern.
- Readers affected: C8 (verdict per arm), the listing (span_facts now arm-dependent), §6/§5.2 prediction (only the default arm is predicted). `make test-axes` compares answers only, so it stays green. The gap is a silent speed/coverage difference between arms, and the sentence in §3.1.
- Fix shape (not a method ruling): either state that the straight walk's length is NFA-shape-dependent and count the axes arms in the census/§6, or compare successor subsets by their next-SET (as today's exact loop does) before calling it a branch.

### FIXIND-4 — the cycle rule needs subset identity ACROSS depths, but the `sw_take` that §3.1 keeps dedups only WITHIN a depth, and its storage is sized by the deleted constant
- Status: CONFIRMED (code). Severity: answer-adjacent (a compile hang) / design. Effort: S. Blast: every compile through the straight walk. The witness is `[ab]*\z\W`.
- `sw_take` (`kset.c:780`) searches `for (s = nsub-1; s >= 0 && w->sub[s].depth == depth; s--)`, so equality is per depth. A subset that recurs at a later depth gets a NEW index. §3.1 step 3 ("If that successor is a subset already on the line, the line is a cycle ... dead") cannot be read from `sw_take`'s index, and the design says the walk "keeps ... `sw_take`". Built as written, the cycle never matches and the walk does not terminate. §5.4 only says "a plant that drops the cycle rule hangs the walk" and leaves that hang to the suite timeout. The unplanted build has the same shape unless identity is redefined.
- Storage: `w.sub` is allocated as `PCREC_SPAN_WALK_SUBSETS` entries (`kset.c:875`), and `sw_take` returns -2 at that count (`:786`). Rev 1 §1.1 cited `kset.c:875` as a P4 site. Rev 2 §8 cites P4 only at `limits.def:393` and does not say what sizes the line's subset store (the line plus up to `np` side successors per depth) once the row is gone.
- Fix: state cross-depth identity (a hash set over the line's subsets, depth excluded from the key) and the growth rule for the store. Then the cycle witness is a real control, not only a timeout.

### FIXIND-5 — step 1's "the LIVE roots must be ONE subset" uses a liveness the design defines only for side subsets
- Status: SUSPECTED (text gap). Severity: design / soundness-adjacent. Effort: XS. Blast: every compile with more than one root subset (context-dependent start: `\b`, lookbehind, `(?m)^`).
- Today the roots' liveness comes from exploration (`kset.c:894-907`), and the exact loop skips dead roots (`live == 0`). Rev 2 deletes the exploration. §3.1 gives SURELY LIVE / SURELY DEAD / undecided only for "a side subset". Step 1 does not say whether a root that is undecided counts as live: if it does, `exact_len` is 0; if it does not, the remaining root alone gives the sets. Read the second way, it is an over-statement whenever the undecided root is in fact live and has a different set. The census's "111 listing compiles, 0 covers" was measured under whichever reading the probe used, and that is not stated either (see FIXIND-2).
- Fix: one sentence. Apply the side-subset rule to the roots. Any root that is not SURELY DEAD counts. If they are not all one subset, `exact_len` is 0.
