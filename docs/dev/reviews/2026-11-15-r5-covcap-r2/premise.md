### PREMISE-1 — CONFIRMED — "`[ab]{1000}` lists 24 today" and "512 subsets capped a literal near 511" are both false at the review tree (doc/design; effort trivial; blast: §2 last bullet, §8 P4 verdict, §9 Q1 "hidden length limit near 511")
- Repro: `kit/facts.sh '[ab]{1000}'` -> `span_facts 0` (byte and utf8), route `unanchored`; `kit/facts.sh 'a{500}'` -> `0`; `kit/facts.sh '(?:ab|ba|aa|bb){24}c'` (width 49) -> `0`; `[0-9a-f]{32}` -> `24:`. Expected per §2: `24`.
- Why (code): `kset.c:891` stops expansion at depth `2 * PCREC_PREFIX_K_MAX` = 48; an unexpanded non-accepting subset gets `live = -1` (`kset.c:897`), which propagates to the root, and `kset.c:919` (`s->live < 0 ... ok = false`) ends the prefix at d = 0. So the cliff today is WIDTH > 48 -> 0 (not 24, not near 511). A straight line holds one subset per depth, so it holds at most 49 subsets under the 48 horizon: the 512 budget (`kset.c:786`) can NEVER bite on a straight line today. "A length cap in disguise" describes a hypothetical (rev 1's horizon-less walk), not the tree.
- Consequence: the deletion of P4 still stands (the walk it budgets is removed), but the §2 premise, §8 P4's "a length cliff near 511" and owner Q1's "its hidden length limit near 511" mis-state today's cliff to the owner. The real cliff (any exact prefix whose live continuation needs > 48 levels to reach accept reads 0) is worse and is the true reason the 49/60/500/1000 corpus shapes list 0. Fix: re-state as "a cliff at width 48 (P2's horizon): past it the whole prefix reads 0"; `[ab]{1000}` lists 0.
Cliff check: `a{48}` -> `24:`, `a{49}` -> `0` (byte): the cliff is exactly width 49.

### PREMISE-4 — CONFIRMED (code reading) — §3.1 "the walk keeps `sw_partition`, `sw_push`, `sw_close` and `sw_take`" cannot implement §3.1's own cycle rule: `sw_take` only finds an equal subset AT THE SAME DEPTH (maintenance/design; small; blast §3.1 THE WALK step 3, TERMINATION, §5.4 the hang note)
- `src/facts/kset.c:780-785`: the equality scan is `for (s = w->nsub - 1; s >= 0 && w->sub[s].depth == depth; s--)`; a subset equal to one at an EARLIER depth is never found, it is stored as a new subset. On a straight line every depth holds one subset, so "that successor is a subset already on the line" is never detected by the kept `sw_take`. With the budget (`kset.c:786`, `return -2`) also deleted, `[ab]*\z\W` (today `0`, design witness `0`) then walks until the arena is exhausted rather than ending — exactly the "plant that drops the cycle rule hangs the walk" of §5.4, but built in by keeping `sw_take` as is.
- Also `sw_take` is where the budget lives and `w.sub` is a fixed `PCREC_SPAN_WALK_SUBSETS` array (`kset.c:875`): "keeps sw_take" is not literally true; it must change in three places (cross-depth lookup, no `-2`, growable list).
- Cost note: the cycle check against every subset on the line is O(L) per step unless hashed across depths (the per-subset `hash` exists, `kset.c:774-779`), so §3.1's "Work is O(L x subset size)" holds only with a cross-depth hash lookup; the design should name it. Fix: state that `sw_take`'s lookup becomes a line-wide hash lookup (depth dropped from the key) and that the line ends on a hit.

Confirm: the candidate's `/usr/bin/time -f %M` on `a{5000}` / `a{1000}` against main, in §5.1's `compile_time_census.py` row (which measures CPU, not RSS: add RSS).
