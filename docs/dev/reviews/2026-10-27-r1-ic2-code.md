### Trust tier (goal 1)

**F1. The bidi/invisible refusal list is narrower than the class the spec names** (CON-1, ADV-1, ADV-3; verified HOLDS).
U+061C (a Bidi_Control in the vendored UCD, PropList.txt:28), U+3164,
U+115F, U+00AD, U+180E, U+FE0F, U+E0041 (TAG) and U+2028 all compile inside a
segment. gcc -Wbidi-chars=any is silent on them. Exploit (contract):
``a(?C`c: int ok<U+3164> = 1; int ok = 0; ... return ok<U+3164> ? RX_PASS : RX_FAIL;`)b``
reads to a reviewer as a check that always fails, but it passes.
src/parse/mod_code.c:113-122 holds a hand-typed list.
**PROPOSED FIX-NOW:** generate the refused set from the vendored UCD
(Bidi_Control ∪ Default_Ignorable_Code_Point, plus U+2028/U+2029/U+0085)
through `make gen-tables`, per the official-Unicode-data-only rule. The spec
(match_api §11.9¶3, pattern_language §7.12¶3, design §2.4) should cite the
properties, not restate ranges. Reason: this is goal 1's own stated purpose
("the code a reviewer reads is the code that compiles"), and the hole is
demonstrated end to end.

**F2. A lone CR is accepted and gcc reads it as a line end** (ADV-2; HOLDS).
``// x<CR>return RX_FAIL;`` in a segment: pcrec accepts it, and the compiled
check takes the hidden statement (nomatch, where the control matches). A
terminal shows the line overwritten. **PROPOSED FIX-NOW:** refuse a CR not
followed by LF (or every CR), and amend §11.9¶3's allow-list. Reason: the
same reviewer-vs-compiler split as F1, at one byte.

**F3. Artifact-internal `<PREFIX>_*` macros stay live at the segment block, and the check exempts the same family** (CON-8, EMIT-4, CHK-2; HOLDS).
`RX_CUT`, `RX_PRUNE_*`, `RX_R_*`, `RX_SLOT_*`, `RX_CHARGE_WORK` and
`RX_RUN_WORDS` are live at the segment block. Cause: emit_code.c:160
`{ "\x01Q_", false }` keeps the whole upper-prefix namespace, and
run_code_tests.sh:298 exempts `^${upx}_`. The control shares its source with
what it controls (learnings §3). Design §3.2 and spec §11.9¶4 promise the
`#undef`. **PROPOSED FIX-NOW** (abi 90 open): keep exactly the stamp
catalogue's names (stamp_kinds.c), not a prefix. The check should take its
public set from an independent source (the macros the `.h` defines), and get
a sabotage row. Reason: a contract the spec states, and a check that cannot
fail.

**F4. Granted segment text is unconfined file-scope C, and describe output reads it** (ADV-5; PARTLY).
A segment's `#define RX_FAKE 1` / redefined `RX_CODE_LANGS "zzz"` shows up
as `--emit-facts` decision rows. The TU's effective `RX_CODE_LANGS` becomes
"zzz", while the `.h` stamp is unchanged. **PROPOSED FIX-NOW:** stop
`fd_decisions` at the segment block's start. **DOC:** add one sentence to
§11.9¶4: a segment is C at file scope after the matcher, and it can affect
the translation unit's macros after it (stamps included), never the code
above it. Reason: the describe record must show only what pcrec decided;
the boundary is honest once stated.

**F5. The GRANT gate relies on an assertion that does not exist, and named sets skip it** (SLOT-4, SLOT-6; HOLDS).
enabled.c:176-177 says "registry_check asserts" that every row of a module
carries the same `RF_INVOKER_ONLY`. No such check exists. `all` excludes
flagged ROWS, so a module with one unflagged row (for example a second
`code-c` row written longhand at [SCANNER-DOGFOOD]) would be granted by
`features all`. The named-set arm (`find_module_bits`) never tests the flag.
**PROPOSED FIX-NOW:** compute `all` and named-set expansion minus the
invoker-only MASK, so a mixed module fails closed, and add the uniformity
assertion that the comment claims. Reason: today safe by list content only,
and the next stage adds exactly the row that would open it.

**F6. The harness grants code to any tests/ directory whose manifest says `allow-code`** (ADV-6; HOLDS).
run.sh:1692/1715-1723 checks only the line's shape. Only tests/code/ and
tests/code/frag/ carry the line today. **PROPOSED FIX-NOW:** one check
(an allow-list or an exact count) that fails when any other manifest
carries `allow-code`, plus a spec sentence that the manifest is the
suite-invoker's grant. This also covers CON-3: refuse a second `allow-code`
line and fix the `-I` sentence. Reason: §5.7's T2 promise ("every section
except the code section compiles without it") is otherwise held by
convention.

**F7. Without the grant, a multi-target FILE writes the earlier code-free targets, then refuses** (CON-9; HOLDS, order-dependent).
cli.md §1.22¶1 and match_api.md §11.9¶8 say "nothing is written"; design §5.9 says "emits
zero bytes". **PROPOSED FIX-NOW** (small): check every target's grant before

**F8. An explicit empty grant makes `--emit-ir`/`--emit-facts` refuse code, while `--count-groups` and no grant both parse it** (CON-10, SLOT-5; HOLDS).

## Lessons for the guide (proposed)

1. **A segment of user text is reviewed with the reviewer's eyes, not the
   parser's.** The adversary and contract lenses both found the refusal set
   too narrow because "invisible" was defined by a typed list. A rule that
   protects what a human reads should be generated from the standard's
   property, and the lens should probe the property's members (F1, F2).
2. **A keep-list by PREFIX is a control sharing its source** (F3). The
   emitter and the check both used `<PREFIX>_` to mean "public". The check's
   public set should come from what the caller can see (the `.h`).
3. **A comment claiming "X asserts it" is a finding target** (F5). Grep
   for the assertion; here it did not exist, and a gate depended on it.
4. **A card row must prove it reaches the site** (F19). A prefilter can
   reject the whole subject before the matcher runs.
