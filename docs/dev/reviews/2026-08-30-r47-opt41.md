## Finding 1 (must-fix, borderline BLOCKER) — prefilter_declined_nullable fires on
patterns with nothing to collapse, mislabeling overflowed-dfa as declined-nullable

src/opt/select_engine.c:833-835:

    fit.prefilter_declined_nullable =
        cx->collapse_reason != CR_NONE && fit.prefilter_lang_nullable &&
        !has_bref && !has_call && !force_on;

This conjunct set never checks pcrec_has_collapsible_rep(root). Compare
src/core/compile.c:1024-1043, which computes the twin decision (pfc_wanted) for the
same rung and DOES gate on it:

    pfc_wanted = fit.chosen != ENGM_DFA && !pfc_deny && pfc_rep && (pfc_force || pfc_rung);

The asymmetry matters because on the [SEL-1] rung, when a pattern has NO collapsible
repeat (pcrec_has_collapsible_rep(root) == false), the "collapsed" prefilter and the
"exact" prefilter are literally the same machine — the one that just overflowed the DFA
state cap on this same compile. There was never a distinct rescue to decline in that
case; attempting it would just re-overflow the identical machine (this is precisely the
pre-existing `dfa_disabled && collapse_reason != CR_SEL1` guard's own stated rationale,
a few lines above: "the prefilter would be the IDENTICAL construction that already
overflowed").

Because the new predicate ignores pcrec_has_collapsible_rep, a nullable pattern that
overflows [SEL-1] with no bounded/collapsible repeat at all (e.g. state blowup from a
wide alternation or a chain of `?`-quantified alternatives rather than a `{m,n}`) will
set fit.prefilter_declined_nullable = true purely off pcrec_minw(root)==0, and the
ternary at select_engine.c:878-881 intercepts it as ESEL_DECLINED_NULLABLE
("declined-nullable") BEFORE it can fall through to ESEL_OVERFLOWED_DFA. Per the diff's
own match_api.md addition:

  "declined-nullable" ... a rescue that was REFUSED as useless ... "overflowed-dfa" ...
  one that was NOT AVAILABLE. A consumer measuring what the collapse rung buys must not
  count the first as a case where it had nothing to offer.

This is exactly the inversion the spec warns against: a pattern with no collapsible
repeat never had a distinct rescue to refuse, so it should read overflowed-dfa, not
declined-nullable. Since pcrec-bench explicitly buckets on this macro (stated
repeatedly in the lane's own comments) to measure how often the nullability decline
"costs" a win, this corrupts exactly the population count that justifies the design.

Plausible witness (INFERRED, not run — read-only mandate): the lane's own §6b
control/twin pair is SEL1N_CTL='(?:a|b)*a(?:a|b){15}' /
SEL1_NULL='(?:(?:a|b)*a(?:a|b){15})?' (tests/codegen/run_prefilter_collapse.sh) — but
both use an explicit {15} (rmax=15>1, collapsible), so this gap is untested. Replacing
the bounded {15} with fifteen chained (?:a|b)? nodes (each rmin=0/rmax=1, individually
non-collapsible per atomic.c:207-210) should reproduce the same combinatorial
DFA-subset blowup (bounded repeats are conventionally lowered to exactly this
concatenated-optional shape internally) while making pcrec_has_collapsible_rep(root)
false throughout — i.e.
`(?:(?:a|b)*a(?:a|b)?(?:a|b)?(?:a|b)?(?:a|b)?(?:a|b)?(?:a|b)?(?:a|b)?(?:a|b)?(?:a|b)?(?:a|b)?(?:a|b)?(?:a|b)?(?:a|b)?(?:a|b)?(?:a|b)?)?`.
I traced every relevant conditional (select_engine.c engine_sel ternary, compile.c's
ladder/dfa_was_engine latch) and confirm that absent the bug this falls through to
ESEL_OVERFLOWED_DFA; I could not execute the compiler to confirm the DFA-state count
actually overflows PCREC_MAX_DFA_STATES_TABLE (32,000) on this exact witness.

Neither S206/S207 (the two nullability sabotage rows) nor §6, §6b, §7b of
run_prefilter_collapse.sh, nor the new resource size-rung cells, exercise a pattern
lacking a collapsible repeat — every witness in the diff uses an explicit {n}/{m,n}
with rmax>1. This is a real, unexercised gap, not a restated known-good path.

What closes it: add `pcrec_has_collapsible_rep(root) &&` to
fit.prefilter_declined_nullable's conjuncts (mirroring compile.c's pfc_rep), and add a
§6b-style witness pair using a collapsible-repeat-free blowup shape. Note this does
NOT repeat the R31 E3 "two-sources" defect the emit_vm.c:7617-7621 comment warns
about: that hazard is re-deriving a build decision downstream of flags/caps at
emission time; this is establishing a pure structural fact upstream, feeding one
decision, exactly as compile.c already does for its own copy.

## Finding 2 (note) — same predicate reachable from the SIZE rung has no user-visible
mislabeling risk, only wasted specificity

The same missing-conjunct gap exists for CR_SIZECAP, but it's benign there:
fit.engine_sel's ternary only special-cases CR_SEL1 (by design, stated in the comment
at select_engine.c:868-871 — "the SIZE rung's own decline is not this value... the
route stays selected"), so a no-collapsible-rep pattern hitting PFLW_NULLABLE-style
logic on the size rung can't mislabel ESEL. And compile.c's own PFLW_NULLABLE stamp IS
correctly gated on pfc_rep (pfc_wanted requires it), so RX_VM_PREFILTER_LANG_WHY cannot
show this defect either — confirmed by trace, not just inference. No action needed
here.

## Findings that did NOT hold up (verified sound, not flagged)

- The core predicate pcrec_minw(root) == 0 correctly predicts the collapsed language's
  nullability from the uncollapsed AST. Built a full structural induction over every
  pcrec_minw arm (A_CAT sum, A_ALT min, A_REP rmin*minw(body) vs. collapsed
  min(rmin,1)*minw(body), A_CAP/A_ATOMIC transparent, A_LOOK/A_CALL/assertions
  untouched by collapse) and could not construct a counterexample where minw's
  zero/nonzero verdict diverges between the exact and collapsed trees.
  pcrec_has_collapsible_rep (atomic.c) correctly declines to descend into A_LOOK
  bodies and returns false at A_CALL, consistent with pcrec_minw's own treatment and
  with the NFA builder erasing lookaround bodies — so no divergence there either.
- The SIZE-rung "byte-identity" argument (declining ships strictly fewer bytes than
  the collapsed prefilter would, so "no pattern that compiles today stops compiling"
  holds) is structurally sound: fit.prefilter=false on decline unconditionally
  suppresses the downstream `collapse` build-gate boolean too (pfc_wanted is moot once
  no prefilter is attempted), so there's no path where declining leaves the artifact
  bigger than before.
- -fprefilter's per-rung override is correctly asymmetric: it reaches the decline via
  pfc_prefilter_forced in compile.c's SIZE-rung gate, but on [SEL-1] -fprefilter makes
  ovf_eligible false upstream in compile.c's ladder, so the rung — and the decline — is
  never reached at all (refusal is the correct do-or-die answer there, not an
  override). The lane's own §6b(3) comment states this distinction correctly and the
  resource -fprefilter cell exercises the SIZE-rung override concretely.
- S102/S165 re-anchors: both correctly reproduce the current multi-line fit.prefilter
  expression verbatim (including the new `|| fit.prefilter_declined_nullable` term)
  and still disable only their one intended conjunct (has_bref/has_call). No
  re-anchor drift.
- Registry/stamp closure: axes_registry_check.sh's two new legs (dump-vs-docs,
  dump-vs-pcrec_engine_sel_name) correctly cover the six-value closed set, and
  pcrec_engine_sel_name in emit_dfa.c:213-222 matches. This closes the vocabulary
  contract but — per Finding 1 — not the semantic one.

## Verdict

NOT CLEAN. One must-fix-level finding (Finding 1): the nullability-decline predicate
for the [SEL-1] rung omits the collapsibility check its sibling in compile.c correctly
includes, which can mislabel a pattern that never had a distinct collapsed rescue
(overflowed-dfa) as one whose rescue was refused (declined-nullable) — directly
contradicting the spec's own stated invariant between those two values and corrupting
exactly the telemetry pcrec-bench is documented to bucket on. This is inferred from a
complete conditional trace and cross-checked against every witness in the diff (none of
which exercise a collapsible-repeat-free [SEL-1] overflow); it could not be empirically
confirmed under this review's no-make/no-binaries constraint. The core
pcrec_minw-based nullability predicate itself, the SIZE-rung "no regression" argument,
the override matrix, and the sabotage re-anchors all held up under adversarial
construction.
