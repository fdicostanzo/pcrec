Also case: plan tags are upper-case (M4.6b, MOD-0.4a, DD-13b.panel mixed) while decision slugs are lower-case; say whether lookup is case-insensitive.
Effort: low (spec sentence + selftest rows). Blast: accessor routing, every manager lookup.

### SIM-2 (answer, design) CONFIRMED: plan tags cannot meet the §2.1 slug rule or C5, and `ID.aN` shadows a real tag
Data: 728 distinct tags in plan.md + plan_completed.md; live plan.md has 339 rows. §2.1: "the plan's `[TAG]` IS its slug" and slug = kebab-case, 2-4 words, <=28 chars, unique. Result: 0 of 339 live tags are lowercase kebab (all upper-case); 27 live tags are one word (ARTREV, DFAREC, MEMFN, OPTLOOP, UCP, ID...); 8 live tags carry dots (DD-11.5, DD-13b.W1.3.1, FINDINGS.B4, M3.0, SPEC-1.11 ...); 175 of 728 overall; mixed-case tags exist (M4.6b, MOD-0.4a, DD-13b.panel). Length and word-count (<=28, <=4) hold for all 728. So C5 as written fails every live plan row unless it is plan-profile-relaxed, and the doc's profile table has no per-profile slug grammar.
Second shadow: tags DD-14.A2 and REVW.A1 (both in plan_completed.md) end in `.A<digit>`; `scripts/entry DD-14.A2` under the "ID.aN = addendum N of ID" rule would resolve to addendum 2 of tag DD-14, which exists (plan_completed.md:3672). Case-insensitive `.aN` matching returns the wrong item with exit 0. Fix: `.aN` is lower-case and only for profiles with addenda (decisions); look the string up as a whole tag first.
Effort low; blast: accessor + C5 selftest.
