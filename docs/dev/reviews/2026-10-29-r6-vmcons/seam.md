### SEAM-1 — Site-id keying: walk 3 emits fewer CHECKPOINT events than walk 2, D adds events in walk 2, and the all-KEEP identity check cannot see a keying slip

- **Status:** CONFIRMED (premise, on real emitted C); the keying failure itself is SUSPECTED because the keying code does not exist yet.
- **Severity:** answer (a verdict applied to the wrong site deletes or untrails a live write). **SEAM** (walk 2 -> walk 3; D -> walk 2). **Effort:** S (spec + a keying rule + one check). **Blast radius:** every artifact where a verdict fires.
- **Design text:** Pipeline and stages, "Verdicts are keyed by site id: the ordinal of the site's event in the walk that decided it ... ids match. D's new chain labels are allocated after every walk-1 label" and "A codegen check pins the keying: a walk taking an all-KEEP verdict table must emit byte-identical C".
- **What breaks between the passes.** Checkpoint emission is a function of the emission counter: `vm_jump_closes_trail_cycle` (src/gen/emit_vm.c:3510) fires iff a `_SET` was written in the text since the target label, and each checkpoint logs an event (`vm_trail_check_text`, :3491, VE_NOTE today, VE_CHECKPOINT after Stage -1). The design itself makes walk 3's `vm_set` count KEEP sites only. So walk 3's event sequence loses every checkpoint whose only covering `_SET`s were deleted or untrailed. Walk 2 also gains events walk 1 never had (D's SWITCH/CASE, chain labels, the pushes between candidates). A "site ordinal in the deciding walk" therefore does not survive the hop into the applying walk unless the ordinal counts only sites of the verdict's own kind, includes deleted sites, and excludes D-introduced ones. The design says none of this. "D's new chain LABELS are allocated after every walk-1 label" covers label ids, not event ordinals.
- **Repro (the premise):** `B=worktrees/crit-vmcons/build/pcrec; $B -p rx --engine=vm --features recursion -fno-splice-calls -o ck2/spec.c --pattern '^(?:(?1)y)*(a|b)$'` (scratch `w/ck2/spec.c`). Stock has `RX_TRAIL_CHECK();` at `rx_L7` (the loop back-edge to `rx_L4`). It is there only because the call snapshot `RX_SET`s at `rx_L6` lie between L4 and the back-goto in the text. Apply the rows as written. After `rx_L10` nothing in W(g1) = {START, END, PENDING} is read before the `(a|b)` group rewrites it, so K_c is empty, and V1 and V2 delete all three snapshot entries and all three restores. Walk 3's `vm_set` then writes no `_SET` between L4 and L7, so `vm_jump_closes_trail_cycle(L4)` is false and that checkpoint and its event are not emitted. Every site after `rx_L7` in the text (L5, L13, the region's L2, L15 and the exit) shifts by that event between walk 2 (decided) and walk 3 (applied).
- **Why the stated check cannot catch it.** With an all-KEEP table no event moves, so any keying scheme passes. The check is vacuous for exactly the failure it is said to pin (critics' guide lesson: a control that cannot fail).
- **Fix (for the build row).** Key each table by a per-kind site counter (SET-site ordinal for slot-flow, PUSH-site ordinal for D) that is incremented whether or not the site emits. Keep D-introduced sites out of walk-1 numbering. State that CHECKPOINT/NOTE events carry no site id. Add a check that can fail: a table with exactly ONE non-KEEP verdict at ordinal k must change exactly site k, either by a listing diff, or by the listing echoing each site's id beside its role so walk 2's site k and walk 3's site k are compared.

### SEAM-2 — The verdict rounds are an in-memory program rewrite; the "every pass reads a real emission" claim and Question 3 contradict the round order

- **Status:** CONFIRMED by applying the rounds as written to real emitted C (no run needed: this is about which program each round reads).
- **Severity:** design/doc (and compile-time accounting). **SEAM** (round A -> round A -> round B -> walk 3). **Effort:** S (restate) or M (re-emit per round). **Blast radius:** the pipeline's stated proof structure and Q3's framing.
- **Design text:** Summary "One pipeline: each pass reads a REAL emission"; Pipeline "Each pass reads the events of a real emission, never a predicted one"; the walks table (walk 3 = walk 2 with the verdicts); the rounds ("A1 and A2 alternate with re-analysis", "Round B ... recomputed on round A's result"); Q3 ("An in-memory rewrite ... is a second description of what the emitter would write, which is the failure the listing's design forbids"); "at most three emission walks per VM artifact".
- **What happens on a real program.** On `^(?:(?1)y)*(a|b)$` (`-fno-splice-calls`, scratch `w/ck2/spec.c`), round A iteration 1 deletes the region's `START := PENDING` / `END := pos` at `rx_L15` (dead: every R_c kills W in the stock-restore model) and the snapshot and restore entries (V1/V2). Only in iteration 2 does the region entry's `RX_SET(PENDING, pos)` at `rx_L2` become dead, because its sole reader was the deleted `rx_L15` statement. Iteration 2 reads "walk 2 minus iteration 1's deletions", a program no walk emits. Round B (MAYFRAMES, liveness) likewise reads round A's result, not walk 2. On the recursion specimen family (`^(\((?:[^()]++|(?1))*+\))$` with atomic-groups, scratch `w/pp/spec.c`), round A needs three iterations: L19's writes, then the inner site's PENDING snapshot/restore (a self-propping pair once L19's read is gone), then L2's PENDING write.
- **Consequence.** Either the rounds are in-memory rewrites of the event list (then Q3 is already decided "both ways", and "each pass reads a real emission" is false for every round after the first), or each round re-emits (then the walk count is 2 + 2k + 1 with k unbounded by the text, and "at most three" and STEP 0 card 0i's "3x the emission share" bound are wrong). Soundness is not at stake: deleting a statement from an event list is a faithful model of not emitting it, because DELETE emits nothing and SETU is slot-neutral for liveness. That is exactly the argument the design refuses to make in Q3.
- **Fix.** State the honest form: walks 1-3 are emissions, and the rounds are a fixpoint over walk 2's event list with statements removed or retagged. Name the one invariant that makes that faithful (a DELETE emits nothing, a SETU changes no column but `writes trail`, and checkpoints are slot-neutral, see SEAM-1). Reframe Q3 accordingly: the question is only whether D's verdicts (which ADD statements) may be modelled in memory, not whether the slot-flow rounds may.

### SEAM-3 — "Unrecognised refuses the function otherwise" does not hold at compile time; the completeness check is corpus-only, and the design's own premise test says an invisible statement is not unrecognised

- **Status:** CONFIRMED as a contradiction between two of the design's own sentences, with the base's emitter as evidence.
- **Severity:** answer (latent: a future or rare emitter path with a raw printf runs the analysis on an incomplete program). **SEAM** (Stage -1 completeness check -> the verdict table's V0 row -> G1's proof). **Effort:** S. **Blast radius:** every compile outside the corpus's emitter-path coverage.
- **Design text:** Soundness "Composition ... Each proof's only premise about its input is that the input is COMPLETELY modelled. Stage -1 and its completeness check provide that, and the unrecognised row refuses the function otherwise." Against: The analysis input, "an invisible read is not 'unrecognised', so no refuse row can catch it", and "The completeness check ... For every corpus artifact".
- **The gap.** The completeness check is a TEST over the corpus; V0 fires only on an EVENT of unknown kind. A statement written without an event (a raw `pcrec_sb_printf` of `slot_values[`, a raw `goto`, a cursor write) is neither counted at compile time nor unrecognised. The base has 182 printf sites against 54 `vm_ev` calls (the design's own count). Stage -1 routes the known ones, but the guarantee for a pattern whose emitter path the corpus never exercised is "the corpus covered that path". That is coverage, not proof, and G1 is stated "by proof".
- **Fix (cheap, keeps the text-reading rejection intact).** Run the SAME counts inside the compiler on walk 1's and walk 2's matcher text, which already sits in the scratch buffer (`vm_cls_reads`, emit_vm.c:1771, already `strstr`-counts the program text for a decision). Treat a mismatch as V0: refuse the function, D declines. Counting tokens is not a second description of the program (it builds no graph), so it does not reopen "the build reads TEXT". The corpus check then tests the guard instead of standing in for it.

### SEAM-G2 — The general form of the pipeline, and what it unlocks

The general form is not just "IR + dataflow + render". It is **emission parameterised by a verdict map keyed by stable per-kind site ids**. Walk 1 is the map-free emission, each pass reads one emission and writes map entries, and the final emission renders the map. The rounds (SEAM-2) are this form's in-memory fixpoint over one emission's event list, valid for any verdict that only removes or retags statements.

It unlocks, filed with triggers:

- (a) **Capacities and `subject_ceiling` from the final emission's own cost walk** (F20a). Trigger: a one-shot storage need, or a caller asking why the default depth is not the stamped one. The specimen twin answers to n = 1024 where the stamp still implies 763.
- (b) **Per-cycle margins** instead of the global `nset`: each checkpointed cycle carries its own trailed-site count. Trigger: an `_in` caller at small `ntrail` binding on the margin.
- (c) **A generic "drop verdict class X" rung** for every future program pass that grows code, instead of one rung per pass. Trigger: a second growing pass.
- (d) **A static, compile-time measured-admission input** to the same map (AD's +11 % over-wide admission on idents). Trigger: a 0c cycle cell where FIRST+ admits a dispatch that measures slower. It is not run-time adaptive.
- (e) **The compile-time completeness count** (SEAM-3) turns Stage -1 into an incremental contract: a construct not yet routed declines instead of blocking the build. Trigger: the first emitter change after landing 1 that adds a printf.
