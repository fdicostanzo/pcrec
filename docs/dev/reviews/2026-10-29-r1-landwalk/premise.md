## Findings

### PREMISE-1 — the UNIQUE build-time rule as written rejects the design's own UNIQUE witness (dup-param, `\b`/`(?m)^` forms)
- **Status:** CONFIRMED (by reading the emitted reverse machine).
- **Severity:** design (answer-safe: it errs toward decline, but it removes stage 2's named mover and makes the census and the rule disagree). **Effort:** small (restate the rule). **Blast radius:** every `excl-cand` row admitted only through UNIQUE (the `\b` and `(?m)^` forms; dup-param-detect on the bench).
- **Subject §:** Admission table, "UNIQUE starts": "no accepting state of rev(P) is reachable from another accepting state, by-class accepts included".
- **Repro:** `build/pcrec -p rw --features all -o premise/rw.c --pattern '\b\w+='` (rev(P·L) for dup-param, the same reverse-pass machine the twin wraps). The reverse tables (premultiplied, ncls = 3; class 1 = `\w`, class 2 = `=`): `next_state = {65535,65535,3, 65535,6,65535, 65535,6,65535}`, `is_accepting_by_class = {0,0,0, 0,0,0, 1,0,1}`. State 6 is a by-class accepting state (it accepts when the next byte to the left is non-word) and it has a self-loop on class 1 (`\w`). So it is "an accepting state reachable from an accepting state" (itself), and the rule as stated says NOT unique.
- **Observed vs expected:** expected UNIQUE (the report says `\b` before a `\w`-only P is UNIQUE, and dup-param is admitted as `excl-cand` on that ground). Observed: the stated rule declines it. The census (`population.py`) used the sufficient syntactic forms, NOT the rule, so the 259/12 counts do not measure what the build would admit. The same applies to `(?m)^` with `\n` ∉ alphabet(P), which has the same by-class shape. Only the fixed-width form passes the rule as written.
- **Why:** the accept condition and the continuing step read the SAME byte `subject[p−1]`. The by-class accept is on classes {0,2} and the loop is on class 1, so they are mutually exclusive. A state-level rule cannot see that.
- **Fix:** state the rule over (state, class) pairs: UNIQUE iff for no reachable state `s` and class `c` with `accepts_class(s,c)` does `step(s,c)` reach a state with any accepting (state, class) pair. A plain (floor-0) accept is the `c = none` case. Then make the census run the rule on W, not the syntactic forms, or label the forms as an approximation the rule must reproduce (a check the build lane needs anyway).

### PREMISE-2 — WHICH landmark is unstated; the req fact pcrec picks today gives dup-param a different (worse) row than its twin measured
- **Status:** CONFIRMED (facts listing + a two-start witness by hand).
- **Severity:** design / speed (the stage-2 headline mover). **Effort:** small (a choice rule, itself a first-match table). **Blast radius:** every pattern whose `req_set` has more than one member.
- **Subject §:** the facts row ("the landmark (which req fact, and its offset in the run)"); dup-param twin ("memchr `=`").
- **Repro:** `build/pcrec --features all --emit-facts --pattern '\b(\w+)=[^&]*&(?:[^&]*&)*\1='` → `req_set 38,61`, `req_byte 38` (rate: builtin-prior), `req_landmark_maxoff declined:unbounded`. The artifact's `RX_REQ_BYTE` is `"38"` (`&`). The twin seeded at `=` (61) instead.
- **Observed vs expected:** with `L = &` (the req byte pcrec already chooses), `P = \b(\w+)=[^&]*`. EXCLUSION holds (`&` ∉ alphabet(P)) but the starts are NOT unique: on `a=b=c&` both 0 and 2 are starts of P·L. G4 fails too (`\1` in S reads group 1 of P). So the row would be `excl-lower` (hand LOWER at the first hit, then the VM loop runs as today), not the `excl-cand` the x1.33-1.45 was measured on. Only `L = =` gives `P = \b(\w+)`, which is UNIQUE (modulo PREMISE-1). On 5b the req byte (`@`, 64) happens to be the right one; `.` (46) is the other `req_set` member, and it is inside P's class.
- **Fix:** state the landmark choice as a declared rule over the `req_set` members (each member × its first pattern position → the admission row it would land on; prefer `excl-cand`, then rarity). Note that this needs the members' pattern positions, which `req_set` (a byte set) does not carry; `req_set_maxoff` gives only "unbounded". So the fact needs a new input, not just the four deps listed in the `PF_FACT` line.

### PREMISE-3 — "nfa_of(P·L)" is a DERIVED tree, so the house placement table `compound_place[]` sends it to a compound PART; the design never asks that table
- **Status:** CONFIRMED (read the code and the docs; no build needed).
- **Severity:** design (the R1 placement ruling rests on it). **Effort:** small to argue, medium if the table needs a new row. **Blast radius:** the whole row's home (in-Job `cand_rows[]` vs a [COMPOUND] client).
- **Subject §:** Mechanism, "Where rev(P·L) is built" (`pcrec_build_min_dfa(cx, nfa_of(P·L), …, root=P·L)`); Summary bullet 1 ("ONE new LOCATE row … ruling R1").
- **What is true:** `revend_build_one` exists (src/core/compile.c:450-462). It builds one optional machine, saves and restores the overflow record, returns false on overflow (a decline), and runs `pcrec_scanedge_dfa` over the result. So "an overflow is a decline" and "the revend_build_one pattern" are both TRUE.
- **What is not there:** its `Nfa *` comes from `pcrec_build_nfa(cx, Ast *root, …)` (src/ir/nfa.c:1064), which takes an AST NODE. P·L is a prefix of a concatenation's children (5b: children 0-1 of `CAT(class+, @, class+, \., class{2,})`), not a node. No helper cuts a concat prefix today: `src/opt/derive.c`'s only derivation is `pcrec_derive_split_q` (:354). The `root` argument of `pcrec_build_min_dfa` is an int NFA state, not a tree. So `nfa_of(P·L)` is a new tree derivation.
- **Why it matters:** compound.md §A.2's `compound_place[]` (src/core/compound.c:276-300) is the declared table for exactly this question ("Review asks it of every in-Job candidate"). Its row 1, `different-tree`, says: "the second machine's tree is not P's tree under erasure (a derivation other than `pcrec_derive_none`: split's Q, 4c's per-class searches) → compound PART". Row 3 (in-Job) lists only erasure-only machines: the hybrid prefilter, `rev-end`, a FINISH `verify-at`. W is a derivation (a prefix cut), and its nearest listed sibling, "4c's per-class searches", is a locator placed as a part. D163 add. 1's client 3 ("per-branch locators / 4c … P finishes") is the same shape. locate_finish §4.6 filed rev-inner in-Job ("R of P's prefix machine", 2026-09) before compound_place existed, so the two documents now disagree. The subject cites only the former.
- **Fix:** run `compound_place[]` on W in the design. Then EITHER argue a narrower row 1 (for example, "a locator machine over a sub-tree whose hand is a position, never a span" is in-Job) and amend compound.md §A.2 and the table in the same change, OR move the row to a [COMPOUND] locate part. Either way, add the concat-prefix derivation to stage 1's step list; it is missing from Build plan step 3.

- **Observed vs expected:** for kv-quoted, ipv4 and dotted4, today's NEXT row already does "find the landmark, start at hit − maxoff" (the subject's own relation table calls handoff "the walk's bounded-width special case"). stack-frame already seeds from a fixed offset. Either decline bounded P while req-handoff applies (a row: `bounded → decline to handoff`, the same shape as row 3 `fixed`), or add a twin cell against `handoff` to the card before claiming them as movers.

### PREMISE-5 — no ranked goals, and the implied "never slower than shipped" goal cannot be met: the rarity row is a compile-time fact, so its own fz-me negative control is admitted and loses x1.25
- **Status:** CONFIRMED (by reading the subject's row definitions against its own numbers; the twin is not reproducible under the denylist).
- **Severity:** design / speed. **Effort:** small to rank the goals; larger only if a run-time bail-out is wanted. **Blast radius:** every admitted pattern run over landmark-dense traffic.
- **Subject §:** whole note (no Goals section); Admission row 5 `rarity`; Measurement card "fz-me per line as the NEGATIVE control (it must DECLINE or not lose)".
- **Goals check (docs/dev/guide/architecture.md:7-18):** a design "opens with a short Goals section: three to five goals … a PRIORITY ORDER … and NON-GOALS". The subject has none. The goals it implies are: (G-a) answers identical to shipped and libpcre2; (G-b) 5b x70 on whole-file find-all over acc-main; (G-c) never measurably slower than shipped (the negative control's wording); (G-d) generality, meaning the fold of special-case rows (Question 3); (G-e) small size and compile cost. The design serves G-a, then G-b, and defers G-d (correctly, by D153/one-build-at-a-time). G-c is where it fails.
- **Why G-c fails by construction:** row 5 prices `p(L)` from "the landmark's prior from the byte table F already uses", a compile-time number. 5b's ratio is 1237, so it is "admitted at any F". fz-me is the SAME pattern on a dense subject (about 1 `@` in 10 bytes), so the build admits it, and the subject's own twin measured 150.9M vs 120.9M (x1.25 worse) there. The acceptance cell "must DECLINE or not lose" therefore fails on the first build. Nothing in the mechanism reacts to subject density: the reach guard trips only on overlap. Repricing the card does not help: any F that admits 5b admits fz-me.
- **Fix:** add the Goals section with a priority order. Either (1) rank sparse-landmark speed above dense-landmark speed, make the x1.25 dense loss a stated NON-GOAL with its bound (break-even near 1 hit / 19 B), and rewrite the acceptance cell to "loss ≤ the card's bound"; or (2) keep G-c and design a run-time density fallback (hits per byte since `search_from`, then hand LOWER to `composite`). That is adaptive switching, which memory "adaptive methods unproven" files to BOONIES, so (1) is the consistent choice.

### PREMISE-6 — two small factual slips in the placement and flag arguments
- **Status:** CONFIRMED (code read).
- **Severity:** doc. **Effort:** trivial. **Blast radius:** the row-order argument's wording; the [IFACE-PUSH] bit count.
- **Subject §:** Mechanism "The row" ("Both answer the whole call with at most one walk and no per-hit loop"; "About 8 bits remain").
- (a) `rev-end` does NOT always run at most one walk. `revend_forms[]` (src/gen/emit_dfa.c:13513-13522) ships the `two-seed`, `overflow` and `denied` forms: two walks (`n` and `n−1`), plus an anchored tie run on `overflow`/`denied` where `nl_last`. The ORDER conclusion still holds: both rows are O(match) or one stream, never a per-hit loop over the subject. Fix the sentence to "a bounded number of walks (one or two seeds), never a per-hit loop".
- (b) Flag bits: `lib/pcrec.h` defines `PCREC_BIT(0..54)` and `PCREC_BIT(56)`, and bit 55 is the kit's (pcrec.h:1196). So 57 of 64 are taken and **7** remain, not "about 8". After `PCREC_NO_LANDMARK_WALK`, 6 remain, two above the ≤ 4 hard trigger. Other designs primed in the same loop may also claim bits, so state the count exactly.

## PROBED-AND-HELD

- **Premise table stamps (2/2 reproduced, HEAD 13056c942).** 5b: `RX_ENGINE "dfa"`, `RX_DFA_PREFILTER "byte-class"`, `RX_DFA_SCAN_EDGE "bitmap"`, `RX_DFA_START "reverse-pass"`, `RX_REQ_BYTE "64"`, `RX_REQ_HANDOFF "none"`. dup-param (needs `--features all`, because `\b` is module 'assertions'): `RX_ENGINE "vm"`, `RX_VM_START_SCAN "first-class"`, `RX_VM_PREFILTER "none"`, `RX_REQ_BYTE "38"`. Files: premise/mask.c, premise/dp.c.
- **"The landmark is used only as a PRESENCE pre-check" (for those two).** TRUE. The only use of `@` in mask.c is `!memchr(subject + search_from, 64, …)` (mask.c:84). dp.c uses `&` (dp.c:368) and the `req_set` loop (dp.c:373) the same way. For four other admitted rows it is false (PREMISE-4).
- **"The existing reverse-pass floor code reads subject[lo−1]".** TRUE: `dir_rev_bound_accept` (src/gen/emit_dfa.c:9256-9292) reads `subject[search_from − 1]` through `accepts_class` when `search_from > 0`, and the plain accept at 0. Visible in the emitted reverse block of premise/rw.c:207-211.
- **"revend_build_one's pattern" and "an overflow is a decline".** TRUE (src/core/compile.c:444-462: record saved and restored, `false` on overflow, scan-edge pass after). The missing piece is the tree (PREMISE-3).
- **"pcrec_scanedge_dfa gives the EDGE ADVANCE".** TRUE with a nuance. `pcrec_scanedge_dfa` (src/opt/scanedge.c:568) is pcrec's analysis that marks edge heads, and reverse machines already get it (compile.c:3098 on `rdfa`; mask.c's reverse has `rx_reverse_is_stop`). The run-loop TEXT is the kit's: `emit_scan_edge` → `edge_advance` → `pcrec_memfn_advance_site(DELEG_EDGE, …)` (emit_dfa.c:12493-12573, `PcrecAdvance.reverse` set from the direction). Consistent with D161 add. 17 "Structure".
- **"rev-end … the same scaffolding seeded at n".** TRUE: one seeded reverse block for RECOVER and rev-end (emit_dfa.c:13075-13085 header; `emit_scan_loop` at 12919), and it already takes a dead-seed skip for speculative seeds (its comment names "rev-inner's landmark").
- **"cover … proves the whole match without a machine".** TRUE (emit_dfa.c:10203-10219: `.needs` only PRESENCE; the first kit candidate is the SPAN).
- **"The attempts made are a subset of the shipped loop's" (VM hat).** HOLDS under EXCLUSION + UNIQUE. Each `s*(j)` is a start-set position that the shipped `first-class` loop also attempts, in ascending order. Every failing `s*(j)` lies below the first match's start, so the twin skips attempts and never adds one. With fewer steps spent there is no NEW give-up. (The twin can answer a SPAN where shipped gives up, which is the allowed direction.) For `excl-lower`, the attempts from LOWER onward are a suffix of the shipped loop's.
- **Fixed-width P defers to existing rows (row 3).** TRUE: `[a-z]{3}@[a-z]+` → `offset-set`; `abc@[a-z]+` → `run-pinned`; `[a-z]{1,3}@[a-z]+` → `handoff` (3). All 3 compiled.
- **The handoff tightness claim ("s*(j₀) is never lower").** HOLDS when the walk's L is the handoff's req byte: any start of a hit is ≥ hit − maxoff. It does not hold as a comparison across DIFFERENT landmarks (PREMISE-2), but both are still sound lower bounds.
- **Cheaper existing mechanism for 5b.** Checked the 49 `cand_rows[]` row names at HEAD. No row turns an unbounded-offset landmark into a start: `handoff*` needs a bounded `req_landmark_maxoff` (5b: `declined:unbounded`), `offset-set*`/`run-pinned*` need a fixed width, and `rev-end` needs an end pin. The kit's reverse ADVANCE (`PcrecAdvance.reverse`, memfn.h:691) covers only the one-class-run tier, which is subtri's hand walk (73.1M). D161 add. 17 "Structure" rules the reverse DFA as the scaffolding, with the edge as that run inside it, so the DFA form is the ruled one and costs about 6% over the hand walk by the subject's numbers. Held: no cheaper existing row gets the 5b win.
- **Machine-bit vocabulary.** `CAND_MF/MR/MA/MATT/MVM` exist (src/core/internal.h:9026-9032), so a `W` bit is a sixth member, as the design says.
- **Ladder count.** limits.md §8.4¶3 says "which is all eight", so "becomes nine" is accurate.
- **Bench window.** All probes ran at about 11:20-11:40 local, outside 19:30-00:00. 13 compiles in total, no timing runs.
