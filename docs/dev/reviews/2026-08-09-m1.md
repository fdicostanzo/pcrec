## Critic: architecture (report received)

### FATAL-FLAW
- **A-1** (ARGUED, code-traced) §2 "accept-list islands" contradicts D3's
  accept-pruning DFA: pruning permanently discards lower-priority threads the
  moment a winner accepts, so no "list of accepting positions in preference
  order" exists in the built structure. Deeper: for nested quantified
  fragments (e.g. `(?:aa|a)*`), backtracking end-position preference order is
  NOT monotonic in position, so an accept-list sorted by position is the wrong
  order regardless of construction. Triage: FIX-NOW (doc) → FIXED: APPROACH §2 amended — accept-list islands restricted to fragments with provably monotone end-position preference; non-monotone fragments take the VM path; island DFAs are separate non-pruning fragment automata, not the D3 machine.

### MAJOR-RISK (MEASURED)
- **A-2** Unanchored search measured textbook O(n²): `a*b` over all-'a'
  buffers, 4x time per 2x size, 7.78 s at 160 KB; extrapolates ~8 h on 10 MB.
  Emitted loop restarts the DFA at every start position; no prefilter exists
  yet. Triage: PLAN → M2.0 design gate: adopt search-from-anywhere self-loop automaton (also the M3 shape); prefilters on top.
- **A-3** The 10k-state cap does not protect compile time: `[01]*1[01]{n}`
  needs 2^(n+1) states (provably minimal — Hopcroft can't help); n=12 → 8192
  states → 1.5 MB C → gcc -O1 29 s, -O2 did not finish in 120 s. 512→2048
  states took -O2 from 1.3 s to 62.7 s (superlinear CFG passes on huge
  computed-goto functions). Real usable computed-goto budget is likely
  hundreds of states. Also: the documented "falls back to VM engine" is
  aspirational — M1 just errors; no per-fragment split exists. Triage: PLAN → M2.0/M2.3: hybrid emitter (computed goto small DFAs, table-driven large), state cap re-grounded in measured gcc time, bench with gcc-time budget. VM-fallback wording in APPROACH corrected to "planned (M4)".

### MAJOR-RISK (ARGUED)
- **A-4** Streaming (M3) needs a different automaton/code shape: single
  "search-from-anywhere" automaton (lowest-priority start self-loop) rather
  than per-start restart; and gcc label addresses are invalid after the
  enclosing function returns, so stream re-entry requires int-state +
  dispatch, not saved `&&labels`. The M1 emitter shape won't be extended into
  M3 — it will be complemented or replaced. Triage: DOC → FIXED: APPROACH §6 amended (streaming uses integer-state dispatch loop; label addresses do not survive across calls).
- **A-5** §6 streaming window conflates "not enough data yet" (PCRE2 PARTIAL)
  with "history discarded off the back"; unbounded-match patterns have
  max-match-length = ∞, making "sized from analysis" undefined for the common
  grep-style case. Triage: DOC → FIXED: APPROACH §6 PARTIAL contract split into the two distinct modes (insufficient-data vs discarded-history) with explicit behavior.
- **A-6** Multiline `^`/`$` needs position-context folded into DFA state
  identity (roughly doubles affected states), stacking on A-3's blowup risk.
  Triage: NOTED: multiline design constraint recorded for the assertions module; interacts with state budget (A-3).

### GAP
- **A-7** Case-insensitivity has zero design (only a module-name string);
  Unicode case folding (incl. length-changing folds like ß→SS) collides with
  byte-wise UTF-8 automata and needs a plan before M5/M6. Triage: PLAN → design-debt ledger (case-insensitivity design before M5).
- **A-8** No ReDoS/match-limit/step-budget story for the M4 backtracking VM.
  Triage: PLAN → design-debt ledger (VM match/step limits in M4 design).
- **A-9** Oracle exclusions (`a{,3}`, `a++`) are documented only in the
  journal; "green at every tier" framing should carry the known-exclusions
  caveat. Triage: DOC → FIXED: docs/testing.md now documents oracle exclusions and the `# pcre2-only` mechanism.
- **A-10** No ABI/versioning decision for how the generated API grows
  M1→M3→M4 for already-vendored embedded consumers. Triage: PLAN → design-debt ledger (generated-API versioning policy before M3).
- **A-11** `startpos` semantics vs `\G` (exact-continuation anchoring) for
  global-match iteration undecided. Triage: NOTED → design-debt ledger (\G semantics with the modifiers/global-iteration work, M6).

## Critic: robustness (report received)

### CRITICAL (all CONFIRMED with ASan traces + stock-binary repros)
- **R-1** Parser stack overflow: `p_atom→p_alt→p_cat→p_rep` mutual recursion,
  no depth guard; ~60k nested groups (120 KB argv, under kernel limits)
  → SIGSEGV via the shipped CLI. (Same root as P-C1.) Triage: FIX-NOW → FIXED: same fix as P-C1 (nesting cap 250); 60k-nesting repro now a clean error.
- **R-2** `compile_ast` stack overflow on a FLAT 100k-char literal (no parens):
  p_cat builds a left-leaning CAT tree iteratively, but nfa.c compile_ast
  recurses down its left spine; the NFA state cap is only checked at the base
  case — after the stack is already blown, so the designed safety valve can
  never fire. Nested-nullable `((X)?)?...` variants crash ~15k–40k depth via
  the same missing depth accounting. Triage: FIX-NOW → FIXED: A_CAT/A_ALT left spines flattened iteratively in nfa.c; 100k-literal and 30k-`(a)?`-chain repros now hit the NFA cap cleanly.
- **R-3** Leak class on every longjmp'd compile failure, confirmed by LSan
  AND by +18.2 MB RSS over 20k failing calls on a plain -O2 build (~860
  B/call): (a) dfa.c seen/scratch/pre mallocs skipped by ctx_fail inside
  make_state; (b) nfa.c Patch.v realloc arrays abandoned on the recursion
  stack when nst() throws — 180 KB / 5,644 allocations on one ~15k-group
  pattern. Triggered precisely by the complexity caps doing their job —
  unbounded RSS growth for any long-running embedder compiling untrusted
  patterns. Triage: FIX-NOW → FIXED: dfa.c scratch buffers and nfa.c patch lists are arena-owned; ASan run of 1000 failing compiles (both leak shapes) reports zero leaks.

### MAJOR
- **R-4** (SUSPECTED, code-certain; LP64 box can't execute it) generated
  `long last` truncates ≥2 GB offsets on LLP64 (Windows): silent wrong
  m->end. Triage: FIX-NOW → FIXED: generated code uses size_t last with (size_t)-1 sentinel; no long anywhere in emitted output.
- **R-5** Generated code hard-requires gcc/clang (computed goto fails
  -pedantic-errors / ISO frontends) — characterized exactly; docs say
  "gcc-dialect" so this is a documented constraint, but the promised --std-c
  fallback doesn't exist yet. Triage: PLAN → design-debt ledger (--std-c switch-based emitter fallback); gcc/clang-only is the documented contract meanwhile.

### MINOR
- **R-6** CLI `-e` with missing value consumes/reports the wrong token.
  Triage: FIX-NOW → FIXED: explicit "missing value for -o/-p/-e" diagnostics.

## Critic: semantics (report received)

Oracle: critic built a direct libpcre2-8 binding (hand-declared ABI, no dev
headers on the box) — findings verified against real PCRE2 10.46, not python.

### CRITICAL (both CONFIRMED vs PCRE2; shared root cause)
- **S-C1** Mid-branch `$` with matchable continuation silently drops real
  matches: `a$\n` vs "a\n" → pcrec nomatch, PCRE2 match 0 2. Root: make_state
  computes the eol_ok=true closure only for a boolean and throws away its
  thread list, so continuations reachable only through `$` are absent from
  every transition table. Parser accepts `$` anywhere with no diagnostic —
  silent miscompile, materially worse than the documented "supported only at
  branch end" limitation implies. Triage: FIX-NOW → FIXED: EOL-variant states (the eol-closure list is interned, not discarded); mid-pattern $ now compiles correctly — M1 limitation REMOVED. Regressions in tests/base/review_r1.rxt.
- **S-C2** `$` priority violated: after the runtime EOL check records an
  accept, execution keeps consuming with the UNPRUNED transition list, so a
  lower-priority branch can overwrite with a longer match: `$|\n` vs "\n" →
  pcrec match 0 1, PCRE2 match 0 0. Fuzzing found 3 instances of this class
  in 12,552 pairs; 0 divergences outside it. Triage: FIX-NOW → FIXED: same mechanism — at EOL positions the matcher switches to the variant's priority-pruned accept + transition table. `$|\n` → 0 0 verified.

### MAJOR (accept/reject vs real PCRE2)
- **S-M1** Quantified bare anchors (`^*a`, `a$*`, `${1,2}`) compile fine in
  pcrec; PCRE2 rejects all (error 109 "quantifier does not follow a
  repeatable item"). Dominant cause of 181 accept/reject mismatches in the
  PCRE2-oracle fuzz batch. Triage: FIX-NOW → FIXED: bare quantified anchors rejected with PCRE2's message; `(^)*` stays legal via group wrapping.
- **S-M2** `\x` with zero hex digits accepted as NUL (source comment's PCRE
  claim is factually wrong for PCRE2 10.46 — error 178 "digits missing").
  Triage: FIX-NOW → FIXED: \x requires >=1 hex digit ("digits missing after \x"); wrong source comment corrected.

## Reflection (what this checkpoint taught us)

1. **The green suite certified less than it appeared to.** Every critical was
   in territory the 333 cases structurally could not see: crash-vs-rejection
   conflation, $-edge semantics no curated case exercised, error-path leaks,
   coverage floors. "All tests pass" and "the thing is right" were different
   claims, and the gap was exactly where the critics went.
2. **Evidence-required hostility works.** Demanding a repro or an explicit
   SUSPECTED label kept all four reports dense with real findings and free of
   theater; the probed-and-held lists were as valuable as the findings —
   they turn "not examined" into "examined and clean", which is what lets the
   next milestone build with confidence.
3. **The best tool a critic built should be promoted, not discarded**: the
   semantics critic's direct libpcre2 binding out-oracles python re. Pulled
   into the plan as M2.5 rather than waiting for M7.
4. **Architecture review before the next milestone is cheaper than after.**
   A-2/A-3 (O(n²) shape, gcc superlinear compile) would have had M2 optimizing
   an emitter that M3 must replace; the design gate now forces the shape
   decision first. A-1 caught a self-contradiction between APPROACH §2 and
   D3 while it was still words, not code.
5. **Process gap worth fixing at the root**: verification artifacts must live
   in-repo (fixed), and the project needs version control — recommended
   `git init` + initial commit to Frank (not done unilaterally).
