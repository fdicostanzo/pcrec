### READYR-1 — CONFIRMED — a reference reached THROUGH A CALL from a lookbehind has no rule and no cell; libpcre2 accepts it
- severity: design (G1 accept-set gap; answer tier is a refusal, not a miscompile); effort: small (one rule sentence + cells); blast radius: stage-2 width memo + callgraph's callee width fixpoint.
- Repro (libpcre2 10.46 via ctypes, PCRE2_INFO_MAXLOOKBEHIND=15; pcrec = build tree `--features all -p rx`):
  - `(?(DEFINE)(?<g>a\2))(b)(?<=(?&g))x` libpcre2 ACCEPT lb 2; pcrec REFUSE "every alternative of a lookbehind must have a bounded length (this one is unbounded)" @23
  - `(?(DEFINE)(?<g>a\2))(b|cd)(?<=(?&g))x` ACCEPT lb 3 (VARYING via a call); pcrec same "unbounded" refusal @26
  - `(b)(?(DEFINE)(?<g>a\1))(?<=(?&g))x` ACCEPT lb 2; pcrec "unbounded" @23
  - controls that must stay refused: `(?(DEFINE)(?<g>a\2))(b+)(?<=(?&g))x` REJECT 125; `(?(DEFINE)(?<g>a\1))(?<=(?&g))x` REJECT 125 (self-ref through a call); `(?<=(a(?2)))x(b\1)?` REJECT 125; `(?<=(a(?2)))x(?(DEFINE)(b\1))` REJECT 125.
- §6 stage 2 names "self-reference ... through a call" as a REFUSAL but never says the non-self case (a callee whose body holds a reference to another bounded group) is ACCEPTED, and the acceptance table has no call-through row at all. The mechanism text says only "Callgraph computes callee widths today, but a group named only by a reference has no memo, so stage 2 adds it" — it does not say callgraph's callee-width fixpoint (`u.call.cwmin/cwmax`, src/opt/callgraph.c) must read an `A_BREF` INSIDE a callee through the new memo. Without that, `pcrec_cwmax`'s A_CALL arm keeps publishing UNBOUNDED for these callees and they stay refused.
- The build tree already knows: src/parse/mod_lookaround.c:290-293 (rule 0 comment) "Through a CALL the callee's published `cwmax` is unbounded and this rule cannot see why, so `(?<=(?&g))` with a backreference in `g` still reads "unbounded" (review r4 F1's residual, stage 2's)". The design (frozen before r4) does not carry that residual.
- Also a stage-1 shipped mis-tier today: these three print shape 7's "unbounded" (spec §2.4 shape 7 = "PCRE2 refuses it too") on patterns libpcre2 ACCEPTS — the exact false-fact class S1981/review r4 F1 retired for the direct reference.
- Fix: add to §6 stage 2 "a reference inside a called group counts the referenced group's memo width; the callee's published width is computed with it (callgraph's fixpoint reads the memo for A_BREF)", plus the 3 accept cells and 4 refuse controls above to the table; and order the computation (memo for referenced groups must exist before callgraph's third fixpoint, or be computed in the same fixpoint — a callee referencing a group that itself contains a call).
- READYR-1 addendum: the [VLOOKBEHIND] plan row's "Stage-2 note (2026-11-07, vlbbuild review F4a)" (plan.md @dc1988069, the row at line 307) files the call-through case as "wording tier, D26". The probe above shows it is NOT wording: libpcre2 ACCEPTS the bounded case (lb 2 / lb 3), so it is a G1 accept-set gap and stage 2 must build it (or state it out of scope in G1). The note's second clause (`(a+)(?<=\1)x` is not-built in pcrec vs err 125) is covered by the design's "unbounded group" row.

### READYR-2 — CONFIRMED — the five refusals are three instances of ONE rule (a width cycle), and the instances the list misses are real libpcre2 refusals/accepts
- severity: design (G3 one-mechanism + G1 completeness); effort: small in text, the build's memo must be a fixpoint either way; blast radius: the per-group memo (§6 stage 2 "Timing").
- libpcre2 10.46, all with pcrec refusing today with the shape-5 sentence:
  - group whose body holds a FORWARD reference to a later fixed group: `(a\2)?(b)(?<=\1)x` ACCEPT lb 2; `(a|\2)(b)(?<=\1)x` ACCEPT lb 1 — the memo of group 1 needs group 2, parsed later (the deferral must cover REFERENCED groups' bodies, not only the lookbehind body);
  - group holding a reference to another group: `(a)(b\1)(?<=\2)x` ACCEPT lb 2; `(a|bc)(d\1)(?<=\2)x` ACCEPT lb 3 (varying through a chain); `((a|bc)\2)(?<=\1)x` ACCEPT lb 4; `(?<=(a|bc)(d\1))x` ACCEPT lb 5; `(a+)(b\1)(?<=\2)x` REJECT 125 (unboundedness propagates through a reference chain);
  - MUTUAL references (a cycle through references, not through a call): `(a\2)?(b\1)?(?<=\1)x` REJECT 125;
  - self-reference OUTSIDE the lookbehind (the referenced group references itself; the lookbehind does not sit in it): `(a(?:\1)?)(?<=\1)x` REJECT 125, `(a\1?)x(?<=\1)` REJECT 125.
- §6 stage 2's refusal bullet is worded "a reference inside the group it names (self-reference, directly or through a call)", and its table's only self cell is `(?<=(a\1))x` (reference inside the lookbehind AND inside its group). Read literally, neither the mutual-reference cell nor the outside-the-lookbehind self-reference is "a reference inside the group it names" from the lookbehind's point of view, and nothing says a reference INSIDE a referenced group is resolved through the memo.
- One rule covers recursive group, self-reference (direct / through a call / through references / mutual) and reference-to-unbounded-through-a-chain: the per-group [cwmin,cwmax] memo is a fixpoint over the call+reference graph that SATURATES to UNBOUNDED on a cycle — exactly callgraph's existing maxw fixpoint (tests/recursion/inlookaround.rxt:137 "the fixpoint's SATURATION propagates the callee's UNBOUNDED into `g` for free. One mechanism instead of two"). Then three of the five listed refusals are not refusals of their own but the existing unbounded refusal (err 125's sentence), and only duplicate-name and `(?|` remain as separate rules. Memory rule pcrec-general-mechanisms-not-special-cases / G3.
- Fix: restate the memo as "references and calls are edges; the memo is callgraph's fixpoint extended with reference edges; a cycle saturates to unbounded (err 125)"; add the 9 cells above to the table (5 accept, 4 refuse).

### READYR-8 — CONFIRMED — the `(?|` rule's scope is mis-worded and its timing is unstated: it must hold for a `(?|` written AFTER the lookbehind, and must NOT reach a reference outside the lookbehind
- severity: doc/design (latent; becomes answer-tier the day module branch-reset lands); effort: one sentence + 2 cells.
- libpcre2 10.46: `(a)(?<=\1)(?|b|c)x` REJECT 125 (the `(?|` comes after the lookbehind — every table cell puts it before); `(?|b|c)(a)(?<=\1)x` REJECT 125; `(a)(?<=(?|b|c)\1)x` REJECT 125; but `(?<=(?|(a)|(b)))\1x` ACCEPT lb 1 (a `(?|` inside the lookbehind, the reference OUTSIDE it).
- §6 stage 2 says "ANY reference in a pattern that uses `(?|` anywhere". Literally that refuses `(?<=(?|(a)|(b)))\1x`'s outside reference too; the rule is "any reference INSIDE A LOOKBEHIND, in a pattern that uses `(?|` anywhere". And because a later `(?|` must refuse an earlier lookbehind, the check cannot be made at the lookbehind's parse hook: it belongs to the deferred pass (`pcrec_lookaround_fix_widths` in `pcrec_postresolve`), i.e. every reference-bearing lookbehind defers — which the widened deferral predicate gives anyway, but the design should say the `(?|` fact is read there, pattern-wide.
- Fix: reword the bullet; add `(a)(?<=\1)(?|b|c)x` (refuse) and `(?<=(?|(a)|(b)))\1x` (accept, for the branch-reset module's day) to the table.
