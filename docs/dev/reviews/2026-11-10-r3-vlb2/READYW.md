### READYW-2 — the "per-group memo" is a fixpoint over references AND calls; its home, timing and cycle rule are unspecified (CONFIRMED vs libpcre2 10.46; answer/design; effort M; blast: G1 accept set, compiler termination)
libpcre2 cells (probe.py/probe2.py in this dir):
- `(a)(\1b)(?<=\2)x` ACCEPT (abaabx -> (2,6)): a group's width depends on ANOTHER reference;
- `(a\2)?(b)(?<=\1)x` ACCEPT: a forward reference inside the named group;
- `(?<=\2)(a)((?1)b)x`, `(a)(b(?1))(?<=\2)x` ACCEPT: the named group contains a CALL (needs callgraph's cwmax);
- `(a)(?(DEFINE)(?<g>b\1))(?<=(?&g))x` ACCEPT (abax -> (2,4)) and `(a)(?(DEFINE)(?<g>\1{1,300}))(?<=(?&g))x` REJECT 200: a CALLEE containing a reference. pcrec today: "every alternative ... must have a bounded length (this one is unbounded)" — a false shape-7 claim, the residual mod_lookaround.c:290-294 itself assigns to stage 2. callgraph.c:873-893's cwmax fixpoint calls `pcrec_cwmax(cg->body[i])`, which reaches A_BREF, so the call widths and the reference widths are ONE fixpoint;
- `(a\2)?(b\1)?(?<=\1)x` REJECT 125: a reference CYCLE through two groups. Not in the design's refusal list (which has only "self-reference, directly or through a call").
Also `pcrec_callgraph_build` returns at callgraph.c:701 for call-free patterns before it builds the group->region map (`cg_roots`, :714-718), and setting `cx->callgraph` for a bref-only pattern would move select_engine/emit_vm (`v->cg`) bytes. The design says "stage 2 adds it" with no home.
Fix (text): one joint fixpoint over groups, edges = calls and references on width-bearing paths, start UNBOUNDED and iterate down exactly as callgraph's cwmax does; a cycle stays UNBOUNDED and refuses as err 125's shape-7 text, so a reference cycle (`(?<=(a\1))x`, `(a\2)?(b\1)?(?<=\1)x`) needs no rule of its own (general mechanism, not a list). A lookbehind that sits INSIDE the group it references (`(a(?<=\1))x`, REJECT 125) is NOT a width cycle (the lookbehind contributes 0, so g1 = 1, finite): that half of "self-reference" is READYW-3's re-entry rule. Publish on the A_BREF node with a `known` flag whose arena zero is the safe direction (the `u.call.cwmax_known` precedent, mrl.c:603-643). Name where the group->region map comes from for a call-free pattern without setting `cx->callgraph`.

### READYW-3 — lookbehind re-entry THROUGH A REFERENCE: K127's `recurses` stops at A_BREF (CONFIRMED vs libpcre2; SUSPECTED in pcrec until built; answer (accept-set); effort S; blast: G1/gate 3)
libpcre2 REJECT 125: `((?<=\2)a)(b(?1))?x` (the lookbehind references group 2, whose call re-enters group 1, which contains the lookbehind) and `(a(?<=\1))x` (the lookbehind is inside the group it references). In both, the referenced group's WIDTH is finite (lookbehind = 0): a width fixpoint accepts them. pcrec's re-entry rule is `pcrec_callgraph_lookbehind_recurses` (callgraph.c:964-), whose length walk `cg_length_calls` returns at `case A_BREF:` (callgraph.c:944-946) and which returns false outright when the pattern has no call (`n == 0`, :967), so `(a(?<=\1))x` (call-free) never reaches it. The design's refusal list cites "K127's `recurses` is the existing home" for a RECURSIVE group — but a recursive group is already refused by width (callgraph's cwmax is UNBOUNDED for a cycle, mrl.c:597-605); what K127 must newly do is follow a reference to its group's region as a length edge, and run for call-free patterns. Text fix: state the rule as "a lookbehind whose length (calls AND references) reaches a group containing it", name `cg_length_calls`' A_BREF arm and the `n == 0` early return as readers, add both cells to the table.

### READYW-5 — (b) the width can be loose UP on a varying branch and no named check goes red (CONFIRMED by construction; design (witness); effort S; blast: lb_max/VALID_LB, the cap)
What each named gate sees for a loose memo on a bref cell:
- lo too low on a fixed group (`(a)(?<=\1)x` as [0,1]): gate 3's classification control (one-length vs libpcre2 at max_varlookbehind=0) goes red. HELD.
- lo too high / hi too low: farthest/nearest candidates dropped; gate 1's differential goes red if the generated subjects reach that length. HELD (subject-dependent).
- hi too HIGH on a varying branch (`(a|bc)(?<=\1)x` read [1,3]): extra candidates fail the end-check, so gate 1 is silent; gate 3 classifies it "varying" either way and catches it only at the cap boundary cells (`(a{1,255})` / `(a{1,256})`). But it moves `la_lb_raise`'s LB (`rx_VALID_LB`, emit_dfa.c:3616-3617), which is answer-visible under ill-formed UTF-8 ("a larger LB would refuse subjects PCRE2 accepts", internal.h:4008-4011) and is the acceptance table's own "lb N" column.
The check exists but is not in the design or in `make test`: tests/utfcheck/check.py:244-247 compares `rx_VALID_LB` with PCRE2_INFO_MAXLOOKBEHIND, and tests/utfcheck/CLAUDE.md:22 says it is run once, not built by make; `pcre2_ctypes.py` has no `pattern_info`. Text fix: gate 3 adds, per accepted cell (stage-2 cells included), `rx_VALID_LB == PCRE2_INFO_MAXLOOKBEHIND` (a one-call binding extension), which pins hi exactly at both stages; and add a sabotage row (the memo's hi + 1) that only that check turns red.

### READYW-7 — (b) unit W is NOT separable from the refusals unit (design; effort 0, a sequencing statement)
- The cycle handling is a PRECONDITION of computing the memo: without it the width of `(?<=(a\1))x` recurses (the design says so itself). Under READYW-2's fixpoint the cycle refusal IS the width outcome, so the two are one change.
- Without the by-name duplicate refusal, W's width for `\k<n>` must pick a group or union them; either way `(?J)(?<n>a)|(?<n>bc)(?<=\k<n>)x` compiles where libpcre2 refuses 125, and gate 3 (accept set) goes red.
- Without READYW-3's re-entry rule, `(a(?<=\1))x` compiles: gate 3 red.
- Only the `(?|` refusal is separable (latent until the branch-reset module).
So W and the refusals land together (or refusals first). The fixed-group half (§6 "needs none of stage 1's loop") is separable from the RANGE half, not from the refusals.

## Verdict (unit W)
NOT READY. Every function the unit names exists and does what the text says, except the mrl.c header sentence (READYW-1). But the unit is incomplete against the tree stage 1 left:
- the not-built path (READYW-1);
- the memo's fixpoint, home and cycle rule (READYW-2);
- re-entry through a reference (READYW-3);
- the scoping of the width answer to the lookbehind (READYW-4).
Its witnesses cannot see an over-estimated hi (READYW-5), and it cannot ship apart from the refusals (READYW-7). All of these are text fixes of modest size. With READYW-1..7 written in, the unit becomes "ready with listed text fixes".
