# SOUND findings — vlb2

## Findings

### SOUND-1 — CONFIRMED (accept set; answer-level for G1) — a reference to a group that itself CONTAINS a reference: the width memo as written gives [0, unbounded], so stage 2 refuses (or mis-rows) chained references libpcre2 accepts
- Design §6 stage 2 "Width": "Inside a lookbehind body, an `A_BREF` counts its group's own `[cwmin, cwmax]`" and "a per-group `[cwmin, cwmax]` memo" modelled on callgraph's callee widths. The memo of a group is a walk of the GROUP's body, which is NOT inside the lookbehind; the rule only re-aims `A_BREF` "inside a lookbehind body", and the refusal list includes "a reference to an unbounded group". Today `pcrec_cwmax(A_BREF)` = UNBOUNDED (row ANY) and `pcrec_cwmin(A_BREF)` = 0 (build tree src/opt/mrl.c:588 and :740), and callgraph's callee widths inherit exactly that.
- Witness of the inherited behaviour, measured on the build tree: `(a)(\1)(?<=(?2))x` (a CALL to a group containing a reference, the memo the stage-2 text says it copies) -> pcrec today: "every alternative of a lookbehind must have a bounded length (this one is unbounded)"; libpcre2 10.46 ACCEPTS and on `aaax` answers ((1,4),((1,2),(2,3))).
- libpcre2 on the stage-2 shapes (ctypes oracle): `(a)(\1)(?<=\2)x` on `aax` -> ((0,3),((0,1),(1,2))); `(a|bc)(\1)(?<=\2)x` on `bcbcx` -> ((0,5),((0,2),(2,4))); `(a|bc)(\1d)(?<=\2)x` on `aadx` -> ((0,4),((0,1),(1,3))); `(a{300})(\1)(?<=\2)x` ACCEPT (lb 300, matches a^600 x); `(a{300})(\1)(?<=\2|b{1,2})x` ERR 200 and `(a{200})(\1)(?<=\2b{1,60})x` ERR 200 — i.e. libpcre2 resolves the inner reference to its group's width at BOTH ends.
- As written: group 2's memo = [cwmin(\1), cwmax(\1)] = [0, UNBOUNDED] -> all four accepted shapes REFUSED as "unbounded group" (G1 accept-set failure). If a builder resolves only cwmax through the reference, cwmin stays 0: `(a)(\1)(?<=\2)x` becomes a `range` [0,1] branch (wrong row; G2-irrelevant since new, but the 255 cap switches on: `(a{300})(\1)(?<=\2)x` -> [0,300] varying -> refused ERR-200 shape where libpcre2 accepts).
- Fix: state that the memo's own walk counts every nested `A_BREF` (and `A_CALL`, already memoised) by the named group's memo at both ends, recursively, under the self/cycle refusal (SOUND-2); add the chained cells above to the acceptance table and gate 1. The pre-existing call case `(a)(\1)(?<=(?2))x` (refused today, accepted by libpcre2) should be named in the same row since the same memo fixes it.
- Severity: answer (accept set, G1); effort small (one rule sentence + cells); blast radius: every chained-reference lookbehind; anchor: design §6 stage 2 "Width" and "Timing" bullets; src/opt/mrl.c:583-600, :737-741.

### SOUND-2 — CONFIRMED (accept set / compile-time hang risk) — the self-reference refusal covers "directly or through a call" but not a cycle through REFERENCES; libpcre2 refuses exactly the reached cycles
- Design §6 stage 2 "Refusals": "a reference inside the group it names (self-reference, directly or through a call). Without this rule, a naive 'width of group 1' recurses or reads a half-built memo." A mutual cycle through references only (group 1 contains \\2, group 2 contains \\1) is neither.
- libpcre2 10.46 (ctypes): `(a|\2)(b|\1)(?<=\1)x` ERR 125; `(a|\2)(b|\1)(?<=\2)x` ERR 125; `(a(?2)?)(b\1)(?<=\2)x` ERR 125 (call+reference cycle); but `(a|\3)(b|\1)(c)(?<=\3)x` ACCEPT (the 1<->2 cycle exists, the lookbehind's reference does not reach it; `abcx` -> ((0,4),((0,1),(1,2),(2,3)))); `(a|\2)(b|cd)(?<=\2)x` ACCEPT (`acdx` -> ((0,4),((0,1),(1,3)))); `(a|\2)(b|\1)x` (no lookbehind) compiles in both.
- pcrec today compiles `(a|\2)(b|\1)x` (no refusal elsewhere), so the cycle reaches stage 2's memo. Once SOUND-1's nested resolution is written (it is required to accept libpcre2's chained shapes), a memo walk with no "in progress" mark recurses unboundedly on the 1<->2 cycle (compile-time stack overflow / hang), or, with a zero-initialised memo, reads a half-built [0,0] — an UNDER-estimate, i.e. a candidate range that drops starts (silent miscompile on a positive lookbehind, false match on a negative one).
- Fix: phrase the refusal as "the reference's group width depends on itself through any chain of references or calls" (an in-progress mark on the memo; refuse on re-entry), refused only when REACHED from a lookbehind's reference, as libpcre2 does; add the four cells above.
- Severity: answer/accept set (and a compile crash risk); effort small; blast radius: patterns with mutually-referencing groups; anchor: design §6 stage 2 "Refusals" 5th bullet.

### SOUND-3 — CONFIRMED (accept set, precision of a refusal) — "a reference inside the group it names" must mean "on the group's WIDTH path"; libpcre2 accepts a self-reference under a lookahead and refuses one under a lookbehind
- Design §6 stage 2 "Refusals", 5th bullet, as written refuses any reference inside the group it names. libpcre2 10.46 (ctypes): `(a(?=\1)|b)(?<=\1)x` ACCEPT (a lookahead contributes 0, so group 1's width never reads \\1); `(a|b\1)(?<=\1)x` ERR 125; `(a(?<=\1)|b)x` ERR 125 and `(?<=(a(?<=\1)))x` ERR 125 (the inner lookbehind needs group 1's width while group 1 is being sized). pcrec today compiles `(a(?=\1)|b)x`, so the over-refusal would be a NEW refusal of a libpcre2-accepted pattern.
- Fix: one sentence — the refusal fires when sizing a lookbehind-reachable group reaches that group again through references/calls on the width path (lookahead bodies are not on it; nested lookbehind bodies are, for their own sizing). This is the same in-progress-mark rule SOUND-2 needs; add the four cells.
- Severity: accept set (G1), small; effort: wording + cells; anchor: design §6 stage 2 "Refusals".

### SOUND-4 — CONFIRMED (doc/gate classification) — the inherited zero-width divergence is worded "a group made ONLY of an unbounded zero-width repeat"; the measured class is "a group CONTAINING one", and it lives in the referenced group, not the lookbehind text
- Design §6 stage 2, after the acceptance table: "A reference to a group made only of an unbounded zero-width repeat inherits stage 1's stated divergence". libpcre2: `((?:)*)(?<=\1)x` ERR 125 (the stated shape) but also `((?:)*a)(?<=\1)x` ERR 125 and `(a(?:\b)*)(?<=\1)x` ERR 125. pcrec's `pcrec_cwmax` A_REP arm gives 0 for the zero-width repeat (src/opt/mrl.c:656-668), so a stage-2 build accepts all three (widths [0,0], [1,1], [1,1]). §0 G1's own class says "a lookbehind branch CONTAINING an unbounded repeat ...", so the stage-2 sentence is narrower than the class it inherits.
- Consequence: gate 3's "count the class on its own line" control, if keyed to the stage-2 sentence (or to the lookbehind's own text), counts `((?:)*a)(?<=\1)x` and `(a(?:\b)*)(?<=\1)x` as accept-set violations (gate red) or, if the generator never produces a zero-width repeat inside a REFERENCED group, never exercises the class at all (a population nobody counts, learnings §3 K35). No answer differs (libpcre2 has no answer to compare: it refuses).
- Fix: reword to "a reference whose group contains an unbounded zero-width repeat", state that the classifier must look through the reference into the group, and add the two cells.
- Severity: doc / gate design; effort trivial; anchor: design §6 stage 2 last paragraph before "The fixed-group half"; §0 G1 "stated accept-set divergence".
