### PREMISE-2 — CONFIRMED — "Callgraph computes callee widths today" is true only for CALL TARGETS of a pattern WITH A CALL, published onto A_CALL nodes; and the deferral predicate cannot be `pcrec_has_call` widened
- severity: design; effort S; blast radius: mod_lookaround.c hook, callgraph.c, postresolve.c, possessify/select_engine if done wrong.
- Evidence: `src/opt/callgraph.c:700-701` returns before any fixpoint when the pattern has no call (`if (sc.ncall == 0) return;`), so `(a|bc)(?<=\1)x` has NO width table of any kind. The three fixpoints (`:860`, `:881`) are indexed by `cg_index` over call targets only and published ONLY onto `A_CALL` nodes (`cg_cwmax_publish :317-331`, `cg_cwmin_publish :348-354`); there is no per-group storage a reference could read. They also run `pcrec_cwmin`/`pcrec_cwmax`, whose `A_BREF` arms answer 0 / UNBOUNDED, so a call target that contains a reference is UNBOUNDED in that memo.
- §6 stage 2 says the deferral "widens from 'the body has a call' (`pcrec_has_call`, src/parse/mod_lookaround.c)". `pcrec_has_call` is DEFINED in `src/opt/atomic.c:1000` and is also read by `src/opt/possessify.c:2138` and `src/opt/select_engine.c` (wave G's narrowing, `:959`); mod_lookaround.c only calls it (`:626`). Widening it moves possessify and engine selection. Stage 2 needs its own predicate in mod_lookaround.c ("call or backreference"), stated as such.
- `src/opt/postresolve.c:125-131` states the pass is free "for every call-free pattern in the corpus, since a lookbehind is only ever recorded when its body carries an A_CALL"; `internal.h`'s `widths` comment (`:1878-1884`) states the pending state exists because of an A_CALL. Both are premises stage 2 changes (comment readers, not behaviour).
- So the memo is genuinely new and must be built independent of the call graph's early return, over the FINAL tree (see PREMISE-6), keyed by GROUP NUMBER (duplicate numbers under `(?|`, refs as a SET in `A_BREF.u.bref.refs`, internal.h:1724-1741).

### PREMISE-3 — CONFIRMED — K127's `recurses` is NOT a home for "a reference to a recursive group"; the width fixpoint is not one either; and the call twin already diverges from libpcre2 today
- severity: answer (accept set, G1) + design; effort S-M; blast radius: callgraph.c, the refusal list, G1's stated-divergence list.
- `pcrec_callgraph_lookbehind_recurses` (`src/opt/callgraph.c:977-998`) asks whether THIS LOOKBEHIND's length-bearing calls reach a region containing the lookbehind; `cg_length_calls` returns at `A_BREF` (`:944-946`). For `(a(?1)?)(?<=\1)x` the lookbehind is outside group 1 and has no call: `recurses` = false. It cannot answer the §6 stage-2 refusal "a reference to a recursive group (K127's `recurses` is the existing home)".
- The width alone does not stand in for it: the cwmax fixpoint makes a cycle UNBOUNDED by saturation (callgraph.c:286-296), but a recursion repeated `{0}` contributes 0. libpcre2 10.46: `(a(?1){0})(?<=\1)x` REJECT 125, `(a(?1)?)(?<=\1)x` REJECT 125, `(a(?2){0})(b(?2)?){0}(?<=\1)x` REJECT 125 (the referenced group only CALLS a recursive one).
- Existing divergence on the CALL side (stage 1 / DD-14.LB, not stated anywhere): `build/pcrec --features all --emit-main --pattern '(a(?1){0})(?<=(?1))x'` COMPILES and matches `aax` at 1..3; libpcre2 REJECT 125. That is a pattern pcrec compiles and libpcre2 refuses, outside G1's one stated divergence (zero-width repeats), so G1's "0 patterns" measurable is false at HEAD unless gate 3's generator never emits it.
- The predicate that exists is `pcrec_callgraph_reaches(cg, i, i)` (callgraph.c:918), already read by `vm_cost_call` (emit_vm.c:3010). ### PREMISE-4 — CONFIRMED — the plan row's Stage-2 note (a reference reached THROUGH A CALL) is not a wording-tier item and stage 2's text does not decide it

### PREMISE-9 — standing question SIBLING OF A FAMILY — yes: the per-group width memo is the fourth member of "a fact per GROUP NUMBER, resolved through calls and references", and should be one table
- severity: design (maintenance); effort M; blast radius: callgraph.c, possessify.c, the new memo.
- Members at HEAD: (1) callgraph's three per-target fixpoints `minw`/`cwmax`/`cwmin` (callgraph.c:860,881 + publishers), keyed by call target, published onto A_CALL nodes, A_BREF opaque; (2) possessify's `PossCap` (possessify.c:290-397), per group NUMBER, A_CAP index incl. lookaround/DEFINE bodies, BUSY = widen on a reference cycle, depth-bounded; (3) K127's `cg_length_calls`/`lookbehind_recurses` (callgraph.c:929-998), length-bearing reachability over targets, A_BREF opaque; (4) stage 2's memo, per group number, must see calls (PREMISE-4: `(a(?2))(b){0}(?<=\1)x`) and references (PREMISE-8), and needs a cycle test (PREMISE-3). - They answer the same structural question — "what is group g's X, where X composes through its body, a call to h reads h's X, and a reference to h reads h's X" — with three different treatments of the two edges. One table: per group number, the [cwmin, cwmax] (and minw) computed by one Kleene iteration over a graph whose edges are calls AND references (references only for the ref-aware consumer), with `reaches` over the same edges giving both "recursive group" (PREMISE-3) and K127. - Proposal, not a demand: stage 2 builds the memo as a column of callgraph's target table widened to every referenced group (callgraph.c's early return becomes "no call and no reference in a lookbehind"), not a fourth walker.

### PREMISE-10 — standing question GENERAL FORM + UNLOCKS
- The general form stage 2 approaches: a lookbehind body's width is a function of PATTERN-STATIC per-group widths, so any item whose consumed length is "the length of something the pattern already bounds" (a reference = its group; a call = its callee; a reference to a callee's capture) is a bounded-width item. Stated as "an item's width interval is a lookup into the per-group table", rule 0 shrinks to the items whose length is genuinely caller-supplied (variables, consuming callouts).
- Unlocks, each with its trigger:
  1. Through-call references accepted (closes the plan row's Stage-2 note, PREMISE-4). Trigger: the joint fixpoint exists (stage 2 if it adopts PREMISE-9), plus one corpus/bench pattern or a G1 gate-3 generator row reaching it.
  2. A ref-aware end window / start window (`endwin.c`, `startanch.c`): `(a|bc)\1$` gets a finite match-length bound (4) where `pcrec_cwmax` answers UNBOUNDED today. Trigger: a bench cell with a trailing-anchored backreference pattern (a speed row, G2 abi event, its own row, never riding stage 2).
  3. Variables with declared length bounds (`${v}` with a max) become rule-0-free the same way. Trigger: [IFACE-PUSH] or a caller asking for `(?<=${v})`.
  4. A-REV/stage 3 (`reverse-dfa`) can treat a reference to a fixed group as a fixed-width wall in a reverse run. Trigger: stage 3's own go.
