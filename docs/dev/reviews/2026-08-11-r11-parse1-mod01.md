## Panel 2 — MOD-0.1's design, attacked before building

### The measurement that refutes D30 §2

D30 §2 states a non-optional check as *"pcrec must promise a module wherever
libpcre2 DISPATCHES."* Measured over 1,672 generated probes, all four doorways,
options = 0, libpcre2 10.46:

    libpcre2 DISPATCHED (diagnostic NAMES a construct)   769
      of which pcrec promises a module                   676
      dispatched but NO module promised                   93
    libpcre2 says NOT-A-CONSTRUCT                        206
      pcrec named a module anyway (OVER-promise)           0

**All 93 are pcrec behaving correctly** — 40 REFUSE (`\U`/`\u`, which is D30
§4's own bound-mode decision), 20 POSIX collating, 16 BASE-TIER constructs pcrec
implements, 6 unknown POSIX names, 4 `\N{name}`, 1 `(*MARK)` (D25's deliberate
fourth answer), plus truncations whose wording matches PCRE2's own.

**So "dispatched" does not imply "a module is owed."** That needs the other two
of D30 §3's three facts — does pcrec implement it, and is it REFUSE under the
bound mode. **D30 §3 gets the answer shape right and D30 §2 then writes a check
that ignores it, two sections apart** — structurally the same failure D30 §3
diagnoses in D29 ("the same document stated the rule and broke it").

One clean positive: **0 over-promises in 206 not-a-construct probes**, so Q1's,
Q2's and FIX-2's cleanups hold over a space none of them generated.

### M3 — rank is almost entirely unchecked, and two of the three checks coincide

Swept all 22 bucketed rows x candidate rank in [-5, 250] (5,632 probes) against
faithful models of both proposed checks:

- **20 of 22 rows have COMPLETELY UNCONSTRAINED rank.** Only a coarse "do not
  sink to or below your bucket's fallback tier" boundary is guarded.
- **The `\N` pair is one checked THRESHOLD, not a checked ordering.** Crossing
  40→70 inverts and is caught; the other 68 values in [1,39] ∪ [41,69] pass.
- **The per-row `syntax` check and the rank sweep fire on IDENTICAL boundaries
  in all 5,632 cases.** The sweep is REDUNDANT with the cheaper per-row check at
  the scale tested — and D30 requires both.
- **Module-swap is invisible to the per-row check** (confirmed on real rows):
  swapping two rows' `module` changes nothing the check reads. R10/C4-1
  reproduced one level inside the new instrument, on a TIER 2 property.
- **Row deletion inside a bucket is invisible to both new checks** absent a
  per-bucket count ratchet, which nothing commits to. R5's incident again.
- **`check_tail_precedence` cannot be retired at MOD-0.1.** Two of its three
  obligations have verified successors; the liveness clause's obligation has
  none in the design text. M3 located the natural successor — a "did any
  generated probe have more than one matching row" counter, baseline nonzero per
  bucket (111 / 333 / 333 / 2730).

Positive, measured: **"equal rank is the defect" does NOT repeat D29's bug** —
0 collisions on the correct table over 3,507 generated probes.

### M4 — the returning-doorway defect is FOUR call sites, and one is UB

D31 recorded one instance. The class is worse.

**`pcrec_ext_escape` is called from `esc_atom` and `esc_class_value` as the last
statement of a value-returning function with NO `return`** — legal only because
`noreturn` makes falling off the end unreachable. Make it return:

    a\qb    (esc_atom → Ast*)        exit 0, compiles, stub node reaches the
                                     matcher — the discarded pointer relaunched
                                     out of %rax by calling-convention accident
    [a\qb]  (esc_class_value → int)  SIGSEGV, exit 139 — build/pcrec, the
                                     COMPILER ITSELF, crashes. 3/3 runs.

Two failure shapes, two call sites, same binary, same change — and unlike the
group case (well-defined C: deterministically the same wrong answer) **this is
undefined behaviour.** It is also the only doorway where the compiler warns at
all (two `-Wreturn-type`, build still exit 0); the group and verb doorways
produce ZERO warnings for the identical change.

Latent and NOT reproduced, flagged separately: `esc_class_value`'s return feeds
`cls_set(a->cls, (unsigned)lo)` with **no range check**, and `cls_set` indexes
`b[c >> 3]` into a 32-byte array.

**And the group-discard class, generated rather than listed:** 18 patterns
crossing prefix x head x tail shape. **7 are byte-identical to a smaller
pattern** — `(?%x)b)` → `b`, `(?%x))` → the EMPTY pattern, `(?%x)(?%y)c))` → `c`
(two discards compound), `(?%x)(d))` → `d` (a real nested group absorbed). The
other 11 diagnose the WRONG thing: 8 spurious "missing closing ) for group", 2
wrong "quantifier does not follow a repeatable item", 1 misattributed offset.
**0 of 18 behave as the design's own contract promises.**

## Dispositions — MOD-0.1's design is NOT resolved by this review

1. **Re-specify D30 §2's check.** "Wherever libpcre2 dispatches" is false;
   the rule must be a RESIDUE assertion excluding base-tier constructs, REFUSE
   outcomes, and D25's four `(*` answers — and the circularity of taking
   REFUSE membership from pcrec's own `RS_REJECTED` rows must be answered.
2. **Decide what rank IS.** If 20 of 22 values are unconstrained, a free `int`
   declares 250 values where 4 exist. Either make the tiers the TYPE, or state
   plainly that rank's value is unchecked by design and only its tier matters.
3. **Two of three checks coincide.** Either drop the rank sweep or give it a
   property the per-row check does not have.
4. **Commit to the liveness successor** (M3's >1-matching-row counter) or do not
   retire `check_tail_precedence`.
5. **Add the ratchets** for module-swap and row-deletion, or state that
   `tests/reject/` remains their only guard and that MOD-0.1 does not improve it.
6. **The returning-doorway fix is four call sites across three doorways**, and
   the escape pair is UB. Fix all, or state which are left and why.
7. **Rule on the step boundary.** All 18 tailed rows are in the 4 multi-row
   buckets (22 rows); `ext.c` never reads `.tail`, and only three files do — so
   the migration is cheaper than the row count suggests.

### M5 (re-run, narrow brief) — the signature parameter is `tail`, not the row

Answered by enumerating all 22 rows in the four multi-row buckets rather than
from principle. **No row's recogniser needs any field but `tail`.** The argument
against `const RegRow *self` is not that a row needs less, it is that:

- a recogniser able to read `self->module` becomes a second, contradictable home
  for a TIER 2 fact, which is what D29's "a recogniser does NOT return the
  module" and D24 both exist to prevent — and **the rank/ambiguity guard polices
  ANSWERS, not which fields a function consulted to produce one**, so nothing
  would catch the drift;
- the one bucket with real complexity — `(?-`'s ten digit rows, where `\12` is
  octal-or-backreference by running capture count — is out of a pure
  recogniser's reach REGARDLESS of signature (D30 §6 rejects widening it to
  carry parse progress). So it argues for a THIRD kind of input handed to the
  SEMANTIC port only, not for handing recognisers the row.

**Disposition 8: the last parameter is `const char *tail`.**

## RETRACTION — the `find()` tie-break claim was WRONG

R11's "facts that survive" list, `docs/plan.md`, `docs/dev_journal.md` and
commit `9504e8a`'s message all asserted:

> `find()`'s same-length tie-break falls back to SOURCE ORDER — a latent branch
> that rank converts into a loud defect, which D30 never claims.

**The second half is false and the first half is unreachable.** Verified in
code: `registry.c:995` compares with strict `>`, so a tie needs two rows whose
tails match the same text at the same length — i.e. IDENTICAL tails — and an
identical `(sel,tail)` pair is already forbidden unconditionally by the static
uniqueness check at `registry_check.c:184-193`, independent of rank.

And rank would NOT make it loud if that check were retired: ranks are
hand-assigned and nothing forces two duplicate-tail rows to receive the SAME
integer. Counter-example built and run: two rows both with tail `"="`, ranks 25
and 26 — both plausible hand-typed values in the same tier — produce **zero
equal-rank collisions**, and the rank-26 row silently and deterministically
always wins. That is SR-9's own diagnosed failure shape relocated from "row
order" to "whichever integer someone typed is bigger".

So rank buys nothing here unless the design either keeps the static check
permanently (in which case rank is not what is catching it) or requires
duplicate-tail rows to share a rank (which is closer to the `strlen` derivation
D30 says rank deliberately is not).

## ADDENDUM 2 — M2 again: the honest baseline, and a shipped guard sitting on its floor

Asked for the number nobody had written down — what fraction of the
malformed-body class is covered TODAY — and got it, per the four multi-row
buckets MOD-0.1 cares about:

| bucket | external coverage today |
|---|---|
| `\N` (ESC) | **0%. No sweep exists at all** — no function in `pcre2_check.c` touches the `\` doorway |
| `(?<` | nominal, but structurally VACUOUS — proves nothing |
| `(?P` | live, and already correct on garbage-before-paren |
| `(?-` | live, and already correct on garbage-before-paren |

**2 of 4 buckets have any live coverage. 0 of 4 have complete coverage of the
malformed-body class. 1 of 4 has none.** That is the number a new check has to
beat, and it should be stated in D32 rather than left as "the differential is
not optional".

### Two structural facts, both verified in source

**`check_group_tails` CANNOT generate an unterminated body.** `TAILCOMP[]`
(`pcre2_check.c:1780-1782`) is `")", "a)", "n>a)", "1)", "=a)", ":a)", "i)",
"n)", "]])", "'n')"` — **all ten end in `)`**. So R10/C1-2's own forcing example,
`(a)(?-1` with no close paren, is outside the instrument's space BY
CONSTRUCTION. The existing differential covers "digit + garbage + `)`" and is
blind to "digit + nothing at all", which is precisely the shape the `-\d+)`
collapse would regress. So the new check EXTENDS this one rather than
duplicating it: reuse its byte/prefix loop and its `PCRE2_NO_SUCH_CONSTRUCT`
(111/141) convention, add unterminated completions, and add the ESC analogue
that does not exist.

**`live_prefixes` is a COUNT, not a per-prefix expectation, and it is passing at
its exact FLOOR.** `pcre2_check.c:1832` is `if (live_prefixes < 2) bad(...)`,
and today exactly two prefixes (`P` and `-`) are live. So **if `-` went vacuous
— the one prefix D30 §6 and the collapse depend on — while any other prefix
became live for an unrelated reason, the total stays 2 and the guard says
nothing.** The aggregate liveness signal is anonymous-by-count rather than
named-by-prefix. Per-byte mismatches inside a live prefix ARE reported
individually; it is specifically the liveness signal that can silently relocate.

That is this project's silent-narrowing shape (wake §8) inside a guard written
to prevent exactly it — and it is a SHIPPED check, not a proposed one.

**Circularity ruled out for this instrument:** `pcre2_check.c` has three `.tail`
hits; two are `Wrapper.tail` (`:198-199`, an unrelated struct) and exactly one is
`RegRow.tail` (`:228`). `check_group_tails` never reads `RegRow.tail` at all —
it generates all 255 bytes directly, so its gaps are GENERATION gaps, not
circularity leaks.

### Dispositions, amended again

15. **State the baseline in D32**: 2 of 4 buckets live, 0 of 4 complete, `\N`
    at zero. A check that does not beat that is not worth building.
16. **Make `live_prefixes` name the vacuous prefix** rather than counting, and
    consider pinning WHICH prefixes must be live. It is on its floor today.
17. **Extend `check_group_tails` with unterminated completions** and add the
    missing ESC-doorway analogue — do not write a parallel instrument.

## ADDENDUM 3 — M6: a THIRD independent confirmation, and a hole in my own criterion

M6 reported after addendum 2 was pushed. It is the third independent harness to

**Q1 — the shape reproduces.** 58,709 probes across ESC/GROUP/VERB/top-level

### THE CORRECTION, and it is mine

**R11's criterion is incomplete: it names the "no construct" code for GROUP
(111/141) and VERB (160/195) and NEVER NAMES THE ESC DOORWAY'S OWN.** It is
**103, "unrecognized character follows \"**. Verified here independently by
sweeping the whole alphabet: the 52 letters split cleanly into compiles (29),
a distinct code per real-but-incomplete construct (102 `\c`, 137 ALT_BSUX,
146 `\p`/`\P`, 155 `\o`, 157 `\g`, 169 `\k`, 178 `\x`), and **exactly rc=103 for
the 11 letters PCRE2 gives no meaning to at all — `i j m q y I J M O T Y`.**

**And the reason my published counts are UNCHANGED by this is worse than if they
had moved.** Re-running R11's own 1,672-probe corpus with 103 added to the
not-dispatched set gives identical numbers — 769 / 93 / 206 / 0 — because that
corpus contains **ZERO rc=103 probes.** My escape alphabet was hand-listed
(`N p P x o k g Q E 1 12 8 u U c z Z A G K R X h v d w s b B`) and happens to
contain none of the 11 letters that would have exposed the hole.

**I hand-listed an input space and got away with it by luck, inside the very
measurement I used to refute D30 — which is wake §8's "GENERATE the input space;
never list it" and D27's alphabet finding, on the author, in the same document
that cites both.** The numbers survive; the method did not.

### A partial pushback on disposition 11

M6 also ran a rival **global blacklist** criterion — treat a no-construct code
as such regardless of which doorway produced it — and got **counts identical to
the per-doorway version across its whole input space, delta 0 everywhere.** So
per-doorway calibration was not load-bearing on the spaces measured, even though
it could be in principle (M2 showed a naive uniform CODE rule misclassifies
VERB's 160/195). Disposition 11 should therefore require the classifier to be
THREE-WAY and to name every doorway's no-construct code — including **103**,
which nobody had — rather than asserting per-doorway calibration is necessary.

### Dispositions, amended

    that tested it was hand-listed and contained none of the 11 letters that
    produce it. Any shipped classifier must enumerate the no-construct code PER

19. **Soften disposition 11:** per-doorway calibration is not measurably
    necessary (global blacklist gave delta 0 across 58,709 + 3,164 probes); what
