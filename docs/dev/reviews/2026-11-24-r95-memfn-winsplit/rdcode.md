### RDCODE-8 CONFIRMED (doc; low) — `make strict` does not "catch a missing prototype"
§8 G1 ("`make strict` ... every family file under `-Werror`, which catches a missing prototype or a `MF_NS` collision").
Facts: Makefile :1992-1998, strict = `$(KITFLAGS) -Wshadow -Werror` = `-O2 -g -Wall -Wextra -std=gnu11 -Wshadow -Werror`; no `-Wmissing-prototypes`/`-Wmissing-declarations`. A USE of an undeclared name fails anyway (gcc-16: implicit-function-declaration is an error by default, seen in RDCODE-3's probe), but a function that loses `static` without needing to (a name no other file uses, §10 bullet 4) or whose window.h prototype is missing in its own file compiles silently; only G4's `nm -g` diff at the TIP sees the extra external symbol, not per commit. Strict also never compiles the MF_TRACE regions (RDCODE-7).
Expected: G1 adds `-Wmissing-prototypes` for the family files (or G4's nm diff runs per commit), and an `-DMF_TRACE -fsyntax-only` pass per commit.
Effort: trivial. Blast: G1/G4 wording.
