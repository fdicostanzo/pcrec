### PREMISE-1 (CONFIRMED; severity design/maintenance; effort small-medium; blast radius: C18 + C9-x86 + §2's central claim)
**§2 "OFF and ON then differ only as C18 admits" and §10 "C18 / simdfloor: unchanged ... its own rule (C18 (c))" are false against the RULE as coded (not the docstring).** `tests/memfn/simd_floor_check.py` (build tree 03ce1ee3b) finds SIMD FUNCs only by
`SELECTOR = ^static inline size_t (\w+)\([^)]*\)\n\{\n    return (\w+)__w(\d+)\(.*\);\n\}$` and level helpers by `HELPER = ^static inline size_t (\w+)__w(\d+)\(`.
The subject's selector/helpers (§4.1, §5) are `static inline __attribute__((always_inline)) int rxa_mf1_vs0...`: neither regex matches.
Repro: `premise/c18/probe.py` builds a minimal OFF/ON pair in exactly §5's shape and calls the script's own `text_legs()`: `sel {}`, and the issues `(c) a deleted line that is no SIMD FUNC's floor call: '    return rxa_mf1_vs0__body(rxa_mf1_s, rxa_mf1_c);'` and `a mover with no SIMD FUNC selector`. Expected per §2: admitted. So every V artifact at x86-64-v3 is a C18 RED unless the check's rule changes.
Second, independent leg: C9-x86 ("at -O0 each SIMD FUNC's called helper is defined in the object (read with nm)"). An `always_inline` static helper is NOT emitted at -O0 (repro `premise/c18/ai.c`, `gcc -O0 -c` + `nm`: `g__w32` (plain static inline) is `t`, `f__w32` (always_inline) is absent). So widening the regex alone turns C9 red too; and the guard-lint "no helper of an unadmitted level appears" is blind to `int` helpers today (a `__w32` leaking onto `x86-64` would pass).
Consequence: §10's row, §14 U4 ("simdfloor re-pin") and §17's surface count are under-stated: C18 needs a rule change (selector/helper signature family, the C9 nm leg for always_inline helpers), which is a check-design change with its own controls (learnings §3), not a re-pin. The `size_t`/non-always_inline signature was what ofsskip's routed precedent ships; the design should either adopt a shape C18 already recognizes or name the C18 amendment as a unit.

### PREMISE-3 (CONFIRMED by reading; severity design; effort small (move the decision) ; blast radius: §3, §5, §9.3, MFTRACE)

### PREMISE-7 (CONFIRMED by reading; severity design; effort small; blast radius: §3.1's k, the define half of §5)
**§3.1's k is "`wf_loop_len(w, i, skip)` evaluated with head 0", but `skip` is not a plan fact: it is an OUTPUT of the search row's head RENDERER**, written while the use's text is built: `d_hors_head` (window.c:3977, `*skip = ih >= 0 && w->grp[ih] < 0 ? ih : -1`, ih = the probe's index `plan_ix(w, w->hl)`) and `find_head` (:3988, `*skip = w->stop_alone ? w->stop_ix : -1`), called from `wf_find_expr` (:4038) just before `w->chk->test(..., skip)`. The define (`wf_find_define`, which per §5 must write `__body`/selector/helper for each V stretch with its LO, K, j) never calls a head renderer, and a plan-time table (PREMISE-3 fix) has no `skip` either. So k as defined is not computable where the selection must run without (a) duplicating the two `*skip =` rules into a plan accessor or (b) lifting `skip` into the plan (`w->skip`, set in `wf_find_prepare` from `hl`/`stop_alone`/`stop_ix`) and having both heads read it. (b) is the general form (one fact, two readers); the design should name it, since today the k-defining input is only reachable by rendering. Witness of why it matters: `skip` is what splits the stretch — `[0-9a-f]{17}` probe at offset 16 (k=16), `[0-9]{25}` stop at offset 0 (lo=1, k=24); a probe placed inside a class stretch would split it into two shorter stretches and change which (if any) is eligible.

### PREMISE-8 (SUSPECTED design / maintenance — an argued sibling finding; effort small; blast radius: memfn/src selector + level-block writers)
**The `vs<j>` selector and its bracketed helper are the THIRD member of a family the kit already writes twice, with no shared writer; and the span-form table has a sibling table for the other stretch kind.**
(a) Selectors: `vany_selector` (vany.c:189) and `fn_selector` (ofsskip.c:727) both write: the head, then either `simd_open(top level)` + ONE `    return <fn>__<stamp>(<args>);` + `simd_close`, or the unbracketed `    return <fn>__body(<args>);`, then `}`.
