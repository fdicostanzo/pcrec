### SIZE-1 — the real population is 3 sites, not 4: the corpus row is a LIBC find that `scan-scope` (WALK only) excludes, and k=48 cannot occur at the default width
CONFIRMED. Severity: doc/design (it sizes every population-facing surface). Effort: trivial (re-count, re-word §0.1, §8, §17, D201 add. 2's population line). Blast radius: §0.1, §8 C6 pattern list, §17 "Against the population", D201 add. 2.
- Repro (build tree harness via kit/site.py, SIMD-on, head 0): `site.py --width 4095 -- '(?:ab|ba|aa|bb){24}c'` -> wfE E-find, fd **D1**, loop lo=0 end=48 k=48, hors=0. finder.c:269 maps D1 to **FF_LIBC** (memchr of the stop). Under §3.3 (`scan-scope` RESOLVED: WALK alone) T-vscan does not hold; T-head renders it. At `--width 32` the same pattern has NO window site (fd P3, then none).
- The census script's kind is "scan" for every non-HORS site (COMMON note), so the census's "routed" counted LIBC/PAIR sites the subject's T-vscan now excludes. The other long corpus site, `[ab]{1000}` (k=999), is fd **PAIR** at 4095 and E-stmt/R7w at 32: also never V.
- Bench rows re-derived: `[0-9a-f]{32}` D-hors k=31, `\b[0-9a-f]{32}\b` D-hors k=31, `\d{32}` R7w (WALK) k=31, identical at width 32 and 4095.
- So the population the design serves today is **corpus 0, bench 3, all k=31, all at the default width**. §17's "4 (text, options) pairs route today ... so the 4 are all the default build can show" is wrong on both counts (the 4th is LIBC, and needs width >= 49). §8 C6's "the four routed census patterns" lists a T-head control as a routed cell.
- Consequence for size: no real site reaches the B=32 rung (all k=31 -> B=16 only); no real site reaches either upper bound (1000, 64). k range probed: 31, 48, 999.
