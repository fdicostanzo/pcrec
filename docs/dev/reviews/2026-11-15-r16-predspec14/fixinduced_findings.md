### FIXIND-1 CONFIRMED (answer; effort trivial; blast radius O69 sketch + owner question (10)) - the 3-field tuple compare as written drops `padded` from its equality entries and rejects zero-padded tuples at the bound
Rev 14 §13 O69 (1), line 3624: "Three fields add one entry per bound (`(t1: ==lo1, t2: ==lo2, t3: padded(>=lo3))` and the strict ones before it)". The 2-field body (lines 3617-3620) writes every comparison as `padded(...)`, including `padded(==lo1)`; the 3-field entry writes bare `==lo1`, `==lo2`. A bare comparison set is canonical numerals only (C9; §0.1 L20: `/\d\d/ & between(1, 12)` is {10, 11, 12}), so `==9` rejects `09`. With `a = /\d{1,2}/` and bounds lo = (9, 30, 5), hi = (10, 0, 0): `09:30:05` is REJECTED (entry 1 `padded(>9)` fails on `09`; entries 2 and 3 need `09` in `==9`), though (9, 30, 5) >= (9, 30, 5). Owner question (10) (line 3643) says "a 2- and 3-field tuple compare is a plain macro with nothing missing" on the strength of this text; the 3-field macro as spelled is not the lexicographic order.
Repro: `$R/fixinduced/tuple_check.py` (libpcre2-8 whole match for the fields and for each `/0*(?:SET)/` or `/SET/` condition, python `re` asserted equal): 2 fields as written: 2208 cases (lo, hi in {(9,0),(9,30),(0,0),(5,1)} x {(10,0),(9,30),(12,59),(5,1)}, subjects h in 0..12 and 00..09, m in {00,01,29,30,31,59}), 0 differ from integer lexicographic order. 3 fields LITERAL (equalities unpadded, as the text spells them): 448 cases, 60 differ (e.g. `09:30:05`, `09:30:59` rejected under lo=(9,30,5), hi=(10,0,0)). 3 fields with every comparison `padded`: 448 cases, 0 differ. Output: `$R/fixinduced/tuple_check.out`.
Fix: spell the 3-field entry `(t1: padded(==lo1), t2: padded(==lo2), t3: padded(>=lo3))` and say the strict entries are `(t1: padded(>lo1))`, `(t1: padded(==lo1), t2: padded(>lo2))`.

### FIXIND-2 CONFIRMED (doc/design consistency; effort small; blast radius §2.7 padded paragraph, §2.7 bodies table, §8 anchored paragraph, decision (32), changelog (A)) - the reason given for the group in `padded`'s and `anchored`'s bodies contradicts the document's own hole rule

Under the document's hole semantics the owner's ungrouped `/0*${rx}/` with rx = `/1|2/` already IS `0*(?:1|2)` (accepts `02`); `/0*1|2/` is what a TEXTUAL splice gives, which §2.6 line 846 says only a hand-paster does. Fix: say the `(?:...)` writes out what the hole already means (§3.3), so `/0*${rx}/` and `/0*(?:${rx})/` are one body; drop "without it ... would split" from §2.7, §8 and (32), and drop "RULED as a detail" (nothing deviates from his words).

### FIXIND-3 CONFIRMED (design; effort small; blast radius §2.7 bodies table rows `length`, `month_numbered`, line 1129 "four remain", O67, owner question (9), §11 table line 2440) - two of the four "NOT EXPRESSIBLE" transforms have bodies in the document's own language, with S in a `label:` condition (a filter role)

No compile-time row test is needed: the `label:` condition tests the index at match time (as E-RFC's `(wname.index: ==wd)`).
- `length`: `chars := /(?:(?<ch>(?s:.)))*/`, `nchars := count((ch: /(?s:.)/))` (§4.3 `count`: a canonical numeral, RULED CF:977-978, "tested through a computed label or any ordinary filter", the doc's own `n := count(c)`, `P & (n: ==2)`), body `length(S) := chars & (nchars: S)`. Works for EVERY S (not only finite), S in a filter role; the loop's parse is unique (one character per iteration).
Repro: `$R/fixinduced/bodies_check.py` / `.out` (libpcre2-8 whole match gives the matched entry; count of the unique-parse loop): month_numbered(between(lo, hi)) for 5 (lo, hi) pairs x 34 subjects (abbrevs, full names, `jan`, `Janu`, `Junee`, `Sept`, `JanFeb`, empty, ...): 170 cases, 0 differ from the stated meaning ("Jan" .. "Jun" for between(1, 6); §4.4's `month_numbered(<3)` = `/Jan(uary)?|Feb(ruary)?/`). length(S) for S in {<=20, ==3, even} x 9 subjects (empty, newline, 20/21 chars, ...): 27 cases, 0 differ.
Consequence (not arguing the open question): the premise of O67 / owner question (9) ("five ... cannot be plain macros", "four remain") is overstated; only `any_case` and `json.quoted` (text the match does not yield) survive this check. Caveats to state if adopted: needs two top-level helper bindings (or a binding inside a body, unspecified), `count`'s budget applies to `nchars` (the same cost the primitive would have), and the helper labels `mname`/`ch` are visible (O55's per-call label question).
