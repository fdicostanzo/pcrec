# A. THE ELISION PROOF (§3.2)

## A1 — MAJOR (refutation). Claim A is false as stated, on two artifacts emitted from main.

§3.2 says "the accept probe therefore runs at `scan_position == search_from`
before anything advances… so `last_accept_position = search_from`."

The loop's accept probe is an **axis-E object**, not a fixed slot. `dfa_accs`
(`src/gen/emit_dfa.c:3572-3579`) gives `emit_top` (probe first) only to
`scalar-plain`; `scalar-viewed` supplies `emit_after_view` and `by-class`
supplies neither — both record *below* the scan edges. `emit_scan_loop` calls
them in that order: `:4696` (top), `:4697` (prefilter), `:4699-4703` (skips),
`:4714` (scan edges), `:4715` (view select), `:4716` (after-view probe),
`:4717` (tail). And `acc_viewed_applies` (`:3511`) reads `us->views`, which
`unanch_start` builds as `viewsel || wctx` with
`wctx = fd->clsctx || rd->clsctx` (`:2487-2503`) — an OR over **both** machines,
so a `\b` that exists only in the reverse machine demotes the forward probe.

Two witnesses, both start-accepting (`RX_DFA_PREFILTER "none"`), quoted from the
emitted artifacts:

**(i) `[a-z]{0,8}|9$`** — the loop body *opens* with the scan edge at state 0;
the accept probe is 18 lines later, after the view select:

```c
    for (;;) {
        // [OPT-5] SCAN EDGE: the states between here and state 1 ...
        if (forward_state == 0 && scan_position < subject_length && (unsigned char)(subject[scan_position] - 97) <= 25) {
            unsigned long scan_run_length = 1;
            scan_position++;
            while (scan_position < subject_length && scan_run_length < 8UL
                   && (unsigned char)(subject[scan_position] - 97) <= 25) { scan_position++; scan_run_length++; }
            if (scan_run_length == 8UL) { forward_state = 3; last_accept_position = scan_position; }
            else { last_accept_position = scan_position; }   // the run stopped inside the edge
        }
        rx_forward_state forward_view_state = forward_state;
        if (__builtin_expect(scan_position + 1 >= subject_length, 0) && ...)
            forward_view_state = rx_forward_view_take(...);
        if (rx_forward_accepts(rx_forward_is_accepting, forward_view_state)) last_accept_position = scan_position;
        ...
```

On `"abc"` at `search_from = 0` the edge consumes the run and records
`last_accept_position = 3`; position 0 is never recorded.

**(ii) `a*|\b9`** — the same shape via `wctx` alone (no view select emitted at
all — the machine's only class context comes from `\b`):

```c
    for (;;) {
        // [OPT-5] SCAN EDGE: every state a run of class 3 would pass IS this state ...
        if (forward_state == 0 && scan_position < subject_length && subject[scan_position] == 97) {
            scan_position++;
            while (scan_position < subject_length && subject[scan_position] == 97) scan_position++;
            last_accept_position = scan_position;   // every position the run passed accepts
        }
        if (rx_forward_accepts(rx_forward_is_accepting, forward_state)) last_accept_position = scan_position;
```

For contrast, the plain case the note assumed — `[a-z]{0,64}` — does put the
probe first (`if (rx_forward_accepts(...)) last_accept_position = scan_position;`
as the loop's first statement, with the scan edge below it).

**Consequence.** The *answer* is unaffected: `last_accept_position` is still the
furthest accept, which under Claim B belongs to a thread from `search_from`. But
the sentence the note derives from Claim A — "hence the
`last_accept_position == (size_t)-1` early return is unreachable" — needs a
different argument, and §3.3 and §5.4(6) both rest on it. The repairable form:
*some* accept ≥ `search_from` is always recorded, because the edge and the skips
each record their landing position and the probe records at whatever position
the loop is actually at. The note's citation of `scanedge.c`'s header order is
also misused — that header's own list already names two probe sites ("the accept
probe, … the position-view select, the viewed accept probe"), and which one an
artifact has is the axis-E selection, not a constant.

## A2 — MAJOR (refutation of P3's wording; the kept gate is load-bearing).

P3 says "every **live** seed state satisfies P1 and P2". The *dead* seed state
is exactly the case where Claim A fails.

`d->s1u[u]` can be `-1` (`src/ir/dfa.c:1249-1258`; `make_state` returns `-1` when
no `(view, class-context)` closure is live, `:1113-1116`). `dfa_premul`
(`src/gen/emit_dfa.c:2205-2215`) refuses pre-multiplication *because* of it, and
its comment records the 2026-08-26 sweep finding no negative cell over the 1,256
corpus patterns — a measurement, not a proof, and the transform declines rather
than resting on it.

If a search at `search_from > 0` seeds into a dead state, no accept is recorded,
the kept `last_accept_position == (size_t)-1` gate returns 0, and **that is the
correct answer** — no match begins there. So the gate is not "unreachable"
(§3.3) and not "deliberately dead" (§5.4(6)); on this input it is the only thing
standing between the elision and a fabricated empty match at `search_from`.
Deleting it on the accepted population — which §3.3's own framing invites a
later reader to consider "simplifying" — would be a miscompile in the direction
§3.4(f) says cannot happen (a match reported where there is none, not merely a
`caps[0][0]` that is too small).

**Fix:** P3 must read *every seed state is LIVE and satisfies P1+P2* — i.e. the
predicate declines when any `s1u[u] < 0`. Secondary: the accept probe on a dead
token is already latent UB (`is_accepting[-1]` in the indexed form, `[65535]` in
the premultiplied one — the emitter's own note at `:2205`), so "it records
nothing" cannot be relied on either; declining is the only clean posture.

## A3 — CONFIRMED. No candidate prefilter and no offset-k skip on the accepted population.

`start_acc = state_acc_any(&fd->st[fs])`, OR'd over the seed states
(`src/gen/emit_dfa.c:2542-2547`). The prefilter is gated
`if (!start_acc && o->cand.usable)` (`:2581`), and the offset-k selection rides
that verdict — `if (o->kind != DFA_PF_NONE) pcrec_prefix_ksets(...)` (`:2596`).

P1 (`up[UPC_PLAIN].accept != 0`) implies `state_acc_any` (`:2149-2154`) implies
`start_acc`, so **both are absent by construction** on every artifact the
predicate accepts. Neither a memchr skip, a byte-class bitmap walk, nor an
offset-k reseed can move the scan's entry position. Confirmed empirically:
every pinned probe stamps `RX_DFA_PREFILTER "none"`
(`a*`, `[a-z]{0,64}`, `[a-z]{0,8}|9$`, `a*|\b9`, forced `\Ka*`).

The note's §1.2 blast-radius paragraph is therefore right for a stronger reason
than it gives: it is not that hybrids and pinned artifacts "decline on nearly
the same fact", it is that the *same widened bit* gates both, so the two can
never disagree.

## A4 — CONFIRMED. Stay skips cannot move the entry position either.

`f->nskip = pick_skip_states(d, dir->prefilter_owns_start ? d->s0 : -1, f->skip)`
(`src/gen/emit_dfa.c:4601-4602`), with `prefilter_owns_start = true` on
`dfa_dir_forward` (initializer at `:4080-4092`, the second bool after `reverse`;
field order at `:3107-3128`). So `s0` is excluded from the forward search's skip
set by construction.

Two caveats worth carrying into the implementation:

- The exclusion is `s0` **only**, not the seed states, so a skip *can* fire on
  the first iteration at `search_from > 0` on a seeded machine. Harmless — a
  skip records its landing position and `last_accept` wants the largest — but it
  is a second, independent reason A1's literal claim fails.
- Scan-edge heads are excluded from *nothing*: `dfa_form_derive` takes every
  state with `dfa_edge_taken` (`:4609-4610`), `fs` included. That is exactly
  what the two witnesses in A1 show, and it is where the elision's speed comes
  from — on the acceptance population the edge sits *at* the start state.

## A5 — CONFIRMED. Claim B (no later start is ever live), and C, D, E with it.

**Claim B.** `nfa_wrap_unanchored` (`src/ir/nfa.c:946-955`) sets
`st[sp].t1 = nfa->start` (the pattern) and `st[sp].t2 = any` (the byte
self-loop), so the restart thread is the **lowest**-priority branch of the split.
`closure()` walks the pre-set in priority order and stops the instant an accept
is reached (`src/ir/dfa.c:794`: `if (prune && cl.accept) break;`), and `clo_walk`
discards every deferred branch on accept (`:649-655`:
`if (cl->prune) { cl->ks->n = 0; return; }`).

Under P1+P2 every live `(view, class-context)` closure of `fs` accepts — at most
nine of them, `make_state` at `:1080-1110` — so all of them prune, no restart
thread survives into `fs`'s list, and by induction none reappears downstream
(`any`'s only in-edge is from `sp`). Minimization preserves this: it is a
language-level statement (`L(fs)` = the pattern's own language, un-wrapped), and
`pcrec_minimize_dfa` preserves the language from each state.

**Claim C.** The reverse machine is the **unpruned** reverse language
(`prune = false`, `src/core/compile.c:1103`), hence a superset of the pruned
forward language. Anything the forward loop accepted from `search_from` is
therefore accepted walking back, so the reverse loop — bounded at
`rewind_position > search_from` (`src/gen/emit_dfa.c:4113-4116`) and recording
the furthest-back accept — necessarily lands on `search_from`.

**Claim D.** Both `return 0` paths are accounted for: the `last_accept == -1`
one is reachable only in A2's dead-seed case (where 0 is correct), and the
`match_start_position == -1` one is unreachable by the Claim C argument.

**Claim E.** Confirmed at `src/gen/emit_dfa.c:428-448`: the dead-group
`PCREC_UNSET` fill lives in `emit_search_head`, above both forms, and is gated
`cx->job->fit.chosen == ENGM_DFA && dfa_artifact_ncaps(cx) > 1` so a hybrid's
inlined prefilter never runs it. Neither form touches it.

## A6 — CONFIRMED, with one sentence the note owes.

ENG_UNANCH implies `!nfa_has_bot` (`src/core/compile.c:1096`), i.e. no `N_BOT`,
`N_BOT_M` or `N_GSTART` (`src/ir/nfa.c:990-993`). `s0` is closed with
`bot_ok = true, gst_ok = true` and `s1u[UPC_PLAIN]` with `false, false`
(`src/ir/dfa.c:1249-1258`), so with none of those nodes present the two closures
coincide and intern to the same id — **`fs == s1u[UPC_PLAIN]`**, and
`s1g[] == s1u[]` entry for entry. The predicate reading `fs = fd->s0` is
therefore the right state at `search_from == 0`, P3 covers `search_from > 0`,
and there is no third (`\G`) start family to miss.

The caveat the note should state rather than inherit: `dfa_needs_seed`
(`src/gen/emit_dfa.c:2161-2166`) compares only `s1u[u]` **across `u`** — it
would not notice an `s0 != s1u[PLAIN]` split — and `seed_emit_constant`
(`:3497-3502`) then emits `s0` unconditionally at every `search_from`. Sound
today only because of the routing above.

# B. THE PREDICATE vs M1's CENSUS

## B1 — MAJOR. P5 ("no DFA artifact carries `\K`… free by construction, not by a test") is false.

`emit_unanchored` has two customers; the second is the VM hybrid's inlined
`static <prefix>_prefilter` (`src/gen/emit_dfa.c:1356`, `:4725`, and
`emit_search_head`'s own note at `:438-447`). `\K` forces the *engine* to the VM
— it does not keep the pattern's machine away from this emitter.

Reproducing command and result:

```
$ build/pcrec -p rx --features all -fprefilter -o K3.c -- '\Ka*'
#define RX_ENGINE          "vm"
#define RX_DFA_SCAN        "unanchored"
#define RX_DFA_PREFILTER   "none"

    /* State legend -- the shortest input that reaches each state:
     *    0  (start) nothing consumed yet   ACCEPTING
     *       scan edge: any run of class 1 stays here            */
    static const unsigned char rx_forward_is_accepting[2] = { 1, 1 };
```

A `\K` pattern whose hybrid prefilter is a one-state start-accepting machine —
the STEP 2 predicate accepts it (P1 ✓, P2 ✓, P4 ✓, P3 n/a).

It is **not** a miscompile. The emitted `rx_search_run` consumes the span as a
bound, not an answer:

```c
        if (rx_prefilter(subject, subject_length, search_from, window) != 1) return 0;
        attempt_position = (size_t)window[0][0];
        window_end = (size_t)window[0][1] < subject_length ? (size_t)window[0][1] : subject_length;
```

`window[0][0]` is a lower bound on the attempt start and `search_from` is the
strongest sound lower bound; `window[0][1]` is unchanged by the elision. So the
answer is safe — but the note's *reason* is wrong, and structural check §5.4(5)
as written ("no DFA artifact carries the construct") will either fire on this
artifact or pass vacuously. Reword to the engine-level fact
(`fit.chosen == ENGM_DFA`) and give the hybrid its own bound-not-answer
sentence.

## B2 — MAJOR (K35). "N_hybrid_pinned ≈ 0" is a default-axis fact, not a population.

M1's census ran default flags, and §1.2/§5.2 read its 0 as the population.
`pfc_prefilter_forced` (`src/core/compile.c:1060-1063`) lets `-fprefilter`
build a prefilter whose collapsed language is nullable — do-or-die overrides the
`prefilter_lang_nullable` decline, and the comment at `:1051-1059` says so
explicitly. A nullable prefilter language is precisely the pinned shape, as B1
demonstrates.

`make test-axes` (`Makefile:1138-1140`) runs `tests/axes/run_axes.sh`, which
derives its sweep from the `PCREC_(NO|FORCE)_*` bits — so `-fprefilter` is
inside the gate's own population, on a corpus that contains both `\K` patterns
and nullable patterns. **Count `N_hybrid_pinned` under the force axis** before
§5.2's "expected ~0" is written as an assertion; a check whose expected value
was measured on a narrower axis than it runs on is the K35 shape.

## B3 — no witness found for "passes the predicate and still needs its reverse pass".

For a pure-DFA artifact A5 closes it. For a hybrid the reverse pass's output is a
bound and `search_from` is the strongest sound bound, so eliding is if anything
more conservative than today. I could not construct a counter-example and do not
believe one exists under P1–P5 as repaired by A2.

## B4 — MINOR. P2 is stricter than soundness requires, and it costs population.

`member_ok` (`src/opt/scanedge.c:188-194`) refuses any state carrying a view
*variant* at all:

```c
static bool member_ok(const DState *st)
{
    if (st->eolvar >= 0 || st->endvar >= 0) return false;
    for (int u = 1; u < UPC_N; u++)
        if (st->up[u].accept != st->up[0].accept) return false;
    return true;
}
```

The elision needs only the variant's **accept bit** to agree. The variant's state
identity matters to the *step* (`f->src` feeds the transition — `:3596-3600`,
and the emitted `forward_state = rx_forward_step(..., forward_view_state, ...)`),
not to the *origin*; and a variant that accepts pruned its own closure exactly as
the base view did (A5), so Claim B holds for it too. So M1's 47 `view` declines
are not all view-*accept*-dependent, and the accepted population is smaller than
it needs to be.

Lifting `member_ok` to a shared predicate is still the right move
(`pcrec-general-mechanisms-not-special-cases`, and `scanedge.c`'s header already
apologises for the local copy). But the note should record the stricter conjunct
as a deliberate conservative choice with the measurement that would relax it,
rather than presenting it as the exact condition — otherwise the next reader
takes the strictness for a soundness requirement.

## B5 — MINOR. §5.5's size prediction is optimistic, and the obvious cleanup is a separate change.

`f->viewsel` and `f->views` come from the shared `UnanchStart`, whose `eol`,
`endv` and `wctx` are ORs over `fd` **and** `rd`
(`src/gen/emit_dfa.c:2487-2503`). Deleting the reverse machine's *emission*
leaves in place, on the forward machine:

- its view tables — `if (f->viewsel)` in `emit_machine_tables` (`:4646-4656`)
  emits `<M>_eol_view` / `<M>_end_view` for the machine `f` regardless of which
  machine created the flag;
- its demoted (viewed) accept order, i.e. A1's probe-below-the-edge shape.

Narrowing those flags to the forward machine would move the D11 evaluation order
that cost 53 divergences. It must not ride STEP 2 as a size cleanup; if it is
wanted, it is its own change with its own argument. §5.5 should predict the
reverse machine's tables and accessor block only.

## B6 — MINOR. §1.1's "STEP 2's search-side elision rescues exactly those artifacts, for free" is unquantified, and the bench's own exhibit is not among them.

The population is real and identifiable — the counted ladder above the anchored
cap is both pinned and `search-filter`:


# C. THE FAILING-CALL QUESTION (bench exhibit, 2026-09-01)

## C1 — BLOCKER for the candidate fix as phrased.

The fallback body, from `build/pcrec -p rx --features all -fno-anchored-dfa -- 'a*'`:

```c
ptrdiff_t rx_match(const rx_ctx *ctx)
{
    ptrdiff_t capture_spans[RX_NCAPS][2] = {{0}};
    int found = rx_search(ctx->subject, ctx->len, ctx->pos, capture_spans);
    if (found < 0) return (ptrdiff_t)found;
    if (found != 1 || (size_t)capture_spans[0][0] != ctx->pos) return -1;
    return capture_spans[0][1] - capture_spans[0][0];
}
```

"Bound the search at `start == ctx->pos`" has **no cheap sound spelling here**,
because the wrapped machine's state variable cannot distinguish "the thread from
`ctx->pos` is still alive" from "only a fresh thread spawned here is alive" —
they are the *same DFA state*.

Witness, read off the emitted tables for `a*b`:

```
 * State legend -- the shortest input that reaches each state:
 *    0  (start) nothing consumed yet
 *    1  "b"   ACCEPTING
 */
static const unsigned short rx_forward_next_state[6] = { 0, 0, 3, 65535, 65535, 65535 };
                                                          ^     ^
                                              tr[fs]['a'] == fs |  tr[fs]['b'] == state 1
```

Pattern `a*b`, subject `"aab"`, `ctx->pos = 0`, expected `_match == 3`
(PCRE2 matches `"aab"` at 0). The machine sits in the start state at positions
0, 1 and 2 and accepts at 3. **Any bound that stops when the scan is back in the
start state, or when "no candidate can still begin at `ctx->pos`", stops at
position 1 and returns −1** — a lost match, not a slow one.

This is §1.3's own origin-unknowability arriving at a different site: the note
argues in §1.3 that the forward machine cannot name the origin, and the
candidate fix needs exactly that fact. The note's own §1.3 is the argument
against its §1.1 rider.

The two spellings that *are* sound, for the record:

- **(a) truncating `subject_length` to `ctx->pos + MRL`** — UNSOUND on any
  view-bearing artifact: it makes `$`/`\Z`/`\z` true at a fake end. That is the
  slice-vs-window trap `seed_emit_seeded`'s own comment names
  (`src/gen/emit_dfa.c:3475-3482`: "A constant start state encodes exactly one
  answer, 'the context here is the end of the subject', which is the assumption
  a SLICE makes and not the one this API's contract makes").
- **(b) a separate `window_end` parameter** that bounds the scan without moving
  the views — sound in shape (it is exactly what the hybrid already passes to
  `rx_match_anchored(&ctx, run, window_end)`), but it helps only patterns with a
  finite maximum match length, and it still needs care that
  `last_accept_position` may belong to a later origin, so the `caps[0][0] !=
  ctx->pos` filter is still what makes it correct.

## C2 — it is not STEP 2's, and the already-chartered row subsumes it.

`docs/dev/plan.md:1673` — [OPT-VEDGE], chartered 2026-09-01 on Frank's Q4
"agree" — already records the mechanism: relaxing scan-edge precondition (3)
collapses the `\z` skeletons, "AND the anchored machine's state count on those
skeletons drops below PCREC_ANCHORED_MAX_STATES, so the search-filter fallback
band the bench measured at ×37 O(subject) failing-call cost … shrinks by the
same move — one mechanism, two customers."

That route replaces the fallback with `unwrapped` `_match` — the reverse-pass-free
form already battery-proven at `dfd112b` (§1.1's F1) — so it needs **no new
soundness argument at all**, where the bounded fallback needs one it cannot
have. Recommend: no `_match`-side change in STEP 2. Folding one in would also
break §0's acceptance frame for exactly the reason the note itself gives in Q7 —
two families moving on one pin for two different reasons.

## C3 — a real STEP 2 effect at site (a), and it is a different claim from §1.1's.

On the *pinned* population the fallback's failing calls do not get bounded, they
cease to exist: `rx_search` returns 1 with `caps[0][0] == ctx->pos` on every
call, so `_match` never takes the O(subject) path and never returns −1. Worth
stating separately, because it is the half of §1.1 that survives B6 — and
because it is a *behavioural* fact about the fallback that the structural checks
in §5.4 should assert (a pinned artifact's `search-filter` `_match` has an
unreachable `return -1`).

# D. STEP 3's EXCLUSION (§1.3)

## D1 — CONFIRMED, with the witness the note did not have.

"The position of the last visit to `fs` is a **lower bound** on the winning
origin, not the origin" is exactly right, and `a*b` on `"aab"` demonstrates it
from the emitted table in C1: the last `fs` visit is position 2, the leftmost
origin is 0, and no cursor in the loop names 0 after position 0 is passed.

F2 is confirmed in emitted text as well:

- `unsigned long scan_run_length = 1;` is declared **inside** the edge's own `if`
  block (`emit_scan_edge`, `src/gen/emit_dfa.c:4533` region; visible in

- the unbounded edge emits **no counter at all** — `a*|\b9`'s artifact:
  `while (scan_position < subject_length && subject[scan_position] == 97) scan_position++;`

So the plan row's "start = end − count is already in a register at loop exit" is
false of the emitted code in both halves, as the note says.

## D2 — MAJOR (overstatement, and the note contradicts itself).

*"The only sound way to make the origin a single number is to run a machine that
has ONE origin by construction"* is false as stated. Tagged determinization —
Laurikari-style TDFA: a start-position register carried per thread set, with
copy operations attached to transitions — is a standard, sound construction that
tracks the origin **forward** on a multi-origin machine, and it is what
TNFA-based engines use for submatch extraction in one pass.

It is not free: a register copy per transition, and a substantially larger build
— which is precisely the per-step cost STEP 2 exists to remove, and precisely
the reason it should not be built now. **So the note's recommendation (build
start-pinned and nothing else) survives untouched and I endorse it.**

But §1.3's prose says *impossible* while §1.3's own comparison table says STEP 3
is "sound only under a single-live-origin proof" — the table is right and the
prose overstates. Restate it as a **cost** argument with a D77 trigger, not an
impossibility one; otherwise the next reader inherits "forward origin tracking
is unsound" as a settled fact and will not revisit it when STEP 3's
construction-time synthesis changes the economics (fewer states, fewer register
copies, and a machine whose counted regions are single-origin by construction —
which is the case the note's own STEP 3 column is describing).

merely unpopulated in this corpus.

wave-C comment warns about (`src/gen/emit_dfa.c:2536-2540`: "it therefore ships
