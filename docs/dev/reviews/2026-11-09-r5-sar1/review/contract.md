# contract — crit-sar1
## Findings
### CONTRACT-1 CONFIRMED (doc, small) — §2.28¶3's zero-iteration clause is false for `X{0}`
docs/spec/tuning.md §2.28¶3 (new sentence): "a quantifier admitting zero iterations of a body that consumes breaks it". `X{0}` (and `X{0,0}`) admits zero iterations of a consuming body, yet the subject JOINS across it (T2 row 2 at m=0 is the unit, req.c `rr_rep_exact`'s own comment: "`xy(?:ab){0}zw` is `xyzw`").
Repro: `S/build/pcrec --features all --emit-facts --pattern 'xy(?:ab){0}zw'` -> req_whole_run `78797a77` (xyzw), req_landmark_maxoff 0; BASE -> `7a77`, K 2. Same for `{0,0}`. Answers SAME vs pcre2 (qxyzw, xyabzw, xyzxyzw), so the behaviour is sound; the sentence is what is wrong, and it is a caller-observable mover (req_run/K/REQ_HANDOFF) with no spec text.
Fix: "...while the copies a match MAY add beyond them break contiguity, so a quantifier admitting a NONZERO NUMBER of iterations beyond its minimum..." or simply add "(`X{0}` is no copies: `xy(?:ab){0}zw` reports `xyzw`)". Blast radius: one spec sentence.

### CONTRACT-2 CONFIRMED (doc; advisory listing, small) — req_pieces' reason precedence is unstated and syntax-dependent; R1 widens it (ruling 2 consequence)
Spec: §4.1.3¶1 orders only token CLASSES (harness, deny, decline, rate); 4.1.2 para 8c (lane/sar1) lists `not-fixed-width` and `over-bound` with no precedence. Code rule (desc.c `pd_dropped`, the walk folding right to left, `acc := X . acc`): the reason written is that of the LEFTMOST sub-expression whose OWN description dropped before it was joined; an over-bound that would only arise by joining onto an already-walled right side is never computed (cat short-circuits on the wall).
Ruling 2's own mover is honest: under -e utf8 `(a.){10}xyz` has 31 lengths and no wall, so `over-bound` is the true and only reason (byte: `one-group`). But siblings (S vs B, 30 cells):
- `(?:a|bc){10}x+` (byte+utf8), `(a.){10}x*` (utf8), `(a.){10}(?:b|cd)*` (utf8), `(?:ab|cde){11}|q*` -> S `decline:over-bound` (B `not-fixed-width`). The variable part makes raising PCREC_MAX_REQ_PIECES useless, so the listed reason is not the one a reader should act on.
- `x+(?:a|bc){10}`, `q*|(?:ab|cde){11}` -> `not-fixed-width`: same parts, other order, other reason.
- `(?:a|bc)` written out 10 times then `x*` -> `not-fixed-width`, while `(?:a|bc){10}x*` -> `over-bound`: one language, two reasons, because `pcrec_pd_pow` computes the power in isolation (a new isolated-drop site; BASE already had it for a wide alternation: `(?:a|bb|...|k{11 letters})x*` -> over-bound on both).
Fix (small, order-free): in `pd_dropped` prefer PD_WALL whenever either side is a wall (`why = (l dropped && l.why==PD_WALL) || (r dropped && r.why==PD_WALL) ? PD_WALL : PD_OVER`), and say in ¶8c "where both apply, `not-fixed-width` is written". Then the reason is a property of the language's parts, not of their spelling. Moves only advisory `why` text, no value.
