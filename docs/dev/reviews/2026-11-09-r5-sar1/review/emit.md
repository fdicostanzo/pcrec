# emit — crit-sar1
## Findings
### EMIT-1 — a repeat that fills the 32-byte run store drops its neighbours' bytes; the literal spelling keeps them (CONFIRMED emission; speed CONFIRMED 6.1x on one case)
- severity: speed (plus a listing/emission inconsistency with the unrolled literal); effort small-medium; blast: every exact or split repeat whose copies reach PCREC_MAX_REQ_RUN_SCAN (32) bytes and that has literal neighbours; file src/facts/req.c rr_cat best/join order (:461-482 in S) as reached from rr_rep_exact/rr_rep_split (:604-628); design §3.1 point 3, §3.4 row `(?:abc){20}`.
- Repro (facts): `S/build/pcrec --features all --emit-facts --pattern 'A{33}x'` lists req_whole_run = 32 x `41`, req_byte 65; the unrolled literal `AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAx` lists `41..4178` (A^31 x), req_byte 120. Same for `A{32}x`, `A{33}xyz`, `(?:abc){12}xyz` (whole_run `abc..ab`, the literal spelling ends `...cxyz`), `x(?:abcd){8}y`, `qA{40}`, `Q(?:ab){20}Z` (whole_run ab^16: both Q and Z gone).
- Mechanism: once the repeat's run is the full 32 bytes, the following join (`rn_app`, head form) is the same 32 bytes truncated, and the tail `A^31 x` only TIES the repeat's best; rn_better keeps the earlier argument, so the repeat's own best wins. A literal is walked one byte at a time from the right, so there the right window wins the same tie. The walk's tie rule thus gives a different answer for a repeat and its unrolled spelling (contradicts rn_better's own comment that "the answer does not depend on traversal order"). Ruling 1 accepted the tie for the two 6-byte cells; this is a different consequence: the rarer neighbour bytes are lost entirely, and req_byte gets commoner.
- Emitted moves (BASE -> SUBJECT, -p rx): `A{33}x` REQ_BYTE 120->65, HANDOFF 33->24; `A{33}xyz` RUN `78797a@2`->`4141414141414141@7`, BYTE 122->65; `qA{40}` WHY dominated->emitted, DFA_PREFILTER memchr->handoff, BYTE 113 (q)->65 (A); `Q(?:ab){20}Z` DFA_SCAN landmark-walk->unanchored, DFA_PREFILTER memchr->handoff, WHY dominated->emitted, RUN `6162@1`->`6162616261626162@7`.
- Speed, measured: `perf stat -e instructions:u`, `taskset -c 7`, 3 repeats each (identical to 6 digits), bench driver iterating rx_search over a 2.4 MB English-letter-frequency text (no match), gcc -O2: `Q(?:ab){20}Z` BASE 806,913 vs SUBJECT 4,960,839 (6.1x more). `qA{40}`, `A{33}xyz` on the same text: within 3% (A is rare there); on a text where A is common the BASE x/q byte would win: SUSPECTED for those.
- Fix shape: on a run that is truncated at the store, prefer the candidate with the lower rate (or keep the tail-anchored window as the literal walk does); or let the tail/join compete by rn_info+rate rather than by argument order.

### EMIT-2 — a newly emitted cube/caseless run displaces a dominated memchr locator on the DFA side; 3.8x-5x more instructions (CONFIRMED)
- severity: speed; effort medium (a pick-row question, not a walk bug); blast: split or `+` repeats of a cube or caseless body between literals, where BASE had no run (`none`/dominated) and the DFA used memchr on a rare outer byte; file: the DFA prefilter pick that reads RX_REQ_WHY/handoff (src/core/findings.c pick rows / emit_dfa.c), reached by req.c rr_rep_split; design §3.3 ("readers whose OUTPUT moves are the pick readers"), §3.7 ("slower only through the pick rows ... each with its own deny").
- Repro (emission): `S/build/pcrec --features all -p rx -o rx.c --pattern 'x(?:a[bc]){2,3}y'` vs the same on B: DFA_PREFILTER memchr->handoff, REQ_WHY dominated->emitted, REQ_RUN none->`6162616279@4/fffefffeff`, REQ_BYTE 120 (x) -> 121 (y), HANDOFF none->3. `x(?i:ab){2,3}y`: memchr->handoff, run none->`4142414279@3/dfdfdfdfff`. `x(?i:ab)+y`: WHY dominated->emitted, run `414279@1/dfdfff`.
- Speed, measured (perf stat -e instructions:u, taskset -c 7, 3 repeats, identical; 2.4 MB English-frequency text, no match, gcc -O2): `x(?:a[bc]){2,3}y` BASE 1,625,115 vs SUBJECT 6,230,759 (3.8x); `x(?i:ab){2,3}y` 1,624,980 vs 8,194,905 (5.0x); `x(?i:ab)+y` 1,624,982 vs 2,115,195 (1.3x).
- Two causes stack: (1) ruling 1's tie (the tail `abab·y` beats the head `x·abab` at equal length, rate not consulted) drops the rare leading `x` and moves req_byte to the commoner `y`; (2) the pick then prefers the emitted run's handoff over the memchr it used when the run was none. (1) is the accepted tie's consequence, reported as such; (2) is the reader not pricing the new run against the locator it replaces.
- Not all split movers lose: `xy(?:ab){2,3}zw` 6.69M->1.11M, `q(?:ab){2,3}z` 6.52M->1.10M, `xy(?:ab){16}zw` 6.69M->4.96M (wins, same text).
