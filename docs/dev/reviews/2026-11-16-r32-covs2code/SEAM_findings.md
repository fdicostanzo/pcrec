# SEAM findings (crit-covs2code)
## Findings
### SEAM-1 CONFIRMED: a legal width refuses the compile at the code-bytes cap; limits.md section 3.12¶4 promises the size-cap ladder and "the compile does not fail"
- severity: answer/contract (a compile the spec says succeeds is refused; the default-width compile of the same pattern succeeds). Effort: small-medium (either route the cover past PCREC_MAX_VM_EMIT_CODE_BYTES into the ladder's engine retry, or have C15 price the cover's code size, or fix the ¶4 text). Blast radius: every cover with k >~ 3,330 under the default code cap, i.e. the top ~19% of the legal width range 1..4095.
- repro (subject build `worktrees/crit-covs2code/build/pcrec`):
  `build/pcrec -p rx --window-search-width=4095 -o a.c --pattern '[0-9a-f]{3400}'` -> rc 1, "pcrec: pattern too large: 510352 bytes of emitted code (limit 500000), which gcc cannot compile in reasonable time. A repeat's body is replicated ... raise --max-emit-code-bytes".
  Same pattern, default width: rc 0, RX_DFA_SCAN "unanchored", 19,831 bytes.
  `{3300}` at 4095: rc 0, cover, 495,234 bytes (warn). `{3000}`: cover, 451,134. `{4095}` at 4095: rc 1 (612,516 code bytes); with `--max-emit-code-bytes=2000000`: rc 0, cover, 612,099 bytes.
- expected (limits.md section 3.12¶4): "a width whose artifact exceeds PCREC_MAX_EMIT_BYTES also runs the engine, through the size-cap ladder (§8.4), stamped size-cap-retry; the compile does not fail." Observed: the cap that binds is the CODE-bytes cap (PCREC_MAX_VM_EMIT_CODE_BYTES, 500,000, limits.def), which the ladder does not catch; ¶4 names the other cap. The cover's code grows ~150 bytes per position (linear; the engine artifact is flat at 19.8 KB), so the two limits DISAGREE: the width's legal range says 4095, the code cap makes ~3,330 the real ceiling, and the refusal's advice never names the width option (lowering it is the obvious fix: the engine compiles).
- seam reading: this is the one bound in the chain that the width's range does not derive from (width <= ANCH-1 <= kit bounds is asserted; width vs code cap is not), so the "legal 1..4095" range is partly unreachable at default caps.

- design root cause: cover_cap.md §11.2 (lines 1239-1244, "A SECOND CLIFF, cap-driven (rev 5.2 FIND-1)") priced only `PCREC_MAX_EMIT_BYTES` (1,000,000) and concluded "no width up to 4095 reaches it ... about 630 KB at 4095"; it never names the 500,000-byte CODE cap `PCREC_MAX_VM_EMIT_CODE_BYTES`, which a cover artifact (almost all code, few tables) reaches first, at ~3,330 positions. The extrapolation itself held (612 KB measured at 4095); the cap it was compared to was the wrong one.

### SEAM-2 CONFIRMED (by derivation + plant set): C15's three kit-bound conjuncts are unreachable, one fact is spelled four times, and the table comment that justifies them is stale
- where: src/gen/known.c:360-361 (`cc_fits`: `k <= MF_WSPAN_POS && k + 1 <= MF_WREACH && k < MF_MAX_FWD`), :351-355 (the seam assertion), :611 (`cover_window`'s internal error), :461-463 (table comment "until the seam carries a counted span the kit's own shape bounds with it").
- derivation: compile.c:2099 and cli/main.c refuse any width outside 1..PCREC_ANCHORED_MAX_STATES-1, limits.h:783 asserts the -D default inside it, so `k <= width <= ANCH-1`; the seam assertion makes ANCH-1 <= MF_WSPAN_POS and ANCH <= MF_WREACH = MF_MAX_FWD. Hence the width conjunct implies all three kit conjuncts at every legal build; `k + 1 <= MF_WREACH` and `k < MF_MAX_FWD` are moreover the SAME fact (memfn.h: `#define MF_MAX_FWD MF_WREACH`). Probe: `[0-9a-f]{4096}`/`{5000}` at width 4095 decline at `anchored-A` (KITPROOF trace), `{4095}` covers: the walk never exceeds ANCH-1, independently of C15.
- no row can witness them: S3223 removes the WHOLE C15 (width and kit conjuncts together); S3266 removes the build assertion; no plant removes a kit conjunct alone, because none could be seen (dead code has no witness; cf. learnings §3 on controls that cannot fire).
- stale text: the table comment says the kit bounds ride "until the seam carries a counted span" -- since MF_SITE_ABI 30 (this subject) it does (mf_wspan.len uint16_t + host lists), so the stated retirement trigger has fired and the conjuncts stayed.
- owner: the ONE mechanism is the seam assertion (build time) + the width's range check (compile time). Proposed: drop the three run-time conjuncts from cc_fits (C15 = the width alone, which is what its `why` `width-limit` already says), keep cover_window's named internal error as the single run-time defect guard, fix the comment. Severity maintenance; effort trivial; blast radius none (route-identical by the derivation; a 0-mover sweep confirms).

- the kit's binding bound for a non-cover run span is now MF_RANK_MAX (32) and MF_MAX_TERM (32): memfn.h:657-664 says a presence RUN span is "refused at its define (window.c run_part_terms)" past them, and memfn.h:290-297 claims "pcrec asserts MF_RANK_MAX >= that bound where it fills the ranking". `grep -rn 'MF_RANK_MAX' src cli lib` in the review tree: ZERO hits. ### SEAM-4 CONFIRMED (by the kit's declared contract in memfn.h + memfn_sites.c; not exercised): the ask's ANSWER depends on the caller's storage size, a non-fact that a text seam cannot carry; the cover ask relies on it
- where: memfn.h mf_rows_need comment ("A text that tests past the minimum is refused at the minimum and answered at the ceiling (where a host's own control reads the over-read)"); src/gen/memfn_sites.c:189 (`PCREC_ROWS_PROOF_CEILING`); known.c:440 (C13 asks at the ceiling), emit_dfa.c:7174/8524/8938/11613 (every other ask at the minimum).
- what: the same statement asked with `proof_cap` = minimum vs ceiling can return -1 vs a class. So mf_ask is not a function of (site, hooks, art) alone: a buffer capacity -- memory management, not a D157 fact -- is an input that selects refuse vs answer. Serialized to text (statement out, counted reply back; plan_as_text_seam), the capacity has no spelling: the reply would just carry its count, and the minimum-cap callers' refusal path ("more rows than the caller's storage holds") disappears. pcrec's cover path is the one that leans on it on purpose (ceiling, so C14's equality sees an over-read as `over@d` rather than C13 `refused`).
- the rest of the seam round-trips: mf_wspan's `set`/`table_ref` and mf_class.proof/proof_n and mf_wreply.plan/plan_term/plan_test are COUNTED lists (len/proof_n/nplan) -> text-able; the hooks carry strings plus two callbacks (`fn_name`, `table_name`) and `u` (a PcrecMfU holding the Ctx) -- callbacks into pcrec, not facts, but naming-only (`cover_fn_name` returns the stored stem: pure of its input) so a text form can carry the resolved names. Pointers that are presumed: none of a kit METHOD; PCREC_ROWS_PROOF_CEILING's comment presumes a kit DEFECT shape (an over-read), which is a control, not a method.
- proposed: state the over-read refusal as a FACT in the reply (e.g. the reply's own `proof_n` > what the statement needs => the host's check, as C14 already does) and let the kit's ask not depend on capacity, or document capacity as a declared non-fact of the in-process binding (plan_as_text seam note). Severity design; effort small (kit + one pcrec line); blast radius every mf_ask caller (five sites). Kit-side change: belongs to the kit's next request, not this landing.

**Under a `-D` (reasoned; no build here: read-only lens):**
- lower PCREC_ANCHORED_MAX_STATES to N >= 34: builds; width range 1..N-1; covers end at k <= N-1. To N <= 33: the build FAILS at limits.h:783 unless PCREC_DEFAULT_WINDOW_SEARCH_WIDTH is also lowered below N (limits.md section 3.12¶3 states it; commit 37f1dbacb's subject says the lowered-ceiling reference builds pass the width -D, and S3266's REACH compile passes both). A coupled pair of -Ds; a derived default `min(32, ANCH-1)` would remove the coupling (design choice, not filed).
- raise PCREC_ANCHORED_MAX_STATES past 4096: the seam assertion fails the build (S3266's REACH reads it at 4097). Held.
- raise/lower PCREC_DEFAULT_WINDOW_SEARCH_WIDTH: within 1..ANCH-1 builds; outside, limits.h:783 fails the build. Raised above ~3,330 the DEFAULT build refuses every cover-shaped pattern of that width at the code cap (SEAM-1 by construction).
- -D PCREC_WSTMT_POS / _REACH: plain `#define` with no `#ifndef` -> a -D is overridden by the header (gcc "redefined" warning only): not a lever, and not in --list-limits. Correct for an internal seam bound, but it means S3261/S3262 can only move it via the construction bounds, as they do.
- -D lowering PCREC_MAX_VM_EMIT_CODE_BYTES (a FLAG_D row): the cover's code ceiling moves down with it; at the run_size_term reference value the cliff in SEAM-1 moves into the populated widths.
- kit-side: lowering MF_WSPAN_POS/MF_WREACH below 4095/4096 fails pcrec's build at the seam assertion (good); lowering MF_RANK_MAX does NOT (SEAM-3).

**Family (standing question 1).** The width limit is a sibling of the SELECTION KNEES that carry their own per-compile option: `PCREC_DEFAULT_UNROLL_K` / `--unroll=N` (same `PCREC_DEFAULT_*` naming, same `cli_int_value` range refusal, cover_cap §11.2.1's own precedent) and `VM_INLINE_CHAIN_MAX_BYTES` / `--vm-entry-shape`, and through those of the `--tune=N` dial family (limits.md §8b: knees the dial sets per position). It has joined the first (limits.def row, FLAG_D, its own anchor section 3.12 per [8b¶1]'s new clause); it has NOT joined the dial, correctly while its default is UNMEASURED. It should join the dial (a §8b row with per-position cells) when §11.4's timing gives an exchange rate. It is ALSO, unacknowledged, a member of the artifact-size family (PCREC_MAX_EMIT_BYTES, PCREC_MAX_VM_EMIT_CODE_BYTES, the size-term ladder): a wider width is a bigger artifact at ~150 B/position, and the size-cap ladder is where that family's members fall back; SEAM-1 is the price of not joining it.

**General form + unlocks (standing question 2).** The general form is a PRICED EXTENT: "how many positions of a fixed-width match the window search proves before the engine takes over", decided per artifact by one cost row (time per position vs code bytes per position), of which today's whole-or-nothing width is the degenerate cell (prove all k or none). D198 (d)'s "kit proves the quick stretch out some distance ... the rest is an engine" is that form; [EARNED-SKIP] is its parked owner. Unlocks, each with its trigger:
1. the width as a `--tune` dial cell (limits.md §8b): trigger = §11.4's night produces a measured slower/faster width boundary.
2. the size-cap ladder gains "decline the cover" as a rung (or C15 prices the cover's code bytes against the code cap): trigger = SEAM-1 now (a legal width refuses a compile); general form = every optional route an artifact takes is a ladder rung when a cap refuses.
3. the no-cliff partial proof (prove first N, engine finishes): trigger = [EARNED-SKIP]'s own (lookaround-as-run landed + a bench cell where the finish is a measurable share).
4. the seam as text (plan-as-text): the counted lists already round-trip; the remaining non-facts are the storage capacity (SEAM-4), the two naming callbacks and the art's levers/target (which a text form must carry as a header): trigger = the first out-of-process planner or a second emitter.
5. one derivation for the four "32"s (PCREC_WSTMT_POS, MF_RANK_MAX, MF_MAX_TERM, WF_LEGACY_POS): trigger = the next raise of any of them (SEAM-3 makes it a build failure instead of a run-time refusal).

**Ranked goals (§0) served in order?** G1 (answers): held on every probe below (all SAME vs libpcre2 10.46), and the width moves only the route. G2 (only predicted movers): at default 32 the width is route-identical (k=32 cover, k=33 engine, as main); not swept here.
