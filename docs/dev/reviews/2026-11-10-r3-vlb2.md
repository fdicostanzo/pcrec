### F1. The per-group width memo is a fixpoint over calls AND references, with cycles; the doc describes neither (accept set, G1; compile-hang risk) — **FIX-NOW (design choice)**
Found by READYW-2, READYR-2, SOUND-1, SOUND-2, PREMISE-8, PREMISE-9. Verified V1.
- The doc says a reference counts "its group's own [cwmin, cwmax]" and that "stage 2 adds" a memo. A referenced group's own body may hold references and calls. libpcre2 10.46 resolves them at both ends:
  - `(a)(\1)(?<=\2)x` ACCEPT (on `aax`, ((0,3),((0,1),(1,2))));
  - `(a\2)?(b)(?<=\1)x` ACCEPT (forward reference inside the referenced group);
  - `(a|\3)(b|\1)(c)(?<=\3)x` ACCEPT (a cycle exists but is not reached).
- libpcre2 refuses (125) reference cycles that are neither "direct" nor "through a call": `(a\2)?(b\1)?(?<=\1)x`, `(a|\2)(b|\1)(?<=\1)x`, `(a(?:\1)?)(?<=\1)x`. The doc's refusal list misses these.
- As written, the memo walks a group with today's `A_BREF` arms ([0, UNBOUNDED]), so it refuses every chained shape libpcre2 accepts. If the walk resolves nested references with no in-progress mark, it recurses forever on `(a|\2)(b|\1)` (pcrec compiles that pattern today). A zero-filled memo instead reads [0,0]: an under-estimate that drops candidate starts, a silent miscompile.
- Proposed text: one fixpoint over GROUP NUMBERS, edges = calls and references on the width path, started at UNBOUNDED and iterated down as callgraph's cwmax already is. A cycle saturates to UNBOUNDED and refuses with err 125's shape-7 sentence. "Recursive group", "self-reference" and "reference to an unbounded group" then stop being separate rules (G3). Cite `possessify.c`'s `PossCap` (per-group-number index, BUSY state on a reference cycle, `PCREC_MAX_POSS_REF_DEPTH`) as the house precedent, or make the memo a column of callgraph's table widened to every referenced group (PREMISE-9). Key it by group number and build it over the FINAL tree at postresolve: altcls rebuilds `A_CAP` nodes after the parse hook (PREMISE-6, V12). Add the cells above to the table.
