### SOUND-1 — CONFIRMED (structural) — a kind-AMBIGUOUS template pair: SPAN "init only" and LSET "assign" print the SAME bytes, so a site can call the wrong builder and E1/RT cannot see it
- Design: §"Why kind can no longer be wrong" ("If it calls the wrong one, the program it emits is a different program. For (a) that is a red identity diff"), Disposition SOUND-1, kind table rows SPAN / LSET, M-table (no row), RT (0n).
- Review tree: `src/gen/emit_vm.c:5159` (`lazy0`, typed SPAN init_only by rev 3) and `emit_vm.c:5221` (`resume`, typed LSET assign by render_check.py) are the SAME format, `"    %s_span_cursor = scan_position;\n"`.
- Repro (format level): `sound/rc/rc_base.py` = render_check.py + a cross-template pass (every statement's joined text tried against EVERY template): `python3 -I sound/rc/rc_base.py sound/calls_rt.tsv` → `sound/rc/ambig.log`: `AMBIG lazy0 (SPAN,init_only): also matches [('LSET','assign')]` and the mirror for `resume`. These are the ONLY two cross-kind collisions among the 91 template statements.
- Repro (artifact): `cells/C5b.c` (C5b, `^(?:.*?x|y)(z)`, `--features all`): line 281 (`rx_span_cursor = scan_position;` after L4, from 5159 = the SPAN opener) and line 289 (the same bytes after resume label L9, from 5221) are byte-identical statements with different rev-3 kinds.
- Why it matters: SPAN carries `opens(id)` (FIRST+ adds the class and opens the group; rule 3), LSET is "continue iff non-effect", never a group opener. Rev 3's whole SOUND-1 fix is "5159 is a SPAN record, same bytes" — i.e. the fix is ONLY the site's choice of builder, and the text cannot witness the choice: E1 (byte identity) is green either way, and RT ("parses each record's rendered bytes into kind") cannot recover which kind printed the line, so RT's "two-way triage" has nothing to disagree about. The design's sentence "the only judgement a site makes is WHICH builder it calls ... a different program" is false for this pair.
- Mis-typing table: no M row covers "SPAN init-only built as LSET" (r8 SOUND-1's own shape) or "LSET built as SPAN init-only" (5221 opening a fresh group on the RESUME path, where the walk reaches L9 via PUSH(SPAN id) — an extra opener on a resumed path). C5b's sabotage tests "member without opener", not the builder choice at 5159.
- Answer impact today: none found (rule 3's OPAQUE default makes the "LSET at 5159" mis-typing fail safe; the mirror adds the class to F, the safe direction for D, as the design's bullet 3 says). No rule-as-written twin moves an answer, so severity is design/check, not answer.
- Fix (small): give the two spellings DIFFERENT renderer identity in the checks: an M-row "5159 built as LSET / 5221 built as SPAN" whose detector is NOT the text (e.g. the record dump `--harness=stmt-records` compared against a pinned per-site kind list for C5b/C5c, or an assertion in VM_SPAN that `opens(id)` is fresh and VM_LSET refusing the span cursor as target, making the span cursor writable ONLY by SPAN/its members). Also state in render_check that a template set must be checked pairwise for collisions (my 2-line extension).
- Blocks: not (a) (bytes identical either way); must be fixed before (c) 2b (D reads `opens`).

### SOUND-3 — CONFIRMED (rules as written; no current kit text) — R3 and R1 are token-shape rules, not the classes they claim: writes and exits that are not spelled `name op=`/`++name`/`&name`/a listed keyword lex CLEAN, and R4 does not cover unprefixed callees at all
- Design: §"The lexer", R1 ("no noreturn call (`abort`, `exit`, `_Exit`, `quick_exit`, `__builtin_trap`, `__builtin_unreachable`)"; "rules come from C's own classes"), R3 ("Read means: never followed ... by an assignment operator or ++/--, never preceded by ++/--, never the operand of unary &" and "Calls are then harmless. A helper can see only what it is passed, and it cannot be passed an address of matcher state"), R4 ("Every `<p>_`/`<P>_` identifier ...").
- Repro (rules): `python3 -I sound/lex/r3holes.py` → `sound/lex/r3holes.log`: 15 rows, ALL CLEAN under frag_lex.py (which implements the text of R1-R4): `((scan_position) = 3)`, `(scan_position)++`, `*(slot_values + 2) = 0`, `2[slot_values] = 0`, `(*run).steps_left = 0`, `memset(slot_values, 0, 16)`, `memset(rx_revdet_group_seen, ...)` (an array local decays), `some_helper(run)`, `_mm_storeu_si128((__m128i *)(slot_values + 2), v)` (the `-fmemfn-simd` idiom), an asm output operand `"=r"(scan_position)`, `__builtin_return`, `__builtin_abort`, `__builtin_longjmp`, `siglongjmp`, `#if/#endif`; plus (appended to the log) a write through a pointer local declared from a scope name inside a statement expression, `({ ptrdiff_t *q_ = slot_values; q_[2] = 0; 1; })` (CLEAN; the `run` twin is refused only because its type name `rx_run_state` trips R4, which `__typeof__(run)` would not).
- A REGISTRY helper the design lists as PURE has an out-parameter: `<p>_decode(const unsigned char *s, size_t end, size_t p, unsigned *cp)` (e.g. `sound/census2/k11.c:166`, written for every `-e utf8` WCLASS). `(rx_decode(subject, subject_length, scan_position, (unsigned *)(slot_values + 3)) != 0)` lexes CLEAN (appended to `r3holes.log`): R4 passes it (registry "pure"), R3 sees `slot_values` followed by `+`. "Pure" must mean "writes only through arguments that are block locals of the window", and the registry's purity column must say which parameters are outputs.
- The claim "it cannot be passed an address of matcher state" is false in the artifact's own scope: `slot_values` (`ptrdiff_t *const`), `run`, `ctx`, `subject` and the `revdet_group_*` arrays ARE addresses; passing them is a "read" under R3, and an unprefixed callee (libc, a builtin, an intrinsic) is outside R4. Today's kit text already relies on this unstated allowlist: `!memcmp(subject + scan_position, "ab", N)` (kit_census.log shape 10) is clean only because nobody checks `memcmp`.
- Twin (shows the clean text is a real write that changes the answer; NOT a stock answer change, since no kit emits it): `sound/twin/C8_twin.c` = C8's artifact (`^(a)b+c`, `--features all`) with the kit span window's while condition extended by `&& (__builtin_memset(slot_values + 2, 0xff, 2 * sizeof *slot_values) != 0)` (diff `sound/twin/C8_twin.diff`). frag_lex on the twin window: CLEAN. Run (`ev/run.sh`, drv.c): twin `abbc` → `0:0,4 1:-1,-1`, `abc` → `0:0,3 1:-1,-1`; base and libpcre2 → `1:0,1` both.
- R1's confinement premise ("no loop or switch of the matcher body encloses a fragment, so C itself confines `break`/`continue`") is false at the level C applies it: every renderer macro is a `do { ... } while (0)` (`RX_SET`, `RX_TRAIL`, `RX_PUSH`, `RX_CALL`, `RX_CUT`, `RX_CHARGE_WORK`, `RX_TRAIL_CHECK`; `sound/cells/C6.c:117-199`), so a SET source, a WORK count or a PUSH position IS enclosed by a loop, and a `continue`/`break` there (GNU statement expression) would leave the macro half-run (e.g. skip `slot_values[s] = v` after `RX_TRAIL`, or skip the `R_WORK` exit). Today those operands are pcrec's typed pieces and the lexed classes (kit windows, CLS pieces) never sit inside a macro argument or another window's loop, so nothing is reachable; but the allowance rests on an unstated layout fact. Cheaper rule: refuse `break`/`continue`/`case`/`default` unless the window itself opened the enclosing `for`/`while`/`do`/`switch` (a brace-depth count in the lexer).
- Severity: design (the rule is the ONLY guard for kit text, and from (c) it is what makes a function V0). Fix: state R3/R4 as an ALLOWLIST over the window's whole token stream, not a denylist over shapes: (i) every identifier is a scope name, a declared block local of the window (`it_`, `lim_`), a registry helper, or one of a declared list of unprefixed PURE callees (`memcmp`, `memchr`, the `__builtin_ctz*` family, the named load intrinsics) — anything else refuses; (ii) a scope name may appear only as the head of an rvalue chain whose next token is a binary/relational operator, `)`, `]`, `,`, `?`, `:` or `[`-then-index, and a pointer-typed scope name may appear only under `[..]`/`+`/`-` inside an argument of a registry or pure-list callee; (iii) refuse `*`-deref and `=` anywhere outside a declared block local's own declaration/update; (iv) refuse `asm`/`__asm__`, every `__builtin_` not on the pure list, and every preprocessor line except the kit's SIMD guard arms. Add the 15 rows above to FL.
- Blocks: (a)'s FL as written (it would pass a set that does not test the classes); (c)'s V0.

### SOUND-4 — CONFIRMED (structural; no answer) — macro EXITS and the CALLOUT cursor write are in the rendered text but NOT in their kind rows; M10's stated mechanism ("whose row lists the macro's exits") is false for SET, SNAPSHOT, RESTORE, PUSH and CALL
- Design: §"Why kind can no longer be wrong" ("the text's successors are the record's successors; the text's writes are the record's writes (renderer-owned writes are read off the kind row)"); kind table rows SET/SNAPSHOT/RESTORE ("next"), PUSH ("next, L"), CALL ("next ..."), CALLOUT writes ("slot 0 transiently (net none); `run->callee_gave_up`"); M10.
- Text (any VM artifact with these statements, e.g. `sound/cells/C6.c:130-160`, the prologue the renderers' macros expand to): `RX_TRAIL` (inside every `RX_SET`, i.e. SET, SNAPSHOT and RESTORE) has `if (run->trail_depth >= run->trail_cap) return RX_R_FRAMES;`; `RX_PUSH` and `RX_CALL` have `if (run->resume_depth >= run->resume_cap) return RX_R_FRAMES;`. Only WORK and STEP rows list their exit. CALLOUT: review tree `src/gen/emit_vm.c:9141-9143` renders the SUCCESS edge of a consuming callout (`a->u.callout.consume`, emit_vm.c:9055) as `{ scan_position += (size_t)r; goto <p>_L<n>; }` — a CURSOR write absent from the CALLOUT row (BREF and VAR rows do list "cursor (unknown amount)").
- So a control effect (a give-up exit, 5 kinds) and a write (the cursor, CALLOUT) reach the body through renderer text that the record's row does not carry — the exact class the inversion claims impossible. Today's columns are SAFE by luck, not by construction: an exit ends the path with no capture read (liveness and FIRST+ unaffected), FIRST+ is OPAQUE at CALLOUT and its copies column is "kill all". A future column that reads successors or cursor writes (R's write-back placement; the C-move; u3 per-kind attribution) inherits the error.

- Fix (small, table text): add "exit (R_FRAMES, the macro's)" to SET, SNAPSHOT, RESTORE (via RX_TRAIL), PUSH, CALL; add "cursor (unknown amount, SUCCESS edge of a consuming site)" to CALLOUT; make RT's unit half read the macro definitions the prologue writes (or a declared macro-effects table checked against them).
- Blocks: not (a); fix before (b)/(c) consume these columns.

### SOUND-5 — CONFIRMED (structural; check domain) — the respell post-pass is a truncate-and-regrow of the WHOLE body after the last record: final CLS bytes are not any renderer's output, every later record's `at`/`end` is stale, and the final atom/kit spellings are never lexed; nested records (BREF→WORK, BRANCH/GOTO→CHECKPOINT, CONSUME/SPAN→CLS/KIT) have no tiling rule
- Design: §"The one writer, structurally" (tiling: "Assert that the body's uncut length equals the previous record's `end`"); "Moved verbatim: `vm_cls_respell` (the same strstr pass over the body, after the walk and after the tiling check)"; RT (0n: "parses each record's rendered bytes"); E6 ("every record of E1's default population: 0 disagreements"); builder step 5 (lex at render time).
- Review tree: `src/gen/emit_vm.c:1722-1763` — `vm_cls_respell` builds `out` and then `b->len = 0; ... pcrec_sb_puts(b, out);`; called at emit_vm.c:1830 from `vm_cls_tables` (emit_vm.c:14529) AFTER the program is emitted.
- Repro: `$B -p rx --engine=vm -o sound/rs/b.c --pattern '[ac][bd][ce][df][eg][fh][gi][hj][ik][jl][km][ln]\(rx_class_bitmap0'` (12 table classes ≥ `atom_min_sites` 11, clskit.c:128): all 12 CONSUME class reads are rendered as `((\x01q_class_bitmapN[(subject[scan_position]) >> 3] >> ((subject[scan_position]) & 7)) & 1)` (gdb, `sound/rs/gdb.cmd`) and leave the compiler as `(rx_class_atomN(subject[scan_position]))` (b.c:256-289), ~40 bytes shorter each, so from the first read on every record's stored offsets point at the wrong bytes of the final body.
- Consequences as written: (i) "text is rendered from the record" fails for every respelled CLS piece (the atom/kit text is the post-pass's, not a renderer's); (ii) RT, if it reads the final body by record offsets, reports disagreements on every atom-form artifact (E6 false red) — or, if it reads pre-respell text, it never checks the shipped bytes; the design picks neither; (iii) the lexer (step 5) lexes the bitmap spelling and the shipped atom/kit spelling inside kit span windows is never lexed (compare SOUND-2: the census lexed ONLY the shipped spelling). (iv) Tiling cannot see the post-pass by construction (it runs after the last record) and a post-pass that changed anything but the CLS pieces would be invisible.
- Tiling compares LENGTHS, so "a write that reaches the body by any route is an internal error at the next record" (Summary) holds for appends and truncations only: a same-length in-place overwrite (through a cast of `vm_stmt_text()`'s `const char *` view, or `job->vmsb.p`, Job staying a complete type) changes bytes with every length equal. Today's only in-place editors of `vmsb` are the respell's truncate (emit_vm.c:1761-1762) and compile.c's end-of-compile placeholder/layout renders (after the frame); grep of emit_vm.c for `b->p[`, `->len =`, `memcpy(b->p` finds nothing else. Say "appends and truncations", or checksum the text at each record boundary in the test build.
- Pattern-byte safety HELD: the needle is `(\x01q_class_bitmap`, and pattern bytes reach the body only escaped, so a pattern literal `(rx_class_bitmap0[...]...` (87 bytes, exactly the recorded read text) is NOT rewritten (`sound/rs/c.c:292`, memcmp literal intact) and raises no internal error.

Builder step 1's assertion is defined only BETWEEN records; for a nested builder the enclosing record has no `end` yet. Whatever exemption the build picks (skip the check while a record is open; check against the parent's last write) defines a window where a foreign write is attributed to the enclosing record; the design does not state the rule.
- Fix (small): make the respell a RECORD-LEVEL re-render (the CLS piece's renderer reads `clsrd[ci]` in a final re-render pass, or the post-pass rewrites the record list's CLS operands and re-tiles), state that RT and the lexer read the FINAL rendering, and state the nesting rule for tiling (a record stack: a nested builder asserts against the innermost open record's last write; a renderer's own prints advance it).
- Blocks: (a)'s E6 as written (domain unstated); not answers.

### SOUND-6 — CONFIRMED (design; one answer-level reading) — operands the ANALYSES read but the renderer does not PRINT have no detector: E1 and RT read text, the M-table has no row for them, and the SPAN row's "class" lost rev 2's "first-byte" qualifier (a stride-k reading moves an answer)
- Design: §"Why kind can no longer be wrong" (the guarantee is stated for "control text ... printed by the renderer of its kind from the record's operands"); kind table SPAN "(opens id: class, min, stride)" with FIRST+ "F ∪= class"; LABEL `opens(ISLAND id, F, nullable)`; PUSH `D: by site kind`; M-table M1-M15; RT ("parses each record's rendered bytes into kind, successors, writes and reads").
- The gap: rev 3's inversion makes a record agree with its text only for operands that PRINT. A wrong value in any of them leaves C and listing byte-identical (E1 green), and RT cannot recover them from bytes. The M-table rows are all text-visible mis-typings (M1-M4, M7, M9-M14) or lexer rows; none is a wrong non-printing operand. Rule 3's OPAQUE default makes wrong ids and wrong opener PLACEMENT fail safe (I checked: an opener on the wrong LABEL leaves the members OPAQUE; an extra opener only adds bytes), but a first-byte SET that is too small is unsafe.
- Concrete: rev 2's row read "SPAN (group opener: FIRST-BYTE class, min, stride, span id ...)" (vmcons2_report.md:411); rev 3's reads "class". For a stride-k span the class is a SEQUENCE (`vm_span_advance`'s `seq[0..stride-1]`, emit_vm.c:4784-4800), and "F ∪= class" has three readings: seq[0] (correct), the union (safe), any other position (unsafe).
- Rule-as-written twin (reading "class" = the span's last position, stride 2): pattern `^(?:((?:ab)+)c|bd)` (default engine, VM; the span is a VMSTRIDE block `subject[rx_span_cursor + 0] == 97 && subject[rx_span_cursor + 1] == 98`, `sound/stride/s.c`). Results (`ev/run.sh`, drv.c): base `abc` → `0:0,3 1:0,2`, `ababc` → `0:0,5 1:0,4`, `bd` → `0:0,2 1:-1,-1`; twin `abc` → NOMATCH, `ababc` → NOMATCH, `bd` same; libpcre2 10.46 equals base on all four (`abd` nomatch everywhere).
- Fix (small): restore "first-byte class (`seq[0]`)" in the SPAN row; and add an M-row class "a non-printing operand wrong" with its detector: every first-byte operand (SPAN, island F, CONSUME lit/class) is DERIVED by the builder from the same value it renders (the CLS piece's `ci`, `seq[0]`, `run[0]`, the trie's root kids), never passed separately, plus a cell per kind where a too-small F turns `-fno-<dispatch>` against default red (C5c/C7a/C7b are the right shape but their sabotages are "contributes nothing", not "contributes the wrong bytes"). PUSH site-kind: derive it from the builder entry point (one PUSH builder per site kind) so it cannot be passed.
- Blocks: (c) 2b (D); not (a).
