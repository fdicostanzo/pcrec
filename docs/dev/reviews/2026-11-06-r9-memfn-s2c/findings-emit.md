## Findings

### EMIT-1 — the recorded dep names only the CANONICAL instance; class instances' timed texts are hashed nowhere in the set
- CONFIRMED (code + output). Severity: answer (for the set: a stale price passes "the hash decides"). Effort: small. Blast: every verify_cmp row whose cls is not the canonical one (settest c1/cn, rc-words w1/w3).
- `slot/est.py:178-185,219-222` (write_draft) records `kit:form.<form>=<FORM hash>` = `mf_form_hash(form)` = the canonical instance, for every row of that form. But the cells time per-class texts (link.py:294-295 checks each cell against its FORMCLS hash). `fx.s --hash`: rc-words w1 0538945cb4a8d9d8, w2 (canon) 8957c3f88142ab53, w3 19e26b4da50a49ec; settest c1 b2abe5278b2f6fa0, c2 (canon) 206d9992b608b279, cn 189186e257d7fbcb. So row `kit.verify_cmp.rc-words.w3.*` records 8957c3f8... (w2's text), not 19e26b4d... (what it timed).
- Failure scenario: a kit change that moves only the w3 text (e.g. rc_width's 8-byte cap or the last word's overlap placement at L >= 17: runcmp.c rc_width) or only cn's (kit_set_test merging ranges): w2's/c2's text and hash stay put, the recorded dep still matches, and check C / a reader keeps the stale w3/cn price.
- Fix: record per-instance `kit:form.<form>.<cls>=<hash>` (or define the id's hash as the fold of ALL its instances' texts, so any instance moving moves `mf_form_hash(id)`). Either needs a span_cards §2.4 / measure_sets §2.4 hunk; the second keeps the dep grammar.

### EMIT-2 — est.py reads a binary nothing builds (`TREE/build/arm_fixtures`), a second hash source beside link.py's
- CONFIRMED (LOUD today). Severity: maintenance, with an answer risk (silent if the binary exists but is stale). Effort: trivial.
- `slot/est.py:179` runs `TREE/build/arm_fixtures --hash`; no make target, no slot script builds it (not in $T/build, $B/build or main's build). Repro: `(cd $R/emit && python3 -I -c "import sys; sys.path.insert(0,'$SLOT'); import est; est.form_hash('walk')")` -> `FileNotFoundError: .../worktrees/crit-memfn-s2c/build/arm_fixtures`. So `est.py draft` crashes at its first form-bearing row.
- The cells are rendered and checked by link.py's OWN fx (`fx_path(rundir)`, built once per rundir and reused while it exists). If someone builds build/arm_fixtures by hand at another time, the recorded deps come from a binary that did not render the timed texts: rc 0, wrong hashes (SILENT-MOVE class). Related: link.py's existence-cached fx goes stale if a rundir is reused across a kit change, and the cell-text check then passes against the same stale binary.
- Fix: est.py uses `link.fx_path(rundir)` and the FORMCLS (per-instance, EMIT-1) hash. link.py should rebuild fx when libpcrec.a is newer, or never reuse it.

### EMIT-3 — settest's class boundary (text compare count) is not the machine cost; c2's instance is the cheapest member shape
- CONFIRMED (codegen at the declared target, gcc -O2 -march=x86-64 -mtune=generic, emit/cls.c, emit/c2.c). Severity: speed / answer-representativeness (c2 = 290 of the RTE verify sites in vcls.out). Effort: small (pick the instance), medium (re-class).
- vcls.py classes sets by kit_set_test's TEXT compare count, and the entry picks `{X,x}` for c2. gcc folds the case pair into ONE compare (`andl $-33; cmpb $88`), the same instruction shape as c1 (`cmpb $47`). The class also holds an inner range ([0-9]: `subl $48; cmpb $9`, one compare), a complement ([^\n]: one `cmpb $10`) and two unrelated singletons ([ax]: two cmpb + sete + or). cn's \w lowers to a branch plus a `btq` bit test, and 3 singletons also lower to a bit test. So c2's cell prices a 2-compare class with a 1-compare instance, and unrelated pairs are under-priced.
- Fix: choose c2's instance as two non-foldable singletons (e.g. `{a,x}`), or split the class by lowering shape (case pair / range / pair). At the least, record that the instance is a lower bound. vcls.py's header claim "[0-9] ... is two compares, the same as {X,x}" holds for the text and fails for the code.

### EMIT-4 — the verify shapes do not reach their forms the way the design and the header say; RUNCMP's row guard re-derives instead of reading
- CONFIRMED (reading). Severity: doc / maintenance (no answer impact today: see PROBED, the texts equal production). Effort: small.
- The span_cards.md §3.2 table says the verify ids are reached at the "window verify step" by "the facts that make T-VERIFY pick it". formhash.c's header says ONE path "reaches the form by the kit's own selection". As built: `settest` calls the leaf `kit_set_test` directly (formhash.c:483-494). That is no site and no selection, its `row` is NULL, so its row guard checks nothing. `rc-*` render through the COMPOSER's EXPR/VERIFY/BOOL site, not the window's verify step (wf_test_to -> run_cmp_render). Their guard (`*row = run_cmp_row(...)`, formhash.c:478) re-runs rc_row_of after mf_art_end and never checks that the arm that rendered was `runcmp_arm`. The FIND shape does read `art->sites[..].arm->id`, and compose.c's arm table puts ofsskip/precheck arms before runcmp_arm. If an earlier arm ever claimed the site, `--facts` would still say entry runcmp_arm / row words over another arm's text. That is SUSPECTED and unplanted; the hash would move, so it is a mislabel, not a stale price.
- Fix: guard `art->sites[res->handle-1].arm == &runcmp_arm` in the RUNCMP case. State settest as a leaf render with no selection, in the header and in the §3.2 table (the table's "window verify step" row is stale).

### EMIT-5 — PAIR has two production texts; the entry and its dep cover only one
- SUSPECTED (texts CONFIRMED, cost difference not measured). Severity: speed (minor). Effort: small to confirm.
- `[Xx]` (E-find, window statement expression) equals the `pair` entry byte for byte modulo the prefix (python compare, emit/s/xx.c). `[Xx]abc` (and `[Xx]a+b`, `a[Xx]`) reach PAIR through B-fn, the offset-skip function `rx_mf1_ofsskip__body`: the same two memchr streams, but its own loop control (`while (pos + 3 < n)`, return on verify, `pos = cand + 1`) and its own `wa/wb = 128` source (ofsskip.c, J1's widths). `kit.find_byte.pair` prices both askers' PAIR, yet `kit:form.pair` hashes only the E-find text, so a B-fn-only change moves no dep.
- To confirm: time the B-fn PAIR body at the J2p cell's subject next to the entry's, or file it as a second instance (`pair` cls `fn`).

### EMIT-6 — standing questions (design)
- SIBLING OF A FAMILY: yes. The entry table is at least the THIRD declared catalogue of kit site descriptions:
  (1) `tests/memfn/arm_fixtures.c` `fixtures[]` (C5, pinned in tests/memfn/pins/arms.tsv). Its `pf-walk` and `pf-memchr` are the same composer FIND sites as the entries `walk`/`libc`: `pf-memchr` renders the identical `memchr(..., 120, ...); if (!q) return 0;`. Its `run-masked-words`/`run-memcmp8`/`run-overlap*` are the rc-* sites.
  (2) G2's generated window sites (g2_win_gen.c).
  (3) The new entry table.
  Satellites: arm_fixtures' gate cases; the slot's `enter/fixtures.tsv` (pattern-level); and `hash_mode`'s hand lists (`ids[]`, `hash_edits[]`, keyed by id and kept in step with `entries[]` by hand). The composer's `arms[]` and T-CMP's `rows[]` are row tables, not site descriptions (the entries name rows from them).
- GENERAL FORM: one declared SITE CATALOGUE (id, cls, shape, facts, policy, deny, expected row), read through projections. C5 pins digest each entry's parts. Form hashes fold an id's instances. The slot renders cells. run_rows/rows_check runs under MF_TRACE.
- UNLOCKS:
  (a) A per-instance dep for free (EMIT-1). Trigger: the next verify class or form (rc-overlap/rc-bytes, which the census lists).
  (b) A pin and a hash of the same site that can never disagree: C5's pf-walk and form `walk` today are two descriptions of one site under two name sets. Trigger: the first C5 re-pin that touches pf_walk/pf_memchr/runcmp.
  (c) A production differential: a trace that reports each real site's normalized text hash would let vcls classify sites BY HASH (the instance a site's text equals, modulo offsets) instead of re-deriving classes from S2b's sweep fields. It would also catch a B-fn PAIR-style second text (EMIT-5) mechanically. Trigger: the next census refresh, or the first class whose instance turns out unrepresentative (EMIT-3).
