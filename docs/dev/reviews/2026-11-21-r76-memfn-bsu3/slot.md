# CRITIC SLOT: r76 memfn-bsu3

## Findings

### SLOT-1: the K >= 16 SAFETY assert borrows T-vwin's MEASURED row bound, so a permitted re-measure turns valid T-vscan stretches into a compile failure
- CONFIRMED by reading (latent: needs a constant change to fire; no plant run, per brief). Severity: answer-adjacent / maintenance (a hard kit_fail, i.e. the pattern stops compiling at -fmemfn-simd=x86-64-v3). Effort: small (one named constant + 2 _Static_asserts). Blast radius: window.c only, no byte moves.
- Where: memfn/src/window.c:4373 `if (k < WF_VWIN_LO) return kit_fail(art, "... (16 at least)", k);` and :4375 `b = k >= 32 ? 32 : 16`; the constant at :1932 `enum { WF_VWIN_LO = 16, ..., WF_VSCAN_LO = 24, ... }` whose comment (:1927-1931) and design §12 say "a re-measure may RAISE it, never lower it".
- One slot, two owners: the safety floor is a fact of the BLOCK (the smallest B, §4.2/§12 "DERIVED: the level's vector width and its half"), but the code reads it off the T-vwin ROW's measured bound. They coincide today (16). The ruling explicitly allows WF_VWIN_LO to rise (e.g. a C6/Zen 1 run moves T-vwin to 32). Then T-vscan (a different row, k 24..64, bound WF_VSCAN_LO) still selects V for k 24..31, wf_span_v_define reaches vs_w32_block, and the assert refuses k=24..31 with kit_fail "a vector span of 24 positions (16 at least)" - the message even contradicts the check. Expected: k 24..31 renders at B = 16 (sound, §4.2).
- The literal 16 also appears three times beside the constant (the message, `b = ... : 16`, and implicitly `b / 16`).
- Fix: a block constant, e.g. `WF_VBLOCK_MIN = 16` (the smaller B), used by the assert, its message (%u) and the B choice; `_Static_assert(WF_VWIN_LO >= WF_VBLOCK_MIN && WF_VSCAN_LO >= WF_VBLOCK_MIN, ...)` so a re-measure that LOWERS a row bound below safety fails the build, which is what the enum comment's "never lower it" means. The enum comment then drops "ALSO the safety floor".

It names the selector lift (vany.c:189 vany_selector -> kit_selector) and nothing about the level block.
- Consequence: the code now holds the three-member level-block shape the deferral was waiting for: ofsskip.c:743 fn_level_block, vany.c:155 vany_level, window.c:4367 vs_w32_block (each: simd_open(level); include bit; head(s); body; simd_close).
