## Findings

### EMITTED-1 — the TOP set step leaves an EXISTING member's `req_set_maxoff` loose after a meet narrowed it (less informative than the spelled pattern; the compare's one DIFFER row)
- CONFIRMED (value is SOUND, not wrong). Severity: speed (small; facts/K only, no answer risk). Effort: one line + a census. Blast radius: patterns where a guard narrows a position to a byte the set ALREADY holds at a larger offset.
- Site: `src/facts/req.c` `rb_top_set_step` (~1587-1601 at SUBJECT): `if (rb_has(set, b)) continue;` — the step adds absent members only; it never lowers a present member's offset to `run.off + i`. It follows design §14.3 D-3 "CAT-SET, re-spelled" literally ("joins ... at its offset ..., if the set lacks it"), so the gap is in the design, and the census model (which takes the narrowed offset) disagrees: this IS `$K/compare/compare.txt`'s single DIFFER row.
- Repro (`OUT=<lens> $K/cmp.sh base subject P`, byte facts):
  - `[ac][ac](?<=ac)cc`: SUBJECT `req_whole_run 61636363` (exact `accc`), `req_set 97,99`, `req_set_maxoff 97:0,99:2`. BASE `99:2`.
  - `[ac][ac](?<=ac(?=cc))cc` (the corpus row, tests/litscan/spanarms.rxt): the same, `99:2`.
  - Spelled control `accc` (both trees): `req_set_maxoff 97:0,99:1`. Every match of the lookaround pattern holds `c` at offset 1, so `99:1` is the informative value; the subject states `99:2`.
- Expected per the feature's own claim ("fixed bytes NARROW the necessary run/set"): `99:1`. Not a regression against BASE (BASE also `99:2`), but the narrowed run and the set now disagree about where `c` is.
- Fix sketch: `set->off[b] = min(set->off[b], o)` for a present member. CAUTION: that is no longer a no-op without guards in general (a set member's offset can exceed `run.off + i` where the run is a repeat's copy), so it would need its own census of non-lookaround movers; or record the gap as a sound known loss in §14.1 and in the compare's expected-DIFFER list. Also: explain_l1.py never reads DIFFER rows (see EMITTED-3), so this row is unclassified by the instrument.

### EMITTED-2 — a meet-narrowed run LOSES its `run_pin` (and the `run-pinned` DFA prefilter): an unpredicted, less-informative pick move; the third member of a "run walk knows more than the k-set walk" family
- CONFIRMED. Severity: speed (unmeasured direction; a fact is lost) + design. Effort: small to medium (see fix). Blast radius: every pattern where a guard narrows a masked consumed run position to one byte (4 of the 124 lookaround movers in the corpus; any `xy(?=b)[bc]c`-shape in the wild).
- Mechanism: `src/facts/kset.c` `pcrec_run_pin` (:302-345 at SUBJECT) pins ALL-OR-NOTHING over the maximal EXACT stretch of the shipped run around its pick, proved by the k-set walk's singletons (`o->k[ro+i].count == 1 && byte == run byte`). The k-set walk does not see the lookaround's meet, so the narrowed position (k-set `count == 2`) fails the proof; before L1 that position was MASKED, so the stretch stopped short of it and the pin held on the exact part. Narrowing makes the stretch the whole run, the proof fails, and `run_pin` becomes `none`.
- Repro (byte facts and `-p rx` stamps, `$K/pc base|subject --features all ...`):
  | pattern | BASE run / run_pin / RX_DFA_PREFILTER | SUBJECT run / run_pin / RX_DFA_PREFILTER |
  |---|---|---|
  | `xy(?=bc)[bc]c` | `78796263/fffffeff` / `0:0+2` / `run-pinned` (offsets `0*,1`) | `78796263` / `none` / `handoff` (offsets `none`; also `RX_VM_RESEED` adaptive→adaptive-dense, `reseed_steps 64→1024, block 0→64`) |
  | `ab[xy][xy](?=(?<=xx)y)[xy]` | `6162787878/fffffefefe` / `0:0+2` / `run-pinned` | `6162787879` / `none` / `offset-set` |
  | `[ac][ac]cc(?<=acc)(?<=cc)d` | masked / `2:2+3` / offset-set | `/fdffffffff` / `none` / offset-set |
  | `[ac][ac](?<=ac(?=cc))cc` | masked / `2:2+2` / offset-set | exact `61636363` / `none` / offset-set |
  | `xy(?=b)[bc]c` (own) | masked / `0:0+2` | exact `78796263` / `none` |
  Control: the spelled `xyb(?=c)c` and `xybc(?=q)` keep `run_pin 0` on both trees (the k-set walk proves an exact spelled run).
- Not predicted: design §14.2's L1 column and §14.4 L1's expected movers list `req_whole_run/req_set/req_byte/req_set_maxoff/why` and `RX_REQ_RUN/RX_REQ_BYTE` only; neither `run_pin` nor `RX_DFA_PREFILTER`/`RX_VM_RESEED` is named. The design ALREADY knows this mechanism for L2 (§14.1 table A5 / line ~773: "an extended run loses its pin ... Fix: `pcrec_run_pin` reads `cons` ... so the pin and the `run-pinned` prefilter stay"), i.e. it treats losing the pin as a defect to fix, but did not see that L1's narrowing trips it too.
- SIBLING OF A FAMILY (emitted side): this is the THIRD case of "the run walk states more than the k-set walk can prove, so the pin's proof fails": (1) R-38 K38-2's clip to the walk's reach (`nwalk`), (2) §14.1 A5's AHEAD extension at L2 (fix-by-`cons` planned), (3) L1's meet narrowing (this). The general form is ONE rule for the pin: prove the stretch against the run walk's own exact positions (or have the k-set walk read the same meets), or at least fall back to the longest k-set-proved sub-stretch instead of all-or-nothing; not a third per-case patch. The TABLE lens owns the general form; flagged here as the emitted sibling.
- What would settle "worse": a bench cell for `run-pinned` vs `handoff`/`offset-set` on these shapes (no timing run made here, box rules).

### EMITTED-3 — the instrument: `explain_l1.py`'s `rep-copy` test is VACUOUS for dead-only rows, it never reads DIFFER rows, and `compare_l1.py`'s "agreeing" verdict ignores `run_pin`/`req_landmark_maxoff`
- CONFIRMED. Severity: maintenance (check design, learnings §3: a test that cannot fail on its population). Effort: small. Blast radius: the L1 gate's verdict and every later unit that reuses the two scripts (L3's census reuses the L1 model).
- (a) `rep-copy` vacuous for dead-only movers. `explain_l1.py` :116-120 accepts a row when `vals(restore=rep) == vals(restore=rep+look)`; `vals` reads the VALUE column only, and a dead-only mover moves only the WHY column. So any dead-only row with a lookaround that is not a `(*pla:`-style spelling passes, with or without a repeat. Repro: a fake compare file with the row `  OBSERVED-ONLY probe:1 (?x) (?=a) x observed=dead byte-facts=req_whole_run (abstained)` (no repeat at all; the census model abstains on `(?x)`; SUBJECT lists `dead`, BASE not), then `python3 -I .../explain_l1.py FAKE base/build/pcrec subject/build/pcrec subject/build/pcrec-harness OUT` prints `rep-copy probe:1 (?x) (?=a) x`. An UNSOUND `dead` on such a pattern would be classified the same way. On THIS population the three dead-only rows it labels (`((?=a))x+\1x`, `((?=a))x++\1x`, `\s+(?<=a)b`) do hold: I checked that under `--harness=restore=rep` their why is no longer `dead` (the dead needs the repeat's copy) and that the dead is true (contradiction by hand). So no hidden wrong mover here, but the class proves nothing for that shape. Fix: for dead rows, test the why (`dead` under `restore=look` absent AND under `restore=rep` absent), and require the text to contain a counted/variable repeat.
- (b) DIFFER, MODEL-ONLY and ASYMMETRIC rows are never read: explain's regex (:81) takes `OBSERVED-ONLY|UTF8-ONLY` only, so its "every row explained" rc 0 is silent on the compare's single DIFFER row (`[ac][ac](?<=ac(?=cc))cc`, EMITTED-1). Fix: classify or explicitly list DIFFER rows (here: "design D-3 'if the set lacks it' vs the model's min").
- (c) `compare_l1.py` `obs_byte_set` (:84-96) reduces a mover to `dead` + `WATCH` (`req_whole_run, req_set, req_set_maxoff, req_byte`), and the `both, agreeing` verdict compares only that; `run_pin` and `req_landmark_maxoff` moves are in `rec["moved"]` but never judged. So `xy(?=bc)[bc]c` and `ab[xy][xy](?=(?<=xx)y)[xy]` count among the 61 "agreeing" rows while their `run_pin` was lost (EMITTED-2). The design's own observed-fact list (§14.4 L1 Census) has the same omission. Fix: add `run_pin` and `req_landmark_maxoff` to the judged facts (a lost/raised one is a DIFFER unless predicted).
- (d) the `leaf-dead` class does not check that `dead` is TRUE (only that it is not the look arm's). I checked it by oracle: the 192 non-lookaround dead rows (corpus + bench:377), libpcre2-8 on a subject of all 256 bytes: 106 `N` (no match anywhere), 0 matches, 86 the oracle's own `unknown property` (Age/Block names its build lacks). Holds; a mechanical oracle row in the class would make it a check.

### EMITTED-4 — the "no abi event; only `RX_REQ_RUN`/`RX_REQ_BYTE` move" statement is too narrow: eight more per-pattern stamps and whole route templates move (none of it scaffolding)
- CONFIRMED (doc). Severity: doc. Effort: trivial (one sentence in span_arms §14.4 L1 "abi" and the design's mover list). Blast radius: anyone reading the gate's verdict or reusing the list for L3/L2.
- Over the 124 lookaround movers (248 compiles, `-p rx --features all`, BASE vs SUBJECT), 17 `.c` files move; the moved `#define`s are `RX_REQ_RUN`, `RX_REQ_BYTE` AND `RX_REQ_WHY` (none→dominated/emitted on 7), `RX_REQ_HANDOFF` (`\w{1,3}(?<=a)b` 3→2; `[a-]{1,3}(?<=a|bc)\b` none→2; `\b(?=a)\w+\b` none→0), `RX_DFA_PREFILTER` (run-pinned→handoff, run-pinned→offset-set, byte-class-bounded→handoff), `RX_DFA_PREFILTER_OFFSETS`, `RX_DFA_SCAN_EDGE` (bitmap→none), `RX_MEMFN_LIBC`, `RX_RUN_WORDS` (1→0), `RX_VM_RESEED`; 12 of the 17 also move code (scanner bodies, the DFA tables of `\b(?=a)\w+\b` under its new scan edge).
- Why it is NOT an abi event: `git diff --stat 07c840368 40e2e8626 -- src/gen memfn cli lib` is EMPTY, so every emitted byte that moved is printed by an unchanged emitter from a moved fact value (a pick, not scaffolding). The sweeps agree: sweep 1 (the 300 observed movers) .c movers 17/300 = exactly the value movers; sweep 2 (300 lookaround NON-movers, 274 reached, 26 refused on both) 0 movers on c-default, c-vm and facts. So the subject's "no scaffolding moves" HOLDS; only the enumeration ("only per-pattern stamp values (`RX_REQ_RUN`, `RX_REQ_BYTE`) and run text", §14.4 L1 abi) is incomplete, and with it the expected-mover list the census was told to watch (EMITTED-2/3 (c) are where that bites: the `RX_DFA_PREFILTER` moves come from the lost `run_pin`).
- Several of these moves are GAINS the design did not list either (new handoff/landmark on `\b(?=a)\w+\b`, `[a-]{1,3}(?<=a|bc)\b`, `(?=a(b)?)\w\1?`; `req_byte` none→97 on five `\w`-class rows via the rep-copy meet).
- EMITTED-2 addendum (own population): over 200 constructed `HEAD LOOK TAIL` patterns (seed 55; 400 facts calls), `run_pin` is LOST on 16 (BASE pinned, SUBJECT `none`), every one a literal head followed by a lookahead that narrows the next class, e.g. `foo(?=b)[bc]{2,4}` (BASE `run_pin 0:0+3`, `run-pinned-bounded` → SUBJECT `none`, `handoff`), `xy(?=bcd)[a-z]{3}` (`0:0+2`, `run-pinned`, `RX_VM_RESEED adaptive` → `none`, `handoff`, `adaptive-dense`), `abc(?=b.)[bc]+d` (`0:0+3`, `run-pinned` → `none`, `offset-set`).
