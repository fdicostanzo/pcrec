**Syntax settled (manager, under Frank's 14:5x delegation):**
- B1 numbered group: **`(?<3>…)`**, named-and-numbered **`(?<name=3>…)`**
  (one bracket, one dispatch point after `(?<`; both invalid in PCRE2
  today).
- B2 scope prefix: **`(?&^.name)`** — `^` is "one scope up", a path
  segment that is not a name character so it can never collide with a
  call-site name; `^.^.name` composes; downward paths are the delivered
  call sites' member names (`(?&from.local)`). The "reads as an anchor"
  objection is noted and outweighed by collision-freedom.
- B3 delivering call: **`(?&from=email)`**, default-named **`(?&=email)`**
  — `=` makes the call delivering, the name to its left is the member.
  The brief's own leading shape `(?<from>&email)` is DISQUALIFIED by
  measurement: it is a legal PCRE2 named group matching the literal
  `&email` (both oracles, (0,6)). The lane's catch, recorded here so it
  is never re-proposed.
- Serialization: **`--emit-composed`**.
- A definition's own wrapper is NOT a capture slot (a callable body; no
  struct member); the harness's textual control therefore agrees with
  the composer up to a DERIVED offset reported by the composer's closure
  — a closure-size mismatch is a failure in its own right.
- Q7 (the oracle control no longer covers absolute refs / colliding
  names): ACCEPTED for W1 with the named trigger (the first [LIB] entry
  that needs either); `--emit-composed`'s round trip + the hand-verified
  M1/M2 cells are the interim control; measure the uncovered population
  at the store's first ten entries.
