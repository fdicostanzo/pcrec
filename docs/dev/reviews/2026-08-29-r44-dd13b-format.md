## Frank's rulings during the panel

- **Spelling and syntax details are the manager's decision** (14:5x);
  Frank rules semantics and the §7 questions. D-e (`analysis freq
  <name>`) ACCEPTED by the manager on the grammar-ambiguity argument.
- **Q1 is answered the OTHER way — a `description` is a FIELD, not a
  comment** (15:0x): "consider we may want to summarize via script what a
  library or other rxt file has: therefore a description may be helpful
  outside of comments, which should be operational." So the format
  carries machine-readable prose: a `description` line kind at FILE
  level (head), per DEFINITION/TARGET, and per BLOCK (and per data
  block), readable by a summarizing script (a library's index, a
  sub-bench's objective); `#` comments are for operational notes only.
  Spelling (manager): `description <text>`, one line, REPEATABLE within
  a scope — repeated lines concatenate with a single space — which keeps
  §1.2's line-oriented property while allowing a paragraph. The bench's
  `objective`/`description` sidecar fields map onto it (§4.5); the
  one-token `tag objective=…` stays for the machine key. The note's
  §7 Q1 recommendation is overturned; NOTES.md is no longer the
  prose's home.
