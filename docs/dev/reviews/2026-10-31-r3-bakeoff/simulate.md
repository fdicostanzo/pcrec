# SIM findings: bakeoff (pricing_bakeoff.md @ a7b229f3f)
## Findings
### SIM-1 The census walk, as written, would point L-ROW at rows whose predicates are only sound because of table order (`memchr-bounded` -> `memchr`, `exact`/`clamped` -> `adaptive`): the "no wrongness risk" claim for L-ROW is false
- status: CONFIRMED
- severity: design
- effort: small
- blast radius: the census builds wrong-answer or give-up-moving arms as part of its normal walk. §5.5 makes an answer failure of a pickable arm a HARD STOP, so the bake-off either halts on arms its own walk made, or (where the timed subjects miss the end-of-subject hazard) times an unsound arm as if it were a valid strategy.
- where: §3.4 L-ROW ("Why it carries no wrongness risk ... It can only do what a flag deny does"); §3.1 item 1 ("for every slot on the observed path whose row is not the slot's fallback, add a compile with that row denied ... by the test-only row deny of §3.4 otherwise"); review tree `src/gen/emit_dfa.c:6599-6609`, `:4603-4605`, `:4664-4668`, `:10430-10447` (the RETRY comment), rows at `:10391-10412` (NEXT) and `:10449-10489` (RETRY).
- finding: the walk only works because a flag deny only ever removes rows whose deny bits were placed on purpose. A deny by NAME can drop one row of a pair whose lower row's predicate does not repeat the upper row's condition. (1) `pf_memchr_applies` is `forward && kind == ONE_BYTE`: it does NOT exclude `views`. The `-bounded` row above it adds `&& views`, so on a `views` site BOTH predicates hold. The code says the unbounded loop is wrong there: "a skip may pass a position whose accept was not the one evaluated -> every skip is bounded at n-1" (`:4603-4605`). Denying `NEXT:memchr-bounded` lands `memchr`, the unbounded skip on a site that needs the bound. The same pairing holds for `byte-class-bounded`/`byte-class` and `run-pinned-bounded`/`run-pinned`. The public flags never split those pairs, because both rows carry the same deny bits; L-ROW by name does split them. (2) RETRY `exact`, `clamped` and `retry-anchored` have deny 0 and `.contract = CG_FIXED`. The code calls them "undeniable": "nothing may make an exact-language hybrid's retry adaptive ... a step would carry it stale", and past `clamped` "a give-up can become an answer". None of them is its slot's fallback, so §3.1's walk names them for L-ROW. §3.3 calls them "validity" rows, but §3.1's step and L-ROW's semantics do not exempt them.
- repro: `python3 -I simulate/bin/walk.py` (the §3.1 walk over 35 salted patterns, 20 rwquest + 15 `.rxt`, public flags only, row-deny targets recorded and not compiled) lists these L-ROW targets: `RETRY@vm exact` 6 times, `RETRY@vm clamped` 1 time, `NEXT@dfa byte-class-bounded` 6 times, `NEXT@dfa memchr-bounded` 2 times (out `simulate/w/walk1.jsonl`). Example sites: `POP_EST:(\d{9,})`, `\bid="([^"]+)"`, `a(?J)(?<g>x)(?<g>y)` (VM hybrid, default RETRY `exact`); `[^a]{0,}?(?!a*)-` (RETRY `clamped`); `\b[A-Z]{4,}\b` (an arm on `byte-class-bounded`); `</?([a-z][a-z0-9]*)\b` (an arm on `memchr-bounded`). Read `emit_dfa.c:6599-6609` for the predicates. Expected: every row L-ROW may deny lands on a row that is sound in its place. Observed: by the code's own comments, at least 5 row pairs land on an unsound or contract-moving row.
- proposed fix: L-ROW refuses a row with `.contract` set. Its unit becomes the row's DENY CLASS: denying a `-bounded` row also denies its unbounded twin, exactly as the shared bits do. Alternatively, every L-ROW-reachable landing gets a predicate that repeats the conditions of the rows above it. §3.1's step names "the slot's alternatives", not "every non-fallback row".
### SIM-2 The deny-set walk never reaches a route-pair alternative, so the "route pair" stratum and every site whose arms differ only in engine are empty
- status: CONFIRMED
- severity: design
- effort: small
- blast radius: the backend level's argmin over paths (§6.2) never sees the route pair as a choice. The §7.3 "engine route" stratum and the non-goal's promise ("sites where the route pair is a live choice are timed and reported as their own stratum") get no sites. A placement whose advantage lies in route pricing ([SEL-COST]) is graded on a population that lacks such sites.
- where: §3.1 item 1 (the walk adds compiles only by denying `cand_rows[]` rows on the observed path); §3.1's qualification text and §3.3 (route pair listed as priced, forceable by `--engine=vm`, `-fno-prefilter`, `-fprefilter`).
- finding: the route pair is not a `cand_rows[]` slot. Its levers are FORCES (`--engine=vm`, `--engine=dfa`, `-fprefilter`) or an admission deny (`-fno-prefilter`) that is no row's `c.deny`. The walk's only step is "deny the row on the path", so it never emits any of them. "Denies compose, so the walk reaches every path first-match can reach under some deny set" is true only of row denies.
- repro: in the 35-pattern walk (`simulate/w/o1/walk.json`), 71 arms, 0 patterns had arms differing in `RX_ENGINE`, `RX_VM_PREFILTER` or the CANDPATH route pair. Yet `POP_EST:(\d{9,})` (default `ENGINE dfa`) compiles at `--engine=vm` to `ENGINE vm`, `VM_PREFILTER none`, `VM_START_SCAN first-class`. `(?<=^|\W)\w+(?=\W|$)` (default `vm`/`hybrid`) compiles at `-fno-prefilter` to `vm`/`none`. Both are valid route-pair arms that the walk never builds.
- proposed fix: seed the walk with every route-pair lever as a first-level arm (`--engine=dfa|vm`, `-fno-prefilter`, `--engine=vm -fprefilter`), then run the row walk from each seed.
### SIM-3 "The path" is not one row per slot: one artifact holds several selected rows in the same (slot, route), keyed by asker and hand, and the stamps cannot tell same-token rows apart
- status: CONFIRMED
- severity: design
- effort: small
- blast radius: C-FM ("the simulated FM path equals the default compile's observed path") and the census's "slots in which they differ" have no single-valued label to compare. As written, C-FM either goes red on every handoff/FINISH site or is computed on an ad-hoc projection the prereg does not fix. The stamps alone cannot separate `handoff`/`handoff-attempts`/`handoff-attempts-entry`/`handoff-reentry` (all stamp `handoff`).
- where: words list ("path: ... its row in every slot of `cand_rows[]`"); §3.1 item 2; §6.4 C-FM.
- finding: the trace shows one `CANDROW` record per ask, with an asker field (`pf-of`, `form-fwd`, `scan-state`, `finish-match`, `finish-search`) and a hand field. Different asks of one (slot, route) select different rows in one artifact. NEXT@dfa holds `first-class-bounded` for the forward asks and `next-none` for `scan-state`. Under handoff, NEXT@dfa holds `handoff-reentry` and `memchr`. FINISH@dfa holds `report`, `verify-at`, `prio-const` and `nomatch`, one per hand. The stamp `RX_DFA_PREFILTER` reports a row's `.tok`, which several rows share.
- repro: walk over the 35 patterns: 71 arms, 30 with FINISH@dfa = {report, verify-at}, 33 with FINISH@vm holding two or three rows, and 14 with NEXT@dfa holding two rows (`byte-class-bounded`+`next-none` 6, `handoff-reentry`+`memchr` 4, `first-class-bounded`+`next-none` 2, `first-memchr-bounded`+`handoff-reentry` 1, `memchr-bounded`+`next-none` 1). Example: `build-trace/pcrec -p rx --features all -o b3.c --pattern '\b[A-Z]{4,}\b'` gives `CANDROW NEXT dfa first-class-bounded form-fwd|pf-of|scan-state` and `CANDROW NEXT dfa next-none scan-state` (2 records).
- proposed fix: define the path as the set of (slot, route, asker, hand) -> row records from CANDROW, and C-FM as equality of that set. Use the stamps only as the independent cross-check where a stamp names a unique row.
### SIM-4 The walk enumerates the CROSS PRODUCT of independent slots, including slots the design does not price (RECOVER, FINISH, WINDOW, BOUND), so arm counts multiply past §3.1's prediction and §5.6's sizing
- status: CONFIRMED (the product structure, with public flags only); SUSPECTED (the size once L-ROW exists)
- severity: speed
- effort: small
- blast radius: §5.6's ~9 arms per site and the "all cross-path arms are timed" rule (§3.5) undercount. With L-ROW, typical literal-led real-world sites reach tens of arms, and the cap of 64 starts to bind. Timing cost scales with it, or the cap truncates silently relative to what the rules can pick (UNCOVERED, INCOMPLETE).
- where: §3.1 item 1 ("for every slot on the observed path whose row is not the slot's fallback"), §3.1's prediction ("median 3-5 distinct arms ... p90 about 10"), §3.5 ("Cross-path arms are few ... so all are timed"), §5.6; §3.3 says RECOVER is "a dominance on time; timed only as the dependent slot it is".
- finding: denies compose, so the walk's arm set is the product of each independent slot's reachable rows. RECOVER (`-fno-start-width`, `-fno-start-landing`) doubles every NEXT arm, although the design treats RECOVER as a dependent slot, not a choice. Once L-ROW exists, the walk as written also denies FINISH (`verify-at` -> `search-from`, on 32 (pattern, route) cells), PRESENCE `dominated`/`presence-none` (18 cells), WINDOW, BOUND and LOCATE `empty`. None of these is in §3.1's list of priced slots, and each is another factor.
- repro: walk at cap 64 with public flags only (`simulate/w/o2/walk.json`). `req-[0-9a-f]{8}-(?:[0-9a-f]{4}-){3}[0-9a-f]{12}` (rwquest L11) gives 10 distinct arms = {run-pinned, offset-set x2 handoff states, handoff, memchr} x {end-minus-width, reverse-pass}. `a(?J)(?<g>x)(?<g>y)` gives 8 = 4 NEXT x 2 RECOVER. That is already the predicted p90 before any L-ROW row. The same walk records L-ROW targets in FINISH on 34/34 compiling patterns, PRESENCE on 18/35, LOCATE `cover`/`empty` on 5/35 (`simulate/w/walk1.jsonl`), each an independent factor.
- proposed fix: restrict the walk's step to the priced slots (§3.1's own list). Reach dependent slots (RECOVER, FINISH) only as the default of the upstream choice, or time them as a separate stratum. Restate the prediction and §5.6 from a dry-run census before the bench sizes the run.

### SIM-7 Row 4's site-count tie precedes row 5, so a large loss concentrated on a few sites (the shape the SRS witnesses show) is read as a TIE, and the 15-site floor leaves the priced options only TIE or INCONCLUSIVE on an H-open of ~110
- status: CONFIRMED
- severity: answer
- effort: small
- blast radius: a placement that loses 1.8x on 5 % of real sites (3.6 pp of mean regret, nearly twice δ) is ruled a numeric tie and handed to architecture, which can then crown it.
- where: §9.3 row 4 ("pick timing-equivalent arms ... on at least 95 % of H sites"), row 5; §7.2 power floor ("fewer than 15 sites"); §3.2 size (H-open ~110); §9.1 item 2.
- finding: row 4 counts SITES and ignores how much is lost on the rest, and it is read before row 5's mean-regret test. With H-open ~110, 5 % is 5.5 sites. So two options that differ on 6 or more sites fail row 4, and §7.2 makes any pair differing on fewer than 15 sites UNDERPOWERED, which never PASSes. Between 6 and 14 differing sites the result is INCONCLUSIVE; at 5 or fewer it is TIE, whatever the size of the loss. A pair can only be separated with at least 15 differing sites (13.6 % of H-open). §9.1 predicts at most 5 % disagreement among A1/HY/Dx, so this design cannot separate them by construction.
- repro: `simulate/bin/verdict.py` S2: A1 loses 80 % on 5 of 110 sites and equals the others elsewhere (mean A1 - Dx = 3.6 pp > δ = 2 pp) gives `row4 TIE (105/110 sites equivalent)`. Arithmetic for the floor: 15/110 = 13.6 % > 5 % = §9.1's predicted maximum disagreement.
- proposed fix: make row 4 a mean-regret equivalence (the paired difference's interval inside ±δ). Add an explicit worst-site guard. State the power target from the predicted disagreement rate: the differing-site count H needs, which sizes J3.
### SIM-8 "Model error" is measured against the per-CELL oracle while every rule picks once per SITE, so it includes a loss no model can remove: row 3 is inflated, and C-SCORE's ORACLE rule cannot score 0
- status: CONFIRMED
- severity: design
- effort: small
- blast radius: row 3 ("improve the model first") fires on loss that comes from the compile-time pick itself, not from the model. C-SCORE, a §8 control, goes red by construction on any site whose best arm differs between cells, which §5.2 says happens by design. Row 0 then reads NO VERDICT.
- where: §6.1 "A pick is a compile-time choice ... one arm per site ... the oracle is per cell"; §5.2 ("a no-search path wins on DENSE cells and loses on MISS cells by construction"); §7.1 decomposition; §8 C-SCORE ("an ORACLE rule (picks the measured best) must score 0 regret exactly"); §9.3 row 3.
- finding: the oracle is the best arm per (site, subject, call shape) cell, but any rule, J included, is one arm per site. Where the best arm varies across a site's cells, even a perfect model has regret > 0. That share is counted as model error. An ORACLE rule bound by the one-pick rule cannot reach 0. If it is not bound by that rule, it is not scored like the others, and the control does not test the join the rules use.
- repro: arithmetic. One site, two cells: no-search arm N = (DENSE 1.0, MISS 3.0), search arm S = (DENSE 1.6, MISS 1.0). Per-cell oracle: N, then S. The best single pick is S, with site regret (0.6 + 0)/2 = 30 %. A perfect model's "model error" is therefore 30 %. Row 3 fires against any placement-loss spread under 10 pp. A site-bound ORACLE rule scores 30 %, not 0, and C-SCORE is red.
- proposed fix: measure model error against the best SINGLE arm per site (per site and subject class under P-SUBJ), report the per-cell-oracle gap separately as the "compile-time choice" loss, and define the C-SCORE ORACLE rule as that site oracle.
### SIM-9 J is the MODEL's optimum, not a measured ceiling: an option can beat J, placement loss can be negative, and row 2's "no placement of it can" is false
- status: CONFIRMED
- severity: design
- effort: small
- blast radius: row 2 can stop the bake-off ("THE MODEL CANNOT BEAT FIRST-MATCH") while a placement such as MN, whose seam ignores the term J mis-prices, beats FM by more than δ. The pricing that pays is then never built. §0 item 2 ("the ceiling any placement can reach") misstates what (a)'s numbers mean.
- where: §0 items 1-2; §6.2 J; §7.1 decomposition; §9.3 row 2.
- finding: J minimizes the MODELLED price. A placement restricted by its seam picks a different arm on some sites, and wherever J's model is wrong there, the restricted pick is measured faster. So rule-against-J (placement loss) can be negative, and the split "regret = model error + placement loss" is not additive for ratios: (1+r) = (1+m)(1+p) per cell, and means of products differ from products of means. Row 2 reads only J against FM.
- repro: `simulate/bin/verdict.py` S6: FM 6 %, J (and A1/HY/Dx/KF) 4.5 %, MN 3 % gives `row2 MODEL CANNOT BEAT FM`, although MN beats FM by 3 pp > δ. Per-cell arithmetic: t_O = 1, t_J = 2, t_A1 = 1 gives model error 100 %, A1 against J -50 %, A1's regret 0 ≠ 100 % + (-50 %).
- proposed fix: row 2 reads "the best option beats FM by less than δ" (J included). Define placement loss as the difference of mean regrets (signed) and state that it can be negative. Drop "ceiling".
