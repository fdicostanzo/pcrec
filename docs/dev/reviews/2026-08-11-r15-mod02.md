# R15 — MOD-0.2 implementation panel (2026-08-11, ninth session)

Three read-only critics on the LANDED MOD-0.2 migration (recogniser + rank,
commits 1cc6ed6..c1e203d), one primary question each per the R12 narrow-brief
standard. The design had R10/R11/R12; this panel attacked the implementation
and its checks. Critics never ran `make`; the engine critic ran the shipped
binary read-only. All three disclosed their ambient injections (root
CLAUDE.md, memory index, per-directory CLAUDE.mds on first entry — the
standing D27-adjacent leak, disclosed and not consumed as evidence).

## Checks critic — "what would let the new checks pass while the arbitration is wrong?"

**F1 (CONFIRMED as stated, REFUTED in consequence — the sharpest finding to
read).** Neither `check_row_ranks` nor `check_arbitration_liveness` ever
calls the arbitration; both are blind to which row WINS. The critic
constructed the right sabotage — `\N{U+` at rank 24, leaving `\N{` at 25, a
clean winner-swap with no tie — and claimed it ships through `make test`
green. **Measured: it does not.** The rank-24 sabotage fails
`check_table_to_parser` twice inside `make test` ("atom diagnostic matches
the row" + "in-class refusal promises no module"): the per-row syntax check
is exactly D32 §9.1's PRIMARY instrument ("feed `\N{U+0041}` to its bucket;
if the wrong row outranks, the wrong diagnostic surfaces and the check
fails"), and it was in place before MOD-0.2 began. The critic surveyed
pcre2_check's branches, the byte sweeps and the reject pins — and missed the
one check that owns the property, two hundred lines above the checks it was
attacking. Disposition: REJECTED as a defect; the division of labour it
describes is D32's design and is now stated in tests/registry/CLAUDE.md.
The verification run is the part worth keeping: the winner-swap sabotage is
CAUGHT, measured, not argued.

**F2 (contingent on F1): REJECTED** for the same measurement. The claim
"nothing in `make test` checks emitted content for the `\N` pair" is false —
`check_table_to_parser` compares exact diagnostics for every row's syntax,
in `make test`.

**F3 (CONFIRMED): FIXED.** registry_check had no count guard and no
manifest, in the directory whose OWN documentation records a critic deleting
three instruments with everything staying green (R9/C1-7) — the protection
existed for PC-3 and was never extended. run_registry_tests.sh now carries
both for registry_check: exact count 166 (R9/C1-final2 wording split
respected), a manifest naming the three MOD-0.2 checks, and one NEGATIVE
needle outside the loop — the retired check_tail_precedence's PASS line must
NOT reappear. Validated in the failing direction: deleting the
check_row_ranks call fires the count guard AND the manifest line naming it.

**F4 (CONFIRMED): FIXED.** The class-bracket and verb lookups ask the
tail-less question and discard the ambiguity flag; "no class-bracket row
carries a tail" was discipline stated in a scans.c comment, not a guard.
check_row_ranks now asserts tails exist ONLY at the escape and group
doorways — the assertion placed where the fact lives (the R9 rule). The
critic's duplicate-fallback scenario (two tail-NULL rows, one bucket) was
checked and is already caught by check_wellformed's (sel, tail) uniqueness.

**F5 (SUSPECTED): FIXED.** row_answers_here duplicated the engine's dispatch
predicate. The predicate is now exported as `pcrec_registry_row_answers` and
the check uses the engine's own — acceptable sharing, because the liveness
counter is not the oracle for the predicate's correctness (the per-row
syntax checks and PC-3 are), and the duplicate's only future was drift.

## Engine critic — "find a reachable input where the engines disagree"

**No CONFIRMED, no SUSPECTED divergence.** Systematic case: the equivalence
reduces to "same-rank tailed rows sharing a bucket have mutually exclusive
tails" — verified by full manual enumeration of all four multi-tail buckets,
independently re-deriving the 18-row count. Live probes: the `\N` family
(including two truncation points inside `{U+`), `(?P`/`(?<`/`(?-` families,
`(?` at end-of-pattern, lone trailing `\`, high bytes 0x80–0xff at two
doorways — all matching pinned behaviour. PROBED-AND-HELD: REG_SEL_ANY
collisions (one catch-all per kind, captured before sel comparison),
avail=0 ⇔ at=NULL (single invariant in tail_at), multiple tail-less rows
per bucket (none exist; cross-checked against the 18-row pin), the old
engine's `tl > best_len || !best || !best->tail` quirk (coincides with rank
on the shipped table).

**SUSPECTED (coverage, not behaviour): FIXED.** After the D32 §9.5 scaffold
was deleted with the retired engine, NOTHING probed the `ambiguous`
out-param over a swept space — a future same-rank prefix pair would fire the
runtime internal error in a user's compile with no check-time warning, and
detection would be indirect (whichever string comparison it happened to
break). check_arbitration_liveness now ends with the no-ambiguity sweep:
every kind × selector byte × generated text (261,193 probes, the same space
the floors count over), zero winning-rank ties, floored population.
Validated in the failing direction: the equal-rank sabotage (`\N{U+` 70→25)
fails it directly, naming the exact probes.

## Reflection

- The panel's one near-miss repeats the project's oldest shape in reverse:
  a critic proved two checks blind to a property and concluded the property
  was unguarded, without sweeping the rest of the suite for the check that
  owns it. The measured refutation took one sabotage build. Verify a
  critic's CONSEQUENCE claim the same way you verify your own: run it.
- Every accepted finding was cheap because the probe spaces already
  existed: the no-ambiguity sweep and the tails-only-here assertion reuse
  bucket_probe_texts and check_row_ranks' loop; the count/manifest guard is
  the directory's own PC-3 pattern extended to its neighbour.
- All three critics disclosed ambient injections; none consumed them as
  evidence. The leak remains a standing property of spawning (instances now
  beyond six; not re-counted here).

## NOTED — the honest inventory of what R15 leaves unguarded

- A NEW construct given the same wrong module in both parse.c and
  registry.c, with no tests/reject/ row, is still caught by nothing (the
  registry CLAUDE.md's standing residual risk — unchanged by MOD-0.2).
- Module-swap between two rows and row deletion inside a bucket remain
  guarded only by tests/reject/'s hand-written manifest (D32 §10, restated).
- Two REG_SEL_ANY rows for one kind would silently last-one-win in both the
  old and new engines — a table-population invariant no check pins (engine
  critic, out of scope for MOD-0.2; belongs to whoever next touches
  check_wellformed).
- K10's blind-net count stands at four after the successor swap; the
  in-class tail sweep that could see it stays scheduled with MOD-0.6.
