# CRITIC meas: memfn-bsu5 (r79)

## Findings

### MEAS-1 CONFIRMED (design / measurement; effort small; blast radius: every C6 and C6c verdict and the A/A rate printed beside it) — the A/A arm times ONE pool, the comparison it calibrates times TWO
- Where: §8 "What replaces the A/A line"; cards.py `C6_RULE["replaced"]` (line ~1025), `arm_flags` (H64.b -> H64's flags), `text_key`/`pool_variants`/`build_cell` (pool and exe cached by the TEXT key).
- Per-arm axes, read from the code and the finished dry (`$RD/dry/dry.out`, `$RD/dry/run/art`):
  - V vs H64 at `on` (C6): (1) the text: wrapper `__body`, `__w32_b`/`__w32`, selector call (intended); (2) the header: `#include <immintrin.h>` (intended, §8 "on purpose"); (3) stamps `RXA_MEMFN_FORMS` "none" -> "span-vector@w32", `RXA_SIMD_GUARDED_BYTES` 0x267 -> 0x6cc (hex32; preprocessor macros, run-time inert, intended); (4) **the layout POOL**: `pool_variants(textkey)` draws each text's four preludes from its own hash, so V's and H64's code sits at different 64-B phases (dry: `pool c6_hex32 V on: v0 64B 0,25 ... v3 31,56` vs `pool c6_hex32 H64 on: v0 64B 16 ... v3 52`); (5) the launch draws (independent per arm, by design). Same: compiler and flags (gcc -O2 -std=gnu11 -w, parity variant v%2), driver, subject file, CPU, interleaved rounds.
  - H64 vs H64.b (the A/A arm): **one text key, one pool, literally the same four executables** (dry: "22 timed texts x 4 variants = 88 exes" for 33 arm-texts; H64.b has none of its own). The only differing axes are the launch-draw sequence and the launch slot.
  - V vs H64 at `off-clang` (C6c): the wrapper text only (diff of a_dc51.. vs a_085a..: `__body` + selector + the one call; no header, no stamp moves), plus the pool axis (4); clang's alignment-off variant `CLANG_ALIGN_OFF` is the same for both arms (no between-arm axis). The clang machine code really differs (objdump of v0 `rxa_search`: 12/12/267 differing lines at hex32/hexb32/dig32), so C6c is not A/A by construction.
- Which axis the verdict is meant to read: C6 = axes (1)-(3) together (§8, G-3 "what the caller gets"); C6c = the wrapper alone under clang (§2.2.1, [BSPAN-CLANG-DIFF]). Axis (4) rides every V-vs-H64 reading and is ABSENT from every A/A reading, so the A/A rate cannot bound the comparison's false-LOSS rate: the arm moves two axes (text and pool) and its control moves neither.
- 710's A/A line, which this "replaces", was Hspk vs H64@on on the identical-walk patterns: TWO compiled texts, each its own layout (R/decision_rule_710.md "A/A LINE"). The replacement is strictly weaker on exactly the axis that matters.
- Repro (synthetic, no timing): `python3 -I $RD/meas/drill.py`. A V pool whose odd (alignment-off) variants run 25 % slower, true default-build ratio 1.00, 2 % launch noise, 4000 cells: single LOSS 0.304, REPEATED LOSS 0.091 per cell. The A/A arm with the SAME pool effect on both sides: repeated non-TIE 0.001. Over C6's ~35 readable cells a 9 %/cell false repeated LOSS blocks the level (D155 item 2) almost surely, while the printed A/A rate reads ~0.
- Expected: the A/A arm shares the comparison's layout structure. Fix (small): make H64.b a second TEXT of H64 (a byte-different, code-identical TU, e.g. one trailing comment line in the timed TU), so it gets its own pool as V does; or state in §8 and `C6_RULE` that the A/A rate is launch noise only and add the between-pool term. (Salting `pool_variants`' hash with the `.b` suffix gives the same result without touching the TU.)

### MEAS-2 CONFIRMED (measurement; effort small-medium; blast radius: every "repeated" reading C6 would gate on) — the RE-TIME cannot draw fresh layouts
- Where: `C6_RULE["applies"][1]` ("re-timed on further fresh pool draws"); `pool_variants`, `POOL_SIZE`/`pool_size_refusal` (any value but 4 refused), `launch_variant`.
- 710's re-time ran on variants 10, 11, 12, layouts never timed in the main pass (R/decision_rule_710.md "RE-TIME"). In cards.py a text's pool is a FIXED function of its text hash (four exes, POOL_SIZE locked at 4); a re-time can only re-draw among the same four built layouts (the `launch_variant` salt changes the sequence, not the set). So "repeated" means "the same four layouts agreed twice", not "a fresh layout agreed": a layout-caused LOSS (MEAS-1) repeats with conditional probability ~0.3 in the drill (0.091 / 0.304), where 710's design aimed at independence.
- Expected: the clause says what a re-time draws. Either the record states the deviation (the re-time is a launch-noise re-read, not a layout re-read) or the re-time builds a fresh pool (a re-time salt in `pool_variants`, four new preludes).

### MEAS-3 CONFIRMED (measurement; effort small; blast radius: the LOSS check in every cell) — the floor over LAUNCHES lets one outlier launch or a bimodal pool hide a LOSS; the unit is left open
- Where: `C6_RULE["applies"][0]` and `C6_RULE["unit"]` ("UNMEASURED DEFAULT ... U6's reader rules whether three fresh variants or LAUNCHES draws are the unit").
- As recorded, spread = (max - min) / median over an arm's 5 launches, each launch on one of 4 layout variants, so the floor absorbs the pool's layout RANGE plus any single outlier. Drill (`$RD/meas/drill.py`, deterministic rows):
  - clean, V 10 % slower: TIE (floor 0.15); V 16 % slower: LOSS.
  - one outlier launch x2 in EITHER arm, V 25 % slower: floor 1.0 -> TIE (a 25 % loss is invisible).
  - bimodal V, 2 of 5 launches on a 40 % slower layout: floor 0.40 -> TIE; 3 of 5: median moves -> LOSS. The verdict is a coin flip on the draw.
  - equal-effect sweep (2 % noise, 4000 cells each): repeated LOSS 0.000 at 1.10, 0.075 at 1.14, 0.505 at 1.16, 0.996 at 1.20. G-3's "no repeated LOSS" therefore admits a ~14 % regression in every cell; the record says 0.15 is 710's constant "not re-derived here", but 710's spread was over 3 per-variant readings, not 5 launches spanning a pool.
- No bimodality clause applies (cards.py's own C1-C5 rule voids BIMODAL arms at GAP_K; C6_RULE neither applies nor drops it), and the CPU-quiet control voids only on CPU 7 busy / nivcsw, not on a layout or frequency outlier.
- A rule "written before data" whose UNIT is still to be ruled by a later reader can still change its verdicts after the data are in. Expected: the unit fixed now (per-variant medians, as 710, or launches with a stated bimodal/outlier clause), and the floor's power stated beside G-3.

### MEAS-4 CONFIRMED (design / measurement; effort small; blast radius: the card's verdict) — the record has no VERDICT clause and no readability floor: an unreadable run passes G-3
- Clause-by-clause against R/decision_rule_710.md. 710's clauses: CLAIM, TABLE, ARMS, CELL, FLOOR/WIN/LOSS/TIE, N/A, CPU-QUIET, WINDOW (TRUNCATED/NOT-RUN), RECORD (FIDELITY-2: the run copies the rule, and decide REFUSES a run whose rule sha differs), S, RE-TIME, A/A LINE, CONTROL, VERDICT (first match, incl. - G-3 (§0) is "0 repeated LOSS"; with the half-readable clause gone with the verdict population, nothing requires any cell to be READ. Drill (on paper): every C6 cell INCONCLUSIVE-NOISE (a busy box) or N/A -> no clause fires -> "0 repeated LOSS" -> by §8 "What it settles" the box counts as run and V's CANDIDATE label may lift. ### MEAS-5 CONFIRMED (design; effort small; blast radius: claim 3) — the A/A arm can READ non-TIE, but nothing makes that a FAILURE, and nothing computes it
- Claim 3 ("the A/A arm can fail"). What the arm can produce: a non-TIE between H64 and H64.b, yes, by draw imbalance alone (drill: H64.b drew only the fast variant [1.0 x5], H64 drew a 20 %-slower variant 4 of 5 [1.0, 1.2 x4] -> floor 0.167 -> LOSS; Monte Carlo with one 30 %-slow variant: single non-TIE 0.043, repeated 0.001).
- What the record says follows: `C6_RULE["replaced"]` and §8: "its repeated-LOSS-or-WIN rate is printed beside the verdict". No threshold, no consequence: no clause voids a pattern's V-vs-H64 readings, or the run, when its A/A reads non-TIE; 710's line at least turned the rate into "expected false WINs = population x rate" (dropped here, not named as dropped). "Repeated" is undefined for the A/A pair: the RE-TIME clause names only V-vs-H64 LOSSes and WINs.
- Code today: none. `grep -n 'H64' cards.py` finds only `arm_flags`, the CARDS rows and `check_c6`; no command times C6 (by design, U5), and no reader exists: `C6_RULE` defers the N/A source and the unit to "U6's reader", but §14's U6 row lists only "C6's timing owed to main's window" -- no unit owns the reader that would compute the floor, the re-time, the A/A rate or the verdict.
- So as written the A/A arm cannot fail: it is information. Expected (if claim 3 is to hold): a stated failure (e.g. any REPEATED non-TIE of H64 vs H64.b at a pattern -> that pattern's V-vs-H64 non-TIEs are INCONCLUSIVE-HARNESS, listed; above N patterns the run is VOID), and a unit that owns the reader. Combine with MEAS-1, else even a stated failure fires only on launch noise.
