- Consequence: the `layer` value `off-clang` carries TWO facts (SIMD level: `LAYER_FLAGS["off-clang"] == LAYERS["off"]`, True; and compiler) in one slot. Adding the obvious next arm (SIMD-on under clang, `on-clang`, or gcc -Os, see SLOT-4) needs edits in `LAYER_FLAGS`, `cc_of`'s string test and `flags_for`'s test: three sites, and `cc_of` silently returns CC for any new clang-named layer that is not literally `off-clang` (a silent default, memory pcrec-no-silent-defaults).

- The general form (coding.md/architecture.md "one table per slot"): ONE layer row table, `LAYER = {"off": ([], CC), "on": ([SIMD], CC), "off-clang": ([], CLANG)}` (or a `compiler` column naming a compiler row `{gcc: (CC, ALIGN_VARIANTS), clang: (CLANG, ([], CLANG_ALIGN_OFF))}`), read by `artifact` (flags), `build_cell` (cc), `pool_variants` (that compiler's variant list) and `cc_ident`. `cc_of`/`flags_for` become lookups; `LAYERS` stays the C1-C5 subset (or the C1-C5 cards name their layers, which they already do in CARDS). Fix: replace the two name tests by the table and drop the nonexistent name from the comment.
