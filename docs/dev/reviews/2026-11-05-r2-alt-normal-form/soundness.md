## Findings

### SND-1 — CONFIRMED (answer) — stage 2b width groups reorder branches across an unequal-width sibling inside the "maximal adjacent run"
- Where: §3 "width groups" + "Preference" (¶ lines 87-93, 119-123), §3 table row `altcls` ("over adjacent capture-free fixed-width literal branches"), §5 Stage 2b, §6 rule table row (1)/(2).
- The rule as written: altcls hands the owner a maximal ADJACENT run of capture-free fixed-width literal branches; the owner groups by width and merges siblings inside a group. The Preference paragraph argues soundness from adjacency alone ("as altcls's existing soundness boundary"). But altcls's existing argument holds only because every stage-1 member has width 1 (and stage-2 keeps branch order). A run that mixes widths is still "adjacent", and grouping by width moves a branch past a shorter/longer sibling that can match at the same start: under leftmost-first that changes the span.
- Repro (byte spelling of the rewrite; `soundness/c1.tsv`, `python3 -I soundness/bin/cmp.py soundness/c1.tsv`):
  - `(?:ab|a|ad)` on `ad`: pcrec (0,1), libpcre2 (0,1) [today, correct].
  - merged with the group in its first member's slot, `(?:a[bd]|a)` on `ad`: (0,2) — answer moves.
  - merged into the last member's slot, `(?:a|a[bd])` on `ab`: (0,1) vs original (0,2) — answer moves the other way. No slot placement is sound.
  - a realistic keyword shape: `(?:for|fo|fox)` on `fox` = (0,2) (pcrec = libpcre2); width-grouped `(?:fo[rx]|fo)` = (0,3). Caseless code-point level, utf8: `(?i)(?:αb|α|αd)` on `αd` = (0,2); `(?i)(?:α[bd]|α)` = (0,3) (`soundness/c5.tsv`).
  - the same for SUFFIX factoring grouped across an intervening branch: `(?:ac|x|xc)` on `xc` = (0,1); `(?:[ax]c|x)` = (0,2).
- In lowering (stage 1) this cannot happen (UTF-8 branches are prefix-free and pairwise disjoint), so the defect is confined to stage 2b, and only to the code-point caller.
- Fix (small, doc): state the boundary as "a merge/factor of branches i<j is allowed only if every branch between them has the SAME width as both" (equal-width capture-free branches are interchangeable: same end, no captures), or simply restrict the owner's code-point input to maximal runs of EQUAL-width branches and factoring to CONSECUTIVE branches; add `(?:ab|a|ad)`/`ad` and `(?:ac|x|xc)`/`xc` as the concrete S-d witnesses (S-d currently has none, see SND-4).
- Effort: doc line + witness; blast radius: every user alternation of mixed-width literal branches (keyword lists like `in|int|if`-style with a shared stem: `(?:ab|a|ad)` shape is common, e.g. `(?:for|fo|fox)`). Severity: answer (a wrong span, no crash), only once stage 2b is built as written.

### SND-2 — CONFIRMED (answer) — stage 2b "any identical capture-free factor as the key" admits non-fixed-width keys; prefix factoring on such a key reorders
- Where: §5 Stage 2b "Change" ("prefix AND suffix factoring, any identical capture-free factor as the key"); contrast §3's narrower "capture-free, fixed-position literal branches". The §5 sentence is the one a build lane would implement from.
- Prefix factoring `KX|KY -> K(?:X|Y)` is NOT a leftmost-first identity when K can match more than one length: the original tries every way of K with X before any with Y; the factored form interleaves.
- Repro: `(?:a|ab)c|(?:a|ab)b` on `abc`: pcrec (0,3) = libpcre2 (0,3); factored `(?:a|ab)(?:c|b)`: (0,2) (pcrec and libpcre2 agree it is (0,2), i.e. the rewrite itself changes the answer).
- Suffix factoring `AC|BC -> (?:A|B)C` is, by contrast, a true identity for backtracking semantics for ANY A, B, C (right distributivity holds in priority order) — provided A and B are adjacent (SND-1). So the note's sentence has the asymmetry backwards in strength: suffix factoring needs only adjacency, PREFIX factoring additionally needs a key that matches at most one length (fixed width; capture-free so the ways are indistinguishable).
- Fix: §5 should say "any identical capture-free FIXED-WIDTH factor" for the prefix key (it follows from §3's input domain, but say it at the site); Effort: one phrase.

### SND-3 — CONFIRMED (test: the witness cannot fail) — S-f does not reach its site: `(?i)xk`'s run is below the 16-bit floor in BOTH the correct and the sabotaged build
- Where: §5 Stage 3m, S-f; §4.4 (floor 16, info(S) = 8 − ⌈log2|S|⌉).
- By the note's own arithmetic: correct stage-3m run of `(?i)xk` = `[xX]` (7 bits) + `{4B,6B,E2}` (6) = 13 < 16 → no run ships. Sabotaged ("misses the long member's first byte") = `[xX]` + `{4B,6B}` (a 2-cube, 7) = 14 < 16 → no run ships either. Both builds compile the same matcher; `xK` MATCHes in both. Measured today: `-e utf8 --emit-facts --pattern '(?i)xk'` → `req_whole_run none`; `x[kK]` (15 bits) → none.
- Fix: lengthen the left context so the run clears the floor, e.g. `(?i)xyzk` against `xyzK` (`78 79 7a e2 84 aa`): today's run is already `58595a/dfdfdf` (21 bits), stage 3m's is `[xX][yY][zZ]{4B,6B,E2}` (27), and a sabotaged `{4B,6B}` position rejects the subject IF the emitted window covers position 3 — so REACH must show the position is inside the tested window, not only that the run exists. Effort: one line. Same check is owed to S-e (see SND-5).

### SND-4 — CONFIRMED (test gap) — S-d names no witness; SND-1's shapes are the discriminating ones
- Where: §5 Stage 2b, S-d ("exact witness chosen by the build lane").
- The sabotage it describes (merge crossing a non-adjacent branch) and the defect in SND-1 (merge crossing an unequal-width branch) are distinguished only by a witness whose intervening branch can match a PREFIX/EXTENSION of a merged branch at the same start. Concrete, libpcre2-checked: `(?:ab|a|ad)`/`ad` → (0,1); `(?:for|fo|fox)`/`fox` → (0,2); `(?:ac|x|xc)`/`xc` → (0,1) (suffix factoring). Capture-bearing is not needed (the span alone moves), and a capture-bearing witness would be excluded from the owner's input anyway (capture-free branches only), so the note's "capture-bearing so the span differs" hint points away from the reaching case.
- Effort: one line.

### SND-5 — PLAUSIBLE (test, minor) — S-b/S-c/S-e discriminate only some forms of their sabotage; add the missing subjects and a window-coverage REACH
- S-b (`(?i)k`, subjects ASCII `K` and `\xe2\x84`): a sabotage that aligns `6B`/`4B` with `E2 84 AA` at the RIGHT or keeps the long branch's tail (`[4B 6B E2] 84 AA`) answers `K`(ASCII)→NOMATCH (caught), but one that truncates to `[4B 6B E2]` answers ASCII `K` correctly and is caught only by `\xe2\x84` (ill-formed; pcrec's contract is MATCH_INVALID_UTF semantics, cli.md §1.7¶2, so NOMATCH is normative — checked: today pcrec and libpcre2+MATCH_INVALID_UTF both NOMATCH). - S-e (`(?i)xβy`/`xϐy`): reaches only if the emitted window/verify covers the hull position the sabotage drops; with every position non-exact the pick may scan a pair and leave the DFA to verify, in which case no answer moves. - Stage 2's A_EMPTY → rr_unit arm has no sabotage witness at all (S-c covers only the width test). A cheap one: widen the arm to `A_KRESET` and check `ab\Kcd`/`xabcd` (expected (3,5)) plus a startpos case; whether it discriminates must be shown by REACH (I could not build the sabotage).
- Effort: a few subject lines.

### SND-6 — SUSPECTED (doc, low) — stage 3 says cubes are "derived by `pcrec_cube_of` where a reader wants one", but `pcrec_cube_of` is an EXACT detector (false on a non-cube set)
- Where: §5 Stage 3 "Change"; src/core/cpset.c:394 (`pcrec_cube_of` returns false when the cube would spill onto a non-member).
- A cube-wanting reader handed a non-cube set position (e.g. β's `{90,92,B2}`) gets `false`; the note does not say whether that reader then declines the position or uses the cube HULL (`Ta & K'`, the superset; sound). Using the member-AND without the hull mask, or treating `false` as "no constraint" on an exact-only reader, is the one way a stage-3 build could emit a compare that rejects a member. Not a defect in the rule; a missing sentence ("a cube reader of a non-cube position takes the hull, from the one cpset hull function of §3, or declines"). Effort: one sentence.

## PROBED-AND-HELD

- **Stage 1 sibling merge is exact (§3, §6 rule 2), run to a fixpoint on `u8_box`-shaped branches.** Mathematically exact (A1×…×Ai×…×An ∪ A1×…×Bi×…×An = A1×…×(Ai∪Bi)×…×An). Applied by `soundness/bin/st1.py` (a re-implementation of the UTF-8 band split + the §6 first-match pair fixpoint) to 10 classes: `[^é]`, `(?i)β`'s set, `[a\x{3b1}]`, `[\x{100}-\x{17f}\x{1e00}-\x{1eff}]`, `[^\x{3b1}-\x{3c9}]`, band edges `[\x{7ff}\x{800}\x{d7ff}\x{e000}\x{ffff}\x{10000}]`, the k/K/K set, Cyrillic both cases, `[\x{80}-\x{10ffff}]`, a range with a hole `[\x{100}-\x{2ff}\x{301}-\x{3ff}]` (box counts 12→9, 12→10, 3→2, 4→2, ...), bare and in `x…y` context. Merged and unmerged byte spellings (`-e byte`) vs the utf8 compile of the class vs libpcre2 (UTF|UCP|MATCH_INVALID_UTF — pcrec's ill-formed-subject contract, cli.md §1.7¶2): **3112 subject checks, 0 divergences**, subjects drawn from members, non-members, lone continuation bytes, truncated leads (`ce`, `e2 84`, `f0 90`), overlong `c0 80`, `ff`, a surrogate encoding. (`soundness/c3.tsv`, `bin/run1.py`.) The UTF-8 branches are prefix-free and pairwise disjoint, so width grouping cannot reorder an observable choice in lowering (contrast SND-1).
- **S-a discriminates.** `(?i)β` today vs `ΐ` (`ce 90`): NOMATCH (pcrec = libpcre2); the two-position sabotage's form `[\xce\xcf][\x92\xb2\x90]` matches `ce 90` at (0,2); the correct merged form `(?:\xce[\x92\xb2]|\xcf\x90)` does not (`c4.tsv`). With the pair order of §3 the first merge (`ce92`,`ceb2`) is legal under both builds, so the sabotage is reached on the second step.
- **K123 lookbehind with the seal's job taken by `A_WCLASS`.** `(?<=[a\x{3b1}])x`, `(?<=[a\x{3b1}\x{4e00}])x`, `(?<=[^a])x`, `(?<=(?i)\x{3b2})x` under default, `-fno-cls-kit`, and `--engine=vm -fno-cls-kit`, on 8-9 subjects each incl. ill-formed: 0 divergences from libpcre2. Code read: `pcrec_lookbehind_branches` (src/parse/mod_lookaround.c:321) peels exactly `nbranch-1` spine nodes, back-step widths come from the parse-time `u.look.widths`, and `wclass_of` wraps EVERY multi-unit lowering (lower_enc.c:311), so a bare byte alternation never reaches the branch split; stage 1 does not change that. (A user-spelled byte `(?<=(?:a|\xce\xb1))x` is refused as variable-length — the wrapper is load-bearing for the utf8 case, keep it.)
- **Suffix factoring `AC|BC ≡ (?:A|B)C` for ADJACENT A, B** holds for any A, B, C under leftmost-first (right distributivity preserves priority order: every way of A then C, then every way of B then C); checked unequal widths, A a prefix of B (`ac|abc`), lazy/possessive/backrefs by argument. The note's statement is true; only its premise "inside a maximal adjacent run" is too wide (SND-1) and prefix factoring needs a fixed-width key (SND-2).
- **Stage 2 hull into `all` (§4.2) and `A_EMPTY` as `rr_unit`.** Read `rr_cat`/`rr_alt`/`rb_rep_into`/`rb_class_into` (src/facts/req.c:302-575): a hull of equal-width, untruncated `all` branches is a position-wise superset of every branch, so "every match contains the run" holds; head `off`=0 and `rn_tail_off` are unchanged. Every `A_EMPTY` producer was enumerated (parse empty branch/group, bare option runs, `(*UCP)`-style starts, the bare-anchor wrapper's trailing empty, `derive.c`'s `x{0}`-of-never and negative-look-of-never, altcls remainders, the lowering seal; `callout.c:317` only temporarily and restores): every one is a true epsilon. `\K` is `A_KRESET`, `\G` `A_GSTART`, anchors `A_EOL`/`A_CTX`, lookarounds `A_LOOK` — all stay `rr_none` under the rule as written, and a min-0 repeat of an empty body stays a cut (`rb_gap_into`), a min-≥1 repeat stays `rr_none` with the body's best. `(*ACCEPT)`-family verbs are refused ("requires module 'verbs'"), so no consuming-cut construct can be an `A_EMPTY` today. No pattern found whose real match the stage-2 run would reject.
- **§4.4 info formula** equals popcount(K) on every cube (2^(8−p) members → 8−p) and rounds a non-cube set DOWN; it only ranks and floors, it cannot exclude a match.
- **§4.5 affix rule** (union of first positions ends the left run, union of last positions begins the right run): every match of a mixed-width letter starts with a byte in the first-union and ends with one in the last-union, so the two runs are supersets; the right run's offset varies by group (0 for `k`, 2 for `K`) and is covered by the existing maxw-based upper bound (K82 semantics "begins AT MOST off bytes in"). Checked by argument on k/K/K, s/S/ſ; no reader in §4.2's audit treats `off` as exact.
- **S-c's discriminating form checked**: the min-width sabotaged run spelled as `xy[ac][bd]zw` rejects `xycdezw` (NOMATCH) where the pattern MATCHes (0,7) (`c5.tsv`); see SND-5 for the other form.
