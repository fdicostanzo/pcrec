### PREM-1 — Stage 1's sibling merge REMOVES VM alternation islands; the note's premise that the VM reads the lowered byte child only under `-fno-cls-kit` is false for the island (CONFIRMED)

- Note: §2.1 row `src/gen/emit_vm.c vm_isl_words/vm_isl_build` ("reader (unlock U4)"), §5 preamble ("`-fno-cls-kit` where the VM reads the lowered byte child"), §5 stage 1 predicted movers and Gate U4 (DFA `ci-*`/`cls-*`/`prp-*` regimes only).
- Code: `src/gen/emit_vm.c:4091-4092` — `vm_isl_words` descends an `A_WCLASS` into its byte child UNCONDITIONALLY (no `vm_wcls_bytes` test, so on the default kit-on axis too); `:4100-4110` an `A_CLASS` is a word only if `vm_isl_single` (`pcrec_cls_single`, one byte) says so. Today `u8_box` emits one branch per box, so a non-contiguous non-ASCII set (`[éà]`, or a fold pair such as `(?i:é)` = `c3 89|c3 a9`) is an alternation of SINGLETON byte sequences and enumerates into island words. Stage 1's merge turns that into `c3 [a0 a9]` (one non-singleton position): `vm_isl_words` returns false and the whole enclosing island is declined.
- Repro (today's compiler, 6 compiles): `build/pcrec -e utf8 --engine=vm -p rx -o x.c --pattern 'x(?:[éà]1|q2|r3)y'` → `RX_VM_ALT_ISLANDS 1` (both default and `-fno-cls-kit`); `'x(?:(?i:é)1|à2|q3)y'` → 1; control `'x(?:[éê]1|q2|r3)y'` (contiguous, one box) → 0. Byte-spelled stage-1 control, `-e byte -fno-altcls-merge -fno-altcls-factor --engine=vm`: today's shape `x(?:(?:\xc3\xa0|\xc3\xa9)1|q2|r3)y` → islands 1, 19,514 B; merged shape `x(?:\xc3[\xa0\xa9]1|q2|r3)y` → islands 0, 20,201 B (+3.5%).
- Expected per note: island is a reader that only GAINS (U4); observed: stage 1 loses islands on utf8 VM patterns with a multi-box wide class inside a literal alternation, on the DEFAULT axis.
- Severity: speed + size (VM). Effort: small to state — add these to Gate U1's predicted set by name and to Gate U4 (a VM island census on the utf8 movers, as stage 2b already has), or have the island read the merged node as a set edge (that is U4 itself, so U4 becomes a stage-1 obligation rather than an unlock). Blast radius: utf8 VM artifacts whose literal alternation holds a non-ASCII multi-box class; answers do not move.

### PREM-5 — §8 caveat "cause not traced" for the k/s byte-spelling table counts: traceable in three compiles; it is the START row, not the tables (CONFIRMED)

- `(?i)k -e utf8`: `rx_forward_next_state` 24 + `rx_anchored_next_state` 24 = 48, `RX_DFA_START "landing"`. Byte spelling `(?:\x4b|\x6b|\xe2\x84\xaa)` with altcls denied: forward 24 + **`rx_reverse_next_state` 24** + anchored 24 = 72, `RX_DFA_START "reverse-pass"`. `(?i)s`: 15+15 vs 15+15+15, same split.
- Cause: the `landing` row needs the `land_char` fact (every one-CHARACTER path from the start ends dead or accepting, `src/facts/kset.c` [START-LANDING]); under utf8 a character is the whole `e2 84 aa`, under byte the one-byte path through `\xe2` is neither, so the byte spelling cannot take `landing` and emits a reverse machine. Per-machine tables are identical. `pred.py`'s `size()` sums every `*_next_state` array, so its entry counts are a machine-SET metric, not a table metric.
- Consequence: k/s predictions are recoverable (compare per machine, or forward+anchored only); and the same artefact can hit any stage-1 prediction whose FIRST character is a mixed-width or non-ASCII letter whenever today's utf8 compile takes `landing` (the §8 rows match today only because their utf8 compiles did not take it — worth one line saying so).
- Severity: doc (evidence quality). Effort: small.
