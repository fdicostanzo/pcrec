Panel: three read-only critics. `i2crit-chk` (sonnet) took checks, oracles and the
measurement gate. `i2crit-sem` (opus) took semantics and the macro. `i2crit-fam` (opus) took
the family, the ABI, simplification and unlocks.

**Verdict.** No BLOCKER. The macro's text was confirmed by hand expansion (sem-6), and so
were equivalence to PCRE2's global loop and K75 across batch boundaries (sem summary).

  fallback copy.
- **No new entry** (fam-1).
- **The doubling starts at 1** (sem-1). This changes the start of 4 in Frank's charter, so
  it is the manager's call, which Frank may reverse.

The measurement gate was rebuilt (chk-1/2/3): A/A floors, a positive gain cell, gated
early-stop bounds and an objdump hypothesis.

## The critics' findings, verbatim

### Critic i2crit-chk (sonnet): checks, oracles, measurement gate

1. MAJOR, CONFIRMED. The timing gate has no A/A arm and no verdict rule for F/I.
 - §4 lists I, I_info, N4, N64 and F, with no A/A arm and no L_old.
 - "floor defined in findall_iter.md §5.3" is the A/A noise of I/L_old (findall_iter.md:1122). It is not defined for F/I or I_i2/I_i1.
 - Fix: before the run, add an A/A pair (I_i1 built twice, F built twice) and define floor = max(|median ratio-1|, IQR/median) for each new ratio.
 - Floors in the parity run range 0.36% to 5.59%. c6 R2 is 3.29% and c7 R2 is 5.59%, so a gate on those blocks is nearly vacuous.
 - Also state a re-queue rule. The parity run was not quiet (load1 1.33-2.76, 61 of 1,080 rows had the sibling above 10% busy), and §4 is silent on invalid runs.
2. MAJOR, CONFIRMED. No cell checks that I2 delivers the gain. The F gate is only "F <= I(1+floor)"; F equal to I passes, yet the motivation is c3-4k R2, where N64/I is 0.74. Fix: one positive cell, F/I < 1-floor on c3-4k R2 (and c3-1m R2). c7 is only "reported (predicted ≈ I + one search)" — that is the doubling-start promise (k=4 vs the 26x loss at k=64), so it should be a gated bound. N4, N64 and I_info decide nothing (D77). Keep N64 on c6 only as the diagnostic.
3. MAJOR, PLAUSIBLE. Gating on the unexplained c6 loss is sound only because the gate runs on the built artifact. Do not treat "one shared __pull" as the explanation: in the parity data I_shared/I on c6 is 0.9994 / 0.9633 while N64/I is 1.95 / 1.66; the twin's N64 was in the off build only, and __find was noinline. Fix: one objdump of the built artifact before the gate (is __find inlined into __pull; does __pull's loop spill), as a falsifiable hypothesis.
4. Citation CONFIRMED: 0.58 is N64/L_old = 0.5761 (parity_report.md:288), c3-4k R2; 0.74 = 0.5761/0.7785; 1.95 and 1.66 = 2.1802/1.1163 and 1.6665/1.0064. The derived ratios take medians of different arms and carry no IQR; say so.
5. MAJOR, CONFIRMED. entry_shape_driver `iter` is not an oracle (§5.2): rung identity cannot fail on a __pull defect because every rung runs the same __pull; compare to `_next` and libpcre2. The gstart arm (libpcre2) is independent; encseam's python finditer is independent but its "pcre2-only" differences are unchecked. iter_drv's arms compare to I and G (sound); N0/Fcount/Fabi are self-checks (fine).
6. MAJOR, CONFIRMED. No sabotage row at the batch boundary (the S1300-shaped risk). Add a plant: clear RETRY on the k-exhausted return, witness N1/N2/N3 on `a*`. Add a break exactly at a batch end (j = 4, 12, 28); Fstop breaks only at j = 1, 3, 5. After a break nothing tests `I` resumed on the same `it`: state it undefined or add the arm.
7. Witnesses per row: S1309 N3 on a subject with ≥3 matches, heap-sized exactly; S1310 N2 with NCAPS>1 and ≥2 entries; S1311 a give-up firing mid-batch after ≥1 entry in the same call (else unreached); S1312 a subject with fewer than k matches and a poisoned buffer; S1313 N0 on a FRESH iterator (k=0 on BOUND/ENDED not covered); S1315 needs >60 matches to reach k=64 (Fcount floor 61 right); S1317 3-group cell with ≥3 matches; S1318 conditional on Q2. Each row needs a K35 reach count.
8. MINOR. "I_i2/I_i1 ≤ 1+floor" proves nothing about folding; add a structural objdump compare of `_next`'s text against I1's.

### Critic i2crit-sem (opus): semantics and macro

1. MAJOR, CONFIRMED: over-fetch is bounded in SEARCHES but costs BYTES. One match near the start of a 1 MiB subject, caller breaks after it: `_next` and PCRE2 scan about the match position; F's first fill (k=4) scans all 1 MiB. Fix: start doubling at 1 (1,2,4..64), or spec the byte cost; add a sparse early-break cell to §4.
2. MAJOR, CONFIRMED: give-up timing after an early exit. A prefetched search past the last delivered match can give up and END the iterator; a caller who breaks then checks `it.rc < 0` (§3.1's idiom) reports an error PCRE2 never reaches. Fix: spec (§3.8.2, §3.4's break row) states rc after an early exit may reflect undelivered searches and is meaningful only when the loop ran to its end; fix the example.
3. MINOR, CONFIRMED: §3.3 call-count formula off by one: calls are ⌊(M−60)/64⌋+5 for M≥60 (the ⌈⌉ form is short by one when 64 divides M−60, e.g. M=60 → 5, M=124 → 6), kmax=64; M=4096 → 68 checks. Build Fcount's expected count by simulating the fills.
4. MINOR, CONFIRMED: "r==k ⇔ live" is false at k=0 (an ENDED iterator returns 0 == k; `do r=next_n(..,k); while(r==k)` with k=0 spins). Restrict to k≥1.
5. MINOR, CONFIRMED: the macro's refusal (begin, k==0) ENDs a live BOUND iterator; `lo` is then not "the start of the search that ended it"; PCREC_ERR_ITER means three things (late setter, abi mismatch, ncaps > PAIRS). Spec must list all three and except `lo`.
6. MACRO TEXT CONFIRMED by hand expansion: `for (rx_foreach rx_fe_m, *rx_fp_m = rx_foreach_begin(&rx_fe_m,(info),(it)); !rx_fp_m->brk && rx_foreach_pull(rx_fp_m); ) for (ptrdiff_t (*m)[2] = (rx_fp_m->brk = 1, rx_fp_m->cur); rx_fp_m->brk; rx_fp_m->brk = 0) BODY` — break/continue/return correct; info and it evaluated once; `&rx_fe_m` in the same declaration legal; needs C99 for-declarations (state it); m must be an identifier; 4,168 B correct (4096 + 9×8); NULL next_n / abi mismatch never calls fn. PLAUSIBLE MINOR: clang -Wcomma flags the comma initializer. PLAUSIBLE MINOR: passing f->buf to an indirect call escapes the whole object (brk/head/count stay in memory around each body call); the c1 gate covers it.
7. MINOR: the abi compare is stricter than the layout it protects (D76 bumps abi on any scaffold/comment change). Acceptable now; see unlock (b).
Equivalence to PCRE2's global loop and K75 across batch boundaries CONFIRMED by construction (__step commits lo/flags into *it; __pull carries no per-step local but `at`; give-up after j returns j with rc set). Not re-audited: I1's __next_pos vs pcre2demo's CRLF two-byte advance (I1 scope).
UNLOCKS: (a) RX_FOREACH_IN(f, info, it, m) over a caller-declared rx_foreach f, RX_FOREACH as sugar; state outlives a break (resume by draining f), retiring Q3's rule, allowing off-stack storage; trigger: first stop-and-resume batching caller. (b) a PCREC_RX_INFO_LAYOUT number replacing the abi compare; trigger: U-I2-3 / first cross-build loader.

### Critic i2crit-fam (opus): family, ABI, simplification, unlocks

1. MAJOR, CONFIRMED. Making NEXT_N its own PcrecEntry does not guarantee ".next_n NULL exactly where .next is NULL": requests are per-entry bits (entries.c:388, emit_in->req), so a request can export next without next_n and RX_FOREACH refuses an artifact that has an iterator. NEXT is the last public enum member (internal.h:61); adding NEXT_N moves PCREC_ENTRY_PUBLIC_N, and tests/compound/compound_drive.c:75's hand suffix list must move (unlisted). Seven `pcrec_entry_emitted(cx, PCREC_ENTRY_NEXT)` sites would each need a sibling. Fix: no new PcrecEntry; the single ITERATE row emits both controllers; next_n takes next's linkage bit.
2. MAJOR, PLAUSIBLE. Flip the one-body shape: I1's _next body becomes static always_inline `__one`; `_next` = `__one`; `_next_n` = `for(i<k) if(!__one(..)) break`. `_next` identical to I1 by construction; next_n == k calls by definition. Deletes the fold prediction and §2.3's fallback (a conditional second copy of the dispatch). Cost: one predictable hdr load per match. Keep "I unharmed" as a measurement only.
3. MINOR, CONFIRMED. Stage rename: findall_iter.md uses "I2" 50 times for the st stage and "I3" for pair-hits; §2.3 cites "compound_entries.md §3.0 I3" (unrelated) next to stage I3; memfn docs use "I2" for identity-gate arms; plan line 215 on i2design says "I2 = next_n + batch + RX_FOREACH (findall_iter.md §12)" (still batch; cites a disagreeing §12). Fix: keep rev 3's numbers (this stage = I4) or name the stages; rewrite the plan next-line and D171's gloss in the build commit.
4. MINOR, CONFIRMED (ABI). abi is the version of emitted scaffolding (spec §6 row 1; comment-only changes bump it), so the Q2 compare is all-or-nothing: a precompiled RX_FOREACH caller refuses every record from a later pcrec even with rx_info unchanged — correct and loud, no lasting promise. The doubling schedule is caller-side, spec UNSPECIFIED (fine). Reword Q2 plainly. The other direction (new caller, older record) would read past the end of the record: the check is required for safety.
5. MINOR, CONFIRMED (family). entry_rows[] declares entries but the rx_info slot, fn typedef, header declaration and `.next =` initializer (emit_dfa.c:3484) are hand-written; next_n is the second hand copy. Fix: an "rx_info slot" column. U-I2-5 then one row.
SIMPLIFICATION, PLAUSIBLE: [FINDALL-NEXT]'s title still reads "iterator / callback entry"; RX_FOREACH removes the callback entry — record it deleted. The §3.1.3 hand loop (1,063 pairs differ from the iterator) plus public `_next_pos` are a second find-all with different answers.
UNLOCKS: (a) rx_info layout number separate from abi (trigger: first cross-build record holder, [ART-MGR], U-I2-3); (b) retire §3.1.3 and make `_next_pos` internal at [IFACE-PUSH] (trigger: that push or a user report); (c) the slot column (trigger: [V-E]).
Q1 refuse: agree. Q2 once per loop: agree, reworded per item 4. Q3 state in the spec: agree. Q4 withdraw: agree; also record the callback entry as dissolved.
