### CHECKS-5 (CONFIRMED, severity: design (the no-launch proof), effort: small) -- DRY's guard is bypassed when CARD_TIME is already in the process environment
dry_guard's `guarded` refuses a subprocess.run only if argv[0] is `taskset` or the call's `env=` kwarg contains CARD_TIME (~1566). The untimed gate/reach/pool-proof execs (`_exec`, line 1019-1020: `subprocess.run(argv, ..., env=env)` with env=None at lines 1039, 1131, and c6_reach) inherit os.environ. The generated exes run their TIMED path when `getenv("CARD_TIME")` is set (line 654). So `CARD_TIME=1 cards.py time DIR --dry` makes every exec DRY performs a real timed run (unpinned, no taskset), and the guard stays silent, the summary printing "clock calls 0, timed execs refused 0". Harmless stand-in repro (nothing timed): scratch/guard_probe.py loads cards.py, installs dry_guard(), runs `subprocess.run(["sh","-c","echo child sees CARD_TIME=$CARD_TIME"])` under `CARD_TIME=1`: prints "child sees CARD_TIME=1 {'clock': 0, 'subprocess': 0}" (without the env var: empty). Fix: guarded() also checks os.environ (or cmd_time refuses --dry with CARD_TIME set). The selftest guard row (3 plants) does not plant the inherited-env shape. No other path found: grep shows subprocess.run is the only exec primitive (no Popen/check_output/os.exec*/os.system), `timed_launch` is looked up at call time everywhere (RealProbe.measure line 1438, time_cells default line 1148: no module-level alias or default-arg capture), DryProbe never reaches either.

### CHECKS-7 (CONFIRMED, severity: maintenance, effort: small) -- selftest recomputes cmd_c6decide's exit code instead of calling it
The RECORD drills (rdrills loop) compute `rc = 4 if any(d["notrun"]...) or info["retime_notrun"] else 0` themselves and compare; cmd_c6decide is never called by the selftest. Mutants E2 (never 4) and E3 (re-time notrun not 4) survive c6selftest and the non-deadline DRYs; only a DEADLINE DRY (e.g. `--deadline +65` on c6_dig32: first pass complete, re-time truncated) kills them (verified rc 4 -> 0). The gate that catches them is therefore a manual window-drill, not in `make test`'s selftest. Call cmd_c6decide (capture stdout) in the rdrills and refusals loops; same fix gives CHECKS-1 its exit-1 assertion.

### CHECKS-8 (SUSPECTED, severity: maintenance, effort: trivial) -- DRY is not reproducible run to run
Two identical `time --dry --patterns c6_dig32` runs differ (9 vs 10 void launches, 124 vs 125 synthetic launches; also with --deadline): the layout draw is salted by the run id and DryProbe's near-miss voids are per-exe, so the count depends on which exes are drawn. Not a defect in a rule, but it means DRY cannot serve as a byte-exact regression oracle (my first mutation pass mistook this noise for kills; I re-did the "output differs" classifications with those two numbers normalized). If DRY output is ever used as a golden, seed it.

### CHECKS-9 (CONFIRMED, severity: maintenance, effort: trivial) -- a redraw loop with no bound hangs instead of failing
arm_pool's `while True` loop (cards.py 311-316): mutant P4 (redraw salt constant) makes it spin forever (the selftest hung; I killed it by PID after 4 min; the kit's 25-min timeout would have ended it). Mutants like it are "killed" only by a hang. A bounded loop (e.g. 64 redraws then SystemExit2) is the usual guard; with a good hash it never fires.
