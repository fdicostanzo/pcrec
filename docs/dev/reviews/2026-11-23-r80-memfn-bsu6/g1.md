### G1-1 CONFIRMED: a compile failure or timeout on either side is a silent non-mover, never counted (verdict, population)
- Where: tests/memfn/g1_span_vector.py:52-58 (`compile_c` returns None on timeout/rc!=0), :98-99 (`if d is None or n is None or d == n: continue`), :89 and :123 (the printed "N distinct patterns" is the INPUT count), `cmd_dry`.
- Spec: integration.md §17.2 "The manifest is written by the compile pass, never filtered by an outcome, and printed with its count"; block_span.md §9.4 "manifest ... with its count". K35: a population nobody counts.
- Repro (g1/scratch): root with tests/memfn/{span_seed.rxt (3 sites),c1.rxt}; c1 has `[0-9a-f]{17}` (a real corpus mover). Run via a wrapper binary (g1/scratch/wrap.sh) that exits 3 only when argv has `no-span-vector` and `{17}`. Manifest exit 0, header still says "compile pass over 7 patterns", the 17 mover is simply absent (6 rows vs 8), dry prints `real 2` and nothing about the drop. Baseline (real binary) has 8 rows. The same silent drop applies to a pattern that fails to compile on BOTH sides (c1's `a(b`): not in the manifest, not counted, though it is in the "7".
- Consequence: a deny-side-only failure (or a 60 s timeout under load, TIMEOUT=60 at :38) removes a real mover from its bin; dry still says OK unless it was one of the 3 REAL_BENCH patterns (checked by exact bytes, :168) or it empties SPAN-SEED's witness. Any other real mover (the ones that would reach a bin of 8) can vanish uncounted. Corpus also compiles every pattern with NO head flags (tests with `flags` in the head, 39 files) so flag-needing patterns may fail the same way; nothing says how many.
- Fix: record per (pattern, cell) outcome counts (ok / same / moved / default-fail / deny-fail / timeout) in the manifest meta line and in dry output; fail dry if deny-fail or timeout > 0 (default-fail on both sides may be a printed, counted class). Effort small. Blast radius: this tool only (U6 wired nothing else).

### G1-3 CONFIRMED: `op` is taken from the FIRST moving cell and `length` from the max, per layer (label inconsistency, low)
- :100-103: `op if not cur else cur[1]`, `max(length, cur[2])`. A pattern whose byte cell is `window` and utf8 cell `scan` gets whichever cell enumerates first (byte/c-default, so byte), and a decade can come from a different cell than the op. Binning label only (docstring says so), but bins feed the floor-8 reach, so a mixed pattern lands in one bin by enumeration order. Observed: in my run all moving patterns agreed (0 disagreements in 4 movers x 2 layers), so no live harm at today's population. Fix: key the bin on the (op, decade) per cell or print disagreement count.

### G1-4 CONFIRMED (observation, low): `length` is the read extent of the added lines (max `_c + N` + 1), not the repeat width
- `\b[0-9a-f]{32}\b` reads 33 (vs 32 for `[0-9a-f]{32}`, `\d{32}`); a pattern whose boundary read crosses a decade edge (e.g. `\b..{9}\b` reads 10) would bin one decade up. Docstring states "1 + the largest `_c + N`", so the code does what it says; §9.4 does not define `length`. A DOC/definition gap, not a miscount at today's 3 sites (all 32/33, same decade 10-99). Also a mover whose added lines carry no `_c + N` gets length 0 / decade "0" (not seen in my runs; unverifiable without a larger population).

### G1-5 CONFIRMED (doc, low): population unit differs from §17.2/§9.4 wording
- integration.md §R4.9.5 item 3 says movers are "counted as DISTINCT SITE SHAPES (not patterns)"; §17.2 and block_span §9.4 define the census by artifact/pattern, and the tool counts distinct patterns (an artifact with 2 V sites counts once). §9.4's "SPAN-SEED's 28 V sites at width 32 must appear as movers" counts sites; the tool's seed witness counts PATTERNS ("SPAN-SEED movers 1" in my 3-pattern seed; the witness test is `len(seed) == 0` only, not 28 or any floor). The K35 floor witness is therefore a nonempty test, not a count against the known 28/20 (the pins in tests/axes already hold those counts, so the blind-spot is covered elsewhere, but dry itself cannot fail on a seed that lost 27 of its 28).
