### READY-2 (CONFIRMED by code + contract read; contract/answer-gate; effort medium (a design choice, then text); blast radius L2 and L3) — the run's SCAN MEMBER can become a guard byte, which `req_byte` then publishes outside the necessary SET: §5.4 misses the reader, F16's "no reader of guard-vs-consumed" is falsified

- What that breaks, all at the build tree: `docs/spec/tuning.md` §2.27¶4 ("so every value it carries is a member of the necessary set"); `docs/spec/match_api.md` §6.3.7¶5 (line 2424, same sentence; the L2 hunk names only ¶4 and ¶6); `docs/spec/findings.md:109` (the pick is "which member of the necessary set the pre-check scans"); and the CHECK `tests/codegen/reqcube_check.py:251-262`, which asserts both `RX_REQ_BYTE in req_set` AND `RX_REQ_BYTE == bytes[idx]` at an exact scan member: at a guard scan member those two conjuncts cannot both hold, so the check goes red on any such pattern in its population (or, if its population has none, the contract is silently broken).
- Also a speed/semantics reader: the VM route's one-byte check (`pcrec_emit_req_byte_check`, called from `emit_vm.c:13583` at `search_from`) and the no-DFA K65 set-rest (tuning.md §2.29¶3) read `req_byte` as a set member; at BACK a guard byte lies BEFORE `search_from`, so wherever a one-byte gate on `req_byte` is emitted without the run span's `omin`, a scan from `search_from` misses it (`(?<=foo)bar` from 3 on `foobar`, oracle M 3 6, with `f` as the gate -> NOMATCH). §5.4 A1/A2 move the RUN span's floor only.
- Why it is a readiness finding, not a text fix: the fix is a choice the note has not made. Options: (a) the scan member is chosen among CONSUMED positions only, which needs the run to carry which positions are guards (i.e. the stored "ahead/back extent" F16 removed, now with a named reader: `pcrec_req_pick`, `pcrec_find_run_scan_index`); (b) at L2 the SET takes TOP's AHEAD guard bytes too (offsets stay >= 0, A4 survives), and at L3 (a) or a BACK byte rule; (c) reword §2.27¶4/§6.3.7¶5 and the check, accepting a `REQ_BYTE` outside the set, plus a floor on the one-byte gate. Leaning (a): it keeps the published byte a necessary-SET member and the number of new fields is one per run (consumed extent `[c0, c1)` inside the run), read by the pick.
- Not affected: L1 (TOP drops guards at reach 0, so every run position is consumed).
