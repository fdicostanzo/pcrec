## Lessons for the guide

- A per-write amortisation claim must name EVERY term the routine visits (here trail
  entries AND live frames); a critic asked "what is the cost when the other array is
  huge" finds it in minutes. (critics.md: price every loop bound against each capacity.)
- A cost claim measured on one entry (`_in`, big buffers) does not speak for the tiered
  default entry: the fast tier's wasted attempt is a separate cost path. Measure both
  entries for any change touching the VM's capacity handling.
- A latch (one-way switch) decided by one sample of a non-monotone quantity yields
  non-monotone reach; review any "stop for the rest of the attempt" rule for that.
