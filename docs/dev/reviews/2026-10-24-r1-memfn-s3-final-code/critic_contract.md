## Findings

### CONTRACT-1  `_DFA_PREFILTER "none"` / `rx_info.prefilter "none"` on every `"cover"` artifact misdescribes it, and no hunk states it
- status: CONFIRMED (repro: `subj/pcrec -p rx -o x.c --features all --pattern foobar` -> `RX_DFA_SCAN "cover"`, `RX_DFA_PREFILTER "none"`, `RX_DFA_PREFILTER_OFFSETS "none"`, `.prefilter = "none"`; same on all 60+ cover artifacts probed: `\bcat\b`, `[ab]q`, `a|b`, `\b[0-9a-f]{8}\b`, ...)
- severity: doc   - effort: S   - blast radius: every `"cover"` artifact (the default population of D172 S3); readers of `_DFA_PREFILTER`, `rx_info.prefilter`, `--emit-facts` decision stamps
- where: match_api.md §6.3.4¶3 (value set; `"none"` row), ¶6, §6 table row 21 (`prefilter` "the artifact's candidate-start mechanism; never NULL"); the hunk ¶8 covers `_DFA_TABLE`/`_UNIFORM_FOLDS`/`_SCAN_EDGE` only
- detail: ¶3's `"none"` means "no candidate-start filter: the start state accepts, every position is a candidate, or the artifact provably matches nothing". A cover artifact is none of these: its window search IS a candidate-start mechanism (memchr on one stop byte, two memchr streams, a byte walk, the D-hors skip table, or the ofsskip function). A caller reading the stamp (D174: names say what the caller sees) is told every position is a candidate. Either ¶3 gets a cover clause like ¶8's ("on a `"cover"` scan the value is `"none"` because ...") or the stamp reads a value naming the window search. The D80 hunk for S3 left this reader untouched.
