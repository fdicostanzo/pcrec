### FIX-3 CONFIRMED (design; the [VMREC] wait) — `VK_AUTO` is a new KIND, but the call it renders fits EXISTING kinds plus new MEMBERS of closed lists
The VM record vocabulary is the closed `VmKind` enum (worktrees/crit-arev2/src/gen/vm_stmt.h:38-68, `VK__COUNT`), one renderer each in `vm_kind_rows[]` (vm_stmt.c:688-707). A `VK_AUTO` row adds a KIND, so under review r5's ruling S3 waits for [VMREC]'s analysis stage (and S3 does list that wait, §4.1). The call itself has no control: `t = <part>(subject, subject_length, from, bound)` is a VALUE (vm_stmt.h:7-11: "the only free text is a VALUE FRAGMENT (a condition, a source ...)"). It can therefore be built from existing kinds: `VK_LSET` VLO_ASSIGN (vm_stmt.c:491-499, `x = SRC;`) into a new `VmLocalKind` MEMBER (vm_stmt.h:141-149, closed list), `VK_BRANCH` for `t < 0`, and `VK_SEEK` for `scan_position = t`. The call can be a new `VmPieceKind` MEMBER `VP_AUTO` beside `VP_KIT` (vm_stmt.h:76), or plain text. Under the manager's 2026-11-06 ruling ("new MEMBERS of existing closed lists do not wait for [VMREC]"), the VM half of S3 then needs no new kind. Today `VP_KIT`, the kit window, is a PIECE member, not a kind, so the "second opaque kind" parallel in §2.3 is really a second opaque PIECE.
Also: §2.3 lets `VK_AUTO` write `scan_position` ("the result's destination (`scan_position` or an untrailed local)"), but vm_stmt.h:7-9 gives cursor writes to their kind's renderer (`VK_SEEK`, "a cursor write", :62). A `VK_AUTO` that writes the cursor overlaps VK_SEEK's one-writer ownership. The effect set "a field of the record" is a read set, which vm_stmt.h:24-26 reserves for stage (c) ("Records carry no verdicts, no read sets ... stage (c) adds those"). So the effect set waits for (c) either way, but the record shape need not.
Fix: §2.3 states the composition (LSET + BRANCH + SEEK over a VP_AUTO piece / VL member) or argues why a kind is needed, and re-reads S3's [VMREC] prerequisite under the members ruling. Effort S. Blast: S3's schedule.

### FIX-4 CONFIRMED (doc/design; F4 declared effects) — the declared read set `subject[bound − 1 .. from]` is wrong at both edges
§2.3: "reads `subject[bound − 1 .. from]` (the context byte below the bound ... and the byte at `from`, the seed's right context)". Row 2/3's first call is `bound = 0` (§3.1 L_b_i) and the lookbehind's cursor can be `from == subject_length` (WD8's `(?<=a{1,2}$)` on `aa`, (2,2)). As written, the set then names `subject[-1]` and `subject[subject_length]`. Today both reads are GUARDED, not made. Below the bound: `search_from ? ..._byte_class[subject[search_from - 1]] : <scalar accept>` (dir_rev_bound_accept, worktrees/crit-arev2/src/gen/emit_dfa.c:9318-9332). At `from`: the reverse direction's `seed_cond` "match_end_position < subject_length" before `seed_byte` (:9371-9372). The set is also missing the read of `subject_length` that `$`/`\Z` at `from` need (the eol view: is `from` the last position, or one before a final newline). A stage (c) analysis that trusts a declared effect would record an out-of-range read, or miss the length dependency.
Fix: declare `subject[max(bound,1)−1 .. min(from+1, n)−1]` plus `subject_length`, i.e. conditional reads. Effort S.

### FIX-6 CONFIRMED (bytes: S1's label derivation) — W1 and W2 share machine R and instance 0 but emit different label stems in ONE function

### FIX-8 CONFIRMED (doc) — §2.4's "`revend_build_one`'s shape: overflow record and subset budget restored" attributes the subset restore to the wrong function
`revend_build_one` (src/core/compile.c:454-466) saves and restores only `dfa_overflowed`/`dfa_overflow_why`. The subset budget is restored by its CALLERS: `lmwalk_build` (`subset_before` :551, restored :559) and `revend_build_marked`. dfa.c's own comment says `cx->subset_elems` "is NOT rolled back by the optional build's caller" by default (src/ir/dfa.c:1317-1321), and the AUTO work budget refuses only mandatory machines (:1293). A lookbehind lane that copies `revend_build_one` alone would charge every per-branch build to the per-compile K7 budget. Every mandatory machine built after it (the VM hybrid's prefilter DFA) could then refuse a pattern that compiles today. Fix: §2.4 names the caller-side restore (lmwalk_build's) as part of the shape, and states that the lookbehind machines are built AFTER the mandatory ones. Effort S.
