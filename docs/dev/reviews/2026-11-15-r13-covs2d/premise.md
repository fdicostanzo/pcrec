### PREMISE-1 — CONFIRMED (code reading) — answer (a lost guard) — §11.1 item 4 (subject l.736-737); src/gen/known.c:649-660
The re-pointed proof-diff loop `[MF_PROOF_LO, k + 1)` DROPS a check today's loop runs. Today `pcrec_cover_proof_diff` runs to `MF_MAX_FWD` (33) and, for every offset `d > k`, wants ALL ONES (known.c:654 `memset(want, 0xff, 32)`): a kit text that TESTS a byte past the cover's after-context (offset k+1..32) is caught as `under@d:xx` and the compile fails (emit_dfa.c:14495-14499) or declines C14 (known.c:427-432). Under the new range those offsets are never compared, so a kit over-test at k+1 (a form that reads one byte too far, the classic long-span rendering off-by-one) passes C14 and drops matches whose next-after byte is outside the tested set. The sabotage row §11.6 plants only the OPPOSITE error (range left at MF_MAX_FWD). Fix (small): compare over the reply's WHOLE counted range, wanting all ones past k (the reply's range may be longer than k+1), or assert the reply's range ends exactly at k+1. Witness: kitproof row `a{5}` with a plant that makes the proof claim a set at offset 6. Blast radius: every cover, both encodings.

### PREMISE-2 — CONFIRMED (code reading) — answer/maintenance — §11.1 reader list (l.723-727) and item 3 (l.734-735); src/gen/memfn_sites.c:540-549, 551-555, 565-568
§11.1's list of pcrec's seam-bound readers omits pcrec's OWN span writers in `memfn_sites.c`: `pcrec_memfn_wspan` stores `w->len = (uint8_t)len` and `w->core_len = (uint8_t)len` (l.544, 548), `pcrec_memfn_wspan_core` casts `lo`/`len` to `uint8_t` (l.553-554), and `pcrec_memfn_wpos_bits(w, j, ...)` writes `w->set[j]` with no bound (l.565-568). `cover_window` reaches the kit only through these (known.c:600-601). At k = 256..4095 the cast silently truncates (k 4095 -> len 255, k 256 -> 0), and the generic check at memfn_sites.c:596 then reads the TRUNCATED value, so the named internal error §11.1 item 3 keeps cannot fire. These are pcrec code, not the kit's carrier: a grep of the bound NAMES (the subject's stated build-time method) does not find them, since they name no MF_* bound. Fix: name them in the list; the counted carrier's writers take a width type that holds 4095 and check `j < len` (or the carrier's declared bound) before the write. Blast radius: every window site's span statement (pre-check, offset-skip, cover).

(ii) Existing limits on the same object (the cover's k / its artifact), and whether the new one can bind: `PCREC_MAX_REPEAT` 65535 (parse; never below 4095), `PCREC_ANCHORED_MAX_STATES` 4096 (k <= 4095: `a{4096}` reads `anchored-A`, re-run), `PCREC_MAX_EMIT_BYTES` 1,000,000 (FLAG_D, whole artifact), `PCREC_DEFAULT_WARN_EMIT_BYTES` 250,000 (advisory), `PCREC_SIZE_TERM_THRESHOLD` (unroll ladder only, not the cover). (iii) The legal range `1 .. PCREC_ANCHORED_MAX_STATES - 1` couples the new row to a BUILD_D row: `-DPCREC_ANCHORED_MAX_STATES=N`, N <= 32, makes the built-in default 32 illegal; §11.2 says a value outside is refused but not whether that is a build failure or the default clamps. A sentence (refusal at build, by the same static assert §11.1 item 2 adds) closes it.

### PREMISE-7 — CONFIRMED (code reading) — design — §11.1 item 2 (l.731-733), §11.5 ASK (1) (l.875-876); src/gen/known.c:332-337, 588
C15 today checks THREE kit bounds: `k <= MF_WSPAN_POS` (positions per span), `k + 1 <= MF_WREACH` (the after-context span sits at offset k, so the reach must hold k+1 offsets), and `k < MF_MAX_FWD` (the proof range must include offset k). `cover_window` re-checks the first two (known.c:588). The new build-time assertion compares the ceiling against ONE kit number, "the kit's declared most positions per stated span", and the request asks the kit to "name the bound you declare" (singular). A kit that declares 4095 positions per span but keeps reach or the proof range at 4095 offsets passes the assertion and then states a k=4095 cover whose after-context at offset 4095 is outside the reach (the generic check refuses it at compile time: a named internal error on a pattern the width lever admits) or outside the proven range. Fix: the assertion (and the ask) covers all three: positions >= ceiling-1, reach >= ceiling (k+1), proof range forward >= ceiling (k+1). Effort: two lines + one ask clause.
