# contract findings

## Findings


### CONTRACT-1 — NEVER-MATCH moves the anchored entries' give-up surface; no spec hunk says so (CONFIRMED)
- **What a caller sees.** On the old hybrid, `rx_match`/`rx_match_caps` (and their `_in` forms) do not run the prefilter: they run the VM anchored from `ctx->pos` (`rx_match_run` -> `rx_match_anchored`). That VM can GIVE UP. The new DFA empty artifact's `rx_match` returns `-1` after the refusals. So a give-up code becomes "no match".
- **Repro, default budgets.** `(a|ab)*(?!a)a`, byte, subject = 5000 x `a`, `ctx.pos = 0`. Before (reproduced as `--engine=vm -fprefilter`; `RX_RESUME_FRAMES 2048`): `rx_match` = **-3 (PCREC_ERR_FRAMES)**. Same at n=100000. After (`--engine=auto`, `RX_ENGINE "dfa"`, `RX_DFA_SCAN "empty"`): `rx_match` = **-1**. `rx_search` and `rx_next` give 0 on both (the prefilter already answered them). Driver: `run/gf/{A,B}/one`.
- **Repro, tuned budget.** `(a|aa)+(?!a)a --step-budget=5`, subject = 30 x `a`, pos 0: before `rx_match` = -2 (STEPS), after -1 (`run/gu2/diff`).
- **Contract gap.** The direction is benign (a give-up becomes the true answer, the way tuning.md §2.35¶3 allows and says). But match_api.md §6.3.4's `"empty"` row, facts_listing.md §4.1.2¶12 and the abi changelog ("no answer moves") say nothing about it. tuning.md §1¶2 counts a give-up as part of the failure surface. The spec should say in one sentence that a give-up of the old hybrid's anchored entries can become `-1`. Otherwise this is a contract change with no spec hunk (D80).
- severity: doc. effort: one sentence in §6.3.4 (and the changelog). blast radius: never-matching capture/backref patterns that callers run through `<prefix>_match`. Site: src/core/compile.c (the switch after `machines_final`); docs/spec/match_api.md §6.3.4 `"empty"` row.

### CONTRACT-2 — NEVER-MATCH after a retry rung: the DFA artifact keeps `RX_ENGINE_SEL "collapsed-prefilter"` (CONFIRMED)
- **Repro.** `pcrec --features all -p rx -o x.c --pattern '(a)[ab]*a[ab]{20}(?!c)c'` (auto, byte). Also `[ab]*a[ab]{20}(?!c)c` and `(a)[ab]*a[ab]{20}\b\B`. Observed: `RX_ENGINE "dfa"`, `RX_ENGINE_SEL "collapsed-prefilter"`, `RX_DFA_SCAN "empty"`, `RX_DFA_PREFILTER "none"`, `RX_DFA_MATCH "nomatch"`; `rx_info.engine = DFA`, `.prefilter = "none"`.
- **Expected by the spec.** match_api.md §6.3.3's `"selected"` row (the new hunk) says the DFA artifact of a never-matching VM hybrid reads `"selected"`. The `"collapsed-prefilter"` row says "the retry KEPT a prefilter by rebuilding it from the count-collapsed language". This artifact has no prefilter and is not a VM. The stamp contradicts both rows.
- **Cause.** The switch in src/core/compile.c (after `machines_final`) sets `fit.chosen = ENGM_DFA` and `fit.prefilter = false`, but leaves the fit's selection reason as it is. A hybrid built on any retry rung (collapse, likely also `size-cap-retry` on a hybrid) then reaches the DFA empty artifact with that rung's value.
- **Fix shape.** Either the switch rewrites the reason to `"selected"`, as the spec promises, or the spec names a value for it (for example a new one that says the pattern matches nothing). Note that `"selected"` is defined as "nothing overflowed", which is false here. So a spec decision is needed, not just a code tweak.
- severity: doc/stamp (no answer moves). effort: small (code) plus one spec decision. blast radius: never-matching patterns whose exact DFA overflows (the same 3 shapes, any counted repeat ahead of a contradiction). Site: src/core/compile.c (the NEVER-MATCH switch); docs/spec/match_api.md §6.3.3 `RX_ENGINE_SEL` table.

### CONTRACT-3 — `--emit-ir` refusal text: the edit dropped the "or" between the two UNSET causes (CONFIRMED, wording)
- **Repro.** `pcrec --features all --emit-ir --pattern '(a)\b(b)'` exits 1 with: "...because every capture slot it promises is permanently UNSET (a zero-count repeat, reached only through a call) or it matches nothing." At BASE the text was "(under a zero-count repeat, or reached only through a call)". The parenthesis now reads as ONE condition with two parts, or as an appositive list. The text also names two causes when the actual cause for this pattern is the third ("it matches nothing"), so the caller cannot tell which one applies.
- **Contract.** The refusal itself is specified (ir_listing.md §1¶3: `--emit-ir` on a pure-DFA artifact refuses and names `--engine=vm`), and that part holds. Only the diagnostic's wording is at issue (pcrec's own diagnostic, not a D26 PCRE2-wording question).
- **Fix shape.** Restore "or", and preferably say the cause that applies: the compile knows it (`never_matches == empty-machine` vs the UNSET-slot route).
- severity: doc (diagnostic). effort: trivial. blast radius: `--emit-ir` users on never-matching patterns. Site: src/core/compile.c, the `--emit-ir lists a VM program` diagnostic.

### CONTRACT-4 — D174: the value `empty-machine` names a mechanism, not what a caller sees (SUSPECTED, arguable)
- `never_matches` (the fact name) and `min-width` (a WIDTH row token, internal and test-only) describe behaviour. The value `empty-machine` (facts_listing.md §4.1.2¶12) names the PROOF's mechanism, "the machines the compile built". The facts listing is a debug listing whose vocabulary is promised (§1¶1), and `--emit-facts` is a caller-facing CLI option. D174 (2026-10-22, binds new names) covers "a CLI option, a stamp, spec prose a caller reads". Against that, ¶12 defines the value as naming "why", and the listing already speaks of machines elsewhere. A behaviour-named alternative would be, for example, `proven` or `no-accepting-path`.
- severity: doc/naming. effort: trivial now, a vocabulary change once shipped. blast radius: the `--emit-facts` vocabulary. Site: src/facts/facts.c `pcrec_fact_render` PF_NEVER_MATCHES; facts_listing.md §4.1.2¶12.

## PROBED-AND-HELD
- **(a) Exports.** NEVER-MATCH artifact vs the old hybrid (reproduced as `--engine=vm -fprefilter`), `(a)\b(b)` utf8 `-futf-check`: the `nm -g` export sets are identical (11 symbols: `rx_search[_in]`, `rx_match[_caps][_in]`, `rx_next[_n]`, `rx_next_pos`, `rx_valid_upto`, `rx_info`). Header: only the §10.4 sizing macros differ (0 on DFA, as specified). Held.
- **(a) rx_info and the names table.** `(?<x>a)\b(?<y>b)`: `rx_group_names` is identical and `nnames`/`ngroups`/`ncaps`/`flags` are identical. Only the per-engine fields differ (`engine`, budgets, frames, `engine_why`, `match_form`), all as specified. Held.
- **(a) Run-time edge calls.** 6 patterns (`(a)\b(b)`, `(?=a)\Kb` utf8 `-futf-check`, `ab\Gcd` utf8 `-fno-startpos-guard`, `(a)(b)\b(c)` `--no-captures`, `(a|aa)+(?!a)a` default, `(a|ab)*(?!a)a` default). About 20 subjects (ASCII, euro sign, ill-formed `c3 28`, mid-character starts, startpos = n and n+1). Each call compared `rx_search` rc and caps, `rx_match`, `rx_match_caps`, and `rx_next`. STARTPOS, UTF and range results were identical in every case (about 120 call rows). The only difference is CONTRACT-1, on `rx_match` give-ups.
- **(a) Vars.** 3 never-matching vars patterns keep the VM (the prefilter is off), so `PCREC_ERR_UNSET_VAR` stays. Held.
- **(a) Stamps.** The native empty artifact `a\bb` and the switched one `(a)\b(b)` have an identical `#define RX_*` set. Held, except for the retry rungs (CONTRACT-2).
- **(a) The fact against ¶12.** `never_matches` across `--engine=vm`, `--engine=vm -fprefilter`, auto and `-fno-prefilter` reads as ¶12 says (`no` without a machine, `empty-machine` with one). Survey of 12 patterns: 9 switched, 3 not (`(a)\z.`, `(a)$b`, an alternation with one live arm; one-sided, as specified).
- **(a) Compile path.** The force loop runs after the artifact is complete, and `Ctx`/`Job` are fresh per attempt, so `machines_final` cannot leak between attempts.
- **(b) FIND-MINW refusal order (lever vs subject).** 8 patterns × 10 utf8 `-futf-check` subjects × starts 0..n+1, about 400 rows, all identical: DFA unanchored, VM, VM hybrid, `\K`, lookbehind, lookahead reach, cover. In every shape seen (DFA, VM, hybrid, vars), the refusals (STARTPOS, UTF, UNSET_VAR, range guard) sit in the public wrapper or before the check, so no refusal becomes 0.
- **(b) Widths.** The UTF-8 caseless widths hold: Kelvin sign folded W=3 on both engines; a caseless back-reference `(\x{212A})(?i)\1` counts W=3 with the backref as 0. Held.
- **(b) Give-up surface.** The VM's existing length prune already makes tail attempts free. Step budgets 1..8 over 3 patterns, plus a default-budget frames probe `(a|ab)*[xy]{3000}` at n = 2995/2900/5005, were identical. So §2.55's ANSWER-IDENTICAL holds as probed.
- **Names (D174).** `never_matches` and `min-width` describe behaviour; `empty-machine` does not (CONTRACT-4).
- Compiles used: about 100.
