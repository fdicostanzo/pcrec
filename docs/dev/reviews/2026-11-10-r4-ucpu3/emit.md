# EMIT findings

## Findings

### EMIT-1 CONFIRMED (size, effort S, blast radius: every island artifact) - the forward and reverse island machines emit byte-identical seglo/segat/bot/cls tables twice
`isl_tables` (src/gen/emit_dfa.c, called twice from `emit_island`, once more from `emit_island_retry`) emits every table per machine under its own name, but `seglo`/`segat` depend only on the machine's island SETS, `bot` only on the encoding, and `cls` only on the byte classes - for `(*UCP)\b\w+\b` (`-e utf8 --features all --emit-main`) all four are identical between `rx__find_f_*` and `rx__find_r_*` (checked element-wise). `gcc -O2 -c` keeps both copies (nm: `rx__find_f_seglo` and `rx__find_r_seglo` each 0x1cfc = 7420 B, `segat` 2x1855 B, `cls` 2x256, `bot` 2x128): 9,659 of the object's 19,488 B .rodata (~50%) is a duplicate. The `__retry` machine (nullable island patterns) would be a third copy of `seglo`/`segat`/`bot`. Nullable island patterns make it three copies: `(*UCP)\b\w*` (RX_ITER_RETRY "retry") emits `rx__find_f_*`, `rx__find_r_*` and `rx__retry_n_*` seglo/segat/bot/cls, retry's identical to f's (checked); its object's .rodata is 29,280 B, of which ~19.3 KB (66%) is the two redundant copies. Fix: emit the segment/atom/bot tables once per artifact when the machines' `iset` lists match (they are built from the same NFA sets, so they always should for f vs r), or key them by content. Not an answer issue.

### EMIT-2 CONFIRMED (doc/stamp, effort S, blast radius: every island artifact's `RX_DFA_START` and `rx_info.search_form`) - the island stamps `RX_DFA_START "attempt-start"`, whose spec definition says no reverse pass runs, but the island walk runs one
Repro: `build/pcrec -p rx -e utf8 --features all --emit-main -o i1.c --pattern '(*UCP)\b\w+\b'` -> `#define RX_DFA_START "attempt-start"` (i1.c:32) beside `RX_DFA_SCAN "island"`, while the emitted `rx__find` runs a `/* REVERSE: ... */` loop over `rx__find_r_*` (emit_island, src/gen/emit_dfa.c). Spec docs/spec/match_api.md:2261 (value-set RX_DFA_START): `"attempt-start"` = "the search recovers no start: its scan is "attempt" ..., "cover" ... or "empty" ... No reverse pass runs (§6.3.1¶5a)"; :2260 `"reverse-pass"` = "the artifact walks its reverse machine backwards from the match end to the furthest-back accepting position" - which is exactly the island's start recovery (match_api.md:2133 says so too). Cause: the `island` LOCATE row is `.whole = true` and asks no RECOVER slot, so RECOVER takes its absence value (emit_dfa.c:12326 `[CAND_SLOT_RECOVER] = "attempt-start"`). §6.3.1¶5a/D174: a stamp names what the artifact runs. Fix: the island row hands RECOVER `"reverse-pass"` (or a new value), and the value-set table names the island under it; the stamp value is caller-observable (D80 spec hunk). Not an answer issue.

### EMIT-3 CONFIRMED (maintenance/doc, effort S, blast radius: none at run time) - the T5 row (`isl_kind`, `tr[isl_na]` = DEAD / self / `PCREC_DFA_ISLAND`) is computed for every island state and read by nothing; internal.h says the emitter renders it
`island_cells` (src/ir/dfa.c ~1780-1796) classifies each state DEAD/SELF/ISLAND and writes `isl_kind` and `tr[isl_na]`. `grep -rn "isl_kind\|DFA_ISL_\|PCREC_DFA_ISLAND" src` finds only that writer (and internal.h); the one emitter reader of the column, `isl_tables` (src/gen/emit_dfa.c:14330), overwrites it: `v[k] = (k % nc) == d->isl_na || t < 0 ? -1 : t;`, and the walk decodes every byte >= 0x80 regardless of the state's kind. internal.h:7854-7858 states the opposite: "`PCREC_DFA_ISLAND` ... the emitter renders it as that state's island token". The emit_dfa.c section header does list "the T5 fast path" as a follow-up, so the behaviour is a known gap; the defect is the comment (a reader trusts that DEAD/SELF states skip the decode, they do not) and a sentinel (-3) that lives in `tr[]` where any future generic `tr[]` walker that tests `!= PCREC_DFA_DEAD` before indexing would read `st[-3]` (none does today: the only such test is dfa.c:1790's own). Fix: say "reserved for the T5 fast path; no emitter reads it at this build" in both comments, or drop the computation until the fast path lands (D77).

### EMIT-4 CONFIRMED (doc + speed, effort S doc / M speed, blast radius: every island artifact's `<prefix>_match`) - the island is a fifth `"search-filter"` population that §3.2¶6 does not list, and its failing match-here walks the rest of the subject character by character, with no skim
Repro: i1.c (`(*UCP)\b\w+\b`, utf8) carries `#define RX_DFA_MATCH "search-filter"` and `rx_match` = `rx_search(...)` then `if (found != 1 || capture_spans[0][0] != ctx->pos) return -1;` (i1.c:801-807): compile_driver skips `build_anchored_dfa` for an island (src/core/compile.c, the `if (island) { build_notempty_dfa(&cx); } else {...}` hunk). docs/spec/match_api.md §3.2¶6 (lines ~896-910): "Four populations take it: "attempt" ..., an anchored machine that exceeded a DFA cap ..., any build under -fno-anchored-dfa ..., and an artifact whose anchored machine was dropped to fit an emitted-size cap" and "the state-0 memchr skip keeps it a skim" - the island is none of the four and has no skip (emit_island: "no prefilter, skip or scan edge"), so an expected-to-fail `rx_match` probe at `pos` on a long subject costs a full forward island walk (decode per non-ASCII character) up to the next match, plus its reverse pass. D80: the population list is the contract. Fix: add the island as a fifth population (doc, now); the anchored island machine (the same `isl_forward` over an anchored island build, no reverse pass) is the speed follow-up - name it beside the T5 fast path in the emit_dfa.c section header's follow-up list.

### EMIT-5 CONFIRMED (size, trivial; effort S) - an island machine with one position view emits BOTH view tables, one all -1, and loads it at run time
`isl_tables`/`isl_views` (src/gen/emit_dfa.c) emit `_eol` and `_end` whenever `isl_has_views` sees either. `(*UCP)\b\w*` (utf8): `rx__find_f_eol[4] = { -1, -1, -1, -1 }` beside a live `_end`; `(*UCP)x\B[\d\p{Greek}]+\b$`: `rx__find_f_end[10]` all -1 beside a live `_eol`. `gcc -O2 -S` of the first keeps the table and 6 loads of `rx__find_f_eol` (not folded). Runs only at the last two positions (`pos + 1 >= n` guard), so the cost is bytes and a dead branch, not speed. Fix: test each view separately (as the byte walks presumably do). Low priority.

### EMIT-6 SUSPECTED, latent (maintenance; would become answer/crash if reached; effort S; blast radius: island machines under a retry rung) - the DFA memo's U3 key compares arena POINTERS, and its "deep copy" restore leaves `seg_lo`/`seg_atom`/`iset[].iv` pointing into the attempt that built them
src/opt/dfamemo.c: `nstate_same` adds `a->wiv == b->wiv` ("the same list is the same pointer"), and `dfa_copy` (`*dst = *src`, then only `tr`/`up`/lists re-duplicated) does not copy `Dfa.seg_lo`, `seg_atom` or `iset[].iv`, which `island_atoms` (src/ir/dfa.c) allocates in `cx->arena` / takes from the AST. The memo outlives attempts (header: "every retry ladder ... is a whole new pass of the pipeline over a fresh arena"; the AST is re-parsed per attempt, compile.c:2831), so on a later attempt a deterministic re-parse into a recycled arena can land the word set at the SAME address: the key then matches and the restore hands the emitter `seg_lo`/`seg_atom` in freed (or since-reused) storage, which `isl_tables` prints. Where no address coincides, the key simply never hits for an island machine (memo dead weight). This breaks the file header's own two contracts ("THE KEY ... by content"; "A RESTORE IS A DEEP COPY"). NOT REACHED today as far as I could probe: an island has no optional contributor for the size-cap ladder to drop - `(*UCP)\b\w{9000}\b` (utf8) is refused outright ("pattern too large: 1164213 bytes"), no retry, and valgrind on that compile reported nothing; selection makes the island DFA-only, so [SEL-1]/[OPT-4] rungs refuse rather than retry. Confirm by: any rung that re-runs `pcrec_build_min_dfa` on an island NFA in a second attempt (e.g. a future island optional machine, or K53 drop) under valgrind/ASan. Fix: key `wiv` by content (interval compare, as `nonascii_same` already does) and deep-copy `seg_lo`/`seg_atom` (and `iset[].iv`) in `dfa_copy`, or simply bypass the memo when `nfa->island` (it is the D77 choice until a retry exists).
