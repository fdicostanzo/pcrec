## Findings

### ANSWERS-1 — CONFIRMED (pre-existing, every engine; not island-specific) — `\B` between two adjacent ill-formed NON-continuation units, mid-subject, diverges from libpcre2 outside §9.5's wording
- Severity: answer (narrow) / doc. Effort: S (a §9.5 sentence + K74-family note), or rule it a PCRE2 inconsistency (D26 addendum). Blast radius: `\B`, `(?<!\w)(?!\w)`-shaped empty matches whose position has an ill-formed unit on BOTH sides, where the right one is a lead/invalid byte (C3, C0, C1, E2.., F5..FF), so neither §9.5¶2 (stray continuation byte) nor ¶3 (subject END) covers it.
- Repro: `build/pcrec -p rx -e utf8 --features all -o rx.c --pattern '(*UCP)\B'` (stamps dfa/island) + a driver calling `rx_search`/`rx_next`. Subject `61 c3 c3 61`: island `rx_search` from 0 and from 1 -> (2,2); find-all `(2,2)`. libpcre2 10.46 (UTF|UCP|MATCH_INVALID_UTF): search from 0 -> NOMATCH, from 1 -> NOMATCH, from 2 -> (2,2); its global iteration from 0 reports nothing. Same on `61 ff ff 61`, `61 c0 c1 61`, `61 f5 f5 61`, `61 c3 e2 61`, `6162c3c320` (island (3,3) from 2, libpcre2 (4,4)). 81 search cells + the matching find-all cells in my matrix, ALL of this one shape (positions with c3|c3 around them in the generated set).
- Island = the plain DFA = the VM: non-UCP `\B` under `-e utf8` (`RX_DFA_SCAN "unanchored"` and `--engine=vm`) give the identical (2,2) on every subject above, so the island inherits a pre-existing line, it does not introduce one.
- Arguably PCRE2's side is the inconsistent one (an unanchored search from 0 misses a match a search from 2 finds, i.e. it never tries the empty fragment between two invalid sequences unless start_offset lands on it), which is the D26-addendum shape; either way §9.5 does not say it. Ask: extend §9.5¶2's family sentence (or K74) to "between two ill-formed units", or rule it.
