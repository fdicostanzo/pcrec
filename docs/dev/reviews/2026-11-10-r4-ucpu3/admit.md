# ADMIT findings

## Findings

### ADMIT-1 CONFIRMED — `--engine=auto` over an island limit (or the state cap) REFUSES, but limits.md §3.9¶4 promises the VM; the refusal text is garbled
- Severity: doc + diagnostic (no miscompile: the compile refuses). Effort: small (spec hunk + a dedicated message). Blast: every utf8 UCP-`\b` pattern whose island machine overflows ANY DFA cap.
- Repro (SUBJECT build/pcrec, `-p rx -e utf8 --features all --emit-main`, default `--engine=auto`):
  - `(*UCP)\b\p{Greek}\p{Cyrillic}\p{Han}\p{Arabic}\p{Hebrew}\p{Thai}\p{Armenian}\p{Georgian}\p{Hangul}\b` → rc=1:
    `a word boundary over the Unicode word set needs the character-stepped DFA ([UCP] U3), and dfa overflowed: >8 context island sets at pattern offset 0 needs the VM engine, which cannot read it until [UCP] U4; restrict the word set with (?aW) (pattern offset 98)`
  - `(*UCP)\b\w*a\w{14}\b` (state cap, limits §3.3.3) → same template: `... and dfa overflowed: >32000 states at pattern offset 0 needs the VM engine ...`
- Expected per limits.md §3.9¶4 (new text, "Over ANY of them ... `--engine=auto` compiles the pattern on the VM"): a VM artifact. That is impossible for an island pattern (the `island` row excludes the VM, select_engine.c:425-432), so the SPEC is wrong, not the code: ¶4 must say that for an island machine auto refuses too (and §3.3.3's auto-falls-back promise needs the same carve-out). cli.md §1.9¶7's refusal list (captures / VM-only construct / --engine=vm / start anchor) also omits this class.
- The message: `forces_dfa_overflow`'s `why` (an internal "dfa overflowed: >8 context island sets" string, src/ir/dfa.c:243-244) is fed through `why_text` into the "%s needs the VM engine" template (select_engine.c:1442-1450), producing "dfa overflowed ... at pattern offset 0 needs the VM engine". select_engine.c:453-455's own comment says exactly this template "reads oddly for a fact that is not a construct's name". Wants its own sentence ("the character-stepped DFA for this pattern is over limit X; restrict with (?aW)").
- "context island sets" also mis-names the population: §3.9¶3b says the island sets are consuming classes AND context sets.
### ADMIT-2 CONFIRMED — `--engine=dfa` over an island limit advises "try --engine=vm", which is itself refused
- Severity: diagnostic (D174/D80: the way out named does not exist). Effort: trivial. Blast: every island over-limit compile under --engine=dfa.
- Repro: `--engine=dfa --pattern '(*UCP)\b\p{Greek}\p{Cyrillic}\p{Han}\p{Arabic}\p{Hebrew}\p{Thai}\p{Armenian}\p{Georgian}\p{Hangul}\b'` → `pattern too complex for the DFA engine (more than 8 context island sets on one machine; try --engine=vm)`; following the advice gives `... which --engine=vm excludes until the VM reads it ([UCP] U4)`. src/ir/dfa.c:246-247 (`ctx_decline`) is shared with the byte machines; on `d->island` the advice should be `(?aW)`.
- limits.md §3.9¶4 also quotes only the "16 context atoms ... try --engine=vm" text as THE refusal while it now covers four limits.
### ADMIT-3 CONFIRMED — the 8-set limit counts the unanchored wrap's own all-non-ASCII loop set, so a user gets 7, not 8
- Severity: doc (limits.md §3.9¶3b says "its consuming classes and context sets together"; the caller cannot see the wrap's set). Effort: one spec clause (or count it out). Blast: patterns at the knee only.
- Repro: `(*UCP)\b\p{Greek}\p{Cyrillic}\p{Han}\p{Arabic}\p{Hebrew}\p{Thai}\b` (6 scripts + the word set = 7 user sets) compiles island; adding `\p{Armenian}` (8 user sets) is refused ">8 context island sets". The 8th is `island_non_ascii` {0x80..0x10FFFF}, the wrap's self-loop N_WCHAR (src/ir/nfa.c:1142, 1395), counted by `island_atoms` (src/ir/dfa.c:478-482).
### ADMIT-4 CONFIRMED — island artifacts stamp `<PREFIX>_DFA_START "attempt-start"` ("no reverse pass runs") while they run a reverse pass
- Severity: answer-of-a-stamp (a caller-observable stamp contradicts the spec's value table; D80). Effort: small (stamp "reverse-pass", or a new value + spec hunk + abi ritual). Blast: every island artifact (also `rx_info.search_form`, which mirrors it).
- Repro: `build/pcrec -p rx -e utf8 --features all -o e6.c --pattern '(*UCP)\b\w+\b'` → `#define RX_DFA_SCAN "island"`, `#define RX_DFA_START "attempt-start"`; the emitted `rx__find` then walks `rx__find_r_*` (the reverse machine) back from the end ("REVERSE: from the end back to the smallest accepting position").
- Spec: match_api.md RX_DFA_START value-set table: `"attempt-start"` = "the search recovers no start: its scan is "attempt", "cover" or "empty" ... No reverse pass runs (§6.3.1¶5a)"; `"reverse-pass"` = "walks its reverse machine backwards from the match end". The new §6.3.2 `"island"` row itself says "the start by the reverse machine stepping back the same way". The value table was not given an island hunk.
### ADMIT-5 CONFIRMED — cli.md §1.9¶7 says the start-anchor refusal is for a pattern that "starts with" ^ \A \G (?m)^; the code refuses ANY start anchor anywhere (any BOT state), and the message points at offset 0
- Severity: doc + diagnostic. Effort: trivial (spec: "contains a start anchor"; message: the anchor's offset). Blast: alternations / multiline patterns with a mid-pattern ^.
- Repro: `(*UCP)\bx|^y` and `(*UCP)\bx\n(?m)^y` (neither STARTS with an anchor) → `a start anchor (^, \A, \G or (?m)^) beside a word boundary over the Unicode word set is not built yet ([UCP] U3: the character-stepped attempt engine); restrict the word set with (?aW) (pattern offset 0)`. Code: src/core/compile.c:3247-3253 fires on the `pcrec_nfa_has_bot` else-arm, `pcrec_ctx_fail(&cx, 0, ...)` — offset hard-coded 0.
- Also: the word-boundary offset in the select_engine refusals names the LAST UCP `\b`, not the first: `(*UCP)\b(\w+)\b` → "(pattern offset 13)", `(*UCP)\b\w+\b --engine=vm` → "(pattern offset 11)" (island_ctx_visit's "first" is the visitor's first, not the leftmost). Cosmetic.
### ADMIT-6 CONFIRMED (against D174) — the new refusals cite plan-row ids, and the new stamp/token/limit names name the mechanism ("island", "nfa", "ISL"), not what the caller sees
- Severity: design/naming (D174: a caller-facing name or message "names the BEHAVIOUR ... never an internal module or mechanism (... lane or row ids)"; binds new names from 2026-10-22, so these are in scope). Effort: small now, an abi event later. Blast: every island refusal and stamp.
- Text: select_engine.c:1435-1450 and :1494-1497 — "needs the character-stepped DFA ([UCP] U3)", "until the VM reads it ([UCP] U4)", "which cannot read it until [UCP] U4"; compile.c:3248-3252 "([UCP] U3: the character-stepped attempt engine)". A caller cannot resolve "[UCP] U4"; "not supported yet" / "is not built yet" says the same.
- Names: `<PREFIX>_DFA_SCAN "island"` (match_api.md §6.3.2 must gloss it as "character-stepped" every time; cli.md §1.9¶7 does); `decline:island-nfa` (facts_listing §4.1.3¶3, "nfa" is the IR); `PCREC_MAX_ISL_SETS`/`PCREC_MAX_ISL_ATOMS` (--list-limits) and the refusal noun "context island sets". A behaviour spelling ("char-step"/"character-stepped") would need no gloss. Argue-or-drop: D174's "not retroactive" covers shipped spellings only; these are all new in this branch.

## PROBED-AND-HELD
- Budget note: I ran ~75 pcrec compiles (over COMMON's ~50; the first 20-pattern batch had to be rebuilt after a shell `read` stripped backslashes). All single compiles under nice; no suites.
- Refusals hold and name a reason, never an internal error or ASCII answer (30 refusal probes): captures without --no-captures (message offers --no-captures and (?aW)); --engine=vm; \K, backref, callout (no --emit-main), atomic, possessive, every lookaround beside UCP \b, including UCP \b INSIDE (?=)/(?<=)/(?!) and as a lookbehind body, and a wide-set one-char lookahead (?=\w); start anchors ^ \A \G (?m)^ (ADMIT-5 for the wording). End anchors $ \z \Z (?m)$ beside \b compile island.
- Admitted: --no-captures with groups and named groups; --engine=dfa and auto; (?aP) leaves \b Unicode (island); (?aW), (?a), (?aW:\b) scoped, (?-aW)/(?-a) re-enable it -> island; (?aW) patterns take their usual route (VM with captures).
- Non-island inputs are byte-identical BASE vs SUBJECT: `-e byte` UCP `\b\w+\b`, `(\w+)\B`; utf8 non-UCP `\b\w+\b`; utf8 `(*UCP)(?aW)\b\w+\b`; and 8 non-ASCII / UCP-set lookaround patterns (`x(?=é)`, `(?<=\p{L})x`, `(*UCP)x(?=\s)` ...) are unchanged, i.e. the island fires only for the UCP word set.
- Answers vs libpcre2 10.46 (UTF|UCP|MATCH_INVALID_UTF), 21 island artifacts x 19 subjects (ASCII, Latin-1, Greek final sigma, CJK, emoji, combining mark, Arabic-Indic digits, NBSP/ZWJ, ß/SS caseless, ill-formed \xff, stray \x80, truncated e2 82, overlong c0 af, surrogate ed a0 80): `_search` from every char-start startpos, `_match` anchored at each, and `_next` find-all: 3,024 checks. Every valid-subject check agrees (0 diffs). All diffs are on ill-formed subjects and are spec'd divergences: libpcre2's ANCHORED crossing an invalid fragment (MATCH and ITER rows; also seen non-UCP), and \B at an ill-formed subject end (match_api §9.5¶3, K74).
- -fstartpos-guard=align (mid-character startpos aligned forward) and -futf-check (ill-formed subject -> -9 for startpos before the bad byte; valid tail searched) behave per spec on island artifacts; retry stamp "retry" on nullable island patterns and the iterator answers PCRE2's spans on valid subjects.
- --emit-facts: land_char and span_facts `decline:island-nfa` as facts_listing §4.1.3¶3 says.
- Set limit: 6 scripts + word set compiles; one more refuses (ADMIT-1/3). NOT probed: the 32-atom limit and the 16 context-atom limit on an island machine (no cheap witness found within budget).
