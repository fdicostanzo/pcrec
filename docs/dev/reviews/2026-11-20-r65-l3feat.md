### A. EMIT-1 + CONTRACT-5 (+ HOUSE-6 unlock 1) — the BACK run displaces a K >= 0 run BASE handed off; R-1's decline then costs the forward re-entry, up to x10 vs BASE — speed, CONFIRMED, verified
- On the default (hybrid) route the run choice prefers the BACK run (K < 0). R-1 then refuses the `handoff` row, so the
  prefilter falls to a start-byte row. `(?<=qz)x?a:`: BASE `handoff` on `a:` (K 1) -> SUBJECT `memchr` with run `qz`
  at −2, whose consumed extent is EMPTY. On 1 MB with no `:`, 225,064 -> 2,325,063 instructions (x10.3). It is faster
  (0.74-0.87) on English-like text. EMITTED also found `-i (?<=foo)bar`, `-i (?<=item )done`, `(?<=a)\Kb` and
  `(?>(?<=a)b)` moving from handoff to byte-class or memchr-bounded.
- CONTRACT-5 adds a second case. `(?<=x)qzjv[a-z]*\d`: the start-byte row now DOMINATES the pre-check, so the pre-check
  and its entry move go away (`RX_REQ_WHY "emitted" -> "dominated"`, `RX_REQ_HANDOFF "0" -> "none"`). This falsifies the
  addendum's "the entry move still applies" and its "no stamp changes under the decline". That census compared decline
  against no-decline; nothing compared against BASE.
- PROPOSED: **FIX-NOW (record)**. The REV 3.3 addendum restates the loss measured against BASE's `handoff` population
  and limits "the entry move still applies" to the cases where it holds. **Ruling needed (code)**: leave the loss as
  ruled, or change the pick. Coordinator's leaning: two steps.
  1. A narrow pick rule at L3: on a route that will decline the handoff, a BACK candidate does not displace a K >= 0
     run that keeps the forward re-entry. At the least, a candidate with an EMPTY consumed extent never does.
  2. HOUSE-6's unlock 1 as a PLAN row, triggered by L2's design. L2 must re-check the re-entry anyway, per the
     addendum's L2 line. The unlock re-enters on the run restricted to its consumed extent,
     K' = whole_maxoff + cons_lo >= 0. That needs its own soundness argument, which is the decline's lesson.
