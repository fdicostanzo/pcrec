## Lessons for the guide (proposed)

1. A design that adds a LIMIT on a walk over a machine must name every limit that already bounds that machine
   (its construction budget, its state ceiling) and show the new one can bind with a witness that has a machine. Three
   critics found R-1 independently in minutes; the design's census said "0 compiles reach 4096" without asking why.
   Proposed premise-lens text: "for each new limit, find the existing limits on the same object (grep limits.def for
   its producer) and run the limit's witness through the build tree: does the object it limits exist at that size?"
2. When a design re-points an instrument to a new record, the soundness lens runs the instrument on the record's TRUE
   values for one non-trivial row before trusting it as a control (R-4: X0 read true rows RED).
