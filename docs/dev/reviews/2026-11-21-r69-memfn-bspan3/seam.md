### SEAM-1: R7w (the F-4 key) still admits unmeasured V cells, by a deny and naturally; the same hole F-4 closed for D1w

- `[0-9a-f]{32}` default: fd=D-hors, k 31 (T-vwin). With `--memfn=no-window-skip` (D-hors's deny, unrelated to spans): fd=**R7w**, loop lo 1..32, k 31, so T-vscan holds. 710 timed hex only as a WINDOW class (confirm.py SITE_EXPECT: scan classes are dig, hi, upper, num). ### SEAM-2: `plan_of` cannot compute `w->skip`: every input of skip is produced AFTER it; the producer is `wf_find_prepare`
CONFIRMED (code reading, build tree 7b0ac8bae). Severity: build (a U1 lane following §3 literally has no pick, no `hl`, no `grp`, no `stop_alone` in `plan_of`). Effort: small (text). Blast radius: U1. Subject §3 "`skip` becomes a plan fact", §14 U1; r68 F-10.
- Order in `wf_plan_site` (window.c:2516-2518): `decide` -> `plan_of` -> `wf_find_decide` (fd_find: the pick and `fx->brow`, :2423) -> Table E walk -> renderer rows -> `wf_find_prepare` (:2578).
- HORS's skip is `plan_ix(w, w->hl)` where `grp[ih] < 0` (d_hors_head :3965-3977): `w->hl` is written by `b_hors_prepare` (:1997-2000, called from wf_find_prepare :2473) and `w->grp` by `find_groups` (:2471). The find rows' skip is `stop_alone ? stop_ix : -1` (find_head :3988): `stop_alone` is written in wf_find_prepare (:2464). `plan_of` (:1486-1540) has only off/set/core/table/stop_ix.
- Skip does NOT depend on renderer-only state (rc, bound): neither head reads them for skip. So the lift is possible, only at a different home: wf_find_prepare after `w->srch->prepare` (B-hors's prepare already writes `hl`, the sibling plan fact), or a skip column on the search renderer row (`ren_search_row`, :2143: the rule is the row's, B-hors vs the three find rows).
- Silent default: `plan_of` starts with `memset(w, 0, ...)`, so an unset `w->skip` is 0, a REAL entry index. The floor (E-generic passes -1 literally, wf_test :3576) and the fused B-fn row (wf_find_prepare returns before find_groups, :2466-2470) must set -1 explicitly, as `stop_ix = -1` is (:1492).
- Readers the note does not list (every one moves if skip becomes a field): `ren_search_row.head`'s `int *skip` signature (4 E-find rows, :2150-2170), `ren_check_row.test`'s `int skip` (:2224; c_find_test :3581, c_floor_test :3589), `wf_find_expr`'s local (:4037-4040), `wf_test_to` (:3536), `wf_loop_len` (:3498).
Fix: §3 names wf_find_prepare (after the search row's prepare) as the producer, states -1 for the floor and the fused row, and lists the readers. The §1 site-map row "skip" stays right (it describes today).

### SEAM-3: "asked at define and use, agree by construction" holds only through a stretch enumerator the note does not name; the window family's own idiom is store-once in the plan
CONFIRMED as a gap (code reading); the store-once alternative is argued against the ruled F-10 wording. Severity: design / maintenance. Effort: small. Blast radius: U1 (and U2's j naming). Subject §3 "Where the table is evaluated", §3.2, §4.1 (`j`); r68 F-10.
- What differs between the two call points: at USE, stretches exist only as iteration state inside `wf_test_to` (:3540-3552): per entry i, skip `skip`, skip C-run groups, `wf_loop_len(w, i, skip)` with the head INSIDE it (:3500), then `i += len - 1`. At DEFINE, `wf_find_define` (:4062-4072) walks no plan entries at all (it writes run_cmp_prepare and the stream's `_sh`). The stretch START (an index i at head 0), k, "the FIRST eligible stretch only" (§3.2: a counter across stretches) and `j` are not plan facts; both askers must reconstruct them. The two asks agree only if both call ONE enumerator; §3 says "both asks read the same plan facts", which is not sufficient.
- `j` is ambiguous: "the stretch's index within the site" (§4.1). If it counts all stretches, a site whose first stretch is ineligible names `vs1`; if it counts V stretches it is always 0. The define and use must compute the same one.
- The precedent fits less than cited: runcmp asks twice because each asker already HOLDS the input (the term `t`, rc_row_of :214). The window family's own idiom is the plan function storing "WHAT THE DEFINE RENDERS" (wf_plan_site header, :2496-2510: skel, srch, strm, chk, fused, each stored in `w`; define and use read them). A per-stretch list `{i, k, form, j}` computed ONCE in wf_find_prepare (after SEAM-2's skip) and read by define and use is that idiom: agreement is then literal, the trace writes one END per stretch, and the floor gets no asks.
- Trace counting (SUSPECTED; confirm by building): with runcmp's MF_PH_RUN at both asks, every stretch writes two non-use END records, and tests/memfn/reach_equal.py (:73-78) and rows_check.py `trace_chosen` (:193-202) count every END whose phase is neither use nor shadow, so each V stretch counts twice. The floor (E-generic) also renders through wf_test_to, so a use-side ask writes wfS records at every floor stretch.
Fix: §3 names the shared enumerator (or adopts store-once), defines `j`, and states the trace phase and what the counters see. Either way the ruling's intent (one selection, two readers that agree) is kept.

### SEAM-4: the `kit_table` spelling elides what `kit_walk` requires, and the new table's homes (contracts, self-check, trace doc, reach decision) are unstated

So V rows carry `"span-vector"` and the use-side ask needs a `gate_in` with `.s` set (else the deny is silently skipped: `in->s` NULL passes the row).

The note names the phase only by "follows runcmp's" (MF_PH_RUN); the gate `use` rows must be stated for that phase.

### SEAM-5: the "one writer lifted from ofsskip" does not fit V's block or heads as described; its readers are unlisted
CONFIRMED (code reading, line by line). Severity: design / build. Effort: small (a decision in the text) to medium (the lift). Blast radius: U2, U3, ofsskip, vrun. Subject §5 "One writer [rev3, F-11]", §4.1; r68 F-11.
- `fn_level_block` (ofsskip.c:707-718) writes exactly ONE function per block: simd_open; `art->includes |=`; `fn_head(name)`; `r->decl->render(art, h, x, r->decl, fall, o)`; "\n"; simd_close. The render contract (kit.h:901-906, `mf_formdecl.render`) is "the helper's BODY (after the seam's head) ... and the closing brace". V's block (§4.1) holds TWO functions, `__w32_b` and then `__w32`, and `__w32_b` must come first. Lifted as-is, the writer has no place for it. The note must pick one: a pre-head text hook, a forward declaration, or `__w32_b` merged into `__w32` (which changes §4.1's text, so F2 must re-read it).
- "taking the function's head as an input" (singular): ofsskip has ONE head (`fn_head`, :614-621) for `__body`, every rung and the selector. V's heads differ: `__body` has `always_inline, unused` (F-6), the selector has `always_inline`, and `__w32_b` takes `(const unsigned char *p)`. So either every V head carries `unused` (one head), or the helper takes a per-role head.
- The call line: `fn_call_line` (:625-632) forwards `subject, n, pos` plus `table_params(decl=0)`. The helper needs the ARGUMENT list as well as the head.
- `render` is typed to ofsskip's walk input (`const struct fn_in *x`, kit.h:904), so a shared writer needs an opaque body callback.
- Readers of the lifted pieces that the note does not list: `ofs_fn_fits` (:671-685, THE FIT TEST: it counts `fn_head` + render + `fn_call_line` against `guarded_max`), used by vrun.c:683; `ofs_fn_fall` (:636-640), used by vrun.c:592; vrun's PREFIX rows render through `fn_level_block`.
- What holds: `fn_selector` (:727-741) is V's selector shape exactly (head; bracketed call to the top helper, else the plain call to `__body`; "}\n\n"). ofsskip's bytes can be kept, because nothing above forces its text to change.
Fix: §5 states the block shape for a two-function level, the head rule (`unused` everywhere, or per role), the argument list input, and the readers (ofs_fn_fits, ofs_fn_fall, vrun.c, mf_formdecl.render). Alternatively it lifts only `fn_selector` (which fits) and keeps V's level block separate until vany's touch, saying why.

### SEAM-6: `__body` moves the stretch's text to FILE scope, but a C-table stretch names pcrec's FUNCTION-LOCAL table (latent compile error)
SUSPECTED (latent; no pcrec witness found). Severity: build (latent). Effort: trivial (one row condition) or small (a table parameter). Blast radius: U2 `__body`, G2-V. Subject §5 ("The `__body` text is today's renderer, unchanged"), §3.1 ("one set and one table offer"), §4.1 ("never reads ... the C-table offer").
- §3.1's k admits a stretch whose entries share ONE C-table offer (`wf_loop_len` :3506 compares `w->table[j] != w->table[i]`). Its loop text is `tbl[S[C + J]]` with `tbl` = pcrec's name from the define hook (`wf_member_of` :3410-3423, `h->table_name`).
- pcrec's offered tables are function-local statics: `emit_u8_table` (src/gen/emit_dfa.c) writes `    static const unsigned char <p>_<tag>[256]` indented inside the function (e.g. `rxa_anchored_byte_class` inside `rxa_match`). This is why ofsskip's file-scope function takes its tables as PARAMETERS (`table_params`, ofsskip.c, "`, const unsigned char *<table>` in the definition"). V's signature `(s, c)` takes none, so `__body` would reference an out-of-scope name.
- Why nothing sees it today: pcrec's window offers are per-offset tables (`<p>_ofs_k<k>`, a different ref per offset, so no 2-entry stretch shares one) plus `can_begin_match`. G2's generator declares its `g2w_t*` tables at FILE scope ahead of the kit's text (g2_win_gen.c:1927-1943), so G2-V would pass where pcrec would fail. 0 of the 12 distinct probe patterns I compiled for this (window and ofsskip shapes, 4 of them at both engines) put a table inside a site.
To confirm: one pcrec site whose stretch of 16+ entries carries one offer. Fix: T-vwin/T-vscan require C-own entries (`w->table[i] == 0` across the stretch; answer-neutral, today's text keeps them), or `__body`/selector take the table as a parameter (the one writer's `table_params` head gives that for free; see SEAM-5).

### SEAM-7: SIBLING + GENERAL FORM: the plan's segmentation is the fact both fixes are reaching for
Argued (design; no defect by itself). Severity: design. Effort: small, if folded into SEAM-2/3's text. Subject §3, §13.
- SIBLING: `w->skip` would be the fourth "the stop/probe role" plan fact, after `stop_ix` (plan_of), `stop_alone` and `hl` (wf_find_prepare / B-hors's prepare). All four are written by the search side and read by the check side. The general form is one search-row column, "the entry the head proved", next to `prepare`, rather than a rule spelled in `plan_of`.
- SIBLING: T-vscan would be window.c's FIRST decision keyed on a finder row's id STRING. `w->brow` = `fd_rows[d.terminal].id` (finder.c fd_find); today window.c only copies it into traces and replies (:2729-2736, :3012-3017). Spelling `"R7w"` and `"D-hors"` a second time in window.c is a two-file literal. A finder-exported predicate (row identity, not text) keeps one spelling.
- GENERAL FORM: a per-site list of SEGMENTS {first entry, kind: lone / C-run compare / one-class stretch, k, form, j}, computed once in wf_find_prepare. `wf_test_to` and the define then read it instead of re-deriving it. SEAM-2's skip, SEAM-3's enumerator and j, and today's `w->head` all become fields of one fact.
- UNLOCKS (each with its trigger): (1) the phase-1 reply or the trace can state per-stretch forms. Trigger: a census counting V sites by the table's own record (r68 lesson 1), or pcrec needing guarded bytes before define. (2) More than one V per site. Trigger: the default width rising above 32 (§15 Q2). (3) V at the floor (E-generic). Trigger: a census of floor stretches with k >= 16. (4) The periodic segment `(ab){500}` as one more kind. Its existing trigger is the forms header's census row with a periodic span of 36 or more.
