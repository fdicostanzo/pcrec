### SLOTS-3 trailgen's verdict table decides DELETE(COPY) and UNTRAIL "from one liveness pass", but UNTRAIL breaks the TRAIL-EQ lemma COPY's resume-edge facts rest on
- status: CONFIRMED (design computation; no bench/corpus pattern searched for the shape)
- severity: answer (latent; if built as tabled)
- effort: S      blast radius: Stage 1's internal order, one sentence in each of trailgen and vmbc, one sabotage row
- where: trailgen §"Proposed general cleanup" ("It computes slot liveness (least fixpoint) and one forward may-analysis"; "Each SET(s, e) site gets the first matching verdict"; Summary "from one liveness pass plus one forward ... pass"); vmbc table row 4 ("copies (must): `L` inherits the facts at the push | TRAIL-EQ") and TRAIL-EQ ("every slot holds the value it had when F was pushed"); trailgen "Why UNTRAIL is sound" (weakens the invariant to "every LIVE slot").
- claim: vmbc's COPY carries must-facts across the resume edge because TRAIL-EQ holds for EVERY slot. UNTRAIL makes TRAIL-EQ hold only for slots live at the resume label, which is exactly what licenses it. A copy write right after a resume label is what makes its slot dead there. Program, verdicts by the tables as written (one liveness, first match per site):
  ```
        s := slot[t]        ; fact s==t
        PUSH(L)             ; L inherits s==t
    A:  s := pos            ; live after (read next). Row 2 no, row 3 no.
                            ; s dead at L (B writes before any read), dead at entry -> row 4 UNTRAIL
        read s ; fail
    L:  B: s := slot[t]     ; must-fact s==t at L -> row 3 DELETE (COPY)
        read s ; accept
  ```
  Stock: at L, s is restored to t's value, B is redundant, the read sees t. Built: A wrote s untrailed, B is gone, the read sees `pos`. Wrong answer. Both verdicts are individually valid on the one liveness; together they are not, because deleting B makes s live at L, which invalidates A's verdict. vmbc's "repeat both to a fixpoint" protects DEAD+COPY against each other, not UNTRAIL against COPY.
- proposal: State the order in the table's preamble: DELETE (rows 2-3) iterates to its fixpoint FIRST; UNTRAIL (row 4) is then decided on the post-DELETE program's liveness and MAYFRAMES, and no later must-analysis may carry a fact across a resume edge for a slot with an UNTRAIL site in the pushed segment. Add a sabotage row: compute row 4 on the pre-DELETE liveness; a witness must catch it (needs a copy-after-resume shape; the splice park/restore pair is the likely producer, vmbc `emit_vm.c:8331/8392`).
### SLOTS-4 The refuse-to-optimise row protects only the BACKWARD pass; the two forward passes (MAYFRAMES, COPY must-facts) have no unrecognised-statement row, so "D first or second is sound either way" is false
- status: CONFIRMED (design computation)
- severity: answer (latent; ordering claim)
- effort: S      blast radius: one row in each forward analysis; trailgen's ordering sentence
- where: trailgen §"Interaction with B+C and D" ("vmbc's row 11 refuses to optimise anything unrecognised, so D landing first or second is sound either way"); trailgen MAYFRAMES rules (PUSH adds, resume edge, CUT keeps — nothing else); vmbc row 11 ("reads every slot, writes every slot, kill all") and "Copies is a must-analysis with 'no facts' at the function entry and at every return label".

  The twins were safe only because vmopt.py refuses the WHOLE artifact on anything unrecognised (vmbc "Anything it does not recognise makes it refuse the artifact"); the table as written refuses per STATEMENT.
- proposal: Give each forward analysis its own row 11: an unrecognised statement's successors are "every label whose address or name it may reach" (in practice: refuse the function), MAYFRAMES after it = every resume label, copies after it = none. Or simply make the table's row 11 "refuse the matcher function", which is what was measured. Then trailgen's ordering sentence is true; as written it is not.
