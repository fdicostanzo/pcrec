## Findings

### COST-1 The shared substrate (the program graph) is the biggest line item and nobody sizes it; the "event stream" it is said to read cannot carry it
- status: CONFIRMED
- severity: design
- effort: L      blast radius: every one of ~180 `pcrec_sb_printf` emission sites in src/gen/emit_vm.c (14,489 lines) or a text re-parser
- where: V "Twins and measurements" ("A build's analysis will read the emitter's event stream"; "needs ... its rewrite step"), A "FIRST+ on the program graph" and Q1, T standing question 2
- claim: V, A and T all say the build reads the emitter's event stream. `VEvent` is `{VEKind k; int a, b; const char *role;}` (emit_vm.c:380-385); `vm_ev` is called from 54 sites against 180 `pcrec_sb_printf` calls; VE_SET carries a slot, never the value expression (COPY needs `slot_values[t]`), and there is NO read event: reads are text inside printf'd C at 76 `slot_values[` sites plus the RX_* macros (RX_CUT reads its mark slot, RX_CHARGE_WORK reads one, the A_BREF compare, accept). A's FIRST+ needs per-statement byte-class membership: VE_CLASS carries a pool id, but spans (`VE_RUNG` kind only), island switches, eos checks and the PRUNE_TOO_SHORT/anchor forks have no class/guard event. Either (a) the events grow to cover all reads/consumes (a program-IR remodel touching ~126 unevented sites, S10's "one call, one truth" rule demands it), or (b) the build re-parses the text it just wrote, in which case the "independent checker" (vmopt_tg.py, altd.py, which do exactly that on text) shares its source with the build and is no longer independent (learnings §3), and it repeats the pattern the file's own comments reject (emit_vm.c:8058 and 10936, "the first form of this fix was a strstr over the emitted buffer").
- evidence / repro: `grep -c 'pcrec_sb_printf' emit_vm.c` = 180; `grep -c 'vm_ev(' ` = 54; `grep -c 'slot_values\[' ` = 76; VEvent at 380-385. Emitted text for `^(a(?1)?b)$`: `RX_SET(RX_SLOT_GROUP1_START, slot_values[RX_SLOT_GROUP1_PENDING]);` is one printf'd line, with the read only in the string.
- proposal: Make the graph its own explicitly estimated stage ("-1") BEFORE ranking stages, and decide (a) vs (b) in the design: with (a), list the events to add (read set, value expr, class/guard for non-consuming forks) and treat it as a remodel under D153 (it touches every emitter and moves no artifact byte, a zero-mover step). A's "M ~300 lines" and V/T's silence are then re-based on it. Hits: V, A, T (seam).
