## Findings



### COMPLEXITY-1 — CONFIRMED — `pcrec_width_walk` is still Theta(n^2) in a user-controlled size; the repeated-frontier stop cannot fire on acyclic or late-cycle patterns, and no cap binds before the walk runs
- Severity: speed (compile time). Effort: design-sized (needs a different exit or a per-state depth-set method, see below). Blast radius: every unanchored DFA-route compile whose NFA has many states live at many depths; the walk time is pre-existing (base identical) but it is the bound the owner's o(n^2) item asks about, and the fix's docstring reads as if the cost were gone.
- Bound from the code (SUBJECT src/facts/kset.c): the loop at :427-444 runs `j` up to min(first empty frontier, Brent detection <= 4*max(mu, lambda) per the docstring :398-401, the backstop `j > nfa->n` at :442); each step is `wadvance` :200-205 -> `wclose` :166-181, cost = states visited by the closure (stamp-deduped, `wpush` :102-108), up to n + edges; the checkpoint compare :431-435 and store :436-441 are O(ncur). So the bound is O(min(n, 4*max(mu,lambda), L_empty) * C) with C = O(n): O(n^2) worst case. The stop shortens only walks whose frontier becomes periodic EARLY relative to n; it does nothing where (i) there is no cycle (the walk ends at the frontier's emptying, depth ~ the longest path, ~n), or (ii) the cycle is reached only after Theta(n) steps (mu ~ n so 4*mu >= n: the `nfa->n` backstop binds, as before the fix).
- Witness family W1 (acyclic, prefix-guarded so the DFA stays small): `q(?:a|bc){N}` — the union frontier at depth j holds every unit i with i <= j <= 2i (~j/2 states) for 2N steps; the DFA tracks one thread, so the DFA does not bound it. Measured (perf inclusive share of `pcrec_width_walk` x total CPU; `perf/prof.sh subject PATTERN`, default flags):
  N=1000 0.031 s | 2000 0.089 s (x2.9) | 4000 0.333 s (x3.7) | 8000 1.338 s (x4.0) | 10000 2.08 s | 12000 2.98 s | 14000 4.17 s (x1.43, x1.40 per x1.2 / x1.17 step = (ratio)^2). BASE at 8000: 1.313 s — identical: pre-existing, untouched by the fix.
- Witness W2 (cycle reached LATE): `q(?:a|bc){N}d+` — subject 0.031 / 0.093 / 0.333 / 1.299 s at N=1000/2000/4000/8000 (x3.0, x3.6, x3.9); base 0.031 / 0.088 / 0.320 / 1.329 s. The stop gains nothing: mu ~ 2N, n ~ 4N.
- Witness W3 (large frontier, long transient inside a loop): `q(?:(?:a|bc){N})+` — subject 0.059 / 0.177 / 0.703 s at N=1000/2000/4000 (x3.0, x4.0); base 0.398 / 1.493 / 6.136 s. The fix cuts the constant ~9x but the growth is still x4 per doubling.
- The caps: the walk runs only on the DFA route with a forward NFA (`decline:no-forward-nfa` otherwise), so the auto DFA work budget / the table engine's 32000-state ceiling (NOT raisable, limits.def:163) bind at about N ~ 15000 for W1 (at 16000: `dfa overflowed: >32000 states`, VM, no walk). The emitted-size cap (PCREC_MAX_EMIT_BYTES 1,000,000) does NOT protect: it is checked AFTER the walk. `q(?:a|bc){12000}` is REFUSED ("pattern too large: 1364790 bytes", rc=1) after 11.4 s CPU, of which the walk is ~3.0 s (25%); at N=14000, 16.7 s refused, walk 4.2 s. Time at the binding cap: walk ~4-5 s of a ~17 s compile that ends in a refusal. (The whole compile is itself ~x4 per doubling on these families — DFA build/minimize — so the walk is a 9-25% share of a quadratic compile, not the only quadratic term; out of this lens's subject but worth the owner's o(n^2) list.)
- What would remove the walk's term: the width fact is (min, max) accepting depth with cycle detection; that is a shortest/longest-path problem on the NFA's consuming graph (BFS for bmin, SCC condensation + longest path for bmax, unbounded iff an accept-reaching cycle is reachable) in O(n + edges), with no per-depth frontier at all. The superset/assertion-passing semantics carry over (an edge per consuming state, epsilon closure collapsed). That is the general form; the frontier walk is the k-set walk's machinery reused for a question that does not need per-depth sets.

### COMPLEXITY-3 — design (GENERAL FORM + UNLOCKS) — the repeated-frontier stop is the general form of TERMINATING A DETERMINISTIC SET ITERATION, but not the general form of the WIDTH question
- Severity: design. Effort: small to note, medium to act on. Blast radius: kset.c's two union-frontier walks.
- What it generalizes: `cur[j+1] = close(succ(cur[j]))` is a one-letter subset construction (every byte collapsed into one letter), and Brent's checkpoint is the textbook termination for ANY iterate x' = f(x) on a finite state space: memory one set, detection <= 3*max(mu, lambda) steps (checkpoint 2^k >= max(mu, lambda), detection at 2^k + lambda; the docstring's 4*max bound at kset.c:398-401 holds). It is the right stop for any walk whose only exit today is a size bound (the K159 shape). The sibling grep (sub-part a) found no second such loop in src/, so there is no second client today.
- What it is NOT: the general form of the width fact. bmin/bmax are shortest/longest accepting path lengths over the consuming-state graph (epsilon collapsed, assertions passed as the walk passes them): BFS for bmin, SCC condensation + longest path in the DAG for bmax, `unbounded` iff a cycle reaches accept — O(n + edges) with no per-depth frontier, which removes COMPLEXITY-1's Theta(n^2) term outright. Caveat for the ruling: it is TIGHTER than the walk where a live cycle cannot reach accept (the walk reads "live past n" as unbounded; a path analysis would return the bounded max) — sound, but an answer change, so it needs its own measurement, not an answer-identity claim.
- UNLOCK + trigger: (1) one shared union-frontier sequence (memoized `cur[0..mu+lambda)`) read by both `pcrec_kset_walk` (first 24 offsets) and `pcrec_width_walk` — worth it only if a third reader appears. (2) Replace `pcrec_width_walk` by the path form — TRIGGER: a growth-sweep row showing the width walk >= ~10% of a compile the user gets back (COMPLEXITY-1 measured 9-15% on accepted compiles and 25% on refused ones at N 8000-14000), or the owner's o(n^2) item being ruled to cover pre-existing walks. (3) The emitted-size refusal runs after E3's facts: a pre-check of the expanded size before the facts (the K151 "refuse BEFORE the table" shape) would cut the 11-17 s spent on compiles that are refused anyway — trigger: the same growth row.
