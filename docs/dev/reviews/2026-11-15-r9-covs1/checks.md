# CHECKS — covs1

## Findings

### CHECKS-1 — the new REACH probes do not tie a witness to its planted site (facts mode is the clean-tree check itself; REACH-DECLINE accepts any decline)
CONFIRMED. Severity: maintenance (diagnostic: a witness that stops reaching its site scores UNDETECTED, not UNREACHED). Effort: small. Blast radius: S3220-S3224, S1131 (facts mode), S3223, S3225, S1136, S1139 (decline mode).
- `tests/kitproof/reach.sh:24-38` `--facts` prints REACH-FACTS-EQUAL iff the clean build's `cover` row equals cases.tsv's value: exactly the comparison `run_cover.sh:83-94` makes on the clean tree. It asserts the row is green, never that the plant's site is on the witness's path. Repro: `reach.sh $TREE - 'a*?a' --facts` prints REACH-FACTS-EQUAL; given as S3220's probe it would pass although S3220's plant leaves `a*?a` unmoved (measured: S3220 plant `a*?a` -> `cover|1|1|97`, same as clean). cover_cap.md §5.4 says the reach record is "the clean run's value equals cases.tsv AND the planted run's differs"; the second half is in no row (it is the matrix verdict itself).
- Decline mode: `reach.sh $TREE - 'ac|bd'` prints REACH-DECLINE (why exact/machine-inexact), so S3225's probe would read REACHED for a witness declined by any conjunct. The site-specific string exists: the listing's `why` column reads `no-eol-view` for S3225/S1136/S1139's witnesses and `statement-fits` for S3223's (measured, `--emit-facts`, clean tree). [MECH-REACH] doctrine (run_sabotage_matrix.sh:50-55) asks for "the EXACT diagnostic each witness produces AT THE SABOTAGED SITE".
- Fix: let reach.sh print the `cover` row's `why` (e.g. `REACH-WHY=no-eol-view`) and set SAB_REACH_EXPECT to it; for facts rows, assert the specific field the plant moves (e.g. S3220 `exact_len >= 33`, S3221 two depths with `[n]` sets).

### CHECKS-2 — `facts` values cannot see a count-preserving wrong member: every multi-byte set is spelled `[n]`
CONFIRMED (by construction + measurement). Severity: answer-risk on the standing check (the value check is weaker than §3.6 Q2's table claims). Effort: small-medium. Blast radius: every `facts` row with a non-singleton position (a[xy]c|b[xy]d, ac|bd, \w(?=\d)\w, [a-z0-9_ ]\b[a-z ], a{40}(?:b|cc), a{30}(?:b{30}c|d), ab|abc|ad, a(?=b)[a-z]|ac, [ab](?<=a)c|bc).
- `src/gen/known.c:682-687` (`pcrec_cover_listing_cells`) prints a set of n>1 bytes as `[n]` (facts_listing.md §4.1.2¶6's kset_walk spelling). So `run_cover.sh`'s value compare sees a set's SIZE, not its members. Nearby regression it misses: a walk that maps a class member to the wrong byte (e.g. a clsmap/upc off-by-one, or a case-fold slip) turning S_1 of `a[xy]c|b[xy]d` into {x,z}: the row still reads `[2],[2]`. Measured instance of the blindness: S3224's 'z' is seen on `a*?a` only because it changes the COUNT (1 -> [2]); on `a[xy]c|b[xy]d` it shows as `[3]` likewise; a REPLACED byte would not.
- cover_cap.md §3.6 Q2 credits the `facts` rows with seeing (a),(b),(c) "each by value" and X0 (`x0.py stated`, "run once by the build") with overstated sets; once run, X0 is not a standing check, so between builds only the answer rows (cover-admitted patterns only) see a member error. For non-cover rows (exact/machine-inexact, end-at-k, statement-fits) nothing standing does.
- Fix options: spell `[n]` rows in full in the `cover` section (it is a new section; the kset_walk spelling is not forced on it), or add a hash/member column the facts compare reads.

### CHECKS-5 — no `facts` or verdict witness has a set member >= 0x80 or runs under `u`: nearby walk regressions on high bytes / utf8 pass test-kitproof
SUSPECTED (the miss is by construction; the planted compiler cannot be built here). Severity: answer (a missed regression would be a wrong cover answer on utf8 patterns). Effort: small (two or three rows). Blast radius: the walk's set comparison and the loader's `utf8` keying.
- All 16 `facts` rows are FLAGS `-` (byte); no cases.tsv pattern holds a byte >= 0x80 (python scan of tests/kitproof/cases.tsv: the only non-ASCII bytes are `§` in WHY text). So the loader's `enc=utf8` branch (run_cover.sh:86, reach.sh:29) is never exercised by a facts row, and no witness has two rows whose sets differ only in the high half.
- Nearby regression S3221 misses: the row compare at known.c:215 reduced to the low 16 bytes (`memcmp(first, b32, 16)`). Clean tree: `--emit-facts -e utf8 --pattern 'aé|bè'` -> `utf8 exact/machine-inexact - 2 [2],195` (the rows at depth 2 differ only in A9 vs A8). Under that regression the walk reads {a,b}x{C3}x{A8,A9} as a product, both depth-3 rows accept, and the decision would admit a cover that matches "aè" (PCRE2: no match). No kitproof verdict/facts/answer row is on that path.
- Fix: add `facts u aé|bè` (value `exact/machine-inexact|-|2|[2],195`, checked by enumeration) plus a `verdict u ... decline`; it also exercises the utf8 key.

### CHECKS-7 — cases.tsv mixes encodings in its WHY column
CONFIRMED. Severity: doc/maintenance (cosmetic today). Effort: trivial. Blast radius: tests/kitproof/cases.tsv.
