## Findings

### CONTRACT-1 — CONFIRMED (doc/listing; answer-free): a walk that ends one past a `$`-admitted final newline lists `k` `-`, against [4.5¶3]
- Repro: `build/pcrec --features all --emit-facts=byte,utf8 --pattern 'a$\n'` (also `ab$\n`, `a\Z\n`) -> `byte fixed-width - 2 97,10` (both encodings). Expected by [4.5¶3] ("`k` is a decimal where the walk ended at an accept or after that newline"): `k` `2`. Design §3.1 rule 1 gives `k = j` for both "no rows" and "a view-gated newline consumed at j-1"; FI-4 lists `k` for `view`.
- Cause: `src/gen/known.c:195-196` (`kn_walk`) tests `nrow == 0` (EMPTY) BEFORE `viewed` (VIEW); when the view-gated newline is the ONLY continuation it adds `\n` to the set but no row, so the next depth has no row and the stop is recorded EMPTY; `cc_width` (known.c:321) then marks `k_known` false. VIEW is only recorded when some real row also survives.
- Decision unaffected (C7 fails either way: the rows at `k` are empty), so no route or answer moves; the listing's `k` and the record's `stop` are wrong for this class, and [4.5¶3]'s own text is ambiguous ("where no row is left: `k` is that depth" then "`k` ... else `-`").
- Fix: swap the two tests (VIEW before EMPTY), or say in [4.5¶3] that a newline-only end reads `-`. Effort: 1 line + a facts expectation. Blast: listing only.
- Cite: facts_listing.md [4.5¶3]; cover_cap.md §3.1 rule 1, §3.3 FI-4.
