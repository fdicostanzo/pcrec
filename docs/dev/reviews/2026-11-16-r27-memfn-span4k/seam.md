# SEAM findings

Lens: seam round-trip + contract (memfn-span4k, SUBJECT a9d13217c).

## Findings

### SEAM-1 — a refused ask can still write the caller's `rows` (wdecide CONFIRMED; mf_ask SUSPECTED)
- CONFIRMED. Design §5 "Where the rows live" (r45_reply_rev6.md:1116-1118): "on -1 they write nothing to `rows` and leave `*out` zeroed". `mf_wdecide` with a framed call (MF_WCALL_DEFINE) and an `mf_rows` that has `plan`/`plan_term` (plan_cap sufficient) but `plan_test` NULL returns -1 with `*out` zeroed, AFTER `reply_of` has written `rows->plan[0..nplan)`/`rows->plan_term[0..nplan)`: memfn/src/window.c:2801 calls `reply_of` (writes, :1333ff) before `reply_frame`'s check `if (out->nplan && !rows->plan_test) return -1;` (:2699-2701).
- Repro: seam/probe.c (gcc -O1 against SUBJECT build/libpcrec.a; `probe_wdecide`): sites cover32 (k=32 `[0-9a-f]` window span, nplan 31), cover32+after (nplan 32, E-find), lit8+after (nplan 9): plan/plan_term pre-filled 0xAB, observed overwritten on rc=-1 (3/3 framed cases); expected untouched. The R-cap path (plan_cap = nplan-1) and the NULL-`rows` path DO hold (rows untouched, out zero) on every case.
- SUSPECTED (code reading, not driven): `mf_ask`'s `ask_sel` (memfn/src/compose.c:1192-1196) runs `kit_class` (which `kit_proof_open`s and fills the caller's proof rows) BEFORE `fd_pres`/`pres_layout_check`, whose refusal returns -1 with rows already written. Confirm with a FIND site with presence spans whose `pres_layout_check` fails.
- Fix (one of): check every refusal before the first write (move reply_frame's plan_test check into reply_of's precheck; in ask_sel run fd_pres/pres_layout on a verdict-only class first), or weaken the design sentence to "on -1 `*out` is zeroed; `rows` contents are unspecified" and say so in memfn.h's mf_ask/mf_wdecide comments (today memfn.h says neither, so the header and design disagree by omission).
- Severity: doc/contract (no pcrec caller reads rows after -1; every pcrec -1 is ctx_fail). Effort: small. Blast radius: kit only (window.c reply path, compose.c ask_sel) or one design sentence.

### SEAM-2 — pcrec_memfn_rows allocates BOTH parts for every ask; each ask reads only one
- CONFIRMED by reading (sizes by arithmetic, not measured). src/gen/memfn_sites.c:183-200 (`pcrec_memfn_rows`) allocates the proof part (`proof_cap` x 32 B) AND the plan part (`plan_cap` x 7 B) from `cx->arena` for every caller. memfn.h's own `mf_rows` comment (and design §5) says `mf_ask` reads only the proof part and `mf_wdecide` only the plan part ("a part a call does not read may be NULL/0"). So: the three `mf_wdecide` callers (emit_dfa.c window_reply_ask, the PCREC_CAND_TRACE re-ask in ofs_site_define, and req_run_at's COVER wdecide, emit_dfa.c:16347-16348) each take `mf_rows_need`'s proof minimum they never read (cover: (k+1..k+2+8) x 32 B = ~1.3 KB at k=32, ~131 KB at k=4095 once the raise lands), and the cover's `mf_ask` (known.c:418, ceiling) takes a plan part of `plan_cap` x 7 B (~28 KB at 4095) it never reads.
- Design §5 "Stack and arena" prices ASK rows as "proof_n x 32 per class ask ... plus 7 B per plan entry per window ask": the shipped allocation is larger than the design's arena budget by the cross terms (at k=4095 per cover compile attempt roughly +131 KB +28 KB on the ~291 KB stated, summed over the size ladder).
- Fix: `pcrec_memfn_rows(cx, s, part)` with part = PROOF / PLAN / PROOF_CEILING (zero the other cap), or each caller zeroes the unread cap. Severity: size (compile-time RSS, only material after the raise). Effort: tiny. Blast radius: pcrec memfn_sites.c + 7 call sites; no emitted byte.

### SEAM-4 — header comments under-state the implementation in four small places
- CONFIRMED by reading (compose.c/window.c at SUBJECT vs memfn.h at SUBJECT):
  1. mf_rows_need (memfn.h:1605-1614) states `*proof_cap = min(MF_MAX_FWD, last stated position + 2) - MF_PROOF_LO`; the code (compose.c `mf_rows_need`, and `kit_proof_open`) clamps `end` to >= 1 ("rows -1 and 0 always lie inside: the copies"). A FIND whose terms all lie at or below -2 (e.g. one SET term at -3; legal, MF_MAX_BACK 8) gets 9 rows, the formula says 7. Same clamp is missing from mf_class's proof comment ("end = max(last stated position + 2, last tested offset + 1)"). Both sides agree with each other, so no refusal; the header is just not the function.
  2. mf_rows_need says PURE, but `wf_stated_offsets` (window.c, end of file) `calloc`s a 4,104-byte bitmap and on allocation failure silently returns a LARGER plan_cap (every position counted, duplicates included). Same answer under normal memory; an over-count, never an under-count, under OOM. Say "pure up to an over-estimate on OOM" or count without the heap (the offsets lie in a 4,104-wide range: a 513-byte stack bitmap fits the 4 KB bar).
  3. mf_wdecide's refusal list (memfn.h:1835-1837) names "a NULL `rows`, or a plan longer than `rows->plan_cap`", but the code also refuses NULL `plan`/`plan_term` on a non-empty plan (reply_of) and a NULL `plan_test` on a FRAMED call with a non-empty plan (reply_frame, window.c:2699-2701). The second is the SEAM-1 path. mf_rows' own comment says "a part a call does not read may be NULL/0", and DEFINE/EMIT DO read plan_test, so it is implied, not stated.
  4. mf_class's proof comment (memfn.h:1366) still defines the meaning on the removed member ("proven[d - MF_PROOF_LO] is a bitset ...") with a parenthetical that it was replaced; a reader of the struct finds no `proven` field. Respell on `proof[d - MF_PROOF_LO]` for d inside the count.
- Severity: doc. Effort: tiny. Blast radius: memfn.h comments only (no layout, no abi event).

### SEAM-5 — principle 9: everything that crosses is a counted list (round-trippable), but the NEW per-reply state is printed nowhere
- Pointers crossing the seams at SUBJECT (new ones marked NEW), each with the count that bounds it:
  - statement (pcrec -> kit): `mf_site.alts`/nalt, `mf_walt.spans`/nspan, `mf_site.preds`/npred, `mf_term.run`,`mask`/run_len (existing); NEW `mf_wspan.set`/len and `mf_wspan.table_ref`/len (host arena, pcrec_memfn_wspan).
  - request storage (pcrec -> kit, written by the kit): NEW `mf_rows.proof`/proof_cap, `.plan`,`.plan_term`,`.plan_test`/plan_cap. Text form: two numbers (the caps), derivable from the statement by mf_rows_need, so the storage pointers carry no fact.
  - reply (kit -> pcrec): NEW `mf_class.proof`/proof_n (an ask: the caller's rows; a define via mf_defined: the ART's arena), NEW `mf_wreply.plan`,`plan_term`/nplan and `plan_test`/nplan-or-NULL (caller rows).
  - existing callbacks/shared state unchanged: `mf_arena` at mf_art_begin, `mf_hooks` callbacks, `mf_hooks.u` (design calls them pre-existing seam debt; the subject adds none — HELD).
  - SHARED STATE that is new: a reply now ALIASES the caller's storage. A by-value copy of mf_class/mf_wreply (pcrec: CandAsked.cls[][], UnanchStart.wr and `rus = us`) shares rows; a second ask into the same mf_rows would silently rewrite an earlier reply's lists. pcrec avoids it by construction (pcrec_memfn_rows allocates fresh storage per ask, verified at all 8 call sites), but nothing checks it; a text round trip would serialize values and lose the alias, i.e. the in-process seam has a hazard its text form does not.
- Printed? `proof_n` (the per-reply range end, the new fact the whole design turns on) appears in no MFTRACE record (compose.c:1220's `MFTRACE ASK` prints rc/exists/libc_free/includes only), in no emitted comment, and in no memfn/docs/trace_format.md record (which also never documented `MFTRACE ASK` at all: pre-existing gap). An ask's refusal kind (R-out / R-cap / R-short / NULL storage / other) is a bare -1 by design (pure ask), so pcrec's `cc_served` "refused" detail cannot tell an R-cap from a real decline: the design accepts this ONLY because the cover passes the ceiling (ruled), and every other caller fails loudly on -1. HELD for correctness; a gap for the "every seam is a document" reading.
- Suggest: add `proof_n=N` (and on rc=-1 nothing more, staying pure) to `MFTRACE ASK`, and document the ASK record in trace_format.md in the same change. Severity: doc/design. Effort: tiny (one fprintf field + one doc paragraph; MF_TRACE-only, no emitted byte). Blast radius: MF_TRACE builds and their log readers (grep `MFTRACE ASK` readers first).

### SEAM-6 — (b) the family: mf_rows IS the third member as designed, but the define side adds an unnamed variant (an art-owned counted reply list)
- The design's family (r45_reply_rev6.md:1152-1158) is CALLER-owned output lists: (1) inline fixed cap (mf_finder_listing/MF_FINDER_MAX 32, memfn.h:1919-1930; still also mf_class.pres[MF_MAX_PRES], pres_row/pres_led); (2) caller buffer + size (`char *err, size_t n`: mf_opts_check memfn.h:2027, mf_target_parse :2129, mf_family_parse); (3) caller pointers + caps + pure need (mf_rows/mf_rows_need). The subject's ASK side is exactly (3) — HELD. Statement-side lists (mf_wspan.set/table_ref) join the pre-existing host-pointer+count INPUT family (alts/nalt, spans/nspan, preds/npred, run/run_len) — not an output shape, HELD.
- NOT in the census: the DEFINE side's reply list. `mf_defined` returns `mf_result.cls.proof`/proof_n pointing into the ART's arena (compose.c define_sel, `kit_proof_st st = { NULL, 0, art->a }`), lifetime = the art's arena. That is an output list neither caller-owned nor inline: a 4th shape by the design's own definition (its nearest relative is mf_art_error's art-owned string, which is not a counted list). The design chose it on purpose (§5 "The define side is not an ask"), so this is a CENSUS gap, not a defect: the "never a fourth shape" rule should either name it as (3b) "art-owned counted list, valid until the art's arena dies" or fold it into (3) by giving mf_defined a `rows` too.
- Severity: design/doc. Effort: tiny (one sentence) for naming; the fold is an abi event (MF_SITE_ABI) and moves pcrec's two mf_defined readers. Blast radius: design text / memfn.h comment.

### SEAM-7 — (b) the general form and its unlocks (each with a trigger; none to build now)
- GENERAL FORM (agreeing with the design, sharpened): a reply list is `(count, element kind, storage)` where storage is the CALLER's when the call is pure (ask) and the art's when the call mutates the art (define), sized by a pure `need(statement, call kind) -> caps`, with "outside the count = the list's neutral element" (all ones for proof rows, NONE for plan entries). The subject has every piece except the CALL-KIND argument of need: mf_rows_need sizes both parts for every call, which is the root of SEAM-2.
- Unlocks beyond the design's four (finder listing, pres[] counted, run-length proof element kind, one serializer):
  - U1 `mf_rows_need(site, call, ...)` (or a parts mask): each ask gets only the part it reads; removes SEAM-2's cross allocation in every caller at once. TRIGGER: the raise landing (k up to 4095 makes the cover's unread proof part ~131 KB per wdecide), or covcost2's RSS row — whichever first.
  - U2 a STATEMENT-side run element kind: `mf_wspan` positions as `(set, repeat)` runs. A cover `[0-9a-f]{4095}` states 4,095 identical 32-byte sets plus 4,095 table words (~147 KB of host arena, design §5 "Stack and arena") that are one fact. Same element-kind move the design names for the proof rows, on the request side. TRIGGER: covcost2 showing host statement arrays as a material RSS share (the same measurement as the design's run-length proof trigger: build both or neither).
  - U3 mf_defined taking `rows` (folds SEAM-6's art-owned variant into shape (3); define products then outlive any arena policy). TRIGGER: the first host whose art arena is not its compile arena, or the first out-of-process consumer (the design's serializer trigger).
  - U4 one kit-internal LIST DESCRIPTOR table (count member, pointer member, element size), read by the kit's deep compares (kit_class_same, window.c wr_members' WR_L, wf_agree) and by the future serializer. pcrec's wreply_same and the tests' compares stay their own (independence, learnings §3). TRIGGER: a fourth counted list on a reply struct, or the serializer, whichever first (today three hand-spelled compares in the kit).
  - U5 an ask refusal REASON out-param (or MFTRACE field) naming R-out/R-cap/R-short/no-storage. TRIGGER: the first time a pcrec "refused" detail needs triage, or any non-cover caller passing less than the ceiling where a host control (like B5) exists.
- Severity: design (forward-looking). Effort: none now. Blast radius: n/a.
