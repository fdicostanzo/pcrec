## Findings

### EMIT-1 — the cover proof comparison now walks the whole ceiling (4104 offsets x 256 bytes), 100x its BASE work, for rows it knows are all ones
CONFIRMED by reading (no emitted byte moves; probing confirms SAME on every cover pattern tried).
- Where: src/gen/known.c:650-670 (`pcrec_cover_proof_diff`), callers known.c:430 (C14 `cc_proven`, every cover decision) and src/gen/emit_dfa.c:14517 (the [KIT-VERIFY] check on every cover define). Plus src/gen/memfn_sites.c:189/193 (`pcrec_memfn_rows(.., true)`, known.c:418).
- What: the loop is `for (d = MF_PROOF_LO; d < MF_MAX_FWD; d++)` with a 256-iteration `kn_has` compare per offset. BASE: MF_MAX_FWD = 33, 41 offsets. SUBJECT: MF_MAX_FWD = MF_WREACH = 4096, 4104 offsets, about 2.1M bit tests per call. Every offset past `MF_PROOF_LO + proof_n` compares the constant `ones` row against `want`, which is also all ones there (d > e->k), so the extra 4,000-odd iterations can never return a difference. In the same way the ceiling storage (main's cover-ask-storage ruling, which I do not dispute) costs a zeroed 4104 x 32 = 131 KB arena block per cover ask. That is above ABLOCK_MIN (64 KB, src/core/arena.c:6), so each ask mallocs a new head block and abandons the tail of the current one.
- Why it is not an answer finding: rows outside [MF_PROOF_LO, MF_PROOF_LO+proof_n) are all ones by the MF_CLASS_V 11 contract, and want is all ones past e->k (k <= 32 on SUBJECT, side at k <= 32). The verdict is identical to BASE's.
- Fix (small): bound the loop at `MF_PROOF_LO + max(proof_n, e->k + 1 - MF_PROOF_LO)`, i.e. the last row that either side can make non-ones. Or keep the ceiling loop but skip the bit loop when both rows are all ones. The ruled ceiling STORAGE does not need the ceiling LOOP: the B5 over-read check reads every row the kit wrote, and those are exactly the first proof_n.
- Severity: speed (compile time, per cover decision and per cover define; not measured, no timing allowed). Effort: one line. Blast radius: the cover route only. After the raise (MF_WSPAN_POS 4095) the loop bound is the same 4096, so this does not get worse.

### (b) Reading: why each change cannot move an emitted byte at SUBJECT (held)
- **proven[] (41 fixed rows) to proof_n/proof (compose.c kit_proof_open/kit_class/kit_proof_close, window.c wf_plan_class).** pcrec reads only `proven0`/`proven_prev` (emit_dfa.c 7128, 8581, 8617, 8650, 9269, 12200) and, in the cover check only, rows up to e->k <= 32. The kit has no reader of the rows besides the MF_TRACE self-checks. Offsets 0 and -1 always lie inside the range: end >= 1, so proof_n >= 9. term_prove / the plan's `&=` write the same bits there as BASE, so the copies are byte-equal. The rows newly proven past offset 32 (old-field FIND terms at 33..4095, plan offsets) are read by nobody at default. Non-proving classes (VERIFY, EXPR, PRESENCE, the verdict-only kit_legacy_arm) get all-ones copies, as in BASE (BASE's proven[] was all ones for them). kit_legacy_arm's class is used only as a refusal verdict. Its new kit_proof_open cannot refuse: check_out 0, last_t = last_s so R-short is unreachable, and verdict mode does not reach R-cap.
- **R-out / R-cap / R-short at pcrec's callers.** R-out needs a tested offset >= MF_MAX_FWD = MF_WREACH. pcrec's window_bounds_check (memfn_sites.c:617) and the kit's wf_check already refuse a stated offset >= MF_WREACH, and plan offsets are positions of the chosen alternative (C-floor/C-yes from present positions, C-model from span starts, C-run from the run span, the stop from a stop_ok position), so tlast <= last_s. R-cap on the non-ceiling asks (cand_ask, cand_asked_verify_emit, req_pres_ask, window_reply_ask, req_run_at): pcrec sizes by mf_rows_need, which computes min(MF_MAX_FWD, last_s + 2) - MF_PROOF_LO from the same kit_last_stated. With tlast <= last_s the needed n is exactly that. A legacy-translated window site (E_FUNC/E_STMT) is classed on its translation, whose terms are plan offsets, so they also lie within the original statement. A refusal would be LOUD (pcrec_ctx_fail), never silent, and none fired in 724 compiles.
- **Storage sized by mf_rows_need vs the ceiling.** The cover ask passes 4104 rows (ruled), the kit writes exactly n = end - MF_PROOF_LO rows and reports proof_n = n, and the reader treats rows past proof_n as all ones. The bytes are the same whatever the cap; only memory differs (EMIT-1).
- **Whole-struct compares.** pcrec: `cand_class_eq` compares by field (no pointer). emit_dfa.c:1665 `memcmp(&cls.run, ..)` is over 4 x uint16_t with no padding. `wreply_same` replaces the BASE memcmp but sits only under PCREC_CAND_TRACE. dfamemo.c:69 is a different struct. Kit: kit_class_same and the define's re-ask (compose.c 1370-1400) are MF_TRACE only, and so are wr_first_diff and wf_agree. No default-build path compares a struct that now holds a pointer.
- **uint8_t -> uint16_t widenings** (mf_wspan len/core_lo/core_len, mf_wreply nplan/plan_term/run_len, mf_run_reply). Every pcrec write is bounded by MF_WSPAN_POS = 32 (window_bounds_check, cc_fits, the PCREC_MAX_REQ_RUN_SCAN static assert), so BASE's `(uint8_t)` casts never truncated. Readers use the values arithmetically after promotion, and no generic field reader (gate.c FLD tables, offsetof) assumes a 1-byte width.
- **Host-owned span lists** (memfn_sites.c pcrec_memfn_wspan). pcrec_arena_alloc zeroes (arena.c:35), as BASE's memset of the inline arrays did. One allocation per span, so there is no aliasing between spans. pcrec never struct-copies an mf_wspan or reads one back (grep: no `spans[` reader in src/ besides the bounds check). The kit reads only j < len (cl_toffer, kit_wspan_at, merge).
- **Kit working state per extent** (window.c wf_extent/merge/decide/plan_of). pos_at has one caller (merge, the alternative's own span positions, all inside the extent). The direct indexes (offset 0 at 609/616, with hi >= 1; the stop; plan offsets; walk offsets = span starts; c_run's o and o-1, both plan offsets) all lie inside the chosen alternative's extent. Past the extent BASE held non-present all-ones positions that every loop skipped. pcap = max extent >= np. plan_of's cap np+1 covers the plan plus the stop, and the bound loop writes no entry. All allocators zero (wd_alloc calloc, pcrec arena), as BASE's memset/calloc did. run_part_terms sizes rb as 2*(b-a), and run_bytes writes exactly b-a bytes into each half, so the mask content is the same.
- **formhash.c.** The work struct is calloc'd. sp_set/sp_table are inside it, so it starts zero exactly like BASE's inline arrays. The hash covers rendered text, not struct bytes, and no pointer is hashed.
- **MF_WMAX_SPAN** 32 literal = old MF_MAX_TERM 32. MF_SITE_ABI/MF_CLASS_V are not emitted: the generated header stamps pcrec's own abi 108 on both sides.
- **MF_WREACH 64 -> 4096** widens what the kit ACCEPTS. pcrec states nothing past offset 56 at SUBJECT (prefix walk <= 24 + run <= 32; cover k <= 32 + side; find_window offset 0/-1), so no previously refused statement now passes.
