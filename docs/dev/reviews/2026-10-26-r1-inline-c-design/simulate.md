## Findings

### SIM-1  The §1.7 reference flags leave PCRE2's implicit `.*` anchoring ON: they are not "the unoptimized backtracking order"
- status: CONFIRMED
- severity: answer
- effort: paragraph edit (add `PCRE2_NO_DOTSTAR_ANCHOR` to the reference flag set in §1.7, Goal 2, §9.2, §10 Q1 text)
- blast radius: Goal 2's measurable form, §1.7, §9.2's driver flags, §9.3's re-oracling, §10 Q1's wording ("auto-possessification and start optimization off" becomes three optimizations), the spec sentence §8.2 stage 1 writes.
- where: inline_c §1.7 (lines 265-269: "which is libpcre2 with `PCRE2_NO_AUTO_POSSESS | PCRE2_NO_START_OPTIMIZE`"), Goal 2 (line 37), §9.2 (line 959).
- argument: probe `pc ref '(?s).*(?C3)x' 'axbx'` (callout 3 vetoes iff start_match==0) prints 5 fires, all `start=0`, then `NOMATCH rc=-1`. The unoptimized order (start positions in order, every veto applied) tries start 1, where `.*` reaches `x` at 3 and the callout passes: `pc ref+dsa '(?s).*(?C3)x' 'axbx'` prints fires 6-7 at `start=1` and `MATCH [1,4)`. PCRE2's own pcre2callout(3) "Automatic .* anchoring" says the optimization is NOT affected by callouts and is turned off only by `PCRE2_NO_DOTSTAR_ANCHOR`. So the note's reference is NOT what it claims (§1.7 "start positions in order"), and pcrec's VM (which does not dotstar-anchor a pattern whose start-dependent callout can veto, or must not) would disagree with the proposed oracle on every `(?s).*`-led callout pattern whose callout reads the start (`RX_START`) or anything position-relative to it. The non-DOTALL form `.*(?C3)` on `ab` already gives `MATCH [1,2)` under `ref` (the startline restriction IS lifted by NO_START_OPTIMIZE), so the gap is the DOTALL/implicit-anchor case only.
- proposed fix: reference = `PCRE2_NO_AUTO_POSSESS | PCRE2_NO_START_OPTIMIZE | PCRE2_NO_DOTSTAR_ANCHOR` everywhere the flags are named; the spec sentence says "with auto-possessification, start optimizations and `.*` auto-anchoring off"; §1.8's barrier list gains "implicit anchoring of a leading `.*`" (pcrec must not derive an anchored fact from a leading `(?s).*` across a start-reading site either).

### SIM-2  §1.3's static `ncap` hides a group PCRE2 shows: a group that opens AFTER the site inside an enclosing repeat, closed on an earlier iteration
- status: CONFIRMED
- severity: answer
- effort: paragraph edit in §1.3 (and §1.8's barrier set, which inherits `1..ncap-1`); engine_m4.md §3.4's rule needs the same amendment
- blast radius: §1.3, §1.8 ("every group in `1..ncap-1`"), §7's porting table (`capture_top` row), the marked-set union of §1.3 (a retained higher-numbered group must also be readable at the site), engine_m4.md §3.4 / D38.6's "capture slots known so far".
- where: inline_c §1.3 line 149-151 ("`ncap` is `1 + the highest group number whose opening parenthesis precedes the site`") and its closing claim line 161-163 ("This gives PCRE2's view: ... a repeated group keeps its previous iteration's value"); engine_m4.md:785-787.
- argument: probe `pc ref '(?:(?C7)(a))+' 'aa'` (callout 7 vetoes iff group 1 is set): fire#2 at pos 1 shows `top=2 g1=[0,1)` (group 1 retained from iteration 1), the callout vetoes, and PCRE2 answers `MATCH [0,1)`. Under §1.3 the site precedes group 1's `(`, so `ncap = 1`, `RX_CAP_SET(1)` is false at every fire, the callout passes at pos 1, the second iteration runs and pcrec answers `[0,2)`. Same pattern, same pure predicate, different answer: Goal 2 ("zero disagreements") fails, and §9.2's differential, written exactly as the note says (adapter reads `offset_vector` under `capture_top`), is red on it. The log-only twin `pc ref '(?:(?C0)(a))+' 'aa'` shows the view directly: fire#2 `top=2 g1=[0,1)`, fire#3 `g1=[1,2)`. The note's own retention sentence (a repeated group keeps its previous value) is exactly the PCRE2 behaviour the static `ncap` cuts off whenever the group's number exceeds the watermark. A path-independent constant is still available: `1 + the highest group number whose opening paren precedes the site OR lies inside any quantified group enclosing the site` (or simply `ngroups + 1`, since an unset pair reads -1 and `capture_top` is only an upper bound in PCRE2 too, pcre2callout(3): slots below `capture_top` may be UNSET).
- proposed fix: redefine the site `ncap` as above (simplest: `RX_NCAPS` at every site, unset pairs -1) and say the view is PCRE2's `offset_vector` with `capture_top` replaced by a constant upper bound; §1.8's barrier set and §1.3's marked set read the same widened range. Add `(?:(?C"g1set")(a))+` on `aa` to stage 1's differential.

### SIM-3  `scan-end` mispicks for a `verify` segment that also says `consume`: the scan's end is no longer R's end
- status: CONFIRMED (by the note's own rules plus a libpcre2 stand-in for the scan; no consuming callout exists in PCRE2 to oracle the whole case)
- severity: answer
- effort: paragraph edit (one eligibility row, or one sentence in §2.2 forbidding `verify,consume`)
- blast radius: §4.3 table (a row), §4.4 step 2's premise, §2.2 attribute rules, stage 4's tests (one downgrade case), `--list-callouts` row names.
- where: inline_c §2.2 (line 343: `attr := "verify" | "consume"`, only repetition is refused, so `c,verify,consume:` is legal); §1.8/stage 4 (line 917-918: "`W_ANY` [erases] to any bytes"); §4.2 step 1 (`pos = e`) and §4.4 step 2 ("ends at `e` because the scan proves the end of R's leftmost-first answer").
- argument: with a consuming tail `T`, the hybrid's scan is built from `erase(R T)` = `R` followed by "any bytes, any length". Its span END is the end of that erased pattern, not R's end. libpcre2 stand-in for the scan: `pc ref+dsa 'a(?s:.*)' 'ab'` prints `MATCH [0,2)`, while R alone, `pc ref+dsa 'a' 'ab'`, ends at 1. So `scan-end` builds the tail's view at `pos = 2` and, if the segment passes there with `k = 0`, answers `[0,2)`; the reference fires the segment at `pos = 1` (R's first-priority end) and answers `[0,1+k)` or continues. Nothing in §4.3 sends this pattern elsewhere: row 6 lists lookaround/atomic/`\K`/count-collapse as end-unproven causes, not a `W_ANY` site. (Whether the erasure is greedy or lazy is not stated; with neither stated, the proof's premise is not established.)
- proposed fix: add a §4.3 row before `scan-end`: `consuming-tail` — a tail segment is `W_ANY` → hybrid without `scan-end` (or refuse `verify,consume` in §2.2 until a need is measured); §4.4 step 2 then states its premise as "every tail site is `W_PRED`, so `erase(R T) = R`".

### SIM-4  Erasing a `W_PRED` site to the empty string WIDENS the language; the note never says the erasure sets an "erased" bit, so the hybrid's END facts would arm on callout patterns
- status: CONFIRMED (language fact, probe); the code consequence is SUSPECTED (depends on the build lane wiring the new nfa.c arm)
- severity: answer
- effort: paragraph edit in §1.8 and §4.3 row 6
- blast radius: §1.8 (prefilter paragraph), §4.3 row 6's predicate, stage 4's tests (one row-2/row-5 hybrid whose prefilter end is shorter than the match), the `mrl_win`/`VM_RESEED`/`VM_PRUNE_CEILING` readers in src/gen/emit_vm.c:10336 (`v->mrl_win = pcrec_cand_lang_exact(cx)`).
- where: inline_c §1.8 lines 297-305 and stage 4 line 917-919 (the language rule) versus §4.3 row 6 (line 588: end-unproven = "an erased lookaround, atomic group or `\K`, or a count-collapsed superset"); today's exactness is `nfa->erased` (src/ir/nfa.c:715 sets `NFA_ERASED_LOOK` for exactly this reason: "Erasing a lookaround is NOT exact — it throws away a filter").
- argument: a `W_PRED` site is a FILTER (it can only remove paths), the same shape as a lookaround, so `L(P) ⊂ L(erase(P))` strictly and the erased machine's leftmost-first END is not P's END. Probe: `pc ref+dsa 'a(?C2)|ab' 'ab'` (callout 2 always vetoes) answers `MATCH [0,2)`; the erased pattern `pc ref+dsa 'a|ab' 'ab'` answers `[0,1)`. An artifact whose prefilter span `[0,1)` is trusted as the END (the `prefilter-window` ceiling `mrl_win` arms, or `VM_RESEED "exact"`) prunes the real match. Stage 4 admits the prefilter for EVERY callout pattern (rows 2 and 5 included, which keep the hybrid), so the bit matters beyond `scan-end`. Conversely, if the build does set an erased bit for callout sites, row 6 as written fires on every `verify` candidate (its own tail is an erased site) and `scan-end` never runs: the row must exempt the tail.
- proposed fix: §1.8: "erasing a callout site is a widening erasure (an `NFA_ERASED_CALLOUT` bit, like a lookaround's), so a callout pattern's prefilter proves START, never END"; §4.3 row 6: "R (the pattern minus its tail sites) is end-unproven" — i.e. exactness computed with the tail's erasure exempted, which is exactly what §4.4 step 2 needs.

### SIM-6  PCRE2's documented `start_match` is `\K`-moved; 10.46 does not move it. The note's §1.3 matches the binary, not the documentation, and says neither

- where: inline_c §1.3 lines 164-167 ("The attempt start is where the current anchored attempt began (PCRE2's `start_match`), NOT a `\K`-moved start"); §9.2 line 958 ("`RX_START` is `start_match`"); pcre2callout(3): "if the escape sequence \K has been encountered, this value is changed to reflect the modified starting point".
- argument: probes `pc ref 'a\K(?C0)b' 'xab'` → fire `pos=2 start=1` (attempt start 1, \K at 2); `pc ref '(?:a\K)+(?C0)b' 'xaab'` → `pos=3 start=1`; `pc def 'ab\K(?C0)c' 'abc'` → `start=0`; `pc ref '(a\K)(?C0)' 'a'` → `start=0`. libpcre2 10.46 never reports the `\K`-moved start, contrary to its manual.
