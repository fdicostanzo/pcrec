### meas-1 — the A/A twin's "objects cmp DIFFERENT" assertion is vacuous; the pad+reorder does not guarantee a moved loop
- CONFIRMED (toy repro), FIX-INDUCED (MEAS-1's fix). Severity: design (the noise model's placement term). Effort: small. Blast: every `twin-per-arm` row, FRG, sabotage (j). §3.2 "The A/A twin is a PERTURBED build".
- The text claims "the timed loop's alignment against cache lines and the uop cache therefore differs", proven by "the two built objects `cmp` DIFFERENT". The pad's own 40 bytes make the objects differ ALWAYS, whatever the loop's final address. Repro (`w/arm.c`, a 2-byte stop loop; `w/armb.c` = `__asm__(".text\n.skip 40");` + the same text; gcc 15.2 -O2): `cmp` arm.o armb.o -> differ; gcc emits `.p2align 4`/`.p2align 5` in the function, so the 16/32-byte phase NEVER changes (fn at +0x30, inner 32-B loop at +0x160 vs +0x140). Linked against a driver whose `.text` size varies (12 sizes, `w/drv.c`), in the OPPOSITE object order: the hot 32-B-aligned loop lands on the SAME 64-B phase as the arm's in **6 of 12** links (the reorder undoes the pad half the time; the same-order twin differed in 12 of 12). With `main` alone in the driver it lands in `.text.startup` and the reorder moves nothing (6 of 6 links: twin = arm + 0x30 only).
- Consequence: aa is sometimes a run-noise floor and sometimes a placement floor, unknowably per arm; sabotage (j) catches only "no pad".
- Fix: assert on the LINKED executables (nm/objdump: the timed function's and its hottest loop's address mod 64 differ), or set the phase explicitly and check it post-link.

### meas-2 — J1's rule has no placement term: each width is its own binary, and one 128 twin is ONE draw of placement scale
- CONFIRMED (drill, mechanism); magnitude SUSPECTED (τ unmeasured). FIX-INDUCED (MEAS-8's fix + MEAS-1's twin). Severity: design (a false D186 unit change; lost power). Effort: small. §3.6, `span_cards/j1_drill.py:14-23` (no placement draw).
- Each width literal is a separately compiled artifact, so a width with NO true effect still carries a fixed placement offset; the margin's `aa` is the 128-vs-128#b offset, a single draw. My drill (`w/j1p.py`, j1_drill's model + a per-(pattern, width) offset ~N(0, τ) shared by that pattern's 4 cells, 4,000 drills each): no effect, τ = 0/1/2/4 within-sd: (b) 0 / 0 / **1.27 % / 4.78 %**; (c) 0.18 % / 19.8 % / 41.3 % / 48.7 % ("record the cells where a width beat it" records placement). True effect 4 within-sd: (b) 82 % (τ 0, design's figure reproduced) -> **18.9 % (τ 2), 11.7 % (τ 4)**.
- Fix: a perturbed twin PER WIDTH and a margin over both twins (`sqrt(aa_w² + aa_128² + sp2)`), or several perturbations of each; re-drill with τ stated.

### meas-3 — the half-gated unit now gates the WALK'S PLACEMENT SENSITIVITY, and that refusal is deterministic (a re-run cannot clear it)
- Mechanism CONFIRMED (drill); magnitude SUSPECTED. FIX-INDUCED (MEAS-1 x MEAS-4). Severity: design (run REFUSED / PARTIAL by construction). Effort: small (decide), medium (measure). §3.4 step 5, §3.5 outcomes, §3.5 "re-run whole in a later window".
- noise ≥ aa, and aa now includes the walk-vs-perturbed-walk offset. `w/rates.py` (4,000 draws each, launch sd s, twin offset o, unit gate 1.5 %): s 0.5 %: o 0 % -> 0.15 % refused, **o 1 % -> 10.5 %, o 2 % -> 96.4 %**; s 1.0 %, o 0 -> 37.7 %. At the 3 % cost gate: s 1.0 %, o 2 % -> 11.3 % per row; s 1.5 %, o 0 -> 8.7 % per row (J2's byte group has 3 rows). An offset is a property of the frozen text and layout, so §3.5's remedy ("re-run whole in a later window") REFUSES again; the same holds for a placement-sensitive byte-group form (PARTIAL every time).
- Confirm: S2c's dry run times walk vs walk#b (and libc/pair) once before the window. Fix: either placement is NOISE (then estimate its scale from >1 perturbation, not one draw) or BIAS (report it, gate the unit on run noise); say which, and give the deterministic-refusal case its own outcome.

### meas-4 — z = 3.0's "2.3 %" is drilled WITHOUT §3.4's aa term, and on an event the band does not gate
- CONFIRMED. RESIDUAL (MEAS-9, partly). Severity: speed (safe side: wins forgone) / doc. Effort: small. §6, §3.4 step 7, `span_cards/coverage_drill.py:10-12`.
- (a) §3.4's noise is `isqrt_rn(aa² + sp2)`; coverage_drill uses the trimmed s.d. only. A pure-noise twin gives aa ≈ med|N(0, 2σw²)| ≈ 0.95 σw, so noise ≈ 1.38 σ (all launch noise within-launch), not "an ABSOLUTE 1-sigma". `w/cov.py` (100,000 draws each, new-draw event as §6 states it): within-launch share f = 0 -> 2.31 % at z 3 (the design's figure, reproduced), **f = 0.5 -> 0.48 %, f = 1 -> 0.31 %**. f = 0 (all variance common to arm and twin) is exactly what per-launch normalization (§3.4 step 3) removes, so the realistic share is high.
- (b) span_pick.md:234-235 reads "1 sigma departs ~16 % of equal-price comparisons per side": the departure is decided on STORED values; §6 instead drills "a new run's draw against the stored median", which is not in the decision. Under the decision event z 3 departs 0.05 % (f 0) to < 0.01 % (f ≥ 0.5); z ≈ 1-1.5 would give 2.3 %.
- Fix: re-drill with the estimator as written and a stated f, and state ONE event (amend span_pick's sentence or §6).

### meas-6 — the delta NULL floor `FRG x base` is relative to the WHOLE 1 MiB call: walk-form hit rows are NULL below ~32 walkbytes per hit at g = 1024
- Arithmetic CONFIRMED; magnitude SUSPECTED (this run's FRG and walk hit cost unknown). FIX-INDUCED (MEAS-3/MEAS-6 fixes combined). Severity: design (row 1's robustness keys unpriced). Effort: small. §3.5 delta rows, §2.3 `find_hit`.
- Floor per hit = FRG x base / E. For walk and walk-set, base ≈ 1 Mi walkbytes: at grid1's FRG 3.09 % the floor is 0.0309 x 1,048,576 / 1024 = **31.6 wb per hit at g 1024**, 7.9 wb at g 256 (in ns: 0.1892 x 1,048,576 x 0.0309 / 1024 = 5.99 ns). For libc (byte ratio ~0.063) it is ~2.0 wb. smp20's own stand-in range for hit costs is h1 5-40 wb (span_pick.md:300). FRG is a run-wide p90 over twinned arms, and the perturbed twins (meas-1/3) put placement into it, so it likely RISES from 3 %. The row's own paired noise (aa_D, the D_l spread) is the right floor; FRG x base charges a hit row with the 1 MiB base's worst-decile A/A.
- Fix: state the minimum resolvable per-event cost per key (FRG assumed) against the costs row 1 must resolve, or floor on the paired D_l (aa_D and its trimmed spread) only.

### meas-7 — the per-job drift statistic is the component normalization cancels, and its threshold is not the "size that matters"
- CONFIRMED (text + drill), SUSPECTED (placement confound). FIX-INDUCED (MEAS-7's fix). Severity: design/doc. Effort: small. §3.5 Drift, §3.3.
- §3.5: "a common drift cancels" (step 3) — the drift check measures exactly that common component (control vs unit), and is blind to arm-specific drift. Its threshold `max(1.5 %, 3 x isqrt(sp2_U + sp2_C))` is 3 per-launch s.d. of a difference of MEDIANS (whose s.e. is ≈ 0.65 s): `w/rates.py` (4,000 each) at s 1 % a TRUE 3 % drift is refused 17.5 %, 5 % refused 76 %; at s 0.2 %, 1.5 % refused 50 %. So the stated "size that matters" (the unit's half gate) is kept whenever s > ~0.35 %.
- SUSPECTED confound: each job's control walk is linked into a different driver binary (§3.2: per-arm builds, reordered links), so C_j vs U also compares walk PLACEMENTS: a 2 % placement difference refuses the job deterministically (or, under the threshold, biases every walkbytes row in that job by the control's placement). Fix: one prebuilt control executable shared by every job (sha asserted), and either drop the drift check as redundant under normalization or argue the arm-specific drift it proxies.
