### CHK-1 — the row's linear-cost property (re-ask once per passed occurrence) has no check; a re-ask whose result is not KEPT passes every check and is quadratic
CONFIRMED at the emitted level; SUSPECTED-SILENT as a compiler plant. Severity: speed (the row's whole reason to exist, tuning.md §2.41¶8c). Effort: small. Blast radius: every `handoff-attempts-unbounded` artifact.
- Mutation of the emitted C for `[^@ ]+@x` (`--engine=vm`, subject compiler): replace `landmark_position = rx_reqrun(subject, subject_length, attempt_position); if (landmark_position >= subject_length) return 0;` with `{ size_t t_ = rx_reqrun(...attempt_position); if (t_ >= subject_length) return 0; }` (the stop still fires, the kept hit is never advanced). All 225 cells of the six unbounded blocks of tests/litscan/handoff_vm.rxt PASS (scratch harness checks/w/mut.py, control 225/225 first). The guard text `if (landmark_position < attempt_position) {` is still there, so the run_handoff_reach.sh `re` pin passes. Subject `" @x " + "a@y"*20000 + "a@x"` from 0: 0.00 s unmutated, 1.36 s mutated, same answer (match 60003 60007, = libpcre2 via tools/p2). Dropping the guard instead (`if (1) {`) is also 0/225 red and 1.37 s; only its TEXT is pinned (run_handoff_reach.sh `re` grep).
- Compiler-level plant that would produce this: `.result = "landmark_position"` in `emit_req_reentry_use` (src/gen/emit_dfa.c:1770) pointed at a fresh temp. On the BOUNDED rows the same plant is LOUD (the stale landmark makes `landmark_position - pos` wrap and the move goes backward), so it is the unbounded row that leaves this unguarded: its early `return` (emit_dfa.c:7859) removed the move that used to expose it.
- Fix: one count or timing control, e.g. a resource-style cell (`budget steps=` cannot see it, since re-asks spend no steps) or a structural check that the re-ask writes `landmark_position`; plus a sabotage row on the `.result` field with that detector.
