### SND-1 — a declined run on a HANDOFF route subtracts the RUN's K from the BYTE landmark's hit: matches lost (INFERRED, answer)

- Status: CONFIRMED by hand-execution over the code at 35bee4da9 (INFERRED: unreachable until stage 3 states a run with no findable position). Severity: **answer** (a match is lost). Effort: S (pcrec side, but the design's §4 "what pcrec must read" list must name it). Blast radius: every handoff route (`handoff`, `handoff-attempts-entry`) whose stated run the kit declines (§2.4 item 2) and whose head byte is not run position 0.
- The chain: part_d §2.4 item 2 makes a stated run come back untested (`cls.pres[run].verify` 0). In `req_site_define` (src/gen/emit_dfa.c ~1519-1560) `nrun` is then 0, so the landmark is the HEAD BYTE (`if (handoff && !nrun) s->ret_pred = np`), but `s->head_max = req_handoff_k(cx)` (emit_dfa.c:8971) = `pcrec_fact_req_landmark_maxoff` = `req_run.whole_len >= 2 ? whole_maxoff : req_set.maxoff[req_byte]` (src/facts/facts.c:359): pcrec's run IS shipped (whole_len >= 2), so K is the run's position-0 offset, not the byte's. memfn.h `head_max` says K is "the run occurrence's position 0 where a run part is the landmark ... else the one-byte landmark's" — pcrec's spelling keys on "a run shipped", the kit's on "a run part is the landmark"; they diverge exactly on the new decline. `req_handoff_applies` (emit_dfa.c:8828) and `req_handoff_entry_applies` (:8908) likewise read only `whole_len`, never the link.
- Witness, today's half MEASURED: `build/pcrec -p rx --pattern '(a|bc)[a-z]{8}.q'` at 35bee4da9 -> `RX_REQ_BYTE "113"`, `RX_REQ_RUN "none"`, `RX_REQ_WHY "emitted"`, `RX_REQ_HANDOFF "11"` (the DFA `handoff` row, K = q's maxoff 11). (`[a-z]{8}.x` itself is `dominated` today, so no handoff there.) Stage-3 half, hand-executed: the run becomes `[a-z]{8}` (8 x info 3 = 24 bits; `.` carries no information), whole_maxoff 2; the kit declines it (no findable position); the head byte q stays the landmark (`ret_pred`), but K = `whole_maxoff` = 2 (facts.c:359). Subject `bcabcdefgh-q`: hit c = 11, scan start max(0, 11 - 2) = 9 -> NOMATCH; python `re` matches at 0. Expected K = 11.
- Reach note (after SND-4): the head byte exists on a declined site where P4 leads (`led`, finder.c:848 keys on `run >= 0`, so it holds), or everywhere once SND-4's head rule is fixed; without either, SND-4's internal error fires first.
- part_d §4 item 1 and §7 Q4 name only the "nothing tested -> internal error" consequence; neither names K. The readiness memo's §2.1 reader table has no `req_landmark_maxoff`/`req_handoff_k` row either. Fix (pcrec's, but the kit's reply text should state it): K and the handoff predicates key on `cls.pres[run].verify`, not on `whole_len`; or the design states "a declined run is no landmark: pcrec's K must be the head byte's".
