## The lane's own mid-panel result (b0b9b8c), recorded

The §7.2 entry charge — fix-of-record in the plan row, known_issues.md K22
sibling note, and rungselect_design.md §5 item 8 — is REFUTED by measurement
at the real charge sites: possessified loops already charge one step per
start position via the fail label (steps ≡ entries, three sizes, exact);
the charge is linear while the work is quadratic, so an entry charge moves
the give-up point 2x where the gap is ~three orders; the q·n cost model was
wrong (unreached quantifiers are never entered; worst case a doubling); and
the entire four-shape debt is DIAGNOSTIC-PATH-ONLY (--engine=vm) — the
default prefiltered path measures 0 steps / 0.003 s at 1 MB. Replacement
§7.3: charge `iterations >> PCREC_STEP_SCAN_SHIFT` at the EXIT of loops that
push no per-iteration resume frame (exclusion exact by the steps≡entries
identity); SHIFT=0 reproduces the -fno-possessify give-up point; SHIFT=10
recommended. The engine critic's adversarial pass on §7.3 (exclusion
exactness for lazy/nested/cursor/revdet-scan/revdet-walk shapes; multi-entry
undercounting; exit-site hazards) is IN FLIGHT and appends to this file.
