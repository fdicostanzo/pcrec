## Findings

### R5-1. The mover predicate's unit is the stated SPAN, but the kit's segmenter groups plan positions by consecutive OFFSET across spans. "h\* >= 32 moves nothing" is false at h\* = 32. Severity: blocks the forms go until the text is fixed (text only)

- Rev 5 §3 "Which sites move": "A site is a POSSIBLE mover at h\* iff one of its stated spans
  holds a stretch of two or more CONSECUTIVE positions ... and the stretch's last offset is at
  or past h\*". Also: "Every window span pcrec states today has 32 positions or fewer ... So when
  h\* >= 32, NO site moves". §8 says the same: "h\* >= 32 moves nothing today".
- The segmenter rev 5 says it generalises (§3 "The forms": "C-run's `find_groups`") groups
  across spans. At origin/main `memfn/src/window.c` `find_groups` extends a group while
  `w->off[j] == w->off[j - 1] + 1`. These are plan positions keyed by window offset, with no
  span-boundary test. Positions, not spans, are the unit.
- Witness on the build tree: a cover's after side is a SEPARATE stated span at offset `k`
  (`src/gen/known.c` `cover_window`: `{ e->k, e->ctx_after, ... }`, `pcrec_memfn_wspan(&sp[n],
  side[i].off, 1, ...)`).
  - For `\w{k}\B` the after side is the `\w` set itself.
  - Probe: `build/pcrec -p rx --features assertions,classes --pattern '\w{32}\B'` gives
    `RX_DFA_SCAN "cover"`. The emitted chain tests `s[c + 32]` with the identical `\w` range
    test it uses at `+ 30` (w32B.c). `\w{8}\B` likewise tests `+ 8` (w8B.c).
  - So offsets 0..32 carry one multi-member set across two stated spans.
  - Per span, the stretch ends at 31 and is not predicted at h\* = 32. Per plan, it reaches 32.
    A move there is outside the prediction, so the sweep reads red on an intended move.
  - The same holds at any h\* = k for `\w{k}\B`, e.g. h\* = 8 with `\w{8}\B`.
- "32 positions or fewer" is also the wrong quantity. h is an OFFSET, and spans have a `start`:
  - the bound is `start + len <= MF_WREACH` 64 (`memfn_sites.c` `window_bounds_check`);
  - the cover's after side sits at offset 32 at D = 32;
  - the pre-check run span is at 0..31 (`emit_dfa.c:1469`);
  - pf_window_of's R span and k-set spans stay below `nwalk <= 24` (`walk_proves` returns false
    for `d >= wk->nwalk`).
  So the largest stated offset today is 32, not 31.
- Fix, either of:
  - (a) state the predicate over each ALTERNATIVE's stated positions keyed by offset (the union
    of its spans), and the bound as "largest stated offset". Then nothing moves at h\* = 64. At
    h\* = 32, only a cover whose after side repeats its class moves (`\w{32}\B`). The §8 line
    changes to match;
  - (b) the kit declares that a one-class-repeat segment never crosses a stated-span boundary
    (a segmenter choice the build must then hold). The rev-5 predicate stands, but "32
    positions" still becomes "offset 31".

### R5-2. Two rev-5 rulings combine to falsify the void claim: under the RULED cycle clause, a twice-void cell can LOWER h\*. Severity: fix soon (text)

- Rev 5 "A cell missing a regime": "So a twice-void cell can only push h\* toward 64 (fewer
  movers), never below it."
- Drill V (drill/r1.py, R1 steps 1-4 as written, f = 0.04):
  - Heads 8, 24 and 32 at cells k = 36/40/49 take (0.90, 0.93, 0.95), (0.95, 0.90, 0.93) and
    (0.93, 0.95, 0.90). That is a cycle: 8 dominates 24, 24 dominates 32, 32 dominates 8.
  - The k = 24 cell read clean (all heads tie with I): h\* = 32 (E = {8, 24, 32, 64}; counts
    1/1/1/3).
  - The same cell twice-void: W(8) = +inf removes 8. Then 24 has 0 dominators and 32 has 1, so
    h\* = 24. The void ADDED a mover tier.
- Without a cycle the claim holds. The undominated set only grows when members leave E, and a
  removed maximum is replaced by a head >= the void cell's k. So the claim fails only through
  the fewest-dominators clause RULED in this revision. This is a pair of fixes touching one
  check.
- Fix: scope the sentence ("absent a dominance cycle"), or state the consequence ("in a cycle,
  a void can change the kept set either way; the label names the void cell").
