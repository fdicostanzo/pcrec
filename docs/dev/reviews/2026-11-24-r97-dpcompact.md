## Verdict in one paragraph

No answer-level finding. Promise (2) HOLDS: byte-identical emitted C, rc and stderr over ~1,350 compiles across
every table reader (all six namespaces, negation, classes, `-i`, single-letter, UCP recipes, named groups first
and later position, subst templates, code segments), every `--list-*`/`--version`; the find path's 1,384 rows
are identical to BASE row for row; the separate `contains` decoder was checked exhaustively (4.6M checks,
0 mismatches). Its "compile time unchanged" sentence does NOT hold on the group-name path (+8% instructions at
80 non-ASCII names) and peak memory grew (+28% on a 4,000-`\p{L}` class). Promise (1) HOLDS in today's C (one
includer, a header with no layout), but the wall that is meant to keep it is weak: seven working bypasses
pass it silently, its symbol list is hand-copied from the writer, it skips 1,700 code files under docs/, and its
five rows only plant words the needle already holds. A sibling product (`case_tables.inc`) still has the
exact two-reader shape this subject retired.

## Lessons for the guide (proposed)

- A text-scan "only X reads Y" wall gets its bypass shapes from the C preprocessor and the build system (line
  splices, macro-built names, `-include`, including a `.c`): the check-adequacy lens should plant those, and the
  wall's rows should plant at least one shape that does not contain a needle word (W-1; learnings §3 "control
  shares a source").
- A wall's needle derived by hand from the writer's current output is a second copy of the writer (MOD-3): derive it
  from the product.
- "Excluded as prose" must be checked by extension, not by directory (W-2: 20% of docs/ is code).
