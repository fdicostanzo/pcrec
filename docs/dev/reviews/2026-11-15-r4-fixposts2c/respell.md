# respell findings

## Findings

### RESPELL-1 — CONFIRMED, doc, effort trivial, blast radius: one spec example (tuning.md §2.28¶3)
`docs/spec/tuning.md` §2.28¶3 (SUBJECT respelling) says `AKIA|AGPA|AIDA|AROA` reports `A[GIKR][ADIP]A`. The third position is the union of the branches' third bytes I, P, D, O = `[DIOP]`; there is no `A` in it. Repro: `$W/build/pcrec --features all --emit-main -p rx -o x.c --pattern 'AKIA|AGPA|AIDA|AROA'` prints `#define RX_REQ_RUN "41[47494b52][44494f50]41@3"` = A [G I K R] [D I O P] A. Observed spec `[ADIP]` vs compiler `[DIOP]`. The error predates the branch (BASE said `{A,D,I,P}`) but the hunk re-spelled exactly this example and carried it over, so it is in the subject's scope. Fix: `A[GIKR][DIOP]A`. The other respelled examples hold: `((a)|b){3}c` -> `[6162][6162][6162]63` = `[ab][ab][ab]c`; `frank|fred` -> `6672[6165][646e]` = `fr[ae][dn]` (both §2.28¶4 and §2.39¶1); `cat|dog` -> `[6364][616f][6774]` = `[cd][ao][tg]`.

### RESPELL-2 — CONFIRMED (by reading; answer-neutral), maintenance/design, effort small, blast radius: `rn_better`, `rr_alt` in src/facts/req.c
The macro's own contract (req.c:381-388) says `TEST` is "side-effect-free" and the respell then calls the deciding row a SECOND time to get its answer. Two of the four sites pay for that, and one breaks the contract:
- `rr_alt` (req.c:657-667): TEST is `rr_alt_rows[i].row(w,&l,&r,&t)`, i.e. `rr_alt_union`, which is NOT side-effect-free: it writes `*t` and, via `rn_common_head` -> `rb_pd_join`, arena-allocates a fresh 32-byte union set per position whenever neither branch set contains the other (req.c:792-805), and can `pcrec_ctx_fail` via `rn_put`. On every alternation the union row accepts, the whole union is computed twice and the first copy's arena sets are leaked into the compile arena (up to 32 x 32 B per alternation node; a long equal-width word list folds pairwise, so it scales with branch count). Answer-identical today only because nothing compares position pointers (grep: no `pos[..] ==` in src/facts) and ctx_fail is idempotent.
- `rn_better` (req.c:481-489): the deciding comparison row runs twice (pure, so only compile-time: `rn_rarer` recomputes `pcrec_find_run_scan_index` + 256-bit mass for both runs; `rn_content` re-walks positions). rn_better is called 4x per `rr_cat`.
- `rb_rep_row`/`rb_zero_into`: no re-call (they read `.row` of the found index) - clean.
Simpler, single-evaluation spelling within the same macro: `RB_ROW_SCAN(i, w, rn_choice_rows, (c = rn_choice_rows[i].row(w,&a,&b)) != 0); if (i == RB_ROWS(rn_choice_rows)) c = rn_first(w,&a,&b);` and for `rr_alt` scan with `&o` directly (the `RrAltRow` contract at req.c:607-608 already says a row fills `*o` only when it applies; `rr_alt_union` returns false before writing) then `if (i == RB_ROWS(rr_alt_rows)) rr_alt_affix(w,&l,&r,&o);`. That drops `t`, the second call and the "side-effect-free" claim (restate it as "TEST may capture the deciding row's answer"). Minor altitude note on the same macro: it expands to an unbraced `for`/`if`, so `if (x) RB_ROW_SCAN(...); else ...` mis-binds the `else`; all four uses are top-level statements today, so this is a latent hazard only.

### RESPELL-3 — CONFIRMED (by reading), doc/maintenance, effort trivial, blast radius: the macro's header comment, req.c:381-384
The comment says "A table holds only the rows a restored arm can pass over". False for three of the four tables: `rn_choice_rows` row 1 `{ rn_more_info, 0 }` (req.c:470), `rb_rep_rows` `{ rb_rep_min1, RB_REP_BEST, 0 }` (req.c:993), `rb_zero_rows` `{ rb_zero_empty, RB_ZERO_CUT, 0 }` (req.c:1073) carry arm 0 and are never passed over. What the respell actually guarantees is narrower: the CATCH-ALL (an always-true test) is no longer a row. Restate as "a table holds no catch-all row; its catch-all is the default after the scan". (The interior arm-0 rows are correct and needed: BEST answers when REP is restored for min>=1; the E-1 CUT row stops `A_EMPTY` from reaching the ZERO rows when only EMPTY is restored - both verified equivalent to BASE.)

## Standing questions

**SIBLING OF A FAMILY.** The restored-arm `{row, arm}` family is exactly these four tables: `restored` is read only in src/facts/req.c (facts.c just maps arms to facts via walk_arms.def), so there is no other `{row, arm}` table in src/ the macro should cover. Other first-match tables exist without an arm column (src/gen/entries.c `EntryRow`/`PartRef` with `when` + `sh_always`; altnf.c, callsite_rows.c). The macro now DIVERGES from them in one respect: they keep the catch-all as an always-true in-table row (`sh_always`), as did BASE here. That divergence is justified only where an arm column exists (an arm on the last row would run the scan off the end; BASE's `rr_alt`/`rb_zero_into` loops had no bound), so it should stay local to arm tables and not be pushed onto the arm-free ones; the macro comment could say so in one clause.

**GENERAL FORM + UNLOCKS.** General form: a first-match table is `(rows, mask, default)` where the scan skips rows whose `arm & mask` and returns index-or-count; RB_ROW_SCAN is that with `mask = w->restored`. Unlocks, each with its trigger: (1) a capturing scan (RESPELL-2) makes every row evaluated at most once - trigger: now, before landing, it is free. (2) The same scan with mask 0 could serve the arm-free tables - trigger: a third arm-free table hand-writing its own loop with an out-of-bounds risk (none seen today; entries.c's loops are bounded), not before. (3) An observable row id: since `i` is the row index, a `--emit-facts` / RX_REQ_WHY note could name which T2/T3 row answered per node, making restore-arm reach probes (S3129-S3132-style) read the row directly instead of inferring it from RX_REQ_RUN - trigger: the next sabotage row whose reach is argued from a run spelling.

## PROBED-AND-HELD

- Equivalence by reading, per table: `rn_better` (`c >= 0` with default `rn_first`=1 == BASE's `c != 0 -> c > 0 ? a : b`, fall-through `a`); `rr_alt` (BASE's unbounded loop ended on the arm-0 `rr_alt_affix` row; now the default; `rr_alt_union` writes `*o` only on success, so the BASE loop never saw a partial `o`); `rb_rep_row` (BASE stopped at `last` = the GAP row; now default GAP; interior `rb_rep_min1` BEST arm-0 row kept); `rb_zero_into` (BASE's arm-0 `rb_zero_any` CUT row == default CUT; the ZERO-armed `rb_zero_any` row still catches everything when ZERO is not restored). All rows except `rr_alt_union` are pure (RESPELL-2).
- Byte probe, `kit/pair.sh` BASE vs SUBJECT: 25 patterns (tie: `abc.*abd`, `Q(?:ab){20}Z`, ...; alt: `AKIA|AGPA|AIDA|AROA`, `cat|dog`, `xy(?:ab|abc)zw`, `frank|fred`, `(?i)union.*?select.*?from`, ...; rep: `abcd(?:)*efgh`, `ab(?:^)+cd`, `xy(?:ab){2}zw`, `xy(?:ab){1,3}zw`, `xy(?:ab){0}zw`, ...; zero: `abcd()efgh`, `xyz(?<=yz)abc`, `foo\bbar`, `x(?!ab)ac`, `ab\Kcd`, `-+(?:(?=a)|)A`, `[α-ω]+xyz`) x 9 arm sets (default, each of empty/zero/rep/tie/alt, alt+tie, rep+zero+empty, all five) x {byte, -e utf8} = 450 pairs: 450 SAME, 0 DIFFER, 0 compile failures. Reach confirmed (6 SUBJECT-only compiles): alt, rep, empty, zero and tie each move RX_REQ_RUN on a witness, so the SAME results are not vacuous. Budget note: 900 + 6 + 12 compiles, over the ~600 cap (I miscounted the matrix; each compile ~10 ms, single-threaded, niced).
- Spec examples (SUBJECT `--features all --emit-main`): `((a)|b){3}c`, `frank|fred` (twice), `cat|dog`, `-+(?:(?=a)|)A`, `xy(?:ab|abc)zw` all match; only `AKIA|...` is wrong (RESPELL-1).
- House: a statement macro over a declared table is not barred by coding.md (its macro rule, §2.6, is about emitted value stamps); the out-of-table default is a declared first-match table plus one else, not an if-chain (one default, no conditions). No duplication beyond RESPELL-2's re-call.
