## Findings


### SOUND-1 (CONFIRMED; severity doc; effort trivial; blast radius: the `span_facts` mover prediction, §2.3/§4.3)
§4.3's listing row ("every body whose exact prefix passes 24") and §2.3's "a long literal walks 64 levels where it walked 48" miss a second listing population the change moves: bodies of fixed width 49..64, whose span_facts is `0` TODAY because the liveness horizon (2 x 24 = 48, kset.c:891) is below their accept, so every subset's liveness is unknown and the exact loop stops at d = 0 (kset.c:917). Repro (review tree, `build/pcrec -p rx --features all --emit-facts --pattern P`): 48-byte literal -> `24:97,...`; 49-byte and 50-byte literals -> `span_facts 0` (width [49,49], [50,50]). Under the design (horizon 64, bound 32) they list `32:...`: a 0 -> 32 jump, not a 24 -> 32 one. Sound (an under-statement became a statement, exact_len grows, §2.3's claim holds), and no artifact reads exact_len except the cover (whose k <= 32 never needs the horizon), and no committed facts row pins such a body (cases.tsv facts rows are all <= 18 bytes). But the stated mover population and kvcensus-based count are too narrow; the sweep would show them as unpredicted listing movers. Fix: add "bodies of width 49..64 (listing 0 today)" to §4.3's listing row.

### SOUND-2 (CONFIRMED by hand-execution; severity maintenance (check gap); effort small; blast radius: §4.4 witnesses, §2.2 step 2)
§2.2 step 2 changes TWO bounds (the exact loop, kset.c:911, and the liveness horizon, kset.c:891), but no §4.4 witness reaches the second: every proposed witness (24/25/31/32/33-position literals, `[0-9a-f]{32}`, `\d{32}`) accepts at depth <= 33 < 48, so a build that raises the loop bound and LEAVES the horizon at `2 * PCREC_PREFIX_K_MAX` passes every row. Hand-executed: under such a half-applied build the 32/33-byte literal still lists `32:...`; only a body whose accept (or some branch's) lies at depth 49..64 differs. Witness that pins it: a `facts` row on a 50-byte literal, value `32:...` (the half-applied build lists `0`, today's lists `0`; SOUND-1's repro), or `a{30}(?:b{30}c|d)` (hand-run: correct build `31:97x30,[b,d]`; horizon 48: exact loop stops at d = 30 because the b-branch subset at depth 31 has unknown liveness, so `30:...`). No answer risk either way (the cover's k <= 32 and C10 forbid live successors at k, so a covered body never needs the horizon), so this is a listing-only check gap.

### SOUND-3 (CONFIRMED by hand-execution against run_cover.sh + run_sabotage_matrix.sh; severity design (check claim); effort small; blast radius: §4.4 sabotage rows (a)/(b))
§4.4 claims the two plants are told apart by "distinct witnesses (the 32-wide class `[0-9a-f]{32}` for (b), the 32-byte literal for (a))" and that plant (b) "must not also trip (a)". As a VERDICT pair this cannot hold: any k = 32 admission needs BOTH C7 at k = 32 AND C8's `exact_len >= 32` (known.c:275), so every 32-position verdict witness flips under BOTH plants. Computed: plant (a) `PCREC_SPAN_EXACT_MAX` = 31 (assert 31 <= 32 still compiles): 32-literal verdict -> C7 k = 32 passes, C8 exact_len 31 < 32 -> `exact/producer-short`, flips; `[0-9a-f]{32}` verdict flips the same way; facts rows `32-literal -> 32:` and `33-literal -> 32:` read `31:`, flip; 31-literal verdict stays cover. Plant (b) C7 back to `<= KN_CAP - 1`: both 32-position verdicts flip (`fixed-width`); both facts rows STAY (span_facts does not read C7). Correct build: all stay (modulo C13, SOUND-5). run_cover.sh's verdict check reads only `RX_DFA_SCAN == cover` (no `why`), and score_arm counts any failure, so each row is CAUGHT but the witness choice distinguishes nothing. What does distinguish them: (a) uniquely trips the `facts` rows; (b) has NO unique witness (impossible: C7-only admission at 32 needs exact 32). Fix: name the `facts` 32-byte-literal row as (a)'s witness, the `[0-9a-f]{32}` verdict as (b)'s, and drop "must not also trip"; or add a `why` column check to verdict rows (decline `fixed-width` vs `exact/producer-short`) if distinguishability is wanted.

### SOUND-4 (hand-executed; severity doc; effort trivial; blast radius: §2.2 step 5's spelling, the `why` of one corner)
kn_walk (known.c:126-163) sets `w->k = KN_CAP` for TWO reasons today, not one: "no accept below the cap" AND "a view-gated newline at depth KN_CAP - 1" (`ended` set at j = 31, the loop exits before the `ended` test at j = 32 would set k = 32, so the initialiser supplies it). §1.3 names only the first ("the walk's own sentinel"). Step 5 as written ("tests the rows at depth KN_CAP for an accept ... records no accept up to the cap as its own flag") would flag the `ended`-at-31 case when no depth-32 row accepts, where the loop's own rule for every j < 31 sets k = j + 1 unconditionally. Outcome is the same (decline): with the loop's rule C10 (rows at k must all accept) or C7's `nlv[k] > 0` declines; with the flag C7 declines. So it is sound, but the `why` differs (`fixed-width` vs `end-at-k`) from the j < 31 analog, which the K35/KITPROOF records and the §4.2 prediction ("fixed-width decline whose width is [32,32]") read. Fix: step 5 says "after the loop, `ended` gives k = KN_CAP; else an accepting row at depth KN_CAP gives k = KN_CAP; else the no-accept flag".

## PROBED-AND-HELD

- §2.3 "a set stated before is stated identically, exact_len can only grow" HOLDS, shared budget included (hand-executed on kset.c:885-937): subsets are appended breadth first, so indices are depth-monotone and each depth is contiguous (sw_take's same-depth dedup relies on it); every subset at depth <= 48 is created in the same order with the same budget use under 2x24 and 2x32; a budget exhaustion at depth <= 47 is identical in both; one at depth >= 48 only leaves deeper subsets unexpanded (live -1, as the old horizon did). Liveness is monotone (-1 can become 0/1; a known 0/1 has its whole resolving subtree at depths the old run also built). For d < old exact_len every live subset and its successors were already known, so set[d] is identical. Witness classes checked by hand: 31/32/33-literals, `[0-9a-f]{32}`, `\b[0-9a-f]{32}\b`, `\d{32}` (byte, utf8), `[0-9a-f]{24}x?` (stays 24: acc subset at depth 24), `a{30}(?:b{30}c|d)` (24 -> 31), `a{30}(?:b{40}c|d)` (b-branch beyond 64: stops at 30, sound), 49/50-byte literals (0 -> 32), budget exhaustion at depth < 24, 24..47, >= 48.
