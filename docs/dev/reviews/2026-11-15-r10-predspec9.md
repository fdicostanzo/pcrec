## Lessons for the guide (proposed)

1. A re-check after a rule that changes how EVERY label is read (here the one reading) needs a sweep for the old
   rule's GUARANTEES (extensionality, commutation), not only for its sentences: fixB found FIXB-1 by asking what the
   superseded rule had made true; a text sweep for "some-parse" alone came back clean.
2. Acceptance cases need a mode check every re-check: SIM-6 sat in §12 since rev 7 because each re-check asked only
   the revision's own question (ambiguity) of each case. Proposed simulate sub-question: "apply the case in the mode
   the program is actually in (searched vs whole value)".
3. When a design defines a library body as TEXT, the simulate lens should run it spliced AND as specified (SIM-3):
   the difference names the semantics the text leans on.
