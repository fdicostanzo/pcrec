### G1. DEFINE is not `{0}`: libpcre2 skips a DEFINE body, pcrec cannot tell them apart (answer: stage-1 regression + new over-refusals) — **FIX-NOW (design choice)**
Found by FIX-1, FIX-6, FIX-7. Verified V1, V2 (cells and HEAD output; the stage-2 consequence is by construction).
- pcrec's DEFINE port builds `A_REP{rmin=rmax=0}` ("the node the `{0}` idiom produces and nothing else", `src/parse/mod_recursion.c` ~:446-520). libpcre2 10.46 length-checks a `{0}` body and SKIPS a DEFINE body:
  - `(?<=a(?:b+){0})x` REJECT 125, but `(?<=a(?(DEFINE)(?<g>b+)))x` ACCEPT lb 1, and pcrec compiles it today (VALID_LB 1, agreeing).
- Rev 5 then refuses things it should not. Its `hb`/`hs` ("max 0 counts as 1"), its edge walk ("a repeat of maximum 0 is followed") and its re-entry walk all treat a DEFINE as `{0}`. So it refuses:
  - stage-1 patterns that compile and agree today, a regression: `(?<=a(?(DEFINE)(?<g>b+)))x`, `(?<=a(?(DEFINE)b+))x`, `(?<=a(?(DEFINE)(?<g>(?&g)b)))x`;
  - reference/call cells libpcre2 accepts: `(a(?(DEFINE)(?<g>b+)))(?<=\1)x`, `(?<=(?1))(a(?(DEFINE)(b+)))x`, `(a(?(DEFINE)(?<g>\1)))(?<=\1)x`;
  - a duplicate name under a DEFINE: `(?J)(?<n>a)(?<n>b)?(?<=x(?(DEFINE)\k<n>))y`;
  - re-entry through a DEFINE: `((?<=x(?(DEFINE)\1))a)`, which compiles at HEAD.
- HEAD divergence found on the call side (K127 already follows the DEFINE edge): `((?<=x(?(DEFINE)(?1)))a)` is REFUSED by pcrec and ACCEPTED by libpcre2.
- No gate would see any of it. Gate 1's axes say "zero-width (empty, `{0}`)", and no §6.2.5 cell has a DEFINE on the width path.
- Held (FIX-7): the region search for re-entry must still look inside DEFINE. `(a(?(DEFINE)(?<g>(?<=\1)b)))x` is REJECT 125 at 17.
- Proposed: the DEFINE port marks its node (a flag on `A_REP`, or its own kind row). Every EDGE walk (width, bound, duplicate name, re-entry edges) and the lexical value treat a marked node as 0 / not followed. Region searches keep following it. Add the cells above, plus the controls `((?<=x(?:\1){0})a)` and `(?J)...(?<=x(?:\k<n>){0})y`: both REJECT 125, both compile at HEAD, and rev 5 fixes them. Name `((?<=x(?(DEFINE)(?1)))a)` as a HEAD divergence stage 2 closes. `atomic.c` ~:814-881's deliberate "no DEFINE-shaped special case" is the reader to re-argue: the libpcre2 measurement is the problem scenario that justifies one discriminator (memory pcrec-general-mechanisms-not-special-cases: this is a fact libpcre2 has, not a fold).

### G11. The column, as specified, is a second fixpoint beside callgraph's table, not a column of it; callgraph's `cwmin` fixpoint loses its only consumer — **FIX-NOW (design choice; against ruling F1's text)**
