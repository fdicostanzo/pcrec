## Findings

### EMITTED-1 (SUSPECTED, speed, very low) -- runs now take in a low-information head position, and the pre-check tests it first
- What: once rule (1) makes an equal-width alternation `all`, the whole run can join the TAIL position of a variable-width class repeat in front of it (`\w+`, `[a-y]{1,2}`, `.*` under -i). Those are 25 to 63 member positions. They land at run position 0, and the pre-check tests positions in order from 0, so every scan hit pays a 4-range compare chain first. On text that test passes almost every time.
- Repro (CONFIRMED that the emission moves): `pair.sh OUT '\w+(?:(?<=[a-y])dcy|(?<=[a-y])bcc|[db]bc)(?:a|bc)[yxc]' --features=all -fno-altcls-merge -fno-altcls-factor`. RX_REQ_RUN goes from `[6264][6263][6379][6162]@1` to `[30-3941-5a5f61-7a][6264][6263][6379][6162]@2`, and rx_reqrun__body gains a leading `(subject[cand] >= 48 && <= 57) || ...` chain. The scan position and its byte set do not change. Same shape on `[a-y]{1,2}(abxd|axbd|dady){3,4}`, `[cb]xa[a-y]{1,2}(by|ac){3}`, `(?i:d|x|y)[a-y]{1,2}(?:[dab]a|xx|dx)...`.
- Why SUSPECTED: the cost is one compare chain per candidate, which is probably noise. Rule (1) is sound here. The choice belongs to the run metric (`rn_better` in req.c, which prefers more total information) and to the kit's verify order, not to rule (1); rule (1) just makes the shape more common. To confirm: a bench row on a text subject where a scan hit is common, with vs without `--harness=restore=alt`. If it is noise, drop this.
- Effort: if it is real, a small one. Trim a leading or trailing run position whose information is below a floor, or have the kit verify in information order. Blast radius: only runs that begin or end at a class-repeat tail. No answer risk.
- Where: src/facts/req.c rr_cat/rn_better (the join is unconditional; rule (1) widens what joins).

## PROBED-AND-HELD

- (a) Answers. 0 answer findings in 1,500+ subject runs.
  - Fuzz byte mode: 150 generated patterns (seed 2) plus the usable part of seed 1 (57 patterns) x 7 subjects, about 1,450 subject runs. The subjects are built from each pattern's own matches: an exact match, one byte substituted, last byte dropped, first byte dropped, noise before or after, runs at the subject start and end. The patterns mix equal-width 2-4 branch alternations of literals and classes, captures, atomic groups, (?i:), -i, {n}, {n,m}, ?, +, \K, (?=..), (?<=..) and \b inside branches, 0-width (empty) branches, \1 backrefs after, ^ and $, \w+, .*, and the (?:a|bc) unequal width. Half or more ran with -fno-altcls-merge -fno-altcls-factor. Rule (1) moved RX_REQ_RUN on 60 of them, and on about 35 the emitted pre-check code changed too. BASE = SUBJECT = libpcre2 on every run (capture spans compared BASE vs SUBJECT).
  - Fuzz -e utf8 (seed 3): 70 patterns x 7 over `abksxéÉ€ſ` (1, 2 and 3 byte characters, s/ſ and k/K caseless): 490 runs, all agree. Rule (1) fires on 3.
  - Hand-built utf8 witnesses (16 patterns, oracle with (*UTF)): é|ab (2 bytes each), €|abc|éa, (?i:é|ab), (?i:ss|ſa) (correctly NOT unioned: unequal byte width), (?i:ks|ab) with the KELVIN SIGN (not unioned), [éa]b|cd, .b|cd, (?:é|ab){3}, \x{e9}, \r\n|ab.
