## Which lens caught what

- **The answer-level holes all came from the two opus design/behaviour lenses.** Three were found blind by BOTH sound and slots: the event stream is incomplete, UNTRAIL conflicts with COPY, and the forward passes have no successors for unknown statements.
- **sound alone** found the missing call read in the declared table, R's missed value-text cursors, and D on left recursion.
- **contract alone** found the callout read set under `--no-captures`, the FRAMELESS iff, the size cap and the S179/S180 detectors.
- **measure** found that the full stack was never measured, that U's headline is the backreference family, and the R range error.
- **cost** found the unsized substrate, the marginal value of D stage 2 and of C, and the goals gaps.
- **cost and slots** (and measure) independently found the missing deny/stamp axes and the vmbc-vs-trailgen contradiction on [ART-TRAIL-ELIDE].

## Overall reading (coordinator)

- **The measured wins are real** within their regime. The numbers that are shared across the three documents agree to the digit.
- **No build go yet: the designs are not yet one design.**
  1. Each document proves soundness against the STOCK program. The build composes R, DELETE, UNTRAIL, C and D. At two seams the composed rules are unsound as written (F4, F5).
  2. All three documents assume a "program graph read from the emitter's event stream". That stream does not exist in the needed form: it has no slot reads, no SET sources, missing conditional edges, and a cut logged as a note (F1). F1 is the largest unsized cost in the sequence.
  3. Three declared-table rows are wrong or missing, each with a reproduced wrong answer on emitted code: the call read (F2), R's change list (F3), and the callout read set (F8).
- **All of these are paragraph edits now** (learnings §5: design panels are the cheapest reviews).
- **Recommended path.** Write ONE consolidated design with:
  - one statement-kind table (F17);
  - one declared pipeline (F7);
  - one STEP 0 (F34);
  - one goal set (F36);
  - then a short re-review of that document only.

## Lessons for the guide (proposed)

1. **A design whose claim is "answer-identical by proof" gets a soundness lens that APPLIES the rule to real emitted code.** The lens builds the base tree and hand-applies the documented rule, as written, to the emitter's real output for crafted witnesses. In this round it produced every answer-level repro (F2, F3, F6, and F1's witness). Reading the proofs alone would have accepted them.
2. **Multi-document subjects: review the SEAMS.** Each document was internally sound against stock; the holes were in composition (F4, F5, F21). Ask every critic to tag each finding with doc / seam.
3. **"Read from the event stream" is a premise to grep, not a given.** Three documents built on a stream that lacks reads. A premise lens checks every claimed input of an analysis against the producer's struct.
4. **A cited control can stop reaching its site between design and build** (F14, R25 E5's witness now routes to revdet/DFA). Every witness a design names gets a reach probe at the base commit.
