### SOUND-1: the lazy rung at rmin = 0 has NO SPAN record, so cell C5b never reaches the SPAN row, and the "span-cursor PUSH is a member" rule (disposition S-5) drops the lazy body's class from FIRST+

- CONFIRMED (answer, under the S-5 disposition text as written; the kind table's "of the open SPAN" is undefined here). Severity: answer (a reading the build could take) + test reach (C5b guards nothing it names). Effort: S (one row sentence + cell). Blast radius: every lazy cursor rung with rmin = 0 under a D-dispatched alternation (`.*?`, `[..]*?`, the commonest lazy shape).
- Where: design "The statement-kind table" PUSH row ("pos = span cursor of the open SPAN: continue, no fork; any other pos: OPAQUE"), disposition S-5 ("A span-cursor PUSH and the span's SPAN_COMMIT are members: no fork, continue"), SPAN row, cell C5b ("lazy SPAN"). Review tree `src/gen/emit_vm.c:5154-5160`: the lazy arm emits `vm_emit_span_scan` (the SPAN block) ONLY when `rmin > 0`; at rmin = 0 it prints the bare LSET `%s_span_cursor = scan_position;` (site_kinds 5159) and then `vm_push_at(v, again, "<p>_span_cursor", ...)` (5185) and the commit `scan_position = <p>_span_cursor;` (5214).
- Base text of C5b `^(?:.*?x|y)(z)` (`--features all`, `w/c5b.c`): `RX_SET(RX_SLOT_SPAN_LOW0, ...); rx_span_cursor = scan_position; goto rx_L8; rx_L8: if (RX_PRUNE_TOO_SHORT(...)) goto rx_fail; RX_PUSH(&&rx_L9, rx_span_cursor); scan_position = rx_span_cursor; goto rx_L7;` - no `{ ... }` span block, so no SPAN group opener and no span id exists anywhere on arm 1.
- Rule as written (S-5 disposition: a span-cursor PUSH is a member, no fork; SPAN_COMMIT continue): FIRST+(arm 1) walks SET (trailed: non-effect), LSET (dead at L6/L9: non-effect), BRANCH_FAIL (continue), PUSH L9 at `rx_span_cursor` (member: continue, NO fork into L9, the only path that consumes `.`), SEEK SPAN_COMMIT (continue), CONSUME `x`: F = {x}. FIRST+(arm 2) = {y}. D2 admits (byte `a` drops both) and dispatches x -> arm 1, y -> arm 2, else fail.
- Twin (`w/c5b_twin.c`, diff: the `RX_PUSH(&&rx_L6, scan_position); goto rx_L4;` at rx_L2 replaced by `if (scan_position >= subject_length) goto rx_fail; switch (subject[scan_position]) { case 120: goto rx_L4; case 121: goto rx_L5; default: goto rx_fail; }`). Commands: `$B -p rx -o w/c5b.c --features all --pattern '^(?:.*?x|y)(z)'`; `w/run.sh NAME FILE axz aaxz xz yz`; `w/p2 '^(?:.*?x|y)(z)' '' axz aaxz xz yz`.
- Observed: base `axz` 1 0:0,3 1:2,3 / `aaxz` 1 0:0,4 1:3,4 / `xz` / `yz` match; twin `axz` NOMATCH, `aaxz` NOMATCH, `xz`, `yz` match. libpcre2: equal to base (0:0,3 1:2,3 / 0:0,4 1:3,4 / ...).
- Under the other reading (kind-table: no SPAN is open, so "any other pos: OPAQUE") the answer is safe, BUT then C5b reaches no SPAN row at all: its named sabotage "SPAN row contributes nothing" cannot turn it red (there is no SPAN record to sabotage), so the cell guards only the PUSH reading. And the kind table never says when a SPAN CLOSES, so in `a*`-then-`b*?` shapes (a SPAN earlier on the same FIRST+ path, then a rmin = 0 lazy rung whose PUSH names the same shared local `<p>_span_cursor`), "the open SPAN" can bind to the earlier rung's span: same miss, and a pos-text test cannot tell the two rungs apart (every rung uses the one local `<p>_span_cursor`, `emit_vm.c:4833`, 5159, 5221).
- Fix shape: the PUSH member rule must name the span id carried as a PUSH operand (set only by a rung that printed a SPAN), with "no SPAN record of this id on the path -> OPAQUE"; or give the rmin = 0 lazy rung a zero-length SPAN record (class = body class, min 0) so its extend path's class is in F. Re-point C5b (or add C5c) at a lazy rung with rmin >= 1 (`^(?:[ab]{2,}?b|y)(z)`) for the SPAN row, and keep C5b as the rmin = 0 cell, its sabotage being "span-cursor PUSH with no SPAN = member".

### SOUND-4: the per-statement signature, as tabled, mis-counts real statements: comment text under `-fcomments` carries `return`, BREF prints two `goto <p>_fail`, and the `run->` row cannot be counted by `strstr`; the first makes the (c) verdicts and D move with the COMMENT axis

- CONFIRMED (structural, from emitted text). Severity: design (code moves under a comment switch, D112's one promise; plus spurious V0 on the backreference family G3 names). No answer moves (V0 is the safe side). Effort: S (state the count's text domain and per-kind multiplicities). Blast radius: every VM artifact with a negative lookbehind or a linked call compiled with `-fcomments`; every artifact with a backreference.
- Where: design "The per-statement signature" table ("`goto <p>_fail` | 1 if the record has an unwind edge, else 0"; "`return` | the record's give-up/abort/return exits"; "`run->` assignments, `--run->` | the declared run-state writes (CUT_LOCAL, STEP, RETURN, UNWIND)"; "brace balance | 0, except +1 for GUARD/SWITCH openers"), "The primitive counts these tokens in the text it prints (fragments included) with `strstr` loops"; COMMENT row "(no-effect form)".
- (i) Comment text. Comments are NONESSENTIAL (off by default, on with `-fcomments`). `vm_lbl` prints the role as `// %s` (`emit_vm.c:3464-3468`, site_kinds COMMENT 3465-3467). With `-fcomments --engine=vm --features all` the matcher bodies contain `// lookbehind END-CHECK (negative): ... a disagreement returns HARD` (`^x(?<!ab|c)y(a+)\1`), `// the callee region for a capture group returns` and `// the call returned; continue here` (`^(x(?>a(?1)?b)y)$`), and the frame's accept comment `* candidates. The VM returns here immediately` (`emit_vm.c:13328-13332`). `strstr(text, "return")` counts each. If the count runs on printed text (as written), these functions are V0 under `-fcomments` and analysable without it, so D's dispatch and the slot-flow verdicts, i.e. emitted CODE, differ between `-fcomments` and the default: exactly what `src/core/internal.h:379-392` (StrBuf.cmt_dropped) calls "the one thing this axis promises never to do". Card 0m runs the corpus without `-fcomments` and cannot see it.
- (ii) BREF prints `if (ref_start == PCREC_UNSET) goto rx_fail;` AND `if (took < 0) goto rx_fail;` in its one compound (`emit_vm.c:8848` and 8872, `w/br.c` lines 44 and 50 for `(a)(?:(b)|c)\1`): two tokens against the row's "1". It also prints three `slot_values[` for two slots (`ref_start = slot_values[2g]` re-reads the tested slot), which matches only if every `vm_slot_read` call (not every slot) is a pending read - the design says "append the slot", leaving it open.
- (iii) "`run->` assignments" cannot be told from `run->` reads by a `strstr` count ("a count, not a parser"): VAR's text reads `run->var_value[%d], run->var_length[%d]` (`emit_vm.c:8921`), CALLOUT's give-up edge writes `run->callee_gave_up = 1` (callsite_rows edge text, `emit_vm.c:9151`) though CALLOUT is not among the row's kinds (its writes column lists it).
- (iv) Single-line GUARDs (`if (!gs[j]) ga[j][1] = cur;`, `emit_vm.c:5561`, 5568, 5911) print no brace; the brace row says "+1 for GUARD".
- (v) Exits that live inside a macro body have no `return` token in the statement text: WORK prints `RX_CHARGE_WORK(n);` whose macro returns `RX_R_WORK` (artifact lines 101-107; the WORK row lists "exit (R_WORK)"), while STEP prints its `return RX_R_STEPS` literally (`emit_vm.c:9087`). "`return` = the record's exits" is then wrong for WORK (and for SET/PUSH/CALL, whose macros return `RX_R_FRAMES` though their rows list no exit), unless the count is per declared TEXT token rather than per edge.
- (vi) Frame TRACE text (only under `--trace`): the accept trace reads `slot_values[0]` when the pattern has `\K` (`emit_vm.c:13295-13300`) and the backtrack trace reads `run->resume_depth, run->trail_depth`; the frame rows declare no reads. As (i): V0 only under `--trace`, so the traced program would not be the program it traces.
- Fix shape: count on the comment-stripped text always (the fragment/region API knows which bytes are comment-tier), make each row's signature a declared per-kind multiplicity (BREF: 2 unwind-edge sites, 1 per extra ref read; CALLOUT: run-> write 1) rather than "1 if it has the edge", and give the `run->` row a token that is an assignment by spelling (e.g. count `run->X =`/`--run->X` for the declared field list). Add an `-fcomments` pass to card 0m.
