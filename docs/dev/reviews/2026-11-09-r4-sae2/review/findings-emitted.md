## Findings

### EMITTED-1 — CONFIRMED missed fact (design: general form + unlocks): an alternation whose EVERY branch consumes nothing still cuts the run
- Severity: speed (missed fact, never an answer). Effort: small (ALT arm: a both-branches-width-0 result is T3's unit / `pd_zero`). Blast radius: req_whole_run/req_run/req_byte for such patterns only.
- Observed (SUBJECT `build/pcrec --features all --emit-facts --pattern P`, `req_whole_run`): `a(?:\b|)b` none; `a(?:\b|$)b` none; `a(?:(?=b)|(?=c))b` none; `a(?:()|())b` none — while `a(?:|)b`, `a(\b)b`, `a(?>\b)b`, `a(?:\b){2}b`, `a(?:\b){0,3}b`, `a(?:\b\B)b` all give `6162`. Every match of the four "none" patterns contains `ab` contiguous (the alternation consumes nothing on every branch).
- Where: src/facts/req.c T3 (`rb_zero_rows`) covers zero-width NODES; the ALT arm (`rr_alt`) does not fold an all-width-0 alternation into the unit, so `(?:\b|$)`-style groups between literals remain a cut. span_arms §6 T3 has no row for it.
- Trigger that would justify it: a corpus count (harvest counts, D-harvest rules) of patterns with an all-zero-width alternation between two literal runs (`(?:\b|$)`, `(?:$|(?=,))`, `(?:^|\b)` mid-pattern) above a handful; until then a BOONIES/plan note. Not a regression: BASE also says none.

### EMITTED-2 — CONFIRMED (doc/maintenance): `\K` is described as a node that "can FAIL" and gets the inexact `zero` description, but `\K` never fails
- Severity: doc (+ tiny maintenance). Effort: trivial (reword; optionally route `A_KRESET` to `pcrec_pd_unit()` like `A_EMPTY`). Blast radius: none observed in output.
- Text: src/facts/desc.c header ("zero  a node that consumes nothing but can FAIL (an assertion, `\K`, ...)"); src/facts/walk_arms.def (`zero` = "a node that consumes nothing but can fail: an assertion, `\G`, `\K`, ..."); docs/spec/facts_listing.md 4.1.3 para 4a (lane/sae2) (`zero`: "a node that consumes nothing but can fail, an assertion, `\G`, `\K`, a check callout or a lookaround"). Contradicts src/core/kindrow.def's own A_KRESET note ("adds nothing to the language: exact"). Same for `(?=)` (always succeeds).
- Effect: `rb_zero_unit_into` gives `pd_zero` (exact=false) to every non-`A_EMPTY` zero node, so `pcrec_pd_cat`'s identity shortcut is skipped and merges lose exactness through `\K`. `PdGroup.exact` is read only inside desc.c, and `(?:ab|cd)\K(?:ef|gh)` vs `(?:ab|cd)(?:)(?:ef|gh)` give identical req_* facts, so no answer/speed effect found; the spec sentence is the visible defect (advisory arm-name text, D-tier doc).
