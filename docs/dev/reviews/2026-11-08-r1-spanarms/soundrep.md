### SOUNDREP-2 — W-R5's sabotaged value is wrong: "one copy fewer" does not shorten `(?:abc){20}`'s run (CONFIRMED by hand-execution of rn_app/rr_cat, req.c:308-318, :450-468)
- severity: design/doc (a FACT witness whose expected sabotaged value cannot occur); effort: trivial; blast: unit R1's mech row.
- §3.1 point 3 sets the all-body saturation at `ceil(32/w) + 1` copies; for w = 3 that is 12. "One copy fewer" = 11 copies = 33 bytes, which rn_app truncates to the SAME 32 positions (trunc set, `all` false). The table's "29" corresponds to no copy count (10 copies = 30). Since T2 row 3 forces `all` false whenever c < m, and trunc is read only by `all` (req.c:459; grep: no reader outside req.c), the `+1` copy can change NO content field for any w: it is slack. What it CAN change is best.off: unrolled right-to-left through rr_cat, at 12 copies `rb` (X^11's best shifted by w) wins the information tie over `join` (rn_better keeps `a` on a tie, :342-345), so best.off = 3 at 12 copies vs 0 at 11 — the extra copy LOOSENS the K82 offset (sound, worse). So "no stored field can change" after saturation is false for `off`, and the sabotage shows (if anything) only as `req_run_maxoff` moving 3 → 0, never as 29 positions.
- Fix: saturation = `ceil(32/w)` (drop the +1), and make W-R5's sabotage "saturation at ceil(32/w) - 1" (`(?:abc){20}`: 10 copies → 30 positions vs 32), which does show on the listing.

### SOUNDREP-5 — "inside the match" / reach is undefined against `\K`: the walk is attempt-relative, the contract and §4.3 say "match" (CONFIRMED: today's stamp, oracle sweep)
- severity: doc (contract wording, D80) — no answer moves; effort: small (one definition sentence in §2 and in L2's A7 hunk); blast: §2's soundness clause, §4.3, §5.4 A7, §13 Q4's proposed sentence.
- §2 defines reach as bytes "before the match start / after its end", §4.3 says a guarded unit "joins two consumed runs that are both inside the match", and match_api.md §6.3.7¶6 says "a literal run every match must contain". Under `\K` the REPORTED start is not the attempt start: today `abc\Kd` stamps `RX_REQ_RUN "616263@1"`, wholly before the reported match `d` (measured, build tree). E-4 makes it more common: `ab\Kcd` goes from `cd` (inside) to `abcd` (straddling the reported start), `(?:ab\Kc){2}` to `abcabc`. The runs are SOUND (oracle sweep below: every match from every start offset holds the run in [search_from, end)), because every reader (A1-A3, A6) is attempt-relative — but L2's widened sentence ("every match, with up to N bytes before it") would state reach 0 for a run that lies N bytes before the reported match.
- Fix: define "match" once as the attempt span [attempt start, match end) (the reported start may be later, `\K`), in §2's soundness clause and in the A7 spec hunk; note that `back` counts from the attempt start.

### SOUNDREP-6 — T2 row 1 is silent on the GUARD of a width-0 body; a quantified positive lookaround with m = 0 must drop it (SUSPECTED, wording; oracle CONFIRMED)
- severity: answer if built from T2 alone at L1 (doc otherwise); effort: trivial (add "guard: none" to T2 row 1); blast: L1/L2 build, T2, §2's REP rows.
- §2's REP rows say m ≥ 1 carries "the body's guards, per copy" and `X{0,n}` "none"; §3.1 point 3 says a width-0 body is "the unit (zero copies)". A positive lookaround IS a width-0 body, so `(?=ab)?` lands in row 1, and PCRE2 treats a min-0 quantified assertion as optional: `x(?=ab)?ac` on `xac` is libpcre2 `M 0 3` (p2probe, checked). With m ≥ 1 (`(?=ab)+`, obeyed once) keeping it would be sound, dropping it a lost opportunity.
- Fix: T2 row 1 "guard: none (zero copies)"; add `x(?=ab)?ac`/`xac` as a witness to L1's gate.
