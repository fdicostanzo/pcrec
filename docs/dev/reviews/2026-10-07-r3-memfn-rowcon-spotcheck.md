## NEW BLOCKER

### B1. The `UNSTATED` serves token is dead under rules 1-3. Appendix B and R-6 rely on it, so T3a moves bytes.

- **How the rules work.** RC:238-252 are first-match per field.
  - Rule 1 declines every field that is used and unstated, whatever `serves` says.
  - Rule 3 passes every field that is unused and unstated, whatever `serves` says.
  - So `UNSTATED` in `serves` never changes an outcome.
- **What depends on it.** Appendix B (RC:364) puts `floor` in the `uses` of the run-shaped precheck row and gives it serves {UNSTATED, ZERO}. R-6 (RC:336) says pcrec states NOT `floor`.
- **Consequence 1.** Under rule 1, the run-shaped precheck row DECLINES every PRE site with a run part. Generic then renders the site. That is a byte mover at T3a, which the plan lists as "none (gate)".
- **Consequence 2.** `miss` is in precheck's `uses` without condition. R-6 states `MF_MISS_N` only on "valued handoffs". So every ON_MISS PRE site (emit_dfa.c:1486, `handoff` false) also declines.
- **Fix:**
  - Delete `UNSTATED` as a serves token, or define it as "legal only on an unused field". Then `mf_table_check` must refuse it on a used field, and the same for `ANY`.
  - Take `floor` OUT of precheck's `uses`. Its run parts call the ofsskip function, which reads nothing below `pos`, and every row refuses negative offsets (ofsskip.c:100-107). So the row serves `floor` the way ofsskip does: {ZERO} as an unused field. Neither precheck row then needs a split for `floor`.
  - Take `miss` out of precheck's `uses` too (see m1).
  - Make T3a's entry criterion explicit: T2a's WARN-mode census must show **zero would-decline verdicts** over the corpus and G2.

## NEW MAJOR

### M1. `MF_SELECT` has no scope argument, and it captures `rec` and `opts` from the caller's scope (RC:114-115). This is T0's API.

- Walk step 1 filters on scope, but neither `mf_table` nor the call carries a query scope. `route_of` exists; no `scope_of` does.
- `cand_select(CandSlot slot, const DfaSel *s, uint64_t flags)` (stc2:8131) takes the slot as a parameter, and `DfaSel` has no slot member.
- The expansion names `rec` and `opts`, which are not macro parameters.
- **Fix:** `MF_SELECT(t, scope, ctx, flags, "site")`. Pass `rec` and `opts` explicitly, or give them defaults spelled in the macro. Make the scope argument the customer's enum through the typed wrapper (r2 cust m4).

### M2. Under "absent from serves = serves nothing", Appendix B as written declines the specialised row at EVERY pcrec site

These are the fields each builder STATES today that its row's Appendix B `serves` does not list. Under RC:252 each one declines the row, generic renders the site, and bytes move.

| site → row | stated, but not listed in the row's serves |
|---|---|
| OFS define (emit_dfa.c:6199-6212) → ofsskip | `fn_name`, `table_name`, `comment_tier` (plus every SITE field, if SITE fields are in `fields.def`: form, op, handoff, empty, use, consumer, policy, denies, span_hi, cand_ppm_hi, ret_pred) |
| OFS call (emit_dfa.c:6229-6233) → ofsskip | `s`, `n`, `lo`, `table_name` |
| PRE define (emit_dfa.c:1463-1495) → precheck | `fn_name`, `note_tag`, `comment_tier`, `on_miss_leaves`, `ret_pred` |
| PRE use (emit_dfa.c:1549-1557) → precheck | `s`, `n`, `lo`, `indent`, `on_miss`, `result`, `result_decl`, `note`, `comment_tier`. Note that `result` and `result_decl` are stated even on ON_MISS sites, which precheck never reads |
| VMRUN (emit_vm.c:4432-4435) → runcmp | `n` and `comment_tier`, which are stated and **unused** by runcmp (runcmp.c:341 reads only `s` and `lo`). They need `{ANY}`, or runcmp declines at every VM literal run |

- Generic's "serves `OTHER` for every field it uses" (RC:265) is too narrow for the total fallback. It must serve every class, including `MISS_N` and `ZERO`, plus `ANY` for every field it does not use. Otherwise a G2 site with `miss = MF_MISS_N` that ofsskip declines finds no row, and `on_none` refuses it.
- RC:233 must also say whether SITE fields that predicates already test (form, op, handoff, empty, end_back, reverse, guard_by_caller) are `fields.def` fields. If they are, every row must declare them. If they are not, write that down.
- **Fix:** T2a's "fills exact" must produce this table for every row, and B1's zero-would-decline criterion enforces it.

### M3. The snapshot set ("`uses` hooks", RC:281, 294) is not the set of VALUE hooks the rendered text references

`uses` contains three kinds of field that must not be snapshot:
- **Classify-only fields.** ofsskip's `miss` under `MF_MISS_N` renders as the function's own `n`, so a `_mf_OFS_miss` local would be unused, and `-Werror` fails.
- **Callbacks:** `fn_name`, `table_name`.
- **Non-values:** `result` (an lvalue declared BY the site; snapshotting it reads an undeclared name), `on_miss` (a statement), `indent`, `comment_tier`, `result_decl`.

**Fix:** the snapshot set = {`s`, `n`, `lo`, `floor`, `miss` when its class is `OTHER`} ∩ the hooks the chosen row's text actually references. G2's `-Werror` compile of every reached cell is the control.

### M4. A FUNC call nested inside a STMT site is unplaced, and both obvious readings break

- precheck's `run_line` renders the ofsskip call inside the PRE's own STMT text (precheck.c:203-214), so two rows of §5's table overlap.
- **Reading 1: re-wrap with the FUNC rule.** The call has 3 hooks, which is ≥ 2, so it gets wrapped. With the site's own names this gives `const unsigned char *_mf_PRE_s = (_mf_PRE_s);`. The inner declarator is in scope in its own initializer, so the local reads ITSELF, uninitialised. `-Wall -Wextra` does not report it (`-Winit-self` is not in either).
- **Reading 2: pass the original hook text.** The outer STMT snapshots `_mf_PRE_s` and `_mf_PRE_lo` are then unreferenced on a run-only ASSIGN PRE (a handoff site has just the window part). The result is `-Wunused-variable` and `-Werror` fails.
- **Fix:** state that a FUNC call nested in a site's own text takes that site's snapshot names as its hook text, and is never wrapped.

### M5. "`_mf_` is not user-choosable via `-p`" (RC:283) is false

- `valid_prefix` (src/core/compile.c:253-260) accepts a leading `_`, so `-p _mf` is legal.
- Under it, the text that `fn_name` and `table_name` return (`_mf_ofsskip`, `_mf_ofs_k3`) trips §5's refusal "an identifier with the `_mf_` prefix", so a legal compile is refused.
- This is r2 soundness M1 again, under a new spelling.
- **Fix:** derive the reserved stem from the prefix (generic's `<prefix>_mf<k>_` scheme plus a use counter), or narrow `valid_prefix`. Narrowing is caller-observable, so it needs a D80 spec hunk.

### M6. fit_rungs' NULL predicate means SKIP, not HOLDS (RC:99, RC:190)

- `fit_select` reads `if (!r->applies || denied) continue;` (compile.c:754). `unroll-rescue` has `applies` NULL because its choice is made elsewhere (compile.c:637-638).
- It is ROW 0 and has no deny bit except `--fast-or-fail`. Under `MF_PRED_NULL_HOLDS` it would win every `fit_select`, so every size-cap refusal would take the wrong rung.
- **Fix:** give fit_rungs a custom `test` thunk that returns false for NULL (an `MF_PRED_NULL_SKIPS`), or drop the flag. Customer 3a is not in T0, so this gates adoption only.

### M7. sound-B1 residue: fields rows USE with a real 0 and no stated form

| field | who reads it |
|---|---|
| `comment_tier` | ofsskip/precheck legends. `PCREC_CMT_ESSENTIAL` is 0 (internal.h:124), and the kit cannot add an `UNSTATED` member to pcrec's enum |
| `end_back`, `reverse` | every arm's predicate |
| `guard_by_caller` | runcmp |
| `on_miss_leaves` | precheck's `miss_leaves` |
| `fn_ref`, `table_ref` | ofsskip/precheck |

- Most of these are fail-safe: 0 selects the conservative side or a decline. Those are `on_miss_leaves`, `guard_by_caller`, `fn_ref` and `table_ref`.
- `end_back`/`reverse` = 0 and `comment_tier` = 0 are real choices.
- **Fix:** write the exemption list in §4.1:
  - "0 is the contract's conservative value": `on_miss_leaves`, `guard_by_caller`, `fn_ref`, `table_ref`;
  - "0 is a contract value": `end_back`, `reverse`.
  - Give `comment_tier` a kit-side mapping, or make it DEFINE_ONLY and a per-kind obligation at define. pcrec states it at every define today; `pf_ofs_call` omits it, and that is harmless only if it is DEFINE_ONLY.

## MINOR

- **m1. R-6 is not minimal.**
  - precheck requires `on_miss_leaves` (compose.c:131, the `miss_leaves` column), so on a miss `result` is never read after the site, and `miss` is dead for both of its handoffs. precheck should serve `miss` {ANY}, not use it.
  - The minimal R-6 is then `miss = MF_MISS_N` on OFS only, at BOTH define (`ofsskip_applies` reads `def->miss`, ofsskip.c:392) and the call (ofsskip.c:420). R-6 must name the phases.
- **m2. Poison values must be in contract.** Use a different class, never an out-of-range enum. `site_check` refuses out-of-range values before any gate (compose.c:181-184), so the differential would read a refusal as a row reading an undeclared field.
- **m3. `mf_table_check` should refuse contradictions.** `ANY` on a field in `uses`, and (per B1) `UNSTATED` on a used field, are contradictions it can catch.
- **m4. The FUNC ≥ 2-hook `({ })` wrap (RC:290) buys nothing under memfn.h rule 1** (side-effect-free hooks), and it moves every OFS call. Rev 3 never restates rule 1, which r2 sound M2 asked for. Restate rule 1 and drop the wrap, or justify it.
- **m5. ASSIGN names are per site, not per use.** `_mf_<site>_<hook>` is unique per site. Today's three PRE uses sit in three functions (emit_dfa.c:8655, :8948; emit_vm.c:13231), so nothing collides. A second use in one scope is a loud redefinition. Spell a use counter, as RC:292 itself promises.
- **m6. Appendix A's "SET gate lines are identical" (RC:355) is not exact.**
  - WINDOW's record prints route `-` (stc2:983), but WINDOW is a routed walk (stc2:981, `CAND_ROUTE_DFA`), so the engine record would print `dfa`.
  - The record also adds a `table` field.
  - Say "projectable", and keep WINDOW's record as a macro, or call it as a no-route walk.
- **m7. `on_none = pcrec_ctx_fail` needs a thunk** (the signatures differ).
  - `DfaSel.cx` is NULL at N12's walk (stc2:8291-8297, `attempt_cand`).
  - Say what `mf_select_` returns if `on_none` returns.
- **m8. "`MF_DENY_NONE` explicit" (RC:72) cannot be enforced if the token is 0.** If it is a non-zero sentinel instead, Appendix A must rewrite the `0` deny on 25 of the 37 rows. `mf_table_check`'s list does not include it either way.
- **m9. Classify `floor` = ZERO by exact token (`MF_FLOOR_0`), never by text.** The text `"0"` is what generic matches today (generic.c:79). The misclassification OTHER→ZERO is the unsafe direction, and only a token makes it impossible.
