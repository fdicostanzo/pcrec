### RDYR-3 CONFIRMED (by reading against HEAD's code) — §6.2.2's table, applied AS WRITTEN, makes rule 5 (rule 0) unreachable and sends a variable branch to "unbounded" or to the ceiling
- severity: answer-adjacent (a false sentence, F8's class; regression vs HEAD) + doc; effort: one-line text fix; blast radius: every `${v}` / consuming-callout lookbehind (vars.md §6's refusal row, the gated.rxt capability holder V5 keeps).
- design §6.2.2 table rows 4-5 and §6.2.1's `hb`/`hs` definitions. `hb` is "`hi`'s recurrence with a repeat's maximum of 0 counted as 1"; a variable's `hi` is UNBOUNDED (cwmax's ANY row), so `hb` of `(?<=a${v})` is UNBOUNDED. Rule 4's rule 1 "reads `hb`" and is ordered BEFORE rule 5, so it holds first and prints "every alternative ... must have a bounded length (this one is unbounded)" for `(?<=a${v})x` and for §6.2.4's own `(a)(?<=\1${v})x` (which §6.2.4 says "stays in rule 0"). Rule 5's own condition ("`hb` unbounded and `hs` finite") is a subset of rule 4's, so it can never be first.
- Also as written: "rules 2-3 read `hi`": a rule-0 branch has `hi` = UNBOUNDED, so rule 2 (ceiling) holds on it unless the branch is skipped. HEAD's code skips it (src/parse/mod_lookaround.c:323-327, `notbuilt = true; continue;` before the ceiling test); the table does not say so.
- HEAD control: `(?<=a${v})x` and `(a)(?<=(?1)${v})x` both print the rule-0 sentence today (pcrec at build tree, offsets 0 and 3).
- fix (text): rule 4's rule 1 reads `hs` (unbounded even with match-time lengths at 1 = truly unbounded), and rules 2-3 apply only to branches with finite `hb`; rule 5 = "some branch has `hb` unbounded and `hs` finite, after every branch passed rules 1-3". That is HEAD's control flow with `cwmax`->`hb` and `cwmax_static`->`hs`. Check SV9's wording against it.

### RDYR-5 CONFIRMED — nested lookbehinds: following a nested lookbehind's body in the OUTER's verdict refuses at the outer's offset; libpcre2 refuses at the inner's. HEAD's K127 already does this for calls
