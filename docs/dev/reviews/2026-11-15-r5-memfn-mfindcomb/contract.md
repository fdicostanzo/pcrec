### contract-4 (doc/design) — span_cards 2.7 "est's draft writer REFUSES a set mixing ISA levels" is checked against a parallel table  [CONFIRMED by reading est.py:794-796, 917-925]
- The guard is `cls.split("/")[0] != TARGET_LEVEL[tgt]`; `cls` comes from TARGET_SET, `TARGET_LEVEL` is a second hand-written dict beside it. The only way to trip it is table drift between the two literals (the selftest `mf_mixed` plants exactly that: swaps one TARGET_SET entry). It never reads what each cell's TU was compiled with (cell_text.tsv records `target`, `target_isa`; link.py's ISA check does see the object's real features). The spec sentence reads as "rows built for another ISA level than the class names are refused"; what is enforced is "TARGET_SET and TARGET_LEVEL agree". Fix: derive both from one row table (target -> suffix, class, level) or have the guard read `target_isa` from the cell. (learnings 3: a control that shares a source with what it controls; two parallel dicts = the table used as if-chain smell.) Effort small.
