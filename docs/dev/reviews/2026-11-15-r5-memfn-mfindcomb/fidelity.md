## Findings

### FIDELITY-1 — CONFIRMED — the slot times the SIMD finders OUT OF LINE (a call per accepted hit); pcrec's emitted matcher inlines them
- Severity: answer (D197's one-sided test reads the wrong per-hit cost). Effort: small-medium. Blast radius: every JMH row of mfind-w16/-w32 (and their reject-0 vs reject-100 contrast); JMB miss-only slopes barely touched (one call per subject).
- Repro: reduced JMH plan (my copy, GAPS6=(32,)), `run.py dry JMH rd_ctrl ctrl` green; `objdump -d --disassemble=a24_time JMH/obj/arm24.o` -> `call mf_fn__w32` (0x2f5); arm1/arm2 (base.mfind-w16/-w32) the same (`t mf_fn__w16`, `t mf_fn__w32` local symbols); arm0 (mfind-swar) and arm3 (fn-memchr) inline. pcrec side: `kit/lever.sh lvN 'xy[0-9]+z' ... -fmemfn-simd=x86-64-v3` (also `[a-z]+xy`, and `xy[0-9]+z` at x86-64), `gcc -O2 -c`: NO local finder symbol, pcmpeqb only inside rx_search (inlined).
- Why: WRAP_FIND (link.py:233-260) calls `step` from TWO functions (`_time`, `_gate`), so the static `mf_fn__w32` (w16 and body folded in) has two callers and gcc keeps it out of line; pcrec's matcher has one. Observed vs expected: the timed per-hit path is call + ret + prologue + the `va` broadcast re-materialized per call, which the shipped code does not pay; expected the timed code shape to be the shipped one (CLAUDE.md slot: "the thing TIMED is the thing GATED, KEYED and RECORDED"; the r9 table).
- Consequence: D197 says the fused per-hit cost "is a LOWER BOUND for the split shape" and a fused LOSS to libc settles row 1 against the finder. An extra call per hit inflates the fused cost, biasing exactly toward the settling outcome; the bound is no longer a lower bound. The SWAR row (inlined) and the SIMD rows (called) also differ in shape from each other, so w16/w32 vs swar contrasts carry the call too.
- Not caught by: KEY-ARM, cell-text hash (text equal), ISA check (whole .text), placement (`hot_loop` and the arm/twin .text equality read `_time` only, link.py:493-516, 644-650: the finder's hot loop is in `mf_fn__w32`, outside both).
- Cause confirmed: the same arm24.c with `_gate` deleted, same flags (`gcc -std=gnu11 -O2 -march=x86-64 -mtune=generic -c -DSYM=a24 ...`, probe/inl/nogate.c): `nm` shows only `T a24_time`, zero calls: the finder inlines. The GATE'S PRESENCE IN THE TIMED TU changes the timed code.
- Fix direction: a check that the timed function holds the site (no call to a local symbol from `_time`; or fold the gate into a separate TU calling the SAME `_time` object's code), or record "out-of-line" as a cell fact; at minimum name it in the card/§ before the run.

## Sibling of a family
Yes, the third member. The slot records facts ABOUT THE TIMED CODE at dry time and est re-checks them per job KIND, not per fact: (1) r11's manifest/executable check and the fused fact run only for verify jobs (est.py:401-407); (2) the target (cell_text `target`/`target_isa`) is checked against the object at link and against nothing at est, while the DRAFT-ISA-LEVEL guard checks a table against itself (FIDELITY-2, -3); (3) placement's `hot_loop`/arm-twin .text equality read `_time` only, so a finder gcc keeps out of line (FIDELITY-1) escapes them. Unify as ONE declared table "timed-code facts": fact, writer (link.py/run.py), where pinned (manifest), who re-reads it at est, for every ran job; est's checks iterate the table, never a job kind.

## General form + unlocks (with triggers)
- General form: THE TIMED SHAPE IS A CELL FACT read from the object (inlined-or-called site, ISA features, hot-loop function) and compared with the SAME site's shape in a pcrec-emitted matcher (the lever witness: `--harness=mfind` + gcc -O2, as lever.sh does), so "timed = shipped" is checked, not assumed. Unlock: the slot could time the shipped matcher function itself as a whole-artifact arm (art.py's J1/J5 path) when the shapes disagree. Trigger: now (D197's verdict rests on per-hit cost; FIDELITY-1).
- est verifies every ran job's manifest (and pins cells files): trigger = any window without verify rows, i.e. mfcard, the first.
- A declared decision rule per ruling a timing run decides (j1_rule.py's precedent): `mf_rule.py` naming the D197 cells (form pairs, gaps, reject values, margin = noise) and writing its verdict into the record. Trigger: before the mfcard window is cleared (the rule must be fixed before the numbers exist).
- Generalising the `reject` dim beyond find_hit@6 (any find form whose site has a check past the hit: pair's second byte, every offset-skip run) gives the RESTART-vs-MASK stream cells D190 owes as a by-product. Trigger: the D197 WIN branch (building the split shape needs those cells).
