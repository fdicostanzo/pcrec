## Lessons for the guide (proposed)

- A fact-time ask whose answer the define renders later must be checked against EVERY input the define reads (site
  proofs, route, levers), not the inputs the design lists: the purity claim was true of the function and false of
  the decision (F2). Proposed for critics.md: the seam lens enumerates the define's inputs from code.
- An "earned skip" (any rule that drops a finish on a proof) needs a SUFFICIENCY fact, not the necessity facts the
  analysis already carries, and its precondition list must cover every OUTPUT of the match (captures, `\K`, MARK),
  not only its conditions (F1).
