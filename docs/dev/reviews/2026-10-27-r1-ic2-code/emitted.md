## Findings

### EMIT-1 CONFIRMED (answer/trust of the build: a warning, an error under -Werror) — a code site no match can reach leaves its `static const rx_callout_ref` unused
- Input: `pcrec --features all --allow-code=c -p u -o u.c --pattern 'a(?:b(?C`c: return RX_PASS;`)){0}c'`, then `gcc -O2 -std=gnu11 -Wall -Wextra -Werror -c u.c`.
  Also `(?(DEFINE)(?<d>x(?C`c: return RX_PASS;`)))y` (an uncalled DEFINE group).
- Observed: `u.c:119:29: error: 'u__code1_ref' defined but not used [-Werror=unused-const-variable=]` (plain `-Wall` prints the warning; `-Wunused-const-variable=1` is part of `-Wunused-variable` for C). pcrec exits 0 and writes the artifact.
- Expected: warning-clean under `-Wall -Wextra -Werror` (src/gen/CLAUDE.md "Emitted text"). The path it replaces does not warn: the same site as a binding `(?C"x")` gets an `extern` declaration, and an unused extern is silent. match_api.md §11.2¶3 says a site no match can reach is still COUNTED and its binding still declared, so `pcrec_emit_code_protos` (src/gen/emit_code.c:139) writes the prototype and the `_ref` for every CO_CODE node, and the VM never writes the site that would read it.
- Fix (small): mark the file-local binding `__attribute__((unused))` (through the attr-text table, src/gen/attr_text.c), or write the `_ref` only for sites the program emits. The segment function itself is used by its `_ref`, so it needs nothing.
- Blast radius: any code segment inside `{0}`, an uncalled DEFINE group, or any other site the VM drops. No test covers it: tests/code has no unreachable-site row, and the harness compiles with -Werror, so the first user corpus row of this shape fails the build.
- Effort: one line plus a test row.

### EMIT-2 CONFIRMED (speed; design goal 3b) — an empty-predicate segment about doubles the instructions of its `--engine=vm` twin, on paths that NEVER reach the site too
- Method: `perf stat -e instructions:u taskset -c 7`, 3-5 repeats per cell (spread under 30 instructions per run), gcc 13 `-O2`/`-O1`, a find-all driver over a 1 MiB subject (driver and scripts: emitted/code/drv.c, perf.sh). The driver's own subject fill is ~3.47-3.74M instructions in every cell.
- Paths that do not reach the site: pattern `(\d+)(?:y|z(?C`c: return RX_PASS;`))` vs twin `(\d+)(?:y|z)` `--engine=vm`, subject `12y 345y 6y ` (262,146 matches; zero fires, proven by a `__builtin_trap();` segment that never traps). O2: 59,465,857 vs 29,319,027 (+30.1M, **+115 instructions per match, zero fires**). O1: 67,330,246 vs 36,659,132.
- Paths that do reach it: `(\d+)(?C`c: return RX_PASS;`)x` vs `(\d+)x` `--engine=vm`, subject `12x 345x 6x ` (262,656 matches, one fire each). O2: 68,653,197 vs 37,982,082 (**+117 per fire**); O1: 74,420,410 vs 43,749,306.
- Goal 3b(b) (inline_c.md Goals) asks for "within the A/A spread of the same pattern's callout-free `--engine=vm` twin plus `n` direct calls ... on paths that do not reach the site as well as on paths that do". With n = 0 the measured cost is about 2x. The cause shows in the stamps: the twin is `VM_FRAMELESS 1`, `VM_ENTRY_SHAPE "inline"`, `NSLOTS 4`; the segment artifact is `VM_FRAMELESS 0`, `"plain"`, `NSLOTS 6` (`SLOT_SPAN_LOW0`, `SLOT_GROUP1_PENDING`), `RESUME_FRAMES 2`/`TRAIL_FRAMES 5` against 1/3. So the presence of a site, reached or not, moves the whole VM off its frameless form and adds publish-at-close for every group (§1.3).
- This is NOT a stage-2 regression. The same pattern as a BASE-compiled binding in a unity build (`#include "nb.c"` plus a `const` binding whose `static inline` fn returns RX_PASS) measures 59,465,872, the same count. So the new call form costs nothing against the path it replaces at -O2. What it shows is that goal 3b's measurable form is not met by the site primitive both paths share.
- Severity: speed (design goal), and the goal text should change, or the cost should get a named row. Either the goal is restated as "within the binding path's own cost" (what holds), or the frameless/inline-entry loss for a site the path never reaches gets a plan row. Blast radius: every callout artifact, binding or code. Effort: a doc restatement, or a design row (framelessness is decided per artifact, not per path).

### EMIT-3 CONFIRMED (check design; goal 3b) — the inline card's `site_miss` row never runs the matcher, so goal 3b's "paths that do not reach the site" has no row that measures it
- tests/code/card_inline.sh ROWS: `site_miss|(\d+)@x|12y 345y 6y |`. The subject has no `x`, so the artifact's required-byte prefilter rejects the whole subject in one call, and neither artifact runs the VM. Measured (EMIT-2's driver, 1 MiB, O2): segment 3,465,733 vs twin 3,465,701 instructions, i.e. only the driver's subject fill. With the segment replaced by `__builtin_trap();` the run does not trap and finds 0 matches.
- So the card's "miss" row cannot fail, and the shape that does show the cost (EMIT-2: a path the VM really walks that does not reach the site, `(\d+)(?:y|z@)` on `12y`, +115 instructions per match) is absent. This is learnings §3's "witness that stopped reaching its site", in the card itself. `site_hit` and `tail` do reach the site.
- Fix: replace or add a row whose subject the VM really walks on a path that skips the site (e.g. `(\d+)(?:y|z@)` on `12y 345y 6y `). Also make the card report instructions (perf stat, as here) beside time, so that `--smoke`/UNMEASURED runs still carry a number. Effort: small. Blast radius: the card's verdict on goal 3b.

### EMIT-4 CONFIRMED (maintenance/contract; spec §11.9¶4, design §3.2) — the `#undef` block keeps EVERY `<PREFIX>_` macro live, the artifact-internal ones the design names included
- Input: `pcrec --features all --allow-code=c -p x -o - --pattern 'a(\d+)(?C`c: return RX_PASS;`)x'`. Cut the text just before the segment's function, then `gcc -E -dM`, minus the system headers.
- Observed: still live at the segment block are `X_CUT(slot_)`, `X_CHARGE_WORK(n_)`, `X_PRUNE_TOO_SHORT(p_,mr_)`, `X_PRUNE_CLAMP_SPAN`, `X_R_STEPS`/`_R_INTERNAL`/`_R_FRAMES`/`_R_RECURSE`/`_R_WORK`, `X_SLOT_WHOLE_START`/`_END`, `X_SLOT_GROUP1_START`/`_END`/`_PENDING`, `X_SLOT_SPAN_LOW0`, `X_RUN_WORDS`. Every one is defined in the `.c` only (the split build's `.h` has none of them), so none is a stamp. Only `x_VALID_LB` (the lowercase prefix) is `#undef`ed.
- Expected: inline_c.md §3.2 names exactly these as names to `#undef` ("`RX_CUT`, `RX_PRUNE_*`, `RX_SLOT_*`, `RX_R_*`, ... the pattern-dependent ... `RX_SLOT_GROUP<n>_*`", where `RX` is the upper prefix). Spec §11.9¶4: what stays defined is "the public contract: the stamps, the shared block's and §1¶6a's names".
- Cause: `code_keep[]` row `{ "\x01Q_", false }` (src/gen/emit_code.c, the first keep row) treats the whole upper-prefix namespace as "stamps". The check that should catch this, arm 7 of tests/code/run_code_tests.sh, excludes `^${upx}_` with the same blanket rule, so the control shares its source with what it controls (learnings §3).
- Effect: a segment, or a `code-header` the user includes, can read or collide with the matcher's private macros (`-p ip` and a user header defining `IP_CUT` gets a redefinition warning, or silently changes nothing since the matcher is already expanded). A later emitter that adds an upper-prefix internal macro leaks with no test noticing.
- Fix: keep only the names the stamp catalogue (src/gen/stamp_kinds.c, match_api.md §6.3) lists, read from that table, not from a prefix. The check should read the same catalogue independently, or list the `.h`'s macros as the public set: what a caller can see is what the `.h` defines. Effort: small to moderate. Blast radius: every code artifact.

### EMIT-5 CONFIRMED (doc; spec §11.2¶1a) — "Row 3 is always in the artifact's own translation unit ... is called directly" is true only when the optimizer folds the const load; at -O0 the code site is an indirect call
- Input: `ci.c` from `pcrec --features all --allow-code=c -p ci -o ci.c --pattern '(\d+)(?C`c: return RX_PASS;`)x'`, then `gcc -O0 -S`: 1 `call *` (the load of `ci__code1_ref.fn`). It is 0 at -Og/-O1/-O2/-O3/-Os.
- The design's replaced form (§1.4 row 1, a direct call to the segment function) was direct at every level. So the ONE CALL FORM is worse there only at -O0, which costs nothing anyone measures. Still, the spec states "called directly" without the condition. Suggested wording: "called directly (at any optimization level gcc folds a `const` initializer, -Og and up)". Effort: one sentence. Blast radius: doc only. The check in tests/code arm 10 compiles at -O2 only, which matches the reworded claim.

- **Indirect calls through a binding:** 0 at -O1/-O2/-O3/-Os/-Og for 5 code-only artifacts (1 segment; ipv4 4 segments; a segment in a `+` loop; a segment in lookahead and in alternation; `(?i)` with backreference; inside `(?>...)`). - **Instruction cost of the new path vs the replaced path** (perf stat instructions:u, taskset -c 7, 3-5 repeats, spread under 30): segment `(\d+)(?C`c: return RX_PASS;`)x` vs SUBJECT `(?C"x")` unity build vs BASE `(?C"x")` unity build: O2 68,653,197 / 68,653,210 / 68,653,210 (equal); non-reaching shape 59,465,857 (segment) vs 59,465,872 (BASE binding unity). The new form costs nothing measurable against the path it replaces. The cost against the callout-free twin is EMIT-2.

A `--code-header`-only artifact (no segment) gets `#undef` + `#include` in the `.c`, and nothing in the `.h`.
