# crit-altnf3 soundness findings (crit-sound)

## Findings

### SND-1 — Stage 1's island "set reading" is bypassed wherever the class sits at a spine head: `pcrec_ast_seethru` hands the island the merged byte child, so S-i's own witness loses its island and S-i/S-i2 cannot reach
- **CONFIRMED** (code reading + byte-spelling measurement). Severity: speed (VM island loss) + gate (U4 "equality" red on a correct build) + sabotage witnesses dead. Effort: small to state, real to build (an island-local spine walk that stops at `A_WCLASS`, or the set reading moved into the two spine walks). Blast radius: every utf8 alternation whose class is the FIRST element of a branch or the FIRST branch. Unit: 1. Design: §5 stage 1 "Change" (subject lines 794-822), S-i/S-i2 (lines 924-934), Gate U4 (lines 900-906), §3.5 G-2.
- Code (W): `vm_isl_words` reaches its `case A_WCLASS:` arm (`src/gen/emit_vm.c:4091-4092`) ONLY when the class sits in a raw `t->r` slot. Its `A_ALT` spine walk (`emit_vm.c:4114-4119`) and `A_CAT` spine walk (`emit_vm.c:4137-4146`) step `t = pcrec_ast_seethru(t->l)` and store `br[0] = t` / `el[0] = t`, the class's BYTE CHILD (`internal.h:2322-2326`, `while (a->k == A_WCLASS) a = a->l`). So a class at the head of a CAT spine (`[éà]1`) or in the first branch slot of an ALT (`[éà]|q2|r3`) is enumerated from its byte child, never from the arm the design moves onto the set. Today that is harmless (the child holds single-string boxes, under the seal's `A_CAT`, which the CAT walk also unrolls). After stage 1 the child is the MERGED form: `[éà]` = `c3 a0 | c3 a9` merges at p=1 to `c3 [a0 a9]`, the walk reaches `A_CLASS {a0,a9}`, `vm_isl_single` returns -1, and the whole island declines.
- Measured (W/build/pcrec, `--features all --engine=vm -fno-cls-kit`, the stage-1 child spelled as bytes): `x(?:[éà]1|q2|r3)y` utf8 today `RX_VM_ALT_ISLANDS 1`; its unmerged byte spelling `x(?:\xc3\xa01|\xc3\xa91|q2|r3)y` -e byte `1`; its MERGED byte spelling `x(?:\xc3[\xa0\xa9]1|q2|r3)y` `0`. Same for `x(?:[éà]|q2|r3)y` (today 1; merged child at the ALT's first slot). Control: `x(?:q2|[éà]|r3)y` keeps its class in a raw `t->r` slot and does reach the arm.
- Consequences, literally: (a) S-i's stated REACH ("`RX_VM_ALT_ISLANDS 1` in both builds", line 929) is false in the CORRECT build: the witness `x(?:[éà]1|q2|r3)y` has the class at a CAT head, so the correct stage-1 build stamps 0 and S-i fails in the correct build; its sabotage (the set reading enumerating only the lowest member) edits an arm this witness never enters, so the sabotaged build stamps the same 0. (b) S-i2 (`x(?:[éè]1|q2|r3)y`) is also a CAT-head class: the merged child is the single range box `c3 [a8 a9]` (0 today, 0 correct), and dropping the admission predicate cannot raise it because the arm is not entered: 0 in the sabotaged build too, so it cannot fail in either build. (c) Gate U4's island census, stated as an EQUALITY, goes red on a correct build for every merge-moved class at a spine head; the U1 table's "VM islands: never" row is wrong for the same population.
- Fix shape: the design must say which walk reads the set: either the island's two spine walks stop at an `A_WCLASS` (an island-local `seethru` that does not unwrap, so `[éà]1` is read as WCLASS then `1`; `pcrec_ast_seethru` itself must stay, `pcrec_lit_run` and other spine readers depend on it), or the set reading is applied where the walk unwraps. Then re-pick S-i/S-i2 witnesses with the class in BOTH positions (head and non-head), each with a REACH line computed against the correct build.
  Replacement witnesses with the class OFF the spine head reach the arm: `x(?:1[éà]|q2|r3)y` (today 1, `1[éà]` keeps the class in a raw `t->r` slot) for S-i, `x(?:1[éè]|q2|r3)y` for S-i2; the head-position pair stays as the census case that proves whichever fix is chosen.

### SND-2 — S-m is dead and the "remainder re-merge" (FIX-6) is a no-op under THE PROCEDURE's own M → P order; the predicted 2b stamps for `(?:abx|aby|abz)q` are wrong
- **CONFIRMED** (hand execution of §3.3 as written). Severity: gate/sabotage (a witness that cannot fail) + doc (predicted movers). Effort: small. Blast radius: S-m, the 2b mover list, §3.3's FIX-6 sentence. Unit: 2b. Design: §3.3 step 2 (lines 335-341), §5 2b predicted movers (lines 1109-1111), S-m (lines 1140-1143).
- Trace, literally: L = `abx|aby|abz`. Round 1, step M: w = 3, p = 2 first (last position first): all-but-2 keys `ab`,`ab`,`ab`; `aby` reaches head `abx` (nothing between) and folds; `abz` reaches `ab[xy]` (nothing between) and folds: L = `ab[xyz]`. Step P: no run of two branches, nothing. Step S: nothing. No change, stop. Result `ab[xyz]q`, rule-M folds 2 (or 1 if counted per alternation; §5 2b does not say which unit `MERGES` counts), rule-P/S factorings **0**. The design predicts `MERGES 1`/`FACTORED 1` and narrates it as P then M on the rests (`ab(?:x|y|z)q` → `ab[xyz]q`), which is the order THE PROCEDURE rejects.
- Generally: P's rests can never hold a fold M missed. P takes a run of CONSECUTIVE branches, strips a key of class nodes common to all; two rests of mergeable branches that share an all-but-p key had the same key at top level, every branch between them is in the run, and every adjacency row gives the same verdict on the stripped forms (the key's positions intersect, `h` and `w` both drop by |K|, WRITES unchanged). So top-level M already folded them. The "rests not re-run" sabotage therefore leaves `(?:abx|aby|abz)q` at `MERGES` = the correct count in BOTH builds: S-m cannot fail.
- What the re-run DOES buy: (a) P and S recursion (a nested trie: `(?:abcx|abcyz|abd)q` → `ab(?:c(?:x|yz)|d)q`, checked 0 mismatches vs libpcre2 over 37,449 subjects); (b) M on S's HEADS when the top-level branches were not mergeable only because of a shared non-class tail: `(?:ab\b|ad\b)` → P `a(?:b\b|d\b)` → rests: S `(?:b|d)\b` → M on heads `[bd]` → `a[bd]\b` (0 mismatches, 3,906 subjects). A live count witness for "rests not re-run" is `(?:ab\b|ad\b)`: correct `MERGES 1`, sabotaged 0 (P factors, nothing re-runs). Fix: replace S-m's witness with that shape, rewrite the FIX-6 sentence (the re-run serves P/S recursion and the S-heads merge, not "remainder re-merge"), re-state the predicted stamps, and say whether `MERGES` counts folds or alternations.

### SND-3 — "Position" is undefined between node adjacency and the description's positions read through zero-width nodes; under the second reading P's key and M's mergeable set cross `\K` and lookarounds and move answers

### SND-5 — §3.2's callout argument cites §11.6¶1's PURE-callee guarantee, but a pure callee may return a give-up, and the merge changes that answer
- **CONFIRMED**, doc/spec severity (pcrec already behaves this way elsewhere). Unit: 2b (also 1 is unaffected: lowering has no callouts). Design: §3.2 "Held, not in the set" (lines 255-262).
- §11.4¶2 lets a check callee return a give-up, which propagates; §11.6¶1 says a pure callee gets "the BACKTRACKING-ORDER answer ... every fire on every tried path honoured". Measured (W/build/pcrec, callee returning `PCREC_ERR_STEPS` (−2) unconditionally): `(?:ab|(?C1)x|ad)`, `(?:ab|(?C1)ad|ad)`, `(?:ab|a(?C1)x|ad)` on `ad` give `giveup-2 co=1`; their merged forms `(?:a[bd]|…)` give `(0,2) co=0`. (libpcre2 likewise aborts on the original and matches the merged form.) So "the spans agree on every P3 row" holds only for PASS/FAIL returns. pcrec already skips fires a backtracking order would make (`(?C1)x` on `ab`: `nomatch co=0` with the same give-up callee; start scan), so this is not a new class of behaviour, but the design's argument and §11.6¶1's text both need the give-up case stated (a skipped fire's give-up is not part of the defined answer), or the merge must refuse an `m` holding a callout.
