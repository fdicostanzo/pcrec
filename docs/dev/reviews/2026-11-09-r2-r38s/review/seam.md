### SEAM-1 CONFIRMED (design; answer-adjacent) — the define's run decision reads `pres_proof` (P2), so "by construction equal" is false; two equal run-span records, two different rendered extents
- Sheet §2.2 "Contract": "The decision reads ONLY the span, the art and `opts`: never `handoff`, `head_max`, the set-member spans or `pres_proof`. So the reply ... is, by construction, the decision the pre-check's define renders later."

A P2 link is `proven_by`, unverified: no run part is rendered at all.
- Repro (default opts, default prior, both DFA, both `need` OPTIONAL, identical whole run `786162636465666768696a6b71`):
  `$B --features classes --emit-facts --pattern 'xabcdefghijkq\w'` -> RX_REQ_WHY "dominated", `--emit-main` has NO `rx_reqrun*` part;
  `$B --features classes --emit-facts --pattern 'a.*xabcdefghijkq'` -> RX_REQ_WHY "emitted", parts `rx_reqrun` (the 8-window).
  Same run-span record, same art inputs, same opts: the define renders extent NONE on one and [5,13) on the other. A pure `mf_run_decide(span, art, opts)` returns ONE reply for both, so on the first it describes a text that is never rendered (C2/C4 have no find to read; §4's `@idx` "the position whose set the emitted find scans" has no find).
- Also: "verified at all" now lives in TWO slots, `mf_link.verify`/`proven_by` (define time, mf_ask) and `ver_len > 0` (fact time); `verify 0, proven_by 1` with `ver_len 8` is representable. (Slot finding, see SEAM-6.)
- Fix: state the reply as "the run part's decision IF the run is verified", add a none state for "no run part rendered" that pcrec reads off the define's link (P2/proven_by), and gate every §4 reader and the earned skip (§3.4) on the link, not the reply. Or move the ask to define time (SEAM-2/Q6). Effort S (doc) / M (if moved). Blast: §2.2, §2.4 C2/C4, §3.4, §4.

### SEAM-2 CONFIRMED (design) — the reply depends on the ROUTE (`need`), a generation-time decision, but is stored in a PATTERN-grain fact
- Sheet §2.1 states `need` "per route" on the run span, §2.2 says pcrec calls at FACT time from `pcrec_req_window` (`src/facts/req.c:826`) and "stores the reply in the run fact"; §6 Q2 itself says the extent moves on "VM attempt routes".
- Code: `need` is `site_kind_of(cx, SKS_PRE) == MF_SK_VM_ATTEMPT ? REQUIRED : OPTIONAL` (`src/gen/emit_dfa.c:1479`), and `site_kind_of` (:1440) reads `cand_finish_of`, `pcrec_artifact_has_dfa_scan`, `cand_route_of` — emission/route decisions in src/gen. P0 (REQUIRED) keeps the run WHOLE; P3 cuts the 8-window. So one run, two replies by route.
- Repro: `$B --engine=vm --features classes -p rx --emit-main --pattern 'xabcdefghijkq\\w'` emits `rx_reqrun_whole` (extent [0,13)); `--engine=dfa` the same pattern renders no run part (SEAM-1); `a.*xabcdefghijkq` (DFA) renders the 8-window. `--emit-facts` lists `req_run` as grain `pattern`, epoch E2, identical on both engines, and its own header says route decisions are NOT in the record (D124: "the route and emission DECISIONS the record does not hold").
- Consequence: under the sheet the pattern-grain `req_run` row would carry a route-dependent value (D124 breach), and `src/facts/` would have to compute `need` (a src/gen fact) to state the span. The fact-time/define-time split is the wrong seam: the reply is a SITE decision, not a pattern fact.
- Fix: ask `mf_run_decide` where the pre-check site is built (src/gen, which has the route, the art and the span), keep the reply on the Job/site record beside the link (`req_pres_ask`), and leave `req_whole_run` as the pattern fact. The `req_run` facts row shows the whole run (or retires); the stamp shows the decision (Q2). Effort M. Blast: §2.2 call site, §4 readers, §6 Q2/Q6, facts.def epochs (E2 -> a decision).

### SEAM-3 CONFIRMED (design/doc) — the stated input list omits art state the decision reads (levers) and misplaces the layer; the text record is not closed
- Sheet §2.2 "Input": "The art supplies the rates, the measure set, the denies, the layer and the target list."
- Code: `struct mf_art` (`memfn/src/kit.h:276-318`) carries `levers` (KIT_LEVER_PRES_WINDOW, set by `mf_lever`, compose.c:1402), which `precheck.c:146` reads ("`pres-window` keeps every part"); pcrec sets it per Job in `pcrec_memfn_art` (`src/gen/memfn_sites.c` ~:200). The sheet's own C4 (§2.4) depends on "the kit's test-only lever (`mf_lever`, a reversed tie)" — a decision input the list does not name. Equal {span, rates, measure set, denies, targets, opts} with the lever on vs off give different replies (C4's plant depends on exactly that).
- The LAYER is not art state: `mf_art` has `target`/`levels` only; "Policy is a SITE fact (mf_site.policy)" (`memfn.h:1361`, :783). The define's admitted levels are site.policy ∩ art.levels; `mf_run_decide` takes no site, so it cannot know which variants the define renders; §2.3's "held to it or reported at the minimum" over "each SIMD layer" must then be over every level the ART admits (a stronger, but different, statement) — say so.
- Text round trip therefore needs: the span (set form, need, omin, verify), opts, and the art's {analysis byte-rate payload + its state, measure set rows, denies, target row, levers}; NOT the arena/prefix/sites/forms/words. List them exactly, including levers and "every art-admitted level", or the C3 purity harness cannot be a serialization test. Effort S. Blast §2.2, §2.3, §2.4 C4.

### SEAM-4 CONFIRMED (design; no-silent-defaults) — `mf_run_reply` members lack none states and ranges; a zeroed reply is a valid-looking answer
- Sheet §2.2: `scan` "the run position (0..n-1) the kit's search finds first"; `ver_lo`/`ver_len` "0 = none proven"; "`*out` is zeroed whole first, on every return" and -1 where the define would refuse.
- (i) `scan` has NO none state: the zeroed reply on -1 reads as "scan position 0", a legal value. A reader that skips the return code (or the `--emit-facts` listing of a refused span) shows `@0`. The window family's reply has `run_stated`/`has_stop` for exactly this; the run reply has neither.
- (ii) "finds first" is undefined where the rendered form has no single find position: the run part not rendered (P2, SEAM-1); the floor/byte-loop shape (`mf_wreply.has_stop` 0); and `vrun.c`'s w32 level, which ANDs a SECOND position KB into the candidate filter (`memfn/src/vrun.c:41-60`, KA+KB at w32, KA alone at w16). Since §2.3 says the reply covers every layer, `scan` must say "the position whose set every rendered candidate filter tests (others may be ANDed in)", and C2's G2 classification ("the run part's find byte is `scan`'s set") must allow the ANDed KB.
- (iii) With `ver_len` 0, `ver_lo`'s value and meaning are unstated (a silent default: is it 0? unread?). State "`ver_len` 0 => `ver_lo` 0 and unread".
- (iv) Ranges/invariants unstated: `scan < n`, `ver_lo + ver_len <= n`, `n <= MF_WSPAN_POS` so uint8 suffices; whether `scan` may equal a position outside the run's core (it cannot, core is all n) — say it, so a text reader can check a record.
- Fix: add a `stated`/`kind` member (NONE: no run part rendered; FIND: scan valid; FLOOR: no find) and the invariants. Effort S. Blast §2.2, §2.4 C2/C4, §4.

### SEAM-7 (design; standing question) — `mf_run_decide` is the third member of the phase-1 family; the general form is a per-STATEMENT window decision whose reply is `mf_wreply`
- Members: `mf_wdecide(art, site) -> mf_wreply` (a site's window statement), `mf_pres_ports(art, site, proof, start_set) -> mf_pres_picks` (presence picks incl. P3's run scan/window), and now `mf_run_decide(art, span, opts) -> mf_run_reply`.
- Evidence they are one form: §2.1 puts the run on the `pspans` entry THROUGH the window-statement members (`nalt` 1, `alts[0]`, `wfloor` SUBJECT, `memfn.h:728-737`) — the run span IS a one-alternative window statement. `mf_wreply` already has `run_stated`, `run_member`, `run_lo`, `run_len` (`memfn.h:1500-1526`), i.e. exactly (`scan`, `ver_lo`, `ver_len`) plus the none state `mf_run_reply` lacks (SEAM-4) and `has_stop` for the no-find shape. The sheet's reason against `mf_wdecide` is only that it takes a SITE (and, under 3.0b, a frame + call kind).
- General form (proposed): ONE pure phase-1 entry over a window statement wherever it is carried — `mf_wdecide_stmt(art, const mf_pred *holder /* nalt/alts/wfloor */, opts, mf_wreply *)` — with `mf_wdecide(site)` a face passing the site's own statement and `mf_run_decide` retired into it (the pre-check part reads the run triple). `mf_pres_ports` keeps only the SET picks, P2 and the landmark admission (its P3 run half already retires per §5.1).
- Unlocks, each with its trigger:
  1. One member rule for the run on the pre-check AND the PF window site (SEAM-5) — trigger: K38-1's census counts a compile where the two members differ for the same run position.
  2. Set-member presence spans get the same reply (a proven extent per span) — trigger: [MATCH-KNOWN]'s prefix-skip build or the set-side change the sheet lists as a non-goal.
  3. One reply record to serialize for the plan-as-text seam (memory pcrec-plan-as-text-seam) — trigger: plan_frame 3.0b lands; frame/call kind become parameters with call NONE for a span, removing the sheet's stated objection.
- Not a blocker for K38-1 (kit-internal); it decides the K38-2 seam shape, so rule it before K38-2. Effort M at K38-2, saves a struct + an entry + its census row.

### Q6 (layering of the fact-time call): DISAGREE with the sheet's recommendation; move the call out of src/facts/
- Recommend: no call from `src/facts/`. Ask `mf_run_decide` (or SEAM-7's general entry) in `src/gen/` where the pre-check site is built (beside `req_pres_ask`/`req_pres_spans`, `emit_dfa.c:1475+`), which already holds the route (`need`), the art and the span; keep the reply on the Job's pre-check record beside the link; leave `req_whole_run` as the route-free pattern fact; `req_run`/`req_run_maxoff`/`req_landmark_maxoff` rows either show the whole run or move to the decisions section (they become decisions, D124).
- Reasons: (1) `need` — an input of the decision — is a route fact computed only in src/gen (`site_kind_of`), so a facts-side hook to the art is not enough; facts would also need the route (SEAM-2). (2) The define's decision reads `pres_proof` (P2), a site fact that exists only at site construction (SEAM-1). (3) D124: the facts record does not hold route/emission decisions. (4) src/facts' discipline ("Reads no prior and no option", `req.c:788`) and the listing's force-after-art-end path (SEAM-8). (5) Plan-as-text (memory pcrec-plan-as-text-seam): a seam serialized and reread must be asked where all its inputs exist, once.

## PROBED-AND-HELD
- §3.1 omin range: `int32_t` covers PCRE2's largest lookbehind (65535 x 4 bytes = 262140); no bound clamps toward 0 (refusal stated). HELD.
- §3.2 K sign: `head_max` is read only where `handoff == MF_H_ASSIGN` (`presence.c:199`, `emit_dfa.c:1629`); a signed 0 on ASSIGN is a stated K; pcrec's stated/none bit stays its own. HELD (no silent default).
- §3.3 floor arithmetic: `max(0, origin + omin)` with no unsigned wrap is stated as the kit's text with W-K1 as its plant. HELD as a statement.
- Art per Job ATTEMPT: each retry rung is a whole new pipeline pass on a fresh arena (`src/opt/dfamemo.c:4-8`), facts re-derived per attempt, so the fact-time art and the define-time art are the same object within an attempt. HELD (the equality fails on inputs, SEAM-1/3, not on art identity).
- `opts`: one string per compile (`s->opts = cx->opt->memfn`, `memfn_sites.c:468`); denies identical on every site of an art (memfn.h, refused otherwise). HELD.
- P3's run scan/window today reads only the byte-rate and the run term (`presence.c:152-175`): the K38-1 incumbent is reproducible from {span, rates}. HELD.
- `rank_*`/`plan_pos` are written by the kit's translation, never by pcrec on a pre-check (`memfn.h:671-675`, `window.c:1479-1509`): they do not become a pcrec-side duplicate of `scan`. HELD.
- Probes (6 patterns x up to 2 engines, 14 compiles): `xabcdefghijkq\w` (dfa: dominated, no run part; vm: whole part), `\dxabcdefghijkq\w`, `[0-9]+xabcdefghijkq`, `(?:foo|bar)\d*xabcdefghijkq`, `\w+@xabcdefghijkq` (all dominated), `a.*xabcdefghijkq` (dfa, window part), `(a|b)[^z]{3,9}xabcdefghijkq` (vm, window part). `req_run` row identical (`65666768696a6b71@7`, grain pattern) across all of them.
