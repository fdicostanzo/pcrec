### RDY-1 (CONFIRMED; severity design/doc -> the check's census side reads nothing; effort S; NEW in rev 3 (P15's fix text); part_d §5.1 D3 cell "collect.py already keeps every non-REACH MFTRACE line in a site's trace")
The claim is false at the build tree. `docs/dev/lanes/r33_sim/collect.py` `parse()` (lines ~143-165) buffers non-REACH `MFTRACE` lines in `pending`, but stores `s["trace"] = summarize(pending)`, and `summarize()` (lines ~128-140) keeps ONLY `END` (phase define/run) as `ends`, `FDROUTE` as `fdroute`, `WPATH` as `wpath`. Any other record kind (WCAND, ROW, SEL, ASK, FD ... and a new `MFTRACE run_part_terms`) is DISCARDED. So a census reading a collect.py sweep sees no `run_part_terms` record at all; the "ONE parser" has nothing to parse. Fix: D3 names collect.py's `summarize` (keep the raw `run_part_terms` lines, e.g. `trace["rpt"]`) as a changed file, and the swept JSONL format change (census0's sweep re-collected; vcls.out/census0.out goldens re-pinned) as a D3 obligation. Blast radius: D3's census side and the joint-landing floor; the G2-side half is unaffected (G2 does not go through collect.py, see RDY-2).
Addendum to RDY-1: the D3 check as written (G2 records -> the census's parser) BYPASSES collect.py, so it stays green on the kit branch while the production path (pcrec corpus -> probe build -> collect.py -> census0/vcls) carries no record; only the joint-landing pcrec floor (RDY-5) could see it, and that floor is itself under-specified. The cell should also name the path (`docs/dev/lanes/r33_sim/collect.py`, the one census0.py's docstring names as "R-33's raw sweep (collect.py's JSONL)"; `r17b2/collect.py` is unrelated and keeps no MFTRACE).

### RDY-2 (CONFIRMED by code structure, consequence INFERRED; severity design (the check can red on a CORRECT build); effort S; NEW; part_d §5.1 D3 cell "ONE line per derived part where it hands the terms to ofsskip")
`run_part_terms` replaces `derive_run_part` + the family call INSIDE `wf_parts_prepare` (§2.1), which `window_route` (memfn/src/compose.c:1007-1016) calls BEFORE the row is selected, from BOTH `ask_sel` (compose.c:1040, quiet=1, mf_ask) and `define_sel` (compose.c:1107, quiet=0). So (a) the function does not know whether ofsskip, the generic row or another row will consume the terms: there is no "where it hands the terms to ofsskip" inside it; (b) G2's GENERIC PASS (`g2_pres_gen.c` ~632-645, on_miss_leaves 0: "the generic row renders it, its run part inline (no function)") prints a record on every wide site, while `g2_pres_run.c` main loop (~704-712) `continue`s past generic sites WITHOUT classifying: G2's per-site count there is 0 (or undefined) against the census's >= 1, so the per-site equality REDS a correct build unless the population excludes generic-row sites; (c) pcrec's trace builds call `mf_ask` on sites they are about to write (src/gen/emit_dfa.c:7074, 11337, `PCREC_CAND_TRACE`, which r33_sim/build.sh enables), so an ungated print doubles a site's records on the census side (G2's own `mf_ask` calls, g2_pres_gen.c:500/510, precede the part layout, so G2 is not doubled). Fix (text): the print is on the non-quiet path only (the house rule at compose.c:1033: "no trace record of its walk (the walk is quiet: a query is not a selection)"), and the D3 population is "sites whose define chose an ofsskip/FUNC row" (G2 knows `forms`; the record can carry the chosen row, or the census joins the FDROUTE/`fn` END), with generic-pass sites counted as their own literal (or excluded by name, never silently).

### RDY-3 (CONFIRMED; severity doc (reader list wrong; the "no check, silent gap" argument mis-stated); effort S; NEW (rev 3's P15 text); part_d §5.1 D3 cell "which today read only window statements `alts` and the family reply `wr`, both of which F26's direct translation no longer writes for a derived part", and §5.1.1 "the card's forecast, would price the site from its RUN term alone, silently")
The census NEVER saw a derived part through `alts`/`wr`. The R33 probe (`docs/dev/lanes/r33_sim/probe.c` `site_line`, ~140-160) writes a `preds[]` entry's `part`+`wr` ONLY `if (p->nalt)`; a derived part is by rule `nalt 0`, `nterm 0` (`part_derived`, memfn/src/window.c:2457; `derive_run_part` fills `nalt` only in the kit's arena copy, window.c:2543-2570, never visible to the probe's wrapper). census0.py `units()` (~278-292) yields a part only for `"part" in p`, and both `vcls.py main` and `census0.vcls_lines` (~525-552) skip any site without site-level `alts` and outside `row1_class`. So today a derived-part site is INVISIBLE to the forecast and to vcls (not "priced from its RUN term alone"); F26 removes nothing they read. Consequences: (1) the new parser is the FIRST reader, and it needs a NEW population branch (sites carrying a `run_part_terms` record), not a slot in vcls's existing loop, whose `alts`/`row1_class` filter would drop every such site; (2) the only derived-part data the sweep holds today is the family call's MFTRACE END records (wfA..wfE etc., quiet=0 at define) summed into the site's `trace.ends`, which `census0.today_method` reads positionally (`tab["wfE"][0]`, `tab["fn"][part_ix]`) and `r33_sim/sim.py`'s twin of it; deleting the family call removes those END records, a reader of a replaced input the cell does not list (harmless only because units() skips such sites; say so). Fix: rewrite the clause to "the census today has NO population for derived parts; D3 adds one", and list `today_method`/sim.py as checked-unaffected.

### RDY-4 (CONFIRMED (absence); severity design (the check cannot be built as written); effort S-M; NEW; part_d §5.1 D3 check "Per site, the census's count ... EQUALS G2's own count", "recorded from G2's counts at D2"; separability)

### RDY-5 (CONFIRMED (the artifact's unit read); severity design/doc (the joint-landing floor is not well defined); effort S; NEW (P15's text); part_d §5.1 D3 check "the census over the stage-3 corpus sweep counts at least pcrec's own count of stage-3 run parts with a wide verified position (from pcrec's artifact diff, `emit_sweep`)")
`emit_sweep` produces no count of "run parts with a wide verified position". Its artifact-diff counts are DIFFER cells: `(base, flag, stream) -> (bytes_floor, stamp_floor, manifest)`, the number of DISTINCT corpus PATTERNS whose emitted bytes differ between BASE and BASE+FLAG (scripts/emit_sweep.py:423-437), per encoding base (byte/utf8) and stream (c-default/c-vm). The only pcrec artifact diff that isolates wide verified positions is the D2 deny arm `--memfn=no-run-verify-wide` once P13c turns its ASSERT_ZERO cells into DIFFER_PINS at the landing (§5.1.1 D2): its mover count. So the text must name: (i) that cell (base, stream) and its bytes_floor as "pcrec's count"; (ii) the census-side quantity in the SAME unit (distinct patterns with >= 1 unspelled SET term in a `run_part_terms` record, on the same encoding; collect.py compiles `--features all -p rx` once per pattern, RTE arm, over corpus+bench+s588 by default, emit_sweep over the .rxt corpus only, so the census must be restricted to `--sources corpus`); (iii) why census >= movers holds on a correct build (a deny mover whose only moved reader is the reply extent or the twin, with no laid-out derived part, would make the census smaller: e.g. an untested/declined link or a REPORT site; INFERRED, needs stage 3 to measure). Without (i)-(iii) "a literal raised in the landing commit" can be set to any number and the inequality's direction is not argued. The kit-branch value 0 is well defined (the check is vacuous there, as stated).
