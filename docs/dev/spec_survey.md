# [SPEC-1] step 1 — the spec-coverage gap survey

Read-only survey, lane srSpec. Every claim below was checked against the
shipped surface as of commit `841735c` (HEAD at survey time) — the CLI
against a live run of `build/pcrec --help`/`--list-syntax`/`--list-families`,
the header against `lib/pcrec.h`, the spec against `docs/spec/match_api.md`
and `docs/spec/table_contract.md`, decisions against `docs/dev/decisions.md`,
K-rows against `docs/dev/known_issues.md`. Commands run are named per row or
in the "verified" column; nothing here is copied from a design doc without
checking it against what actually ships (match_api.md's own discipline,
applied to this survey too).

**Legend.** `today` column: file:section, or "nowhere". Tier notes:
**SPEC** = already docs/spec-grade prose; **DESIGN** = docs/design/ or
docs/dev/decisions.md, reasoning-grade, not contract-grade; **DEVDOC** =
docs/dev/* process record (plan.md/known_issues.md/journal), not written for
a spec reader; **CLAUDE.md** = per-directory CLAUDE.md, maintainer-grade
prose; **CODE** = comment-only, in source; **BINARY** = observable only by
running the tool, stated nowhere in prose. Priority: **P1** a stranger hits
it in the first hour, or a contributor needs it to land a change; **P2**
important but not first-hour; **P3** completeness/nice-to-have.
