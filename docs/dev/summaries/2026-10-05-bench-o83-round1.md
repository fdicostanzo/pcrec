### [CLS-TREE] S2 range respelling (no flag): 65 real rows, 30 improve / 35 regress

**What it is in pcrec terms:**

- **The change.** D139 item 2 (review fix `ddfefeb7`, merged in
  `1c12395f`; the abi 52 → 53 event). The scan edge stopped choosing its
  own class form. It now emits the general class table's (ROWS) range form
  through the VM's emitter.
- **The new spelling.** "One spelling serves both (the tighter)": the
  scan edge's `(unsigned char)(b - lo) <= span` became the VM's
  `(unsigned)(b - lo) <= spanu`. `docs/dev/lanes/clss2_report.md`,
  "Spelling unification":
  - it found 79 default DFA artifacts moved in TEXT and committed the
    change;
  - it stated that the two spellings "compile the same".
- **What the bench found.** Its machine-code census refutes that: −4 B
  per range test site on 56 DFA artifacts.
- **The timing is a consistent regime split, not a coin flip:**
  - plain throughput is SLOWER on every row: the `cls-upto-*`/`dig-*`
    ladder +0.2..+8%, `cls-upto-1024` +0.054 ns/B, `nest2-letters-6`
    +0.248 ns/B (+19.9%);
  - plain short search is FASTER on every row (−0.6..−8.7%, i.e. −0.5..−2
    ns per subject);
  - whole-subject is mixed (`cls-atleast-4096` −46.6%, `nest*`/`dig-upto-*`
    +3..+8%).
- **Why it has no deny flag.** It is not an optimization. It is the
  emitted spelling of a form that D139 unified: one emitter, so one
  spelling. A flag that brought back the old spelling would be a parallel
  mechanism (memory: general mechanisms, not special cases).

**Is it a D144 item-4 violation? No, by letter:**

- S2 merged 2026-09-30. D144 is dated 2026-10-03.
- S2 is a [CLS-TREE] build (live builds are explicitly not [OPTLOOP]
  candidates, D137), not a round-1 optimization.
- D139 ruled the single spelling.

**It is, however, a gap in D139's own clause** "any default artifact whose
text moves is measured and reported":

- It was measured as TEXT, never as machine code or time.
- It now carries a consistent per-byte cost of about +4% on the bounded
  scan-edge throughput ladder.

The remedy is a measurement, not a flag. A pcrec-side Linux twin of the two
spellings on one throughput cell and one short-search cell (with an
alignment control) decides which spelling the one emitter should keep, per
regime. The finding is drafted as a K row in the lane report.

**The other flagless movers:**

- K78 (email `factored`): flat, 1/1.
- A1 (capability `logparse-atomic`): not a real mover this window.
- 2 bounded `nest2-64`/`nest3-16` rows are unattributed, +3.8..+6.5%.
