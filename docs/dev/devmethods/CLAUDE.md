# docs/dev/devmethods — the development-methods hand-off and its evidence

An analysis of how pcrec was developed, written 2026-10-20 (lane
devmethods) at the owner's request. It has two deliverables built from
one evidence set: a document portable to another project, and proposals
for this one. It is a dated snapshot, not a living rule file. The rules
pcrec actually follows stay in the root `CLAUDE.md`,
`docs/dev/lanes/BOILERPLATE.md`, `docs/dev/learnings.md`, the manager
skills and the manager's memory. The living home for transferable lessons
is `docs/dev/meta/`.

## Files

- `dev_methods_handoff.md`: THE HAND-OFF. Development methods and practices
  that worked, written for a new project's owner and AI manager. It covers
  lane control, critic panels and blinded authors, session management,
  communication between sessions, liveness, testing, process, safety on a
  shared machine and working with the owner. Each practice gives a rule,
  why (the incident, with costs) and how to apply it. It closes with an
  anti-patterns table, a start-up checklist and templates. Portable: roles
  only, no hostnames, addresses, usernames or home paths.
- `apply_here.md`: part A, fourteen ranked PROPOSALS for applying the
  journal's learnings to pcrec now. Each has its evidence by journal date
  and session, what is already in place (checked against the files),
  the gap, the proposal and its cost. Nothing in it is ruled. It changes no
  rule file, skill, script, hook or memory.
- `journal_notes_1.md` … `journal_notes_4.md`: the EVIDENCE INPUTS. Four
  reader notes extracted from the whole `dev_journal.md` by slice (from
  2026-08-09 to 2026-10-18). Each lists practices that worked, failures
  with the rule each produced, and lessons that recur or are not yet
  applied, cited by journal date and session with short quotes. They
  overlap. The two documents above deduplicate them. Kept committed so a
  claim in the documents can be traced without re-reading the journal.

Maintenance: none expected. A later revision of the hand-off is a new
dated file or a new lane; these files are not edited in place except to
fix an error.
