- P4. - P8. Ask which of the branches you just added no test can see. ### 1.2 Testing and check design

- T1. Oracle-verify every test expectation (python `re` for the base tier), record oracle divergences in an upstream-issues file, and exclude the divergent cases rather than bake in the wrong semantics. — 2026-08-09 "Subagent final reports: oracle-divergence notes for M7".
- T2. A differential fuzzer against the real reference library (libpcre2 via dlopen) alongside the corpus; make it deterministic per seed (pre-generate in the main thread). — 2026-08-09 "M2 core"; "R2 complete".
- T3. Sabotage testing: deliberately break each optimization and see what goes red. R2's process critic showed 3 of 6 features could be disabled with zero signal; the fix was structural codegen tests asserting each optimization's signature in the emitted text, validated by re-running the critic's exact sabotages. — 2026-08-09 "R2 process critic reported late" — "3 of 6 M2 features could be completely disabled with ZERO signal".
- T4. Structural tests for behaviour-preserving optimizations: a build with the optimization off must emit byte-identical C (trie identity, `-DPCREC_NO_TRIE`), so the diff tests the soundness rules directly without subjects. — 2026-08-09 "R3 follow-ups" — "the trie IS structurally testable".
- T5. Every equivalence check needs a POSITIVE CONTROL showing the optimization actually fired, and the control must fire INSIDE the corpus's own range (4, 8 and 256 branches, not just 256). — 2026-08-09 "critics on my own R3 work" — "the control must fire INSIDE the corpus's own range".
- T6. A validation of a test improvement is a run against a known bug; a "nicer green" proves nothing. Two fuzzer improvements reported 0 divergences while broken. — 2026-08-09 "Session close (context exhausted)" — "A test-improvement not validated against a known bug is just a nicer green".
- T7. Baseline first: run the divergence sweep against the PRE-change binary to establish whether you introduced or uncovered the divergences. — 2026-08-09 "M2.12" — "I ran the sweep against the PRE-M2.12 binary first and got 0 divergences".
- T8. Interleaved, repeated, pinned measurements for any performance claim; a perf number in a commit message, decision entry or journal must come from an interleaved repeated measurement of the exact build described. — 2026-08-09 "CORRECTION: M2.10 reverted" — "If it does not, do not write the number."
- T9. Gate on the project's OWN absolute per-case numbers (floors) rather than cross-engine ratios, with per-case margins derived from each case's own trial spread; have the tool print its own blind spot ("a uniform regression must exceed 1.43x to fail"). — 2026-08-09 "CORRECTION"; "R3 follow-ups R3.5".
- T10. Tri-state exit codes for gates (0 clean / 1 failed / 2 not gated) and a gate that fails when coverage is incomplete (unmeasured case is FAIL, not SKIP). — 2026-08-09 "R3 critic panel reports (late)", "R3 round 2".
- T11. A known-fail ratchet directory that inverts the verdict (still failing = expected; newly passing = flagged for promotion), so deferred bugs have regressions without keeping the suite red. — 2026-08-09 "M2.9 benchmark rigor, M2.10, M2.11".
- T12. A "never miscompile / name the right module" promise needs its own hand-written reject table with exact exit code, module name and no-output-file assertions, plus ACCEPT controls so rejecting everything cannot score 100%, plus count floors. — 2026-08-09 "PCRE2 compliance survey" — "the mandate's central guarantee had no test".
- T13. Over-rejection is the opposite failure and just as wrong: probe the reference's exact accept/reject boundary (18 forms) before fixing and keep accept-controls. — 2026-08-09 "the survey's second divergence".
- T14. Registry/table conformance checked in BOTH directions (table to parser, and a sweep of every doorway byte parser to table); keep hand-written reject rows as the independent source because iterating the dump cannot see a wrong module name (measured on four sabotaged trees). — 2026-08-09 "SR-1"; 2026-08-10 "SR-3, SR-4, and R5".
- T15. Where the cheap oracle (python) and the real reference disagree on meaning, the python-verified corpus certifies the divergence. Use the real reference (libpcre2) or read the spec. RECUR (`\v`, collating elements, `[:alpha:]`). — 2026-08-09 "survey ... found a miscompile"; 2026-08-10 "SR-2" — "the corpus is structurally incapable of finding this class of bug".
- T16. Test the test-extractor: when tests grep an engine body extracted by name, build a two-engine fixture and require the scoped grep to find the feature in one engine and NOT the other. — 2026-08-09 "OS-0b" — "Neither failure mode can pass by accident."
- T17. Cheap mechanical guards for design invariants (TS-1: every emitted static is const, no non-reentrant libc) with a sabotage number as justification (non-const statics fail 8 checks, 0 corpus cases). — 2026-08-09 "TS-1".
- T18. Build sabotage from a fresh tree per edit with the edit asserted to have landed before the build; a `git checkout` inside a non-git tarball swallowed by `|| true` contaminated a reported number. — 2026-08-09 "critics on my own R3 work"; 2026-08-10 "SR-2" (the MECH-2 failure rebuilt by hand).

### 1.5 Additional testing and critic practices (2026-08-10)

### 1.6 Spec-first blinded testing (D27) and panel discipline (2026-08-10)

- B1. D27: tests written by an author FORBIDDEN to read `src/` or `tests/` (allowed: CLAUDE.md, APPROACH, the public header, the reference library, the binary as a black box). Owner's diagnosis: "the coder is writing the tests based on the code, not the goal". It found a tier-1 miscompile (`[0-[:digit:]]`, 546 instances) in the first hour that four source-reading critics, 1.24M generated patterns, 2.4 billion probes, ASan and the fuzzer had missed. Mechanism: every range in the repo was `a`-based, and 'a'(0x61) > '['(0x5b) masks it. Isolation, not adversarialness, was the active ingredient. — 2026-08-10 "SPEC-FIRST TESTING"; "session close: R9" — "tests derived from the implementation inherit the implementation author's alphabet."
- B2. The blinded readers also produce the first cold read of your own docs (seven ambiguities filed as DOC-1) and independently re-derived a planned step (Q2) from documents alone, a second justification for it. — same entries.
- B3. Knowledge the code does not act on is invisible to tests derived from the code: the fact for the second blinded finding sat in the `\N` row's `note` field, correct and read by no check. — 2026-08-10 "SPEC-classes-F1".
- B4. Run panels as repeated WAVES: send each critic back at the remedies for its own findings, and re-measure the pushed tree. Waves 2-7 found live product bugs (`[[:<:]]` position rule), a guard disarmed by the next fix, and a count that cannot see a swap. Third consecutive panel whose best material arrived after a less patient checkpoint would have closed. — 2026-08-10 "R9, second wave" through "seventh wave".
- B5. When a later fix lands, RE-RUN the earlier positive controls; two guards were found disarmed only that way. — 2026-08-10 "R9 session close" — "That last habit is the transferable one."
- B6. A generated sweep of the construct's space beats a hand-pinned list: 555 generated class-bracket patterns found 126 divergences where the plan listed five. RECUR (R8, FIX-2 "I listed a name space instead of generating it"). — 2026-08-10 "FIX-2".
