# grid1 — the joint timing slot (costmodel §F rows F1, F2, F3)

This directory holds the scripts that build, check and run one timing slot. The
slot directory (`$OUT`, by default `worktrees/memfn-slot/grid1/`) holds everything
the scripts produce. Nothing in it is committed. What the slot measures, and why
it measures those things, is in `../grid1_report.md`. This file is the
**interface contract** that other arm sets plug into, plus the workflow.

## Workflow

    OUT=$OUT bash build.sh          # design, subjects, own arms, every ext set
    OUT=$OUT bash check.sh          # the correctness gate -> check.log, excluded, unreached, landing_fidelity
    OUT=$OUT bash plants.sh         # the gate's failing direction (14 plants)
    OUT=$OUT bash time.sh --estimate
    setsid nohup bash slot.sh >/dev/null 2>&1 </dev/null &     # status: $OUT/slot.status

To add an external arm set:

1. Write the set to `$OUT/ext/<name>/` (contract below).
2. Run `OUT=$OUT bash build.sh --ext`.
3. Run `OUT=$OUT bash check.sh`.
4. Launch `slot.sh`.

`slot.sh` refuses to run while `check.log` is older than any arm table, ext file or
binary.

## The arm contract

### arms.tsv

The file is tab-separated, with `#` comments. Each row has five columns:

    cell  arm  role  subjects  modes

- **role** is `base` or `arm`.
- **subjects** and **modes** are comma lists. A row stands for the cross product
  subjects × modes.
- **modes** are `first` and `all`.
- **Rows add up.** A (cell, arm) pair may appear on several rows. Its role must be
  the same on every row.
- **One base per cell.** Every cell has exactly one `base` arm. The base must cover
  every (subject, mode) that any arm of its cell lists. `time.sh` launches the base
  twice per round (`base` and `base#b`, the A/A pair).
- **Subject tokens.** A subject token is `NAME` or `NAME@OFF`. `NAME` must exist as
  `$OUT/subj/NAME`. `OFF` is the subject's start offset past a 64-aligned block;
  the harness passes it as `GRID_OFF`. Every subject is placed 64-aligned plus
  `GRID_OFF`, default 0. So `NAME` and `NAME@0` are the same placement, timed as
  two separate groups.
- **Validation.** `arms.py OUT validate all` checks all of the above, and that every
  `bin/<cell>/<arm>/run` is executable.

### run (required)

    $OUT/bin/<cell>/<arm>/run SUBJECT first|all

1. **Output.** It prints exactly one stdout line:

       matches=M hash=H ns/pass=X

2. **Method** (slot25c `drv.c`): calibrate by doubling until one loop takes at least
   50 ms, then run 7 rounds of that loop and report the median ns per pass.
3. **One pass.** In `first` mode a pass is one `rx_search` from offset 0. In `all`
   mode a pass is the find-all loop of match_api.md §3.1: after a non-empty match
   `p = rx_next_pos(s, n, end - 1)`, after an empty one `p = rx_next_pos(s, n, end)`.
4. **The answer.** It is computed on one untimed pass over every buffer:
   - In `first` mode, `M = 1` per buffer, and `h ^= (r == 1 ? start*31 + end : 7)`.
   - In `all` mode, M is the match count, and `h = h*131 + start*31 + end` per match.
   - Buffers fold as `M += m` and `H = H * 1099511628211 + h` (unsigned 64-bit).
   - For one buffer this is exactly `drv.c`'s line.

   `check.sh` compares this line to the cell's base and (own cells) to python `re`.
5. **SUBJECT** may be any of:
   - a regular file;
   - a directory, meaning every regular file in it, in name order;
   - a `*.list` manifest, one path per line, relative to the manifest's directory.

   A directory or manifest is a **streamed** subject. One pass is one buffer. The
   timed loops cycle through the buffers with one cursor that never resets, so
   consecutive passes see distinct data. `ns/pass` is per buffer.
6. **GRID_OFF=k** places every buffer k bytes past a 64-aligned block.
7. **GRID_FIXED=N** skips the clock. The binary runs N passes, then prints:

       matches=M hash=H passes=N cycle=C cycleexp=E

   - `cycle` folds a content fingerprint (FNV-1a of the whole buffer) of the buffer
     each of the N passes is handed, read through the timed loops' cursor.
   - `cycleexp` folds every buffer's fingerprint in order.
   - With N = the buffer count the two are equal; check leg C tests it.
   - `GRID_FIXED=0` is the answer line alone (legs O and R).
   - F2's perf pass uses N > 0 and N = 0.

**The easy way to meet all of this:** link `$OUT/lib/gdrv.c` (its `main`) with your
object, which must define the two functions below. Built with `-DKEEP`, the `all`
loop instead holds one `struct rx_keep` (`keep.h`) across a pass and calls
`rx_search_keep`.

    int rx_search(const unsigned char *s, size_t n, size_t from, ptrdiff_t (*caps)[2]);
    size_t rx_next_pos(const unsigned char *s, size_t n, size_t pos);

**Opting in to streamed subjects.** An arm set opts in by listing a streamed subject
(a directory, conventionally with a `-S` suffix) in its rows.

- Linking `gdrv.c` gives the cycling for free.
- A self-written driver must implement items 5-7 above, or must not list streamed
  subjects.
- Check leg C rejects a driver that does not cycle.

### cnt (optional)

    $OUT/bin/<cell>/<arm>/cnt SUBJECT list first|all     (GRID_OFF honoured)

This is a counting twin, never timed. Its stdout is ignored. Its LAST stderr line is
`key=value ...`, and `time.sh --counts` records it verbatim in `counts.tsv`, one row
per (cell, arm, subject, mode). Own arms print
`uses cold cache_hit cache_pass xcall skipped head_hit head_bytes blocks calls nbuf`
(streamed: summed over the buffers). The own cells' site counters are the `G1`
twin's, recorded as arm `site(G1)`, and leg U reads them.

### chk (optional)

    $OUT/bin/<cell>/<arm>/chk SUBJECT list first|all [OFF]

This is `gchk.c`'s list. On a single file it prints every match, then the `drv`
line. On a streamed subject it prints one `buf K matches=M hash=H` line per buffer,
then the folded line. Leg L compares it byte for byte with the base's. It runs only
when the arm and its cell's base both have a `chk`.

### Subjects from an external set

An ext set may use any of the own subjects by name. It may also add its own: give it
an executable `$OUT/ext/<name>/gen_subj`, which `build.sh` runs with `OUT` and
`GRID` set. It must write `$OUT/subj/<name>_*`, with the ext set's name as prefix,
never a `g1-` name. Its subjects have no python oracle, so legs R, L and C check
them against the cell's base only.

### External arm sets

An external arm set is `$OUT/ext/<name>/{arms.tsv,build.sh[,gen_subj]}`.

- **build.sh.** `build.sh` (and `build.sh --ext`) runs `$OUT/ext/<name>/build.sh`
  with `OUT`, `GRID` (this directory), `CPUS` and `JOBS` in the environment,
  pinned to `CPUS`. It must leave `bin/<cell>/<arm>/run` for every row of its
  `arms.tsv`, and may add `cnt` and `chk`.
- **Timing.** `time.sh` merges every ext `arms.tsv` with the own one.
- **Its own cells** (the usual case: a pcrec engine arm and its own base) are timed
  in the slot's **EXT** phase, after F1, F3 and F2.
- **Joining an own cell.** A row may add an `arm` to an own cell. It can never add a
  second `base`; validation refuses that. The arm is then interleaved into that
  cell's groups and timed in F1 or F3. Note that this lengthens those phases; check
  `time.sh --estimate`.
- **Gating.** Every ext arm goes through the same gate as the own arms: legs R, L
  and C. If an arm fails, the slot refuses to run unless `ALLOW_EXCLUDED=1`, in
  which case it is recorded and skipped.

## The timing harness (time.sh)

- **Groups.** It times every (cell, subject, mode) group of the merged tables for
  one `PHASE` (F1 = own cells, F3 = `f3-*`, EXT = cells whose base an ext set
  declares).
- **Interleaving.** Each round launches every arm once, and the base twice
  (`base`, `base#b`). Each round's order is rotated by one from the round before.
  There are `LAUNCHES` rounds (default 5), all `taskset -c $CPU` (default 14).
- **Per-row figures.** Each row reports:
  - the median over launches of each launch's 7-round median;
  - the A/A floor `|base#b - base|`;
  - the per-launch spread (min..max as % of the median);
  - delta per match;
  - a WIN/LOSS/NULL verdict, where a delta inside the floor is NULL.
- **Raw file.** Every launch is also written to `time/raw_<PHASE>.tsv` with its
  round, position, answer, load1 and timestamp.
- **Quiet gate.** Before each group it waits in 20 s steps, at most `LOADWAIT`
  steps (default 60), for load1 < `LOADMAX` (1.5), and records the waits.
- **Skips.** It skips groups in `unreached` (leg U: the site never runs, so the row
  would time an upstream gate). In `first` mode it skips keep arms that `build.sh`
  marked `same_first`.
- **Other modes.** `--estimate` prints launches and wall per phase. `--counts` runs
  the counting pass. `DRY=1` runs the whole loop with no clock.
- **Completion line:** `time.sh: COMPLETE rows=N wall=Ns`.

## Status file (slot.status)

| line | meaning |
|---|---|
| `SLOT_START` | the start |
| `SLOT_REFUSED <why>` | no-check / stale-check / arm-tables-invalid / excluded-arms |
| `EXCLUDED` | the arms skipped under `ALLOW_EXCLUDED=1` |
| `CHECK_OK` | the gates passed |
| `QUIET load1= waited= ok\|NOT-QUIET-proceeding` | the quiet wait |
| `COUNTS`, `ESTIMATE` | the counting pass and the estimate |
| `<PHASE>_START`, `<PHASE>_END rc=` | each phase's start, and its end with return code |
| `F1`, `F3`, `F2`, `EXT` | each phase log's last line |
| `F2_SKIPPED <why>` | F2 could not run, for example `perf_event_paranoid=4` |
| `F2_DONE rows=` | F2 ran |
| `EXT none` | no ext set declares a base |
| `SLOT_DONE` | the end; `$OUT/SLOT_DONE` is also touched |
