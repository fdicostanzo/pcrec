## Item 2 — the two load-sensitive limits
**rxtsource W23-S7 corpus control** (`tests/rxtsource/run_rxtsource_tests.sh`, `"$TIMEOUT_BIN" 120 bash "$RUNSH" --dump tests`): a fixed WALL bound on a no-compile parse of the whole corpus; the sibling C0a pass (~l.840, same `--dump` over the same corpus through a counting wrapper) already allowed 900 s. MEASURED, three runs at load ~3: **9.97 / 10.46 / 9.59 s wall** (8.0-8.6 s user + 2.2-2.3 s sys). 120 s is 12x that, with no derivation recorded, and wall stretches without bound at `make test`'s load 47 or on a spawn-tax box, so it was a load gauge. Fix: it is now a documented CEILING, `${RXTSOURCE_DUMP_SECS:-900}` (same as C0a, ~90x quiet), comment states the measurement, "a firing is a finding". D45-consistent: this is a hang detector, not a speed gate. (CPU-primary was considered; the process tree is bash+python, so a watchdog CPU cap would add ~170 ms and a second number for no added detection.)

**clskit's "10 s chunk wall"** is `gen_run`'s `gen_run_secs` (GENRUNTIMEOUT 10 s plain / 60 s san) applied to each checker unit in `check_chunk`; the CPU budget (`gen_cpu_secs`, 10 s) was already primary but equals the wall, so any contention fires wall first. MEASURED (`KEEP=1 bash tests/clskit/run_clskit_tests.sh`, 118 s wall total, 5/0): 331 units, run wall **min 0.09 / median 0.14 / p90 0.49 / max 1.58 s** with 16 threads busy; the worst unit (chunk_075) solo **0.94-1.10 s** wall = CPU (3 runs); compile CPU max 0.60 s, total 80.9 s (vs the 10 s D45 compile budget; unchanged). So 10 s was only 6-10x a CPU-bound ~1 s unit; the unit size is bounded by construction (`CHUNK_VARS`/`CHUNK_BYTES`), unlike the sub-millisecond matcher runs the tight 10 s was sized for. Fix: the run's wall backstop is `${CLSKIT_RUN_WALL:-$(gen_timeout_secs)}` (60 s plain / 180 s sanitizer: D45's "CPU budget x worst contention" backstop value, the same one the unit's compile already gets), passed as `GENRUNTIMEOUT`/`GENRUNTIMEOUT_SAN` to that one `gen_run` call only. The CPU budget remains the primary bound, so a runaway checker still dies at 10 s of CPU. Re-ran after the edit: clskit 5/0.
