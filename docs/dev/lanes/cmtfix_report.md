# cmtfix — the DFA-emitter COMMENT-ESCAPE fix (2026-09-17, lane cmtfix, sonnet)

pcrec-bench O-31 finding F1: a pattern whose own bytes contain `/*!*/`
(the SQL-comment-obfuscation shape a WAF rule, id
`wild-waf-crs-942500-comment-obfuscation`, matches literally) refuses on
the DFA route with a genuine C compile failure. Fixed. Branch
`lane/cmtfix`, not merged.

## The bug, reproduced minimally

`build/pcrec -p rx --engine=dfa -o out.c -- 'a\/\*!\*\/b'` (the pattern
whose PCRE-parsed bytes are the literal `a/*!*/b`) emitted a DFA
per-state "shortest input" legend line — `*    7  "a/*!*/b"   ACCEPTING`
— with the pattern's own `/*!*/` bytes unescaped inside a `/* ... */`
block comment. The embedded `*/` ends the comment early; everything the
emitter wrote afterward becomes unparsed garbage (`gcc` reports "missing
terminating \" character" cascading into undeclared-identifier errors on
every subsequent line). The forced-VM route (`--engine=vm`) was
unaffected — it has no such legend.

## The fix

One shared primitive, `emit_comment_safe_byte` (`src/gen/emit_dfa.c`,
right above `emit_pattern_comment`): printable ASCII passes through
unless it would complete a STAR-SLASH **or** SLASH-STAR pair with the
byte just rendered (threaded across calls via `*prevp`, since the
per-state legend assembles one example from several calls), or the
caller's own `extra_escape` predicate asks for it; everything else
becomes `\xNN`. Applied at:

1. `emit_pattern_comment` (the banner) — byte-identical refactor, `NULL`
   `extra_escape`.
2. `emit_state_legend`'s per-state example loop — **the actual fix**,
   `extra_escape` = hex-escape `"`/`\` too (unchanged readability
   behaviour, now layered on comment safety rather than instead of it).

**The second hazard.** Building the regression net found gcc's
`-Wcomment` (`-Wall`) fires on a SLASH THEN STAR with nothing later to
close it — no `*/` anywhere, so it never trips the first hazard — and the
harness's own `GENCFLAGS` default IS `-Wall -Wextra -Werror`
(`tests/harness/run.sh:213`; also the pre-existing precedent at
`emit_c_string_literal`'s own `-Wtrigraphs` comment, `emit_dfa.c:107-109`),
so that warning is exactly as fatal to a real build as the first hazard's
missing terminator. `emit_comment_safe_byte` guards both orderings from
the start.

**`emit_orientation_block` deliberately does NOT route through the shared
primitive.** Its own pattern-map paragraph has always passed every byte
through unescaped except the two hazard pairs and a newline — including
raw UTF-8 continuation bytes and literal tabs. Routing it through the
shared primitive was tried, and MEASURED WRONG: it moved 115
currently-compiling corpus artifacts' bytes (every `-e utf8` multi-byte
literal, every pattern with a literal tab in a modifier run), because the
shared primitive's contract (printable-ASCII-or-hex-escape) is strictly
narrower than what this site ever needed. It keeps its own loop, fixed
for the same two hazard pairs, with every other byte passed straight
through exactly as before. That same rewrite also fixed a real,
independent bug the old code had: matching the STAR-SLASH pair by
looking one byte AHEAD (`q[0]`/`q[1]`) and unconditionally advancing by
one leaves the SLASH to be read and printed a SECOND time by the next
iteration — a class holding both bytes rendered `a[*\//]b` instead of
`a[*\/]b` (harmless to the comment itself, wrong as a rendering of the
pattern). Looking BEHIND at the byte just rendered (the shared
primitive's own shape, reused here by hand) cannot make that mistake:
each source byte is consumed exactly once.

## ABI verdict: NO ABI EVENT

**By construction.** The fix only changes output when a rendered byte
pair would form `*/` or `/*` — and under the PRE-FIX code, any such pair
reaching a comment already broke compilation (the `*/` case directly; the
`/*` case via `-Wcomment` under the harness's real `-Werror` default).
So the population whose bytes move is exactly the population that failed
to compile before the fix — provably, not just empirically.

**Measured anyway**, per the brief's requirement: a corpus-wide
byte-diff, baseline (pre-fix, `git archive` of the branch point,
built separately) vs. fixed compiler, over all 2,856 `pattern` lines in
the shipped corpus (`--features all`, same basename in different
directories — `run_trie_identity.sh`'s own documented trap for this
comparison shape). Result: **2,581 identical, 275 both-refuse
(module-gated patterns needing flags this simple driver does not supply,
unrelated to the fix), 0 newly fixed, 0 newly broken, 0 movers.**
`emit_orientation_block`'s FIRST attempt (routed through the shared
primitive) measured 115 movers on this same sweep before being reverted
to its own corrected loop — recorded here as the negative control that
makes the final zero meaningful rather than assumed.

No `abi` bump, no re-pin of `rx_info.abi` or the identity-gate pins in
`tests/codegen/run_recursion_identity.sh`.
