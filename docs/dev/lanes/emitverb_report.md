Lane `emitverb`, branch `lane/emitverb` from `lane/w4`'s tip `4af16eb7`

Rulings implemented: `docs/dev/plan.md`'s `[EMIT-VERB]` row (boolean, an

## 0. What the sources got wrong

Three, each found by building against them.

**(1) `PCREC_EMIT_COMMENTS` is not a spellable force macro in this tree.**
`w4_report.md` §2 item 4 (c) predicts the row as
`PCREC_AXIS(PCREC_NO_COMMENTS, "-fno-comments", PCREC_EMIT_COMMENTS,
"-fcomments", …)`. `tests/registry/axes_registry_check.sh` derives the
header's bit table with `grep -oE 'PCREC_(NO|FORCE)_[A-Z_]+ *= *1u << [0-9]+'`
— the deny/force naming convention is *encoded in a check*, not only in
taste — so an `PCREC_EMIT_*` force bit is invisible to it and direction 1
fails with *"dumped deny/force macro 'PCREC_EMIT_COMMENTS' is not defined in
lib/pcrec.h at all"*. Driven red before the rename, green after. The
shipped spelling is **`PCREC_FORCE_COMMENTS`**; the CLI spelling
`-fcomments` is unchanged, which is the half a caller sees.

**(2) There is no emitted comment that names the abi.** D112's essential
class is *"the one-line generated-by header naming pcrec and the abi, and
the pattern echo"*. The shipped provenance line is
`/* Generated by pcrec. Pattern: <pat> */` — it names pcrec and the pattern
and **not** the abi; the abi lives in `rx_info.abi` (a data field) and
nowhere else in the `.c`. Adding it would be new emitted scaffolding on the
byte-identity path, so this lane did not: the line ships as it is, and the
gap is flagged for the manager rather than closed silently. A one-line
change (`/* Generated by pcrec (abi N). Pattern: … */`) would be a clean
rider on any future abi event.

**(3) The `.rxt` corpus is not the only verbatim-comment producer.** The
brief's site list is the two emitters. The **encoding seam** also emits
comments, and it emits them as *verbatim text blobs* (`PcrecEncEntry.decls`
/ `.defs`, `$`-substituted by `pcrec_enc_emit_text`) — so there is no
emission EVENT to gate unless the split is made in the DATA. §2.3 below.

## 1. EVENT 1 — the axis, byte-neutral

Commit `6bf16eff` (with WIP commits `d3fd444b`, `2fd…`, … before it).
**The default is still ON in event 1**, by the explicit choice the brief
offers: `axes.def`'s row ships `PCREC_AXIS_DEFAULT_ON` and event 2 changes
that ONE token. That is D112 item 4's "implement-then-replace, so a red
gate has a triage boundary" taken literally — everything except the
polarity is already on the branch and already proven byte-neutral before
anything moves.

### 1.1 The axis

| piece | where |
|---|---|
| the row | `src/core/axes.def`, its own family section at the end |
| the two bits | `lib/pcrec.h` `PCREC_NO_COMMENTS = 1u << 26`, `PCREC_FORCE_COMMENTS = 1u << 27` |
| the resolver | `pcrec_axis_on(flags, deny, force)`, `src/core/compile.c` |
| the CLI | nothing: `cli_axis_apply` walks the table (D111) |
| `--list-axes` | two `predicate` rows, axis `comments` |
| the mask | both bits join `emit_info_def`'s `strategy_denials` |
| the spec | `docs/spec/tuning.md` §2.24 |

`pcrec_axis_on` is the **first reader of `axes.def`'s `default_state`
column**, which D111's addendum shipped with no reader on purpose. It is
general over every row — deny wins, then force, then the row's declared
default — rather than a clause for the one axis that needed it. For the
twenty-two DEFAULT_ON deny-only rows it reduces to `!(flags & deny)`,
which is what their call sites already spell inline; those were not
rewritten (they are correct, and rewriting them would move no byte).

`--list-axes`' *which row is the default* sentence is **derived** from the
table through `pcrec_axis_on(0, …)` rather than typed, so the flip in
event 2 does not re-pin it and it cannot go stale.

### 1.2 The gate (D108)

`src/core/sb.c` gains three functions and `StrBuf` three fields:

    void sb_comments(StrBuf *sb, bool on);          /* the policy, set once */
    void sb_cmt_open(StrBuf *sb, PcrecCmtClass k);  /* ESSENTIAL | NONESSENTIAL */
    void sb_cmt_close(StrBuf *sb);

The mute test sits in `sb_putc`, `sb_puts` and `sb_vprintf` — **the three
primitives every other append in that file is built on** (`sb_text`,
`sb_field`, `sb_row`, `sb_join`, the three `sb_stamp*`, and anything added
later), so the gate cannot be bypassed by a helper. Inside a muted region
an append is a no-op, so `len` does not advance and the size term's
`abort_over` and both emitted-size caps see exactly the bytes the artifact
will carry.

The region stack is two plain counters (`cmt_depth`, `cmt_mute_depth`)
rather than a bit stack, because the invariant is exactly expressible that
way: muting starts at the depth of the first NON-ESSENTIAL region and ends
when *that* depth closes, so nesting in either order is correct with no
bound on depth.

The policy is set on the ARTIFACT's buffers only — `csb`, `hsb`, `vmsb`,
`scr_test`. **`irsb` is deliberately absent**: `--emit-ir`'s listing is a
debug surface with its own format contract, not emitted C, which is also
what makes it an independent stream to check the flip against. `scr_desc`
feeds the listing and follows it.

### 1.3 The site classification

**ESSENTIAL (2 regions, emitted under every setting).** Both are FIXED
cost per artifact — they do not grow with the machine, which is the line
this lane drew and the reason it is defensible:

| site | reason |
|---|---|
| `emit_pattern_comment` (`src/gen/emit_dfa.c`) — `/* Generated by pcrec. Pattern: … */`, on both the `.c` and the `.h` | D112's own definition of provenance: a file in someone else's repository still says what produced it and what it matches |
| `emit_rx_abi_types` — the whole `PCREC_RX_ABI_H` block's comments (`rx_ctx`'s field notes, the `rx_matchfn` return-space doc, the error-code notes, `rx_renderfn`, every `rx_info` member's note, the residual-entry pointer paragraph) | this IS "the emitted `rx_matchfn` ABI block" `docs/spec/match_api.md` names as the embedder's contract (its own `docs/spec/CLAUDE.md` line ~71 names two shipped doc-comments; the other is in `lib/pcrec.h` and is not emitted). Taken as ONE unit because it is one: emitted once per file, its size independent of the pattern, and a reader with half of it has a header they cannot use |

**NON-ESSENTIAL: 65 regions** (34 in `emit_dfa.c`, 29 in `emit_vm.c`, 2 in
`src/enc/enc.c`) covering the orientation block, every table legend and
class/state legend, the per-label `// role` line, the prefilter and
scan-edge notes, the VM's struct and macro doc blocks, the accept/fail
label paragraphs, the tier and entry-chain notes, the caller-buffer
surface, and the four encoding-residual entries.

**One classification is worth stating because it has a consequence.** The
FEATURE-SET line (`/* Feature set: std1 (modules: …) */`) is
NON-ESSENTIAL: its two values also ship as `PCREC_FEATURE_SET` and
`PCREC_FEATURE_MODULES`, which are `#define`s and always emitted. But
those macros live only in the `.c` (by `emit_feature_macros`' own design
note), so **a default `.h` no longer records the feature set in any form**.
Stated in `tuning.md` §2.24 rather than quietly accepted.

### 1.4 The scope rule for what counts as a comment

A comment is gated when it occupies WHOLE LINES. That is not a
convenience: it is exactly the population `tests/lib/size_count.sh` calls
`prose`, which is the same population `PCREC_MAX_EMIT_BYTES` excludes and
the same one measurement (c) counts — so the axis, the cap and the metric
all mean one thing by "comment". A trailing comment sharing a line with
code (`size_t nframes;   /* capacity in FRAMES */`) is NOT gated: it is
part of that line's text, it is never the bulk, and removing it would mean
rewriting the code line rather than omitting text.

## 3. FINDINGS

### 3a. THE `.o` PROOF FOUND A REAL DEFECT, and it is not a line-number leak

**Five of 3,517 corpus artifacts compiled to DIFFERENT OBJECT FILES** under
`-fno-comments`. The brief anticipated a `__LINE__`/`#line` leak. It is
something else:

    #define RX_VM_ENTRY_SHAPE "plain"     ->  "inline"
    #define RX_VM_PROGRAM_BYTES 4502ULL   ->  4051ULL
    static void rx_run_state_bind(…)      ->  static inline __attribute__((always_inline)) …

`emit_vm.c`'s entry-shape AUTO rung compares **`job->vmsb.len` — RAW emitted
source bytes, comments INCLUDED** — against `VM_INLINE_CHAIN_MAX_BYTES`
(4,096). A comment-free program is smaller, so an artifact whose program sits
within one comment-share of the knee crosses it and takes a different rung.
That is emitted CODE moving over a comment switch: the one thing this axis
promises never to do, and it would have shipped invisible to every byte
identity gate (they compare DEFAULT builds, and the default was about to
become the comment-free one).

The five witnesses:

| file:line | pattern |
|---|---|
| `tests/backrefs/octal.rxt:81` | `^(a)(b)(c)(d)(e)(f)(g)(h)\8$` |
| `tests/backrefs/d27/octal.rxt:37` | `\10(a)(b)(c)(d)(e)(f)(g)(h)(i)(j)` |
| `tests/backrefs/d27/octal.rxt:72` | `(a)(b)(c)(d)(e)(f)(g)(h)\8` |
| `tests/recursion/d27/sr_captures.rxt:169` | `^(a)(?1)(?<=(a))\1$` |
| `tests/recursion/d27/sr_interactions.rxt:207` | `^(?(DEFINE)(?<g>ab))(?(DEFINE)(?<h>(?&g)))ab(?<=(?&h))$` |

**THE FIX MAKES THE GATE SIZE-NEUTRAL, IT DOES NOT RE-BASE THE TERM.**
`StrBuf` counts the bytes a muted region discarded (`cmt_dropped`), and every
LENGTH-BASED DECISION reads `sb_len_uncut(sb)` = `len + cmt_dropped`, the
length the buffer WOULD have had with comments on. Two readers today: the
entry-shape comparison and its own `RX_VM_PROGRAM_BYTES` stamp (which
documents itself as *"the quantity the size term compared"*, so it must
report the compared quantity), plus the size-term ladder's `abort_over` in
`sb_grow`. The default path moves not one byte.

**The separate question is left open with its measurement**: *should a size
term price comment bytes at all?* Re-basing it on comment-excluded bytes
would change the default for near-knee artifacts and needs its own measured
need and its own abi event (D77). This lane names the population — five
corpus artifacts within one comment-share of the 4,096 knee — and stops.

**The transferable form**: *a render-time gate over emitted text is only
neutral if nothing upstream reads that text's LENGTH as a decision.* The tree
already had a rule for this and it was written in `limits.def` about the caps
(they measure comment-EXCLUDED bytes, deliberately); the entry-shape term was
added later, reads a raw buffer length, and nothing tied the two facts
together. `sb_len_uncut` is now that tie, with the rule stated at its
declaration: *any decision or stamp that compares an emitted LENGTH uses
this, never `len`.*

### 3b. The essential set could not be verified by a byte-identity gate

Nothing in the tree compares a `-fno-comments` artifact against anything, so
every existing gate is blind to this axis's own output. Two instruments were
built for it rather than assumed:

- **the region-BALANCE check** (`src/core/compile.c`, after emission): an
  `sb_cmt_open` with no matching close mutes the rest of ITS buffer, so the
  artifact is silently TRUNCATED under `-fno-comments` and byte-identical
  under the default. **Measured, not hypothesised**: `pf_comment_bcls` gained
  an open and no close during this lane, and four artifacts ended
  mid-function. The default build was perfect.
- **`tests/codegen/run_comments_axis.sh`** (§4.2), whose every artifact is
  COMPILED under `-Wall -Wextra -Werror`, because the other half of the same
  hazard — a comment whose opener is gated while its body is not — leaves
  stray `*` lines that gcc reports as a syntax error about a numeric
  constant, with nothing in the message about comments. That one was measured
  too: the auto-split of `pf_block_ofs`'s banner (whose MIDDLE is a loop over
  the selected offsets) left its continuation lines outside the region.
