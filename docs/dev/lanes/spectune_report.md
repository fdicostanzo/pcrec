## 3. Code wins: corrections (16)

Each checked against `build/pcrec` of this branch, `src/core/axes.def`, `lib/pcrec.h`, `--list-axes`/`--list-limits` or the emitter.

1. **C1, the engine-selecting count.** §1 said "the two named ENGINE-SELECTING" axes, §2.8 "the first of the two", §2.9 "the family's second and last such axis". Live: `emit_info_def`'s `kept` holds THREE engine-selecting denials (`PCREC_NO_ATOMIC_DISCHARGE`, `PCREC_NO_SPLICE_CALLS`, `PCREC_NO_POSS_CTX_FOLLOW`; `.flags` reads 4096 / 8192 / 1125899906842624 under them), and `-fno-ctx-node` moves the engine the same way while masked. Stated as a class (§1¶3) with all four named.
2. **C2, both spellings of a pair.** §2.24 said "deny wins over force, so `-fcomments -fno-comments` is comment-free — the same precedence every other pair in this section has". Live: `-fprefilter -fno-prefilter`, `-fprefilter-collapse -fno-prefilter-collapse` and `-fstartpos-guard=align -fno-startpos-guard` are REFUSED as pairs ("cannot both be requested", `select_engine.c` / `compile.c`); only `comments` and `memfn-simd` compile, deny winning (`pcrec_axis_on`). §1¶10 states both.
3. **C3, comments override direction.** §2.24 said a command line "has to be able to override it in both directions" against a `config`/target. Live: raw `-f` bits UNION across sources (`cli.md` §1.1.4¶7) and deny wins, so a CLI `-fcomments` does NOT restore comments against a file's `pcrec -fno-comments` (tested: 57 comment lines, the essential set), while a CLI `-fno-comments` does strip a file's `-fcomments`. §2.24¶7 states the live rule.
4. **C4, §3's DFA transcript.** `abc` with `--no-captures` now stamps `RX_DFA_PREFILTER "run-pinned"` (§2.30), not `"memchr"`. The transcript is gone; §3.1 carries a re-run hybrid transcript.
5. **C5, `RX_DFA_PREFILTER`'s value set.** §3 listed five values as the set; live it has eleven (`offset-set*`, `run-pinned*`, `first-*`). §3 now points at `match_api.md` §6.3.4's value-set table and names the axis behind each.
6. **C6, §3.1's hybrid transcript.** The listing lacked `RX_DFA_UNIFORM_FOLDS`, `RX_DFA_SCAN_EDGE` and `RX_DFA_START`, all of which a hybrid carries. Re-run live with a grep that shows them.
7. **C7, §4 was not exhaustive.** It claimed to be exhaustive over `flags` but had no rows for `PCREC_NO_POSS_CTX_FOLLOW`, `PCREC_NO_POSS_BREF_FIRST` (bits 50, 51) or `PCREC_NO_MEMFN_SIMD`/`PCREC_FORCE_MEMFN_SIMD` (48, 49), and its "five `flags` bits that are not tuning axes" omitted `PCREC_SIZE_CAP_REFUSE` (bit 41). Rows added; the non-axis list names six bits, no count word.

Replaced by the rule the code obeys: an axis with no row has no dial cell at any position (`src/core/tune.c`'s table). See open question 1.
