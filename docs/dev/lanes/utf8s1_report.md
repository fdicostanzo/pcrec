### Two repairs the refactor forced, both worth reading

**`vm_det_seq` stopped handing back borrowed pointers.** It returned
`&a->u.cls.bits[0]` — valid only because a class payload WAS 32 bytes of
bitmap. There is no bitmap in a node to point at, so each approved leaf now
renders into the caller's row and `const uint8_t *seq[32]` became
`uint8_t seq[32][32]` at three sites (1 KB of stack each). That is the whole
cost of removing the aliasing.

**`src/parse/syntax_dump.c`'s three probe `Ctx`es had no options, and that was
a latent NULL deref this milestone made real.** All three are built by
`memset` and handed to the parser; none set `cx.opt`, which was harmless only
while nothing on a parse path read it. `cls_universe` reads it, so the first
negated class a probe reaches segfaults — **MEASURED**, as an ASan SEGV in
`tests/registry/definitions_oracle_gen.c` through
`pcrec_construct_built_status` → `pcrec_ast_class_from_bits`. Fixed by giving
each probe `pcrec_default_options`, **not** by making `cls_universe` tolerate
NULL: "which encoding is this parse for" has a right answer here, and a
tolerant accessor would let a genuinely optionless Ctx reach the parser and
silently answer for `byte` whatever the caller meant. A sweep confirms
`syntax_dump.c` was the only such builder in `src/` or `tests/`.

## 4. WAVE-TASK (a) — CONSTRAINT 2, MEASURED, AND IT CONTRADICTS THE DESIGN

### What the design says

> **§2.1.2 constraint 2.** "`pcrec_callgraph_build` (:961) must run AFTER the
> lowering — so the lowering cannot run before :961."

**The two halves contradict each other.** The first clause is the correct rule
and is the same rule `altcls` and `discharge_atomic` obey — both of which run
*before* :961. The second clause does not follow from it, and the diagram,
§9.2 and §13 obligation 4 all follow the second clause to `compile.c:1000`.

### The experiment

Stage 1's shipped byte instance rebuilds nothing, so it cannot test the
constraint at all. The experiment therefore used a lowering that **REBUILDS
every node** — which is what §2.3's byte-sequence decomposition does to an
`A_CLASS`, and precisely what the `.body`-staleness argument is about — and
compiled it at both positions. Scratch trees only; nothing below is on the
branch.

| build | `tests/recursion`, 179 distinct patterns |
|---|---|
| shipped stage 1 (identity lowering) | reference |
| rebuilding lowering **at `:1000`** (the design's position) | **45 artifacts DIFFER** |
| rebuilding lowering **above `:961`** | **0 artifacts differ** |

All 45 are restored to byte-identity by moving the pass above the call graph.

### The mechanism, from the diff

On `^(a(?1)?b)$`, the call site's entire activation-private save/restore block
disappears:

```
     #define RX_VM_PROGRAM_BYTES 3831ULL      ->  3624ULL
-    RX_SET(RX_SLOT_GROUP1_START,   slot_values[RX_SLOT_GROUP1_START]);
-    RX_SET(RX_SLOT_GROUP1_END,     slot_values[RX_SLOT_GROUP1_END]);
-    RX_SET(RX_SLOT_GROUP1_PENDING, slot_values[RX_SLOT_GROUP1_PENDING]);
```

`W` comes out **EMPTY**. `u.call.save`/`nsave` are derived from the callee
region reached through the stale `.body` while the main body is walked over the
new tree, so the two disagree — "two programs for one group", exactly as
`compile.c:947-956` predicts. Per the design's own §5.3b, an empty `W` is a
lost match and six false matches on the right shapes.

**HONEST LIMIT ON THIS EVIDENCE:** I did not find a wrong-answer cell in the
time available. `^(a(?1)?b)\1$` on `"aabbaabb"` still answers `(0,8)` on all
three builds. The artifact difference is measured and structural; the answer
consequence is §5.3b's measurement, not this lane's.

### Why this is worse than "constraint 2 is weaker than claimed"

It is **inverted**, and inverted it collides head-on with constraint 3:

```
constraint 2 (as measured):   lowering  <  :961    (the graph must bind after any rebuild)
constraint 3 (as written):    lowering  >  :999    (postresolve asks widths in CHARACTERS)
```

and `pcrec_postresolve` cannot move above :961 because it needs the graph. So
under the two constraints as they actually stand **there is no valid slot**,
and §2.1.2's "there is exactly one line between them" is an artifact of the
mis-stated clause.

**Stage 1 is not affected.** Its byte instance rebuilds nothing,
`pcrec_lower_enc` returns `root` unchanged, and the identity gate reads 100%.
Stage 2 is affected, so this wants ruling before that wave opens.

### Three resolutions offered — RULING R2 TOOK (a)

1. **THE LOWERING MUST NOT REBUILD** — splice in place, so `.body` never goes
   stale and the ordering question does not arise. **← RULED, and implemented
   in this wave.**
2. Re-bind after lowering (run the graph pass twice).
3. Move postresolve below the lowering — rejected by §2.1.2 and by this lane.

### RULING R2, AND WHAT IT COST TO CONSUME

> **THE RULED INVARIANT** (manager, `utf8s1_rulings.md` R2): `pcrec_lower_enc`
> splices IN PLACE — it replaces a leaf `A_CLASS` by MUTATING THE PARENT'S
> child pointer (or, for a root-level bare class, by reassigning the driver's
> `root`), and NEVER reallocates a node that IS or CONTAINS a group root.
> `:1000` stands; constraint 2 becomes a node-identity PROPERTY.

**Implemented, and written so the invariant is STRUCTURAL rather than
remembered.** `lower_walk` takes `Ast **slot` — the ADDRESS of the pointer
holding the current node — so the only write it can make is `*slot = repl`:
one pointer, in a parent it does not otherwise touch. There is no expression in
the file that allocates a node at all. Stage 2 extends it by filling in
`lower_class`, whose signature (`Ast *` in, replacement-or-NULL out) cannot
reach a parent even by accident.

**THE ROOT IS THE SAME MECHANISM**, not a special case: `pcrec_lower_enc`
passes `&root`, so a root-level bare class splices exactly like any other leaf.
The ruling's soundness argument — a bare-class root has no group construct,
hence no `A_CALL`, hence no capture to strand — is **asserted rather than
argued**, at the one moment it could stop being true:

```c
if (root != was && cx->callgraph)
    ctx_fail(cx, 0, "internal error: the encoding lowering replaced the "
                    "AST root of a call-bearing pattern — group 0's "
                    "cached body now names an abandoned node");
```

**Two checks landed with it**, both in `run_cpset_structure.sh` §1d. The
positive one asserts the walk is still slot-shaped; the negative one asserts
`arena_alloc` appears nowhere in the file, which is how a stage-2 author
reaching for the obvious rebuilding shape would spell it. Verified the needle
can match (`revdet.c` reads 2). **The property's own check — that no group
root's ADDRESS moves across the pass — is deliberately NOT written**, because
stage 1 splices nothing and it would assert over an empty population; that is
stage 2's, and the ruling places it there.

**MEASURED AFTER THE REWRITE:** identity gate still 14/14, all four axes,
0 differing. `make strict` clean. Structural checks 28/28.

## 5. THE D70 RE-DERIVATION (§2.2.3) — the clobber went LATENT

### The new arithmetic, from `offsetof` on the built tree

| | old (32-byte bitmap) | new (16-byte interval list) |
|---|---|---|
| `u.cls` spans | `+40..+71` | `+40..+55` (`iv` `+40..+47`, `n` `+48..+51`, 4 pad) |
| `u.rep.greedy` `+48` | bitmap byte 8 | **byte 0 of `n`** |
| `u.rep.possessive` `+49` | bitmap byte 9 (`H`-`O`) | **byte 1 of `n`** |
| `u.rep.revbody` `+56..+63` | bitmap bytes 16-23 (`0x80`-`0xBF`) | **outside `u.cls` entirely** |
| `sizeof(Ast)` | 136 | **136 — unchanged** |

`sizeof(Ast)` does not move because `u.call` (96 bytes) sets the union's size,
not `u.cls`. So this re-layout moves **no other member's offset**, which is the
narrower true statement where §2.2.3 predicted "every offset in the `Ast` union
moves".

### The survey's QUESTION, re-asked

Over every `u.<member>.<field> =` in `src/`: exactly one generic-path writer
survives (`rd_node`, still guarded on `n->k == A_REP`), and
`mod_assertions.c`'s pin is still guarded on `k == A_BOL || k == A_EOL`. Every
other write is inside a producer that owns the kind. **The guards hold and
nothing new needs one.**

### But the hazard they defend against is no longer observable

`rd_node` *clears* — it writes zeros. `possessive` now lands on byte 1 of `n`
and `revbody` lands outside the payload, so the unguarded clear zeroes a byte
of `n` that is **provably already zero**: a class over `[0, 0xFF]` holds at
most 128 disjoint non-adjacent intervals, so `n <= 128 < 256` on every artifact
the `byte` backend can produce.

**MEASURED**, with the `n->k == A_REP` guard removed:

| instrument | result |
|---|---|
| whole corpus, 2,845 patterns | **2,845 byte-identical, 0 differing** |
| `tests/rungselect/revdet_highbytes.rxt` — the file written *specifically* to detect this clobber | **7/7 identical** |

### 6b. ONE CHECK THE BRIEF DID NOT ASK FOR, and why it is here

`tests/codegen/cpset_model_check.c`, run as `run_cpset_structure.sh`'s §4.

Checks 1-3 and the identity gate are all statements about a POPULATION. None
of them exercises the new set algebra outside the narrow slice the corpus
reaches: `pcrec_cpset_complement` is only ever called at `max_cp == 0xFF`,
`pcrec_cpset_remove` has exactly one caller (`.` removing `\n`), and no corpus
pattern builds a list long enough to reach the absorb-many path in
`pcrec_cpset_add`.

**Stage 2's `0x10FFFF` universe and stage 3's ~770-interval property classes
will.** A bug in any of those is invisible today and a miscompile then — and it
would arrive in a wave whose own acceptance is a corpus that did not exist when
the bug shipped. So the algebra is model-checked against a flat byte array,
which has no intervals, no ordering and no invariant and therefore cannot fail
the same way the subject does; the universe is 4,096 so every point can be
compared after every operation rather than sampled.

It checks **two** properties, and the second is what a membership-only check
would miss: membership agrees everywhere, **and** the list stays sorted,
disjoint and **non-adjacent**. A representation answering every query correctly
while leaving `[a-m][n-z]` as two intervals passes the first and breaks
§2.7.2's argument that the artifact does not depend on the pattern's spelling.

Seven edge cases are written out rather than left to the walk: the complement
of the empty set and of the full universe, double complement as the identity,
adjacency coalescing, a mid-interval split, the complement of an interval
touching 0 (where a careless `lo - 1` underflows), and absorbing 100 intervals
in one `add`. **All pass**, including the two that would otherwise first have
been exercised in stage 3.

## 7. WAVE-TASK (b) — the render helper's cost, as a number

The design assumes the per-site conversion is trivial. It is, and here is the
number rather than the assumption.

**Compile-time delta over the corpus** (2,845 patterns, matched optimization
levels, interleaved trials, medians):

| | subject | reference | delta |
|---|---|---|---|
| `-O2` (the shipped build shape) | 13.85 s | 13.81 s | **+0.3%** |
| `-O0` | 25.70 s | 25.69 s | **+0.04%** |

Both are **inside the trial spread** — one `-O2` trial has the reference
*slower* at 15.17 s — so the corpus delta alone only says "below this
instrument's noise floor". The sharper number comes from the two factors:

**Per-call cost** (`-O2`, 20 M iterations each):

| class shape | intervals | ns/call |
|---|---|---|
| a literal / one range | 1 | 3.3 |
| `[a-f]` — **6 members, the corpus mean** | 1 | **12.1** |
| `[a-cx-z]` — 6 members, 2 intervals | 2 | 12.1 |
| `[a-z0-9_]` | 3 | 74.7 |
| `.` (255 members) | 2 | 484.8 |
| 128 alternating (the byte range's worst case) | 128 | 294.6 |

The cost tracks MEMBERS, not intervals — the two 6-member rows agree to 0.1 ns
across a 2× difference in interval count.

**Call census** (instrumented build, whole corpus): **275,498 render calls**
across 2,517 compiles that render at all — mean **109.5 calls/compile**, mean
**5.9 members/call**.

**So: 275,498 × 12.1 ns ≈ 3.3 ms over the whole corpus, against ~13.8 s of
compile time — 0.024%.** The design's assumption is confirmed and priced.
