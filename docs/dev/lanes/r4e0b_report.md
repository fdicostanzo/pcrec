## 1. Summary (resume from here)

- **The routing.** `ofs_fn_define` (`memfn/src/ofsskip.c`) now writes three
  pieces, in this order:
  1. the BODY row's loop, byte for byte, under the head `<fn>__body`
     (`fn_head`, the one head every piece shares);
  2. the PREFIX row's helpers (none today);
  3. `<fn>` itself, the SELECTOR (`fn_selector`), whose whole body is
     `return <fn>__body(subject, n, pos[, tables]);`.

  The PREFIX walk is handed the helper's name (`fn_in.body_fn`): that is a
  PREFIX helper's last fall-through. A later PREFIX row adds `#if` arms above
  the selector's call, which then becomes the `#else` line byte for byte. It
  does not touch the BODY text.
- **One abi commit, `74f941dc`.** It carries the kit change, every reader of
  the number, the second-class byte-count readers and the five checks that
  read the FUNC's loop by name. The FILEPIN self-pin follows in `f7c8624f`,
  because a pin cannot name its own commit.
- **No options.def deny.** D155 item 6 orders the routing as the SIMD-off
  floor shape ("the SIMD-off artifact routes through the helper too ... so
  the floor rule stays exact"). §R4.9.2.6 measures it against its PARENT,
  not against an OFF arm (items 1-3: the un-done diff, the parent's
  assembly, parent-vs-routed timing). memfn/CLAUDE.md's "no frozen
  baseline" excludes keeping the unrouted text as a permanent arm, and the
  same file names R4e′.0b "the one ordered byte move". So no `--memfn=` row
  and no pcrec CLI case.
- **G1 result.**
  - TEXT: exact on every mover.
  - ASSEMBLY: NOT identical on every mover, against the prediction. 326 of
    2,452 differ at `-O2` and at v3.
  - TIMING of exactly those: null throughout (§4).

**Assembly identity**, every routed `.c` mover of the default, VM and utf8
streams (2,452). The two `.s` are compared after renumbering gcc's local
labels and reading `<fn>__body` as `<fn>`. The abi number is object DATA
(`rx_info.abi`), so it is read across.

| recipe | identical | different |
|---|---|---|
| `-O2` (bench recipe) | 2,126 | **326** |
| `-O2 -march=x86-64-v3` | 2,126 | **326** |
| `-Os` (reported, every 20th row) | 123 | 4 |
| `-O0` (reported, same sample) | 0 | 127 (one more call, as predicted) |

The prediction (0 assembly movers at `-O2`) is FALSE. The 326 are:
- **11 `byte`** (`a{2,4}b`, `a{2,4}?b`, `a{2,4}+b`, `a{3,5}b`, `a{3,6}b`,
  `(?:aa|a)+ab`): the same instruction multiset in another block order.
- **315 `-e utf8`**: typically +7 instruction lines. On `ABCD -e utf8`
  the whole difference is the K50 mid-character `startpos` guard's
  `return -7`. In the routed build it takes its own epilogue (`ret`, the
  `.cfi_restore`s) instead of jumping to the shared exit. That is cold
  error-path layout, not the scan loop.
- **0 VM-forced.**

The list is `out/nonid_full.tsv`. The assembly leg's failing direction is
the design's own witness, `__attribute__((noinline))` on `<fn>__body`: 309
changed lines on `(?i)cat`, 419 on `abc[0-9]+xyz`, against 0 clean.

**Timing, only for the non-identical movers** (`routing_timing.py`, tier U
scratch, one core `taskset -c 13`, gcc `-O2`):
- Setup: parent and routed linked into separate executables with one
  driver. Each executable calibrates to ~50 ms, then 7 alternated runs
  each. Regimes: find-all over 64 KiB of `APPROACH.md`, and 64 calls on
  64-byte windows.
- Controls: identical-assembly movers.

| population | thr ratio median [min, max] | call ratio median [min, max] | outside own spread |
|---|---|---|---|
| 6 `byte` movers | 0.993-1.004 | 0.916-1.036 | 0 |
| 221 `utf8` movers | 1.000 [0.937, 1.041] | 1.001 [0.821, 1.175] | 0 of 442 |
| 4 `byte` + 3 `utf8` identical controls | 0.978-1.021 | 0.990-1.044 | 0 |

- **Every cell is inside its own run-to-run spread**, movers and controls
  alike, and every pair answers identically.
- The per-call cells' wide spread (up to 1.39) is this regime's noise on a
  ~10 ns call. The controls show the same width.
- No cell is non-null, so nothing goes to the bench (§R4.9.2.6 item 3).

**Both layers.** With no SIMD row, `-fmemfn-simd` artifacts are
byte-identical to the default. C11's FORMS identity half compared 695
(quick) and 1,197 (full) artifacts at both layers: green. So the SIMD-on
reading IS that identity.

   the §6 entry order. Then `make -j16 && make strict`.
