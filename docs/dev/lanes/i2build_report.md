## 1. What landed (abi 83 -> 84)

- **One body, two controllers** (`src/gen/emit_iter.c` `emit_one`, `emit_controllers`):
  I1's `_next` body is the static `always_inline` `<p>__one`, text unchanged.
  `<prefix>_next` is `return <p>__one(...)`. `<prefix>_next_n(it, caps, k)` loops `__one`
  up to `k` into consecutive NCAPS-pair entries. There is no new `PcrecEntry`: the
  `iterate` row emits both controllers with the NEXT entry's linkage, and the header
  declares `_next_n` beside `_next`.
- **The shared block** gains `rx_nextnfn` and, from `pcrec_emit_iter_abi_types`,
  `RX_FOREACH_PAIRS` (256, `#ifndef`), `rx_foreach`, `rx_foreach_begin`,
  `rx_foreach_pull` and `RX_FOREACH`. These are the note's §3.2 text, with doubling
  1 -> 64. `struct rx_info` appends `next_n`, and `.next_n` is NULL exactly where
  `.next` is. All of it is scaffold.
- **An I1 defect, found by this lane's gstart arm and fixed** (`881eac3cf`). After an empty
  match at `n`, the STEP set `lo = n + 1` and called `__find` there. `__find` has no
  caller-position guard, so on a DFA `\G` artifact (attempt route, `start_max =
  search_from`) it reported an empty match at `n + 1`, outside the subject, forever. For
  example, `\G` on `ab` gave `(0,0)(1,1)(2,2)(3,3)(3,3)...` and never ended (I1 compiler
  output, reproduced). The VM was not affected. Fix: `__step` returns done when
  `lo > n`, one emitted line. Witness: the `\G` group in `tests/findall/cells.tsv`.
  Sabotage S1321. The spec already said "an empty match at n ends the iteration"
  (§3.8¶2), so there is no spec hunk.

## 2. The H1-H3 objdump hypothesis (no clock) and the stop rule

On c3 `\w+`, c6 `^a|b` and c4 `(a)`, at gcc 15.2 `-O2`. Evidence is in
`docs/dev/lanes/i2build/objdump/`.

- **H1 TRUE** on the unanchored DFA: the loop has no call (the only call is the cold
  `__enter`). **H1 FALSE as stated on the VM**: the loop calls the hybrid's out-of-line
  `rx_prefilter`, at the same two sites `_next` has in I1, so it is not a regression.
- **H2 TRUE** on c6: one `call __find` per match, no second copy.
- **H3 FALSE**: `caps` and `k` are spilled and reloaded per match (c3: 2 loads and
  1 store per match; c4: caller-save spills around the prefilter call). This is a
  finding; the timing gates measure what it costs.
- **STOP RULE HIT on §5.3's control.** I4's `_next` OBJECT is not I1's. I pasted I1's
  literal `_next` text into the I4 artifact: on c3 and c6 it compiles to exactly what
  `return __one(...)` compiles to, and both still differ from I1. So the cause is the TU
  gaining a second caller of the shared statics, not `__one`, and no spelling removes it.
  I reported this and the manager ruled (**R1**): the objdump identity is withdrawn and
  replaced by a TEXT check plus gate 1 as the measurement.
  `tests/findall/run_one_body.sh`: `rx__one`'s body equals the `rx_next` body the I1
  compiler wrote (`tests/findall/one_body/`, never regenerated by this compiler), on all
  three shapes, and a planted one-token change fails it. PASS.
