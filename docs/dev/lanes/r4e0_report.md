## 1. Summary (resume from here)

- **`fn_rows[]`** (`memfn/src/ofsskip.c`) is now the offset-skip function's
  body. It is a first-match table with a SLOT column:
  - BODY: `fn-pair` (applies where the scanned position is a two-member
    cube, today's `b >= 0`) above `fn-memchr` (the slot's floor, applies
    always);
  - PREFIX: empty.

  The two bodies are today's text moved verbatim into `pair_body` and
  `memchr_body`. Both are scalar and undeniable, so neither has an
  options.def row.
- **`ofs_fn_define(art, handle, h, p, fn, o)`** is the seam. It asks BODY
  first, then PREFIX (handed the BODY row through `fn_in.body`), then writes
  the text in a fixed order: the PREFIX row's helpers (none today), the
  FUNC head, the BODY loop. That is §R4.9.2.5's order without
  `<fn>__body`, which R4e′.0b adds. Both callers pass their site:
  `ofsskip_define`, and `precheck_define` once per FUNC part.
- **`kit_walk`** (`memfn/src/compose.c`, declared in `kit.h` with its table
  descriptor `kit_table`) is the kit's ONE selection walk. Per row of the
  asked slot, in table order, it applies the deny, then the gate, then the
  row's predicate, and the first row to pass all three is chosen. The
  arms (`select_arm`), the run compare (`rc_row_of`) and `fn_rows[]`
  (`fn_select`) all call it, and its trace records are unchanged. A slot
  holding no row is not a selection, and it records nothing.
- **Trace.** There is a new table `fn` (phase `define`, site = the calling
  site's handle). The gate's reach registry went from 16 to 32 rows,
  because 17 rows would have set `REACH_DROPPED` > 0. `reach_print` walks
  the third table.
- **Zero movers.** The light gates are clean (§3). The full identity gate
  is OWED to the slot (§6).

### 2.1 Deviations from the design text, each with its reason

1. **The site goes in as its handle**, not as an `mf_site *`. The handle
   gives the site (`art->sites[handle - 1]`, the record `define_sel`
   creates before the arm's define runs) and numbers the `fn` trace record.
2. **`fn-memchr`'s predicate always holds.** The design says "applies:
   otherwise", so it is the slot's floor and first-match order keeps it
   off a cube. Its text is right only where the scanned position is one
   byte. S686 (the two rows swapped) is the check that the order holds.
   The alternative, an exclusive `b < 0` predicate, would make the swap an
   equivalent mutant and would turn S454's defect into a refusal rather
   than the deleted-match defect it was written for.
3. **Walk tests 3 (REACH) and 4 (OVER) are not built.** They are PREFIX/
   SIMD tests, and no row reads them yet (D77). They land with batch 1's
   first SIMD row. Test 1 reads only the `MF_D_*` bit: options.def is
   empty, and the `--memfn=` carrier is RQ-1's.
4. **Open for batch 1: the trace word for an empty PREFIX outcome.** A
   PREFIX walk that asks rows and chooses none is NOT a refusal, but the
   trace's `END chosen=-` means a refusal (`trace_format.md`), and the N2
   census's rc 5 counts it as one (S689 shows this). Today the slot has no
   row, so the walk records nothing. The first PREFIX row needs a word for
   "no row, by design" before it lands.
5. **The fn rows' contract** reads `denies` (NONE|RUN_OVERLAP), `table_ref`
   (NONE|REF) and `reverse` (NO), and serves no stated `floor`. Every other
   field belongs to the calling arm, which the arms walk already checked,
   so it is MF_ANY. That includes `pred`/`preds`: the walk's predicate is
   one of them, held by `ofs_fn_applies`. So the gate cannot decline a fn
   row on a site the arms walk admitted. That is the zero-mover condition,
   and it holds by construction rather than by luck.
