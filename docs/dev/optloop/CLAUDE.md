# docs/dev/optloop/ — the optimization loop's per-cycle analyses (D119)

One directory per project, one file set per CYCLE of [OPTLOOP]. A cycle's
analysis step ([OPTLOOP.N.analysis], which for cycle 1 is also
[BENCH-REVIEW]) delivers `cycleN_analysis.md` here, together with the
machine-readable table it is written against and the scripts that produced
it. The plan rows a cycle proposes are written IN the analysis and are
ratified into `../plan.md` by Frank — a lane never edits `plan.md` itself.

These are MEASUREMENT-AND-ANALYSIS documents in `docs/dev/`'s sense, not
designs: a design note for a ratified mechanism goes to `docs/design/`, and
the implementation's own record goes to `docs/dev/lanes/`.

## Files

- `cycle1_analysis.md` — **[OPTLOOP.1.analysis], 2026-09-22, lane optrev**,
  on pcrec-bench's `capability@0.1` at pin `25b1984f` (the `pinconfirm` and
  `fullroster` reports of 2026-09-20). All 128 (pattern, regime) cells
  ranked by D119's priority rule, cause-bucketed off the D81 stamps, five
  target mechanisms with their owed Linux profile commands, the deferral
  dispositions, and six proposed plan rows. **Read §0 first**: it states the
  "algorithmic advantage" criterion (`pcre2-jit` is never the target;
  `vectorscan` is excluded; `rust` counts with its SIMD component separated
  into its own `scalar ×` column) and the class weighting, both applied
  uniformly to every row. Headline: pcrec's best variant is fastest or tied
  on 91 of 125 ranked cells; of the 34 losing cells, nine are rows where
  pcrec already beats every SCALAR engine and only `rust`'s vectorized
  prefilter is ahead (recorded as SIMD-phase deferrals), and the rest are
  dominated by four pre-checks PCRE2 computes at compile time and pcrec
  computes only partly — a required byte, a start anchor, a first-byte set
  that survives a leading `\b`, and an end-anchor window.
- `cycle1_rows.tsv` — the machine-readable ranked table: one row per ranked
  cell, with the weighted score, both engines' absolute medians, the D81
  stamps read off this worktree's own compile of the pattern, and the
  `pcre2_pattern_info` facts. Generated by `table.py`.
- `parse_pats.py` — parses `pcrec --list-source` over the bench's
  `patterns.rxt` into the 64 (name, pattern bytes, family, requires) rows,
  decoding the dump's own escape vocabulary (`\\` `\t` `\n` `\r` `\xNN`,
  `src/core/sb.c`'s `pcrec_sb_field`). Its output was verified byte-identical
  to the bench's derived `patterns/*.rx` exports on all 64.
- `stamps.py` — compiles every pattern at the bench's own three flag sets
  with this worktree's `build/pcrec` and reads every `RX_*` stamp off the
  emitted `.c`.
- `rank.py` — reads the fullroster matrix, reconstructs absolute medians
  from `best_ns × ratio`, applies §0's algorithmic-target rule and the class
  weighting, and emits the ranking.
- `join.py`, `scale.py` — the two views the analysis is written from: losing
  rows joined against their stamps, and each losing throughput row's
  per-subject scaling (the O(1)-versus-linear discriminator).
- `mdtable.py`, `table.py` — render the ranked table as Markdown and as TSV.
- `p2info.c` — the `pcre2_pattern_info` probe: `FIRSTCODETYPE`/
  `FIRSTCODEUNIT`, `LASTCODETYPE`/`LASTCODEUNIT`, `MINLENGTH`, `FIRSTBITMAP`
  population, per pattern. Structural facts only, no timing. Built against
  the Mac's Homebrew libpcre2 10.48, NOT the 10.46 reference — see the
  analysis §6.

**The scripts carry the authoring session's scratchpad path in an `SP`
constant at the top.** They are archived as the reproduction record, not as
a runnable harness: re-point `SP` (and `stamps.py`'s `P`, the compiler
path) before re-running any of them.

Everything here is read-only with respect to `/Users/fdicostanzo/pcrec-bench`:
the scripts read its reports, its `patterns.rxt` and its `captext.py`, and
write nothing there. The throughput subjects they census are regenerated
into a scratch directory and checked against the bench's own committed
`manifest_throughput.tsv` hashes.
