## Panel 1 — PARSE-1, a candidate design attacked before building

Four lenses. Delivered: C1 249 lines, C4 413, C2 823 (in three tranches), C3 71
(after a second prod). Everything substantive was a correction to the author's
own document. Full findings in D31; the headline items:

- **C1-3** — "one integer" is the wrong currency. `ctx_fail` takes a POSITION as
  a required argument, D26 puts pcrec's own offsets against its own convention
  in TIER 2, and `Ast` has no position field, so leaving the AST alone
  forecloses recovering one later. Design changed to `AltInfo {nbr, last_bar}`.
- **C3-1** — defect (c)'s fix IS defect (b)'s edit. Measured 17/17 against
  libpcre2: `(?i)` inside a group holds to the end of THAT group, leaks across
  its sibling alternation branches, restores at the immediately-enclosing `)`.
  The author had been about to defer (c) as scope creep.
- **C4-1** — the design's own primary check was passed by a build containing
  NONE of PARSE-1. Its pass condition held before the feature existed.
- **C4-2** — the wrong liveness precedent was cited. `check_tail_precedence`
  exits 1; these properties were never live, so `pcre2_check.c`'s loud-SKIP is
  correct. A builder copying the citation ships a permanently red suite.
- **C2-8, delivered AFTER THE COMMIT** — `p_alt` had no linkage. `p_alt` and
  `p_alt_info` are static; `pcrec_parse_info` requires end-of-pattern and
  ctx_fails on `)`. **The step titled "make `p_alt` a usable module callback"
  had left the callback uncallable.** Fixed in a follow-up commit as
  `pcrec_parse_body`.

## Panel 2 — MOD-0.1's design, attacked before building

Four lenses; **two delivered (M3 349 lines, M4 184) and two produced only
headers.** Re-run narrowly as M5/M6. That 2-of-4 rate is itself recorded: the
two that failed had five-part briefs; the two that succeeded had briefs with a
clear primary item.

### The measurement that refutes D30 §2

D30 §2 states a non-optional check as *"pcrec must promise a module wherever
libpcre2 DISPATCHES."* Measured over 1,672 generated probes, all four doorways,
options = 0, libpcre2 10.46:

    libpcre2 DISPATCHED (diagnostic NAMES a construct)   769
      of which pcrec promises a module                   676
      dispatched but NO module promised                   93
    libpcre2 says NOT-A-CONSTRUCT                        206
      pcrec named a module anyway (OVER-promise)           0

**All 93 are pcrec behaving correctly** — 40 REFUSE (`\U`/`\u`, which is D30
§4's own bound-mode decision), 20 POSIX collating, 16 BASE-TIER constructs pcrec
implements, 6 unknown POSIX names, 4 `\N{name}`, 1 `(*MARK)` (D25's deliberate
fourth answer), plus truncations whose wording matches PCRE2's own.

**So "dispatched" does not imply "a module is owed."** That needs the other two
of D30 §3's three facts — does pcrec implement it, and is it REFUSE under the
bound mode. **D30 §3 gets the answer shape right and D30 §2 then writes a check
that ignores it, two sections apart** — structurally the same failure D30 §3
diagnoses in D29 ("the same document stated the rule and broke it").

One clean positive: **0 over-promises in 206 not-a-construct probes**, so Q1's,
Q2's and FIX-2's cleanups hold over a space none of them generated.

### M3 — rank is almost entirely unchecked, and two of the three checks coincide

Swept all 22 bucketed rows x candidate rank in [-5, 250] (5,632 probes) against
faithful models of both proposed checks:

- **20 of 22 rows have COMPLETELY UNCONSTRAINED rank.** Only a coarse "do not
  sink to or below your bucket's fallback tier" boundary is guarded.
- **The `\N` pair is one checked THRESHOLD, not a checked ordering.** Crossing
  40→70 inverts and is caught; the other 68 values in [1,39] ∪ [41,69] pass.
- **The per-row `syntax` check and the rank sweep fire on IDENTICAL boundaries
  in all 5,632 cases.** The sweep is REDUNDANT with the cheaper per-row check at
  the scale tested — and D30 requires both.
- **Module-swap is invisible to the per-row check** (confirmed on real rows):
  swapping two rows' `module` changes nothing the check reads. R10/C4-1
  reproduced one level inside the new instrument, on a TIER 2 property.
- **Row deletion inside a bucket is invisible to both new checks** absent a
  per-bucket count ratchet, which nothing commits to. R5's incident again.
- **`check_tail_precedence` cannot be retired at MOD-0.1.** Two of its three
  obligations have verified successors; the liveness clause's obligation has
  none in the design text. M3 located the natural successor — a "did any
  generated probe have more than one matching row" counter, baseline nonzero per
  bucket (111 / 333 / 333 / 2730).

Positive, measured: **"equal rank is the defect" does NOT repeat D29's bug** —
0 collisions on the correct table over 3,507 generated probes.

### M4 — the returning-doorway defect is FOUR call sites, and one is UB

D31 recorded one instance. The class is worse.

**`pcrec_ext_escape` is called from `esc_atom` and `esc_class_value` as the last
statement of a value-returning function with NO `return`** — legal only because
`noreturn` makes falling off the end unreachable. Make it return:

    a\qb    (esc_atom → Ast*)        exit 0, compiles, stub node reaches the
                                     matcher — the discarded pointer relaunched
                                     out of %rax by calling-convention accident
    [a\qb]  (esc_class_value → int)  SIGSEGV, exit 139 — build/pcrec, the
                                     COMPILER ITSELF, crashes. 3/3 runs.

Two failure shapes, two call sites, same binary, same change — and unlike the
group case (well-defined C: deterministically the same wrong answer) **this is
undefined behaviour.** It is also the only doorway where the compiler warns at
all (two `-Wreturn-type`, build still exit 0); the group and verb doorways
produce ZERO warnings for the identical change.

Latent and NOT reproduced, flagged separately: `esc_class_value`'s return feeds
`cls_set(a->cls, (unsigned)lo)` with **no range check**, and `cls_set` indexes
`b[c >> 3]` into a 32-byte array.

**And the group-discard class, generated rather than listed:** 18 patterns
crossing prefix x head x tail shape. **7 are byte-identical to a smaller
pattern** — `(?%x)b)` → `b`, `(?%x))` → the EMPTY pattern, `(?%x)(?%y)c))` → `c`
(two discards compound), `(?%x)(d))` → `d` (a real nested group absorbed). The
other 11 diagnose the WRONG thing: 8 spurious "missing closing ) for group", 2
wrong "quantifier does not follow a repeatable item", 1 misattributed offset.
**0 of 18 behave as the design's own contract promises.**

## Dispositions — MOD-0.1's design is NOT resolved by this review

1. **Re-specify D30 §2's check.** "Wherever libpcre2 dispatches" is false;
   the rule must be a RESIDUE assertion excluding base-tier constructs, REFUSE
   outcomes, and D25's four `(*` answers — and the circularity of taking
   REFUSE membership from pcrec's own `RS_REJECTED` rows must be answered.
2. **Decide what rank IS.** If 20 of 22 values are unconstrained, a free `int`
   declares 250 values where 4 exist. Either make the tiers the TYPE, or state
   plainly that rank's value is unchecked by design and only its tier matters.
3. **Two of three checks coincide.** Either drop the rank sweep or give it a
   property the per-row check does not have.
4. **Commit to the liveness successor** (M3's >1-matching-row counter) or do not
   retire `check_tail_precedence`.
5. **Add the ratchets** for module-swap and row-deletion, or state that
   `tests/reject/` remains their only guard and that MOD-0.1 does not improve it.
6. **The returning-doorway fix is four call sites across three doorways**, and
   the escape pair is UB. Fix all, or state which are left and why.
7. **Rule on the step boundary.** All 18 tailed rows are in the 4 multi-row
   buckets (22 rows); `ext.c` never reads `.tail`, and only three files do — so
   the migration is cheaper than the row count suggests.

### M5 (re-run, narrow brief) — the signature parameter is `tail`, not the row

Answered by enumerating all 22 rows in the four multi-row buckets rather than
from principle. **No row's recogniser needs any field but `tail`.** The argument
against `const RegRow *self` is not that a row needs less, it is that:

- a recogniser able to read `self->module` becomes a second, contradictable home
  for a TIER 2 fact, which is what D29's "a recogniser does NOT return the
  module" and D24 both exist to prevent — and **the rank/ambiguity guard polices
  ANSWERS, not which fields a function consulted to produce one**, so nothing
  would catch the drift;
- the one bucket with real complexity — `(?-`'s ten digit rows, where `\12` is
  octal-or-backreference by running capture count — is out of a pure
  recogniser's reach REGARDLESS of signature (D30 §6 rejects widening it to
  carry parse progress). So it argues for a THIRD kind of input handed to the
  SEMANTIC port only, not for handing recognisers the row.

**Disposition 8: the last parameter is `const char *tail`.**

### The gap this panel did NOT close, stated rather than glossed

**The reachability measurement is the author's own and was never independently
reviewed.** The critic assigned to attack it produced only a header, twice, on
two differently-scoped briefs. So the finding that D30 §2 is false rests on ONE
measurement by the person who wanted it to be interesting — which is exactly the
shape this project distrusts everywhere else. It should be reproduced by someone
else before D32 relies on it. The raw probe corpus and classifier are kept for
that purpose.
