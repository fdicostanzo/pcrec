## Findings and dispositions

### MOD07-1 — TIER 1. `--explain`/`--probe-ask` segfault when a producing module is enabled

`build/pcrec --features modifiers --explain '(?i:[)'` → SIGSEGV (139):
`doorway_call` (and `pcrec_probe_ask` before it) memsets a Ctx and never
setjmps, so a port that reaches `pcrec_parse_body` longjmps through
`ctx_fail` into an uninitialized `jmp_buf`. Nine option letters × any
failing body reproduce; `--features all --probe-ask result -- '(?i:[)'`
crashes identically, dating the defect to the first result-producing port
(MOD-0.3c/0.5c), two milestones before the surface was rewritten. The
compile path is correct throughout. The extracted function CARRIES the
comment naming this exact obligation ("none may ctx_fail … the first
enabled, result-producing module port must revisit here, with a probe that
is false the day before") — the obligation had already come due when slice 1
moved the code. Critic's generated sweep: 0 crashes closed-gate (1270
probes), 9 crashes under `--features all`, all in the `(?X:[)` shape.

**DISPOSITION: FIX THIS SESSION** (mod08fix lane): setjmp guard on the
probe/explain Ctx so `ctx_fail` renders as an honest error answer on both
surfaces. Pins written first and watched crashing (false the day before),
then the fix; the critic's sweep shape re-run at both gate states to zero
crashes. No K number — found and fixed at the same checkpoint. The
carried-forward stale comment is rewritten as a discharged obligation.

### MOD07-2 — TIER 2. The agreement clause dissents on a CORRECT tree once the gate opens

`--features modifiers --explain '(?J)'` → `DISSENT: attribution: declared
'modifiers', live names 'named-groups'`, exit 3, stderr asserting "this is a
pcrec defect" about a tree whose behavior is pinned CORRECT in
tests/reject:663-664. Same for `(?m)`→`assertions`. Root cause: §5.2's
census and the clause design are closed-gate; the enabled set is the axis
the design never varied (§5.3 never mentions it). Measured: 0 dissents at
none/classes/verbs; 2 at modifiers/all.

### MOD07-3 — TIER 2. Two clauses switch off silently for producing rows

`put_agreement` short-circuits on non-refusal answers: promise degenerates
to a status read, attribution is not evaluated. case11 pins the producing
`\d` cell as agreement without recording the coverage shrink.

**DISPOSITION for 2+3 (one fix, manager ruling): CLAUSES EVALUATE AT THE
CLOSED GATE.** The agreement predicate is the censused, closed-gate claim;
`--explain` makes the row-canonical clause call at the default enabled set
regardless of `--features`, while the displayed live answers remain
requested-gate DATA. This makes all three clauses total over the table at
every gate state, un-fires (?J)/(?m), and keeps producing rows'
dissent-capability. Additionally assert, per producing row, that its
declared module IS in the enabled set (a real gate cross-check the
short-circuit was skipping past). §5.3 and the syntax_dump header gain the
gate-scope sentence; case11 gains (?J)+(?m) under `--features modifiers`
(agree ok, exit 0 — measured failing today) and keeps the `\d` cell.

### MOD07-4 — TIER 2. `ExtResult.row`'s NULL contract is false in two of its three named cases

`(?` (c2 == -1 aliases REG_SEL_ANY: catch-all stamped, then the c2<0 branch
answers without the row) and the class-bracket delimiter-scan DECLINE
(stamped before the scan) both report a non-NULL elected row for text the
doorway answered without one. "NULL ⇒ no row" holds; the converse does not.
Confined to query-level display + the contract comment (row-canonical
syntaxes never hit these paths; put_agreement handles EXT_NOT_MINE first).

**DISPOSITION: FIX** — null the stamp on both decline/no-row paths so the
contract reads NULL ⇔ answered-without-a-row; comment corrected; case11
pins `(?`'s `live elected none` and the `[[:alpha]` decline (both false the
day before). MOD07-5 (the `select fallback` tag on `(?q)` asserting
unexercised reachability) falls out of the same fix.

### OPTRUN-1 — TIER 2. `(?P` at end of pattern: pcrec denies a construct PCRE2 finds truncated

pcrec: "unrecognized character after (?P" (the no-such-construct sentence);
libpcre2 10.46: **err 114 "missing closing parenthesis" at offset 3**
(manager-verified by fresh probe). R17's bare-`(?` finding one row over —
the sweep-template lesson's FIFTH recurrence: the tail-sweep template
`"%s(?%s%c%s"` always inserts a byte after the prefix and structurally
cannot generate `(?P`. Sole divergence in 48.7M probes of the region.
Unpinned ((?PX and (? are pinned; (?P is not).

**DISPOSITION: FIX** — `(?P` truncated answers the generic unclosed-group
message, exactly as R17 fixed bare `(?`; reject pin failing-first; and per
the R18 linked-pair rule the PC-3 tail sweep gains TRUNCATED completion
shapes in the same change (see OPTRUN-B1), fix before extension.

## Reflection

Two lessons for the list. (1) **A carried-forward comment is a carried-
forward obligation**: slice 1 moved a function whose own comment said "the
first producing port must revisit this", two milestones after that port
landed — extraction should have triggered the revisit, and the tier-1 sat
exactly there. (2) **An axis your census never varied is an axis your
clauses are wrong about**: the agreement predicate was designed, censused
and validated entirely at the closed gate, and both tier-2 clause defects
live at the first open-gate cell. The check-design memory's rule
("what does this claim when the population it was written for changes?")
now has a gate-shaped instance.
