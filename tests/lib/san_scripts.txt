# tests/lib/san_scripts.txt — [TT-9] THE ONE SUITE LIST for `make ubsan`,
# `make asan` and `make san`. All three targets read this file rather than
# carrying their own copy of the `for s in ...; do` list, which is what let
# them silently disagree before this file existed: wave B+C's first patch
# added tests/recursion/run_recursion_diff.sh to `ubsan`'s list only, and
# `san` (added later, copied from `asan`) never ran it — nobody's `make san`
# ever instrumented that script until the copies happened to be reconciled
# by a later, unrelated edit. A single manifest makes that class of drift
# impossible BY CONSTRUCTION: there is only one list to edit and only one
# list any of the three targets can read.
#
# WHY A MANIFEST FILE, not a Makefile variable (docs/testing.md "Sanitizer +
# lint battery" has the full note). The list needs TWO independent readers —
# the Makefile's own `for s in $(SAN_SCRIPTS); do ... done` shell loop, and
# tests/codegen/run_codegen_tests.sh's [TT-9] structural check below, which
# must read the SAME list from bash without parsing Makefile syntax (the
# K35 lesson: a control sharing no source with what it controls is the only
# kind that catches anything). A plain manifest is one `grep -v '^#'` away
# in either language; a `$(shell ...)`-derived Makefile variable would still
# need a text file underneath for the bash reader to share, so the file IS
# the source either way — this format just stops pretending otherwise. Same
# shape as [SR-11]'s table_contract.md manifest and mlscan.py's self-
# contained rule table: one file, two readers, never a transcription.
#
# One tests/**/*.sh path per line, relative to the repo root. Blank lines
# and `#`-comment lines are ignored by both readers.
