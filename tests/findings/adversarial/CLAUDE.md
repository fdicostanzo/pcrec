# tests/findings/adversarial/ — the ADVERSARIAL ANALYSES ([FINDINGS] B2)

GENERATED by `../gen_adversarial.py gen` (never edit by hand; re-run it and
commit the output). Design §11.1: bundles built to be as wrong as a bundle
can be, so that "findings change SPEED, never an ANSWER, never a GIVE-UP" is
checked against tables that actually move the readers. Every bundle declares
`serves byte-rate when byte,utf8`, so the `utf8` arms the shipped default
leaves at NONE are exercised too.

## Files

- `uniform.rxt`, `inverted.rxt`, `onehot-e.rxt`, `onehot-80.rxt`,
  `floor-but-one.rxt`, `random-20260927.rxt` — the fixed SHAPES (each
  file's header says what it is).
- `fire-c1.rxt` … `fire-c4.rxt` (`c1`, `c2a`, `c2b`, `c3`, `c4`) — ONE PER
  READER: the candidate table that moved THAT reader's stamp on the most
  artifacts of the census sample (its header names the winning candidate and
  its count). One per reader because one `fire-all` table cannot maximise
  five readers' choices at once.
- `census.tsv` — every candidate's per-reader move count over the fixed
  1,200-config sample (hash order) of the reader-bearing corpus.
- `reach.tsv` — for each fire bundle, up to 25 (pattern, encoding) artifacts
  its reader moved on; `gen_adversarial.py reach` re-measures them under
  `make test` (`run_findings_tests.sh` §7), and a zero is red.

The whole directory is the FINDINGS axis of `make test-axes`
(`AXES=--analysis`, or `--analysis=NAME` for one) and the sampled slice of
`run_findings_tests.sh` §10.

Maintenance: update this file when files are added/removed or their roles
change.
