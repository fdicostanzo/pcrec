# tests/harness — test execution engine

Test runner and driver template. The runner (run.sh) orchestrates compilation and execution; the driver (driver.c) template is linked against generated code and exercises the matcher.

## Files

- **run.sh** — bash harness: parses .rxt, compiles patterns with pcrec, builds test executable, runs driver against each case, diffs output. Honours the per-block `flags` directive (only `i` -> `pcrec -i`) and the per-block `features` directive (MOD-0.3c: `features classes` -> `pcrec --features classes`; the SPEC is validated once per distinct list against a trivially-valid pattern, because pcrec refuses an unknown module name with exit 1 and a perr block would read that typo as its expected rejection); an unknown flag letter is a hard error rather than a silent no-op, since a dropped flag would compile a different automaton and verify the block against it. Hardened per R1 review: perr requires clean exit 1 (crash != rejection), unparseable lines and zero-case files are hard failures, per-stage timeouts, -Wall -Wextra -Werror on generated code. `PROCS=N` (2026-08-12) fans out per-FILE workers (self-reinvocations, own temp dirs, output replayed in file order); the parent judges workers ONLY by their printed summaries and hard-fails when one vanishes — validated in the failing direction by deleting a worker's output (guard fires, exit 1) and by a planted wrong expectation (propagates with its detail line). Serial and PROCS=6 runs measured identical: 1139/0/0 over 25 files, 4m25s → 55s. **[M4.5a] (2026-08-14):** parses `g`/`gp` capture-group expectation lines (attached to the preceding `m`/`ms` case's `case_gspec[i]`, "slot,start,end,pending;..."); reads each block's actual `RX_NCAPS` straight from its generated `gen.h` (never assumed); a `g` (live) line whose slot is `>= RX_NCAPS` is a hard FAILURE (population accounting, never a silent skip), a `gp` (pending-VM) line in the same position is counted in a separate `group cases pending-vm:` bucket instead — printed in both the serial and the `PROCS>1` aggregated summary. A block-level compile/build failure fails every attached `g`/`gp` too (`record_case_group_fail`), `gp` included — see docs/testing.md's "Capture-group expectations" section for the full design and sabotage-validation record. **Fix (2026-08-15, post-merge with [M4.5b]):** the `m`/`ms` case check now compares only the WHOLE-MATCH pair (fields 2/3 of the driver's `match ...` line), not the whole line — the original whole-line compare only ever worked by coincidence while `RX_NCAPS` was 1 (this lane's own test environment before the VM emitter existed) and broke the instant a real artifact delivered group pairs on the same line (219 corpus failures on the composed tree, e.g. `(a)` on `"a"`: expected `match 0 1`, got `match 0 1 0 1`, every number correct). Still a strict parsed-field compare, not a substring match: `match` vs `nomatch`, a short/malformed line, or a wrong whole-match pair (even with correct trailing group pairs) all still fail loudly — sabotage-validated in both directions. **[K21-class fix, 2026-08-15]:** a new per-case branch, `trc -eq 3`, sits beside the existing timeout (`-eq 124`)/crash (`-ge 126`) branches — driver.c's own give-up exit (see its own CLAUDE.md entry) — and records a HARD harness-level failure naming which bound fired, the same shape as those two, rather than letting the give-up's `"steps"`/`"frames"` line fall through to the ordinary `match`/`nomatch` comparison (which would already fail it, just without saying why)
- **driver.c** — test driver template: calls generated matcher (rx_search), decodes escape sequences in subjects, prints match/nomatch result. **[M4.4] (D44.2, 2026-08-14):** consumes the caps-array search signature (`ptrdiff_t (*caps)[2]`, not the retired `rx_span *m` out-struct) and prints `caps[0][0]`/`caps[0][1]` via `%td` (`ptrdiff_t`'s conversion specifier), not `m.start`/`m.end` via `%zu` — textually identical decimal output for the corpus's byte offsets, so no .rxt expectation changes. **[M4.5a] (2026-08-14):** prints EVERY `caps[k][0]`/`caps[k][1]` pair for `k` in `[0, RX_NCAPS)`, not just slot 0 — since `RX_NCAPS` is always 1 before [M4.5]'s VM lands, this is a superset that is byte-identical to before on the whole pre-existing corpus, not a reshape. **[K21-class fix, 2026-08-15]:** `rx_search`'s return is THREE-valued, not boolean — the driver used to test it with `if (found)`, which is C-truthy on the negative VM give-up sentinels (`PCREC_ERR_STEPS`/`PCREC_ERR_FRAMES`, unprefixed since [ABI-NS]/D60) too, so a give-up took the match branch and printed `caps`, which the give-up path never writes (uninitialized stack reported as a confident match — verified live: the pre-fix driver against a tiny `--step-budget` artifact printed a fabricated `match` line with garbage spans). Now discriminates `found == 1`/`found == 0`/otherwise explicitly, printing `"steps\n"`/`"frames\n"` and exiting 3 (distinct from the normal exit 0 and the usage/malformed-input exit 2) on a give-up, so run.sh can — and now does — score it as its own HARD harness-level failure rather than comparing it against a `match`/`nomatch` expectation. Same bug shape as `tests/fuzz/fuzz_driver.c` (fixed, fuzzfix arc) and `src/gen/emit_dfa.c`'s `pcrec_emit_main` (K21, docs/dev/known_issues.md); `tests/registry/pc4_driver.c` still has the untouched `if (rx_search(...))` form as of this fix — a fourth, still-open site, flagged rather than silently patched here since PC-4 is a different subsystem outside this fix's scope. Dormant here today: nothing in the .rxt `flags`/`features` directive vocabulary can select `--engine=vm` or a tiny budget, so no corpus case reaches the give-up path — deliberately not exercised by a new .rxt case (that would require inventing .rxt format features for a single fix)
- **verify_rxt.py** — python-re oracle: cross-checks every corpus expectation (D4); `# pcre2-only` blocks are skipped (see docs/testing.md). Understands the `features` directive as a no-op (python re has no module gate; gate-only constructs are `# pcre2-only` blocks like any python-inexpressible pattern). Honours `flags i` as `re.IGNORECASE | re.ASCII` — the `re.ASCII` is load-bearing, since python's IGNORECASE otherwise folds Unicode (Kelvin sign, long s) and would silently disagree with pcrec's ASCII-only fold. **[M4.5a] (2026-08-14):** checks `g`/`gp` lines against python `re`'s `match.span(<slot>)` on the preceding `m`/`ms` case's subject/startpos, identically for `g` and `gp` (pending-ness is a fact about the pcrec ARTIFACT this oracle has no notion of); a slot beyond the pattern's own `compiled.groups` is always a hard failure

## Conventions

run.sh accepts file/directory arguments or scans tests/ recursively. Each .rxt pattern block is compiled to C, linked with driver.c (which includes the generated code), and executed for each m/n line. The driver decodes \" \\ \n \t \r \f \v \xHH escapes. Output is one line per case: "match START0 END0 [START1 END1 ...]" (one pair per RX_NCAPS slot — just "START END" while RX_NCAPS is 1, i.e. today) or "nomatch", compared against expected results; g/gp lines pick their slot's pair out of that line by position rather than triggering a separate driver invocation.
