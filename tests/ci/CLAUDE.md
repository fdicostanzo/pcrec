# tests/ci — CI's shard table, its control and the cloud machinery ([CI-SHARD], [CLOUD-SUITE])

Lane `cishard`, 2026-10-13. CI's serial `make test` outgrew the hosted 4-vCPU
runner's 90-minute step timeout (`docs/dev/lanes/citime_report.md`: growth,
not a hang). Since lane `ciswitch` (2026-11-11) `.github/workflows/ci.yml` CALLS the reusable
`cloud-test.yml` with `kind: test`: 17 shards of `make test-shard CISHARD=K/17` over `cloud_test_shards.tsv`,
one gather verdict, ~18 min wall (was 3 shards, 52-68 min). `make test` itself is unchanged and stays the
local merge/close standard.

- **workflow_perms_check.py** — `make cloud-check` check 6: every workflow a `uses: ./.github/workflows/X.yml` job calls has all of X's declared permissions (top-level and per-job) granted by the calling job or its caller's top-level block (unspecified = none); cloud_check.sh plants a missing `actions: read` in a scratch copy and requires it named.
- **check_shards.sh** — the control (`make test-ci-shards`, a `TEST_SECTIONS` member): the table
  `cloud_test_shards.tsv` (passed as the default `TABLE`; `cloud_check.sh` points it at each kind's selector) holds every
  `TEST_SECTIONS` member (passed on argv by the Makefile — the list is spelled once, there) in exactly one shard, no
  unknown names, shard numbers in range and non-empty, weights numeric with a source. `--selftest` plants one defect per
  check into copies of the table and requires each red naming its cause. `--list K/N` prints a shard's sections (what
  `make test-shard` runs; also the dry-run: `bash tests/ci/check_shards.sh --list 1/17`).
- **shard_rebalance.py** — the library half (`load`, `measured`, `lpt`) `cloud_plan.py` imports; its own CLI still
  re-weights a table (`--table`, default cloud_test_shards.tsv) from measured files. CI's old 3-shard `shards.tsv`
  is deleted (ciswitch, 2026-11-11).

- **cloud_kinds.tsv** / **cloud_kinds.sh** / **cloud_kinds.test** — [CLOUD-SUITE] B: THE kinds table of a cloud run
  (kind, command template, selector, shards, max_parallel, limit_min, needs, owners) and its one reader. The
  workflow's plan job, `scripts/cloudrun` and `cloud_gather.sh` go through the reader; no code names a kind. A new
  kind is a row.
- **cloud_test_shards.tsv** / **cloud_plan.py** — the `test` kind's shard table, GENERATED by `cloud_plan.py` from the
  `pcrec-ci-sections-*` artifacts of recent green CI runs (median per section; floor sections get a shard of their own;
  N = fewest shards meeting the ~10 min target on 20 slots; header lists the floor). It is THE table CI runs, read by
  `make test-shard` (check_shards.sh `--list`; `CISHARD_TABLE=` redirects it) and regenerated in place (cloud_plan.py
  takes its section names from the table itself; a new TEST_SECTIONS member gets a row by hand first).
- **cloud_gather.sh** / **cloud_gather.test** — the script `.github/workflows/cloud-test.yml` calls (`record` a shard's
  result + its make `*** [...] Error` lines, `gather` ONE verdict: GREEN only if every expected shard has rc 0, a red
  shard printed with its error lines; `slug K/N` = the one artifact-name source; `shards KIND`). The test runs it on
  fabricated results plus the run-1 regressions (artifact naming, no ISA names in tests/).
- **cloud_failures.sh** / **cloud_failures.test** / **fixtures/** — the ONE failing-line extractor (every FAIL form,
  make `*** [...] Error`, FATAL, `##[error]`, sanitizer lines; PASS/OK and `fail=0` tallies are not failures). Used by
  `cloud_gather.sh record` (errors.txt, the verdict), the `CLOUD-SHARD-RED` early alert and `cloudrun --status`; a shape
  one misses is missed by none. The test feeds REAL lines from runs 43053543333 shard 8 and 43069897443 shard 7.
- **cloud_status.py** — live view of one run (`gh api`: run, jobs, a red shard's log once): `status RUNID` is what
  `scripts/cloudrun --status [RUN|BRANCH]` prints (kind, name, shards done/total, elapsed, each red shard + its failing
  lines); `reds RUNID --cache F` is the machine form `scripts/queuewatch` turns into `CLOUD-SHARD-RED` lines (test:
  `scripts/tests/queuewatch_cloud.test`). Red shard = a completed `shard (K/N)` job with failure/timed_out.
- **cloud_check.sh** (`make cloud-check`, opt-in, on change) — the cloud table holds TEST_SECTIONS exactly, no kind named
  in code, ci.yml and cloud-test.yml both call `.github/actions/shard-setup` (the ONE copy of the runner setup; ci.yml's
  steps moved there unchanged), one artifact-name source. Not a TEST_SECTIONS member. ci.yml reaches the cloud machinery through `uses: ./.github/workflows/cloud-test.yml`.
  Run the tests: `bash tests/ci/cloud_gather.test`, `bash tests/ci/cloud_kinds.test`, `bash tests/ci/cloud_failures.test`.
- **cloud_axes_shards.tsv** / **cloud_san_shards.tsv** / **cloud_units_plan.py** — [CLOUD-SUITE] C: the shard tables of the
  `axes`, `ubsan` and `asan` kinds, GENERATED by `cloud_units_plan.py axes|san` (axes: `AXES_PLAN=1` listing + a local
  axes.log's per-job seconds, x2 for a 4-core runner with run_axes' job pairing, LPT over units; san: the CI-measured
  `make test` section of each script as a labelled proxy). A table row is a UNIT: the `AXES=` words that must travel
  together (`--engine -fno-start-set`, the start-width/landing pair, `--tune` as DIAL-S3 needs all positions) or one
  sanitizer script. `cloud_table.sh` is their one reader.
- **cloud_axes_shard.sh** / **cloud_san_shard.sh** — what one shard runs (the kinds table's `command`): the axes wrapper
  exports `AXES=` the shard's words (+ `AXES_FULL=1 HARNESS_BATCH=64`; shard 1 alone adds giveup1, the PC-4 oracle and
  the census); the sanitizer wrapper probes the runner's sanitizer runtimes (loud fail) then runs the Makefile's locked
  target with `SAN_SCRIPTS=` the shard's scripts.
- **cloud_axes_check.sh** / **cloud_san_check.sh** — the kinds' `population` checks (`--selftest` plants a dropped, a
  duplicated and a split-group unit): the shards' sum equals the unsplit sweep (`run_axes.sh` under `AXES_PLAN=1` prints
  the jobs/passes a given `AXES=` would run) or `tests/lib/san_scripts.txt`, each exactly once. Regenerate the table
  (`cloud_units_plan.py ... --write`) when a job or script is added.

- **cloud_units.py** / **cloud_measure.py** / **cloud_reweight.sh** / **measured_{test,axes,ubsan,asan}.tsv** — the reweigh
  process below: the per-unit record a shard leaves, the measurer, the one entry point, the committed measured times.

- **cloud_mech_shard.sh** / **cloud_mech_check.sh** / **cloud_mech_shards.tsv** — [CLOUD-SUITE] D: the `mech` kind. A unit is one
  S-id (the file name before its first `_`, as the driver's id arguments spell it); the wrapper runs the shard's ids through
  `tests/mech/run_sabotage_matrix.sh` (`PCREC_BOXLOCK=0`, rows from the runner's checkout of the pushed commit), records per-row
  seconds (`MECH_TIMES_OUT` -> `units.tsv`), names UNEXPECTED/ANOMALY rows as `FAIL:` lines for the extractor and refuses a missing
  or short `== mech run COMPLETE` trailer. Table by `cloud_units_plan.py mech` from run 43108213213's measured rows (/2: a shard runs 2 rows at once; unmeasured rows take the mean, 185 of them). A shard killed at its step limit leaves the finished rows in `units.tsv`; the gather reads `rc=none` as `TIMEOUT` naming the unfinished ones. `SAB_CATCH_OPTIONAL=1` (a row field): a COMPILE-CATCH row whose checks detect it but whose compile catch did not fire reads DETECTED (S1896: the cloud runner has the same gcc 15.2 as the dev box yet compiles the fortify cell).
  The `recidentity` kind is one shard (`selector -`): `make test-recursion-identity`, history from `fetch-depth: 0`.
- **cloud_infra.py** — INFRA vs RED: a shard job whose test step passed and whose upload step failed. The gather names such
  shards `INFRA` (`VERDICT INFRA`), `cloudrun --verdict` says INFRA-RERUN/INFRA, `queuewatch` reruns once, then `CLOUD-INFRA`.
  Test: `cloud_gather.test` (13) on the real fixtures, `scripts/tests/queuewatch_infra.test`.
- **`# extras=` in cloud_test_shards.tsv** — opt-in gates (`cloudgate-strict`, `cloudgate-lint`: Makefile targets, NOT
  TEST_SECTIONS members) in ONE shard of their own; `check_shards.sh` check 6 and `cloud_check.sh` hold the shape.
- **`suite` column** of cloud_kinds.tsv — `scripts/cloudrun --suite` dispatches every kind with 1 (the cloud full suite, one
  commit); relation to the local battery: docs/testing.md "[CLOUD-SUITE] D".

Per-section timestamps in CI come from `scripts/sectiontimes` over
`make --debug=j` (the mechanism `scripts/perfrun` already used), uploaded as
`pcrec-ci-sections-*` on success and failure. Design record and the weights'
basis: `docs/dev/lanes/cishard_report.md`; CI shape: `docs/testing.md` "CI".

## Reweighting the cloud shard tables (the periodic step)

**Who/when.** The manager (or the kit) runs it when a verdict carries `REWEIGHT-DUE kind=K slowest=..s plan=..s`
(`cloud_gather.sh`: the kind's slowest shard step ran more than `reweight_margin` percent over the table's
`# predicted_shard_s`), when a section/axis job/sanitizer script is added or its cost moves, and otherwise after a
batch of runs (about monthly). The tables are measured, not estimated, so a stale one is the only way a shard goes
slow; the margin (cloud_kinds.tsv, UNMEASURED default 25) is a first guess to be tuned from the spread a table shows.

**Process (five lines).** 1) `make cloud-reweight KIND=all MEASURE=1` (or `bash tests/ci/cloud_reweight.sh all --measure`):
`cloud_measure.py` pulls the last N completed runs of each kind (`gh run list/download`), takes each shard's `units.tsv`
(written by its record step: per section, per axes job, per sanitizer script, plus `@wall`/`@baseline`/`@build`), median
over runs, into the committed `tests/ci/measured_KIND.tsv` (provenance header: run ids, dates, runner CPUs; only rc-0
shards count). 2) The kinds table's `reweigh` column runs the generator (`cloud_plan.py` for test, `cloud_units_plan.py`
for axes and the sanitizers, whose two kinds share one table and average their files) on those files; a unit with no
measurement keeps an ESTIMATE, flagged in `weight_source` and in the `# unmeasured:` header line. 3) The table header now
carries `# predicted_shard_s=`, `# predicted_wall_s=`, `# indivisible_floor_s=` (setup + baseline + the largest unit);
`DRY=1` prints the plan and writes nothing. 4) `make cloud-check` validates (population, no kind named in code); run
`bash tests/ci/cloud_gather.test`. 5) Commit the measured files and the tables together; one `scripts/cloudrun` run
confirms. `--apportion` (cloud_measure.py) splits a shard's wall over its units for a run that predates the per-unit
record; basis `apportioned` in the file. CI runs the `test` kind's table, so a reweigh moves CI's shards too.
